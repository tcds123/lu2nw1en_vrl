Ensure Instructions are Logically Coherent and Free of Unnecessary Restrictions

**When to apply**: When synthesizing or revising a complex prompt that has accumulated multiple requirements. When a prompt feels "over-engineered" with arbitrary rules.
**What to do**: Read the prompt as a whole to ensure all parts are logically compatible. Remove any restrictions that do not directly contribute to the correctness, safety, or specified format of the output (e.g., banning certain language features without reason).
**Example**: *Instead of* "Write a sort function. Do not use the built-in `sorted()`. Also, do not use any loops. Output must be in JSON format." *say* "Implement a custom sorting function `custom_sort(arr)` without using the language's built-in sort functionality."
**Why it works**: Contradictory or impossible restrictions (like sorting without loops) can cause the model to fail entirely or produce nonsensical code. Streamlining the prompt to its core, coherent requirements removes cognitive noise and allows the model to succeed.
