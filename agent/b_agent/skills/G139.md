Mandate a Complete Docstring with Specific Sections

**When to apply**: For any function or class that is non-trivial, has multiple parameters, or complex return values. Essential for generating code that is self-documenting and ready for use in a larger project.
**What to do**: Require a docstring formatted with specific, named sections. At a minimum, specify `Args:` (or `Parameters:`), `Returns:`, and `Raises:` (if applicable). Optionally, include an `Examples:` section with doctest-compatible examples.
**Example**: "Provide a complete docstring for the function with the following sections: `Parameters:`, `Returns:`, `Raises:`, and `Examples:` with a brief doctest."
**Why it works**: Models often generate minimal or missing documentation. By specifying the exact sections, you ensure the generated code includes structured documentation that clarifies the intent, types, and behavior, making it immediately usable and testable.
