Explicitly Define Behavior for All Critical Edge Cases

**When to apply**: For problems involving input validation, empty collections, boundary values (like zero, one, or maximum size), or degenerate data (e.g., all identical elements, already sorted data).
**What to do**: List the specific edge cases that the implementation must handle correctly. For each, state the expected output or behavior. Do not assume the model will infer these from the core logic; state them explicitly.
**Example**: "Your function must handle: 1) an empty input list (return an empty list), 2) a list with a single element (return that element), and 3) a list where all elements are negative (return the maximum single element)."
**Why it works**: Code generation models often produce solutions that work for the "happy path" example but fail on edge cases. Explicit enumeration directs the model's attention to these cases, ensuring robustness and preventing common oversights.
