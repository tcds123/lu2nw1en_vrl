Prioritize Instructions: Signature, Logic, Formatting

**When to apply**: For all function or class generation tasks. Especially critical when the problem has multiple components (e.g., specific algorithm, error handling, and a strict output format).
**What to do**: Structure the prompt in a strict, linear order. First, define the complete function signature (name, parameters, return type). Second, describe the core algorithmic or logical requirement. Third, and only after the logic is clear, specify formatting, style, or auxiliary requirements.
**Example**: "1. Define the function: `def find_median(arr: list[int]) -> float:`. 2. Implement logic to find the median value of the input list without using built-in sorting. 3. Ensure the function includes a type hint for the return value and is contained within a single code block."
**Why it works**: Models process instructions sequentially. Presenting the signature first anchors the response structure. Delaying formatting rules prevents them from interfering with the model's understanding of the primary task, reducing the chance of syntax errors or missing core logic.
