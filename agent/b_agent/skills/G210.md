Concisely Specify Core Algorithmic or Structural Constraints

**When to apply**: When the solution must employ a specific programming paradigm (recursion, dynamic programming), data structure (use a heap, avoid using a set), or type-checking approach. The goal is to mandate the "how" without writing the code for the model.

**What to do**: State the constraint in a clear, imperative sentence. Avoid wrapping it in excessive justification or jargon. Use direct language like "must use recursion," "must check types using `isinstance`," or "must implement the algorithm in-place."

**Example**: "You must implement this function **recursively**. Do not use iterative loops (`for`, `while`). Use `isinstance()` to check if an element is a list. The base case should be an empty list."

**Why it works**: Without this directive, the model will default to the most common or simplest pattern it has seen in training (often iterative loops). Explicitly stating a non-default constraint (like recursion) overrides this tendency and guides the model towards the required algorithmic structure.
