Enforce Code Quality with Positive, Non-Restrictive Instructions

**When to apply**: For all code generation tasks where maintainability, readability, and adherence to community standards (like PEP 8) are valued, but without crippling the model's ability to use fundamental language constructs.

**What to do**: Instruct the model to write clean, well-documented code by specifying positive requirements: use meaningful variable names, include a docstring, follow PEP 8 conventions. Avoid negative, absolute prohibitions (e.g., "do not use loops") that conflict with idiomatic Python or basic problem-solving.

**Example**: "Write a Python function with a descriptive docstring explaining its purpose, parameters, and return value. Use clear, intention-revealing variable names (e.g., `max_profit` instead of `mp`). Structure the code according to PEP 8 guidelines for indentation and spacing."

**Why it works**: Models can over-interpret negative commands, leading to syntactically invalid or bizarre workarounds (e.g., using `map` and `lambda` to avoid a forbidden `for` loop). Positive instructions guide style without breaking the logical flow or standard syntax.
