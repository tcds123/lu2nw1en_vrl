Maintain Absolute Consistency in Specifications, Especially for Error Handling

**When to apply**: When defining behavior for edge cases, invalid inputs, or system constraints. Crucial when multiple valid approaches exist (e.g., raise exception vs. return -1).
**What to do**: Choose a single, unambiguous strategy for handling ambiguous or exceptional situations and state it clearly. Do not provide alternative options. Apply this strategy consistently across all similar scenarios mentioned in the prompt.
**Example**: "If the input is invalid (e.g., non-numeric characters), the function must raise a `ValueError` with the message 'Invalid input'. Do not return a sentinel value like `-1` or `None`. All error conditions must use this `ValueError` approach."
**Why it works**: Without a consistent directive, models may implement a mix of error-handling paradigms (exceptions, sentinel values, silent failures) within a single solution, creating unpredictable and difficult-to-evaluate behavior.
