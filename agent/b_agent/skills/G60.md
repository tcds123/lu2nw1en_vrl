Align Prompt Scope with Actual Requirements to Avoid Over-Specification

**When to apply**: When the core task is well-defined but there is a temptation to add "nice-to-have" features, specify internal data structures, or impose design patterns not required for correctness.
**What to do**: Scrutinize the original problem. Include only what is necessary to satisfy the functional requirements and pass the tests. Do not specify implementation details (e.g., "use a heap") unless it is an explicit requirement of the problem.
**Example**: For a task to "merge two sorted lists", the prompt should be: "Write a function `merge_sorted(list1: List[int], list2: List[int]) -> List[int]` that returns a new sorted list containing all elements from both input lists." It should *not* add: "You must implement the merge step of merge sort in-place without using extra space."
**Why it works**: Over-specification limits the model's ability to find a valid solution and can introduce conflicts. If the tests only check the output, a model forced to use a specific, suboptimal algorithm might fail on edge cases (e.g., large inputs) where a simpler approach would have passed.
