Prioritize Core Logical Accuracy Over Stylistic Polish

**When to apply**: When the correctness of the algorithm, mathematical formula, or business logic is paramount. When dealing with complex rules, subtle edge cases, or non-intuitive transformations.

**What to do**: In the prompt, explicitly de-prioritize code style, advanced language features, and premature optimization. Emphasize that getting the fundamental logic and correct outputs is the primary goal. You can ask for clean code *after* correctness is assured.

**Example**: "Focus entirely on implementing the correct business logic for tax calculation. It is more important that the amounts are computed accurately according to the brackets than that the code uses list comprehensions or follows PEP 8 line length. We can refactor for style later."

**Why it works**: Models are trained on well-formatted code and often prioritize generating idiomatic, "pretty" solutions. This can lead them to use elegant but incorrect constructs (e.g., a slick one-liner that fails on edge cases). This instruction shifts the model's priority to robustness and accuracy, which is often the harder and more critical task.
