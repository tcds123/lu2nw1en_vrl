Impose Strict Constraints but Preserve Flexibility

**When to apply**: When you need to enforce a specific challenge (e.g., no built-in functions, O(1) space) but the algorithmic approach should not be micromanaged. This is common in educational or interview-style prompts.
**What to do**: Clearly state the prohibitive constraint. Then, use open-ended language for the implementation. Avoid coupling the constraint with a specific method that would satisfy it.
**Example**: "Reverse a string in-place. Strict Constraint: Do not use any built-in reversing functions or libraries. Do not allocate a new string for the result. The choice of algorithm (two-pointer swap, etc.) is yours."
**Why it works**: A prompt like "don't use built-in functions, use a two-pointer swap" is contradictory—it bans one method but prescribes another. Separating the "ban" from the "method" gives the model a clear problem space to explore, yielding valid and varied solutions that still meet the core constraint.
