Provide Technical Constraints Without Step-by-Step Implementation

**When to apply**: When the problem tests for specific algorithmic efficiency (O(n log n)) or bans certain data structures; when you need to guide the model away from a naive solution without giving away the answer.
**What to do**: State the complexity requirement or algorithmic family as a constraint. Do not describe the steps of the algorithm (e.g., "first, take a pivot...").
**Example**: "Write a function `find_pair_sum(nums: List[int], target: int) -> Tuple[int, int]`. You must implement a solution that runs in O(n) time complexity and uses O(n) extra space. A naive O(n²) solution is not acceptable."
**Why it works**: Providing a step-by-step recipe risks truncation (if the instruction is too long) and overly constrains the model, potentially preventing it from finding a valid alternative implementation. Stating the goal (O(n) time) allows the model to select an appropriate algorithm (hash map) itself.
