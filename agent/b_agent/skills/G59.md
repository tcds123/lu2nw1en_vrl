Avoid Redundant Instructions to Maintain Focus

**When to apply**: When a requirement is already implied by the function signature, standard practice, or a previously stated, broader rule. When the prompt becomes repetitive.
**What to do**: Review the prompt and remove instructions that restate the obvious. For example, if the signature is `def func(x: int) -> str:`, do not add "the function should take an integer and return a string". Instead, use that space for non-obvious constraints.
**Example**: Instead of "Write a function `def add(a: int, b: int) -> int:` that takes two integers `a` and `b` and returns their sum as an integer.", write: "Implement `def add(a: int, b: int) -> int:` to return the sum of `a` and `b`."
**Why it works**: Redundant text adds noise, increasing the chance the model will overlook a critical, unique constraint buried in the verbosity. Concise prompts direct the model's attention more effectively to the important, non-inferential parts of the task.
