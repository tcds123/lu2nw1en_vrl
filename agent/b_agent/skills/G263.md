Define Persona, Signature, and Return Behavior Upfront

**When to apply**: When the prompt involves role-playing (e.g., "You are a Python expert") or when the return behavior is more complex than a simple value (e.g., printing vs. returning, generator behavior).
**What to do**: Start by establishing a concise, relevant persona. Immediately follow with the exact function signature. Then, explicitly state the return behavior: whether the function must `return`, `yield`, `print`, or modify an argument in-place.
**Example**: "You are an efficient data processing engineer. Implement `def batch_process(items: list, batch_size: int) -> list[list]:`. The function must return a list of sublists, where each sublist is a batch of the original items."
**Why it works**: Without a clear persona, models may adopt an inappropriate tone or add explanatory comments. Ambiguity in return behavior leads to common errors like a function that prints instead of returning, making it untestable. This upfront clarity sets the correct mode and output contract.
