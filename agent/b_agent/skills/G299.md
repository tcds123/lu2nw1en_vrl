Define Function Signature and I/O with Concrete Examples

**When to apply**: For any function or class implementation task. Critical when input can be ambiguous (e.g., list of strings vs. comma-separated string) or when the output format is specific (e.g., return a list of tuples, not a generator).

**What to do**: Explicitly state the function name, its parameters with types, and the exact return type. Provide at least one clear input/output example that illustrates normal operation and, if relevant, an edge case. Show the literal call and result.

**Example**: "Implement `def parse_commands(log: str) -> Dict[str, int]`: The function takes a multiline string `log`. Each line is a command like 'start foo' or 'stop bar'. Return a dictionary where keys are command names and values are their total execution counts. Example: Input log = 'start foo\nstop foo\nstart bar' should return `{'foo': 1, 'bar': 0}`."

**Why it works**: Models often infer incorrect signatures or output formats. Concrete examples serve as an unambiguous specification and a test case, grounding the model's understanding and reducing ambiguity about what "correct" looks like.
