Guide Reasoning with Concise, Non-Conflicting Instructions

**When to apply**: When prompts are long and winding, contain multiple "if-then" style caveats, or use negations and exceptions that create complex logical dependencies for the model to parse.
**What to do**: Structure the prompt as a short series of clear, positive statements. Group related constraints. Avoid double negatives and exceptions to exceptions. If complexity is necessary, use a bulleted list for constraints and a separate section for examples.
**Example**: Instead of: "You shouldn't not handle empty inputs, unless the input is a string, in which case you should return an empty string, but not None. But for lists, don't return an empty list if you can avoid it, but actually, do return an empty list." Use: "Handle edge cases: For an empty string input, return an empty string. For an empty list input, return an empty list."
**Why it works**: Overly complex or negatively-framed instructions can cause "generation paralysis," where the model struggles to reconcile all clauses and produces overly cautious, incorrect, or no code. Simple, affirmative instructions reduce cognitive load on the model, leading to more confident and correct code generation.
