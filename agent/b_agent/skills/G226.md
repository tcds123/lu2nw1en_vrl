Explicitly Mandate Error Types and Messages for Invalid Input

**When to apply**: When function inputs have preconditions that must be validated (e.g., negative numbers, malformed strings, empty lists, out-of-bounds indices). Critical for building robust APIs or following specific error-handling contracts.

**What to do**: Directly instruct the model to raise a specific exception type (e.g., `ValueError`, `TypeError`, `AssertionError`) with a descriptive, human-readable error message. State the exact condition that triggers the error. Avoid passive language like "handle invalid input."

**Example**: "If the input parameter `n` is less than 0, the function must immediately `raise ValueError('Input n must be a non-negative integer.')`. Do not return a sentinel value like -1."

**Why it works**: Code generation models default to silent failures, returning `None` or a special value, or printing a message instead of raising exceptions. Explicitly demanding a specific exception ensures the generated code integrates properly with standard Python error-handling paradigms (try/except blocks) and provides clear, actionable feedback to the caller.
