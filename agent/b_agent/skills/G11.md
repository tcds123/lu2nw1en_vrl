Balance Specificity: State Key Requirements Without Redundant Repetition

**When to apply**: When the user's query already describes the main problem, but critical details about edge cases, error handling, or output format are missing or implicit.
**What to do**: Augment the user's query by explicitly stating the *additional* requirements that are essential for correctness. Do not simply rephrase the original problem. Focus on clarifying ambiguity, specifying edge case behavior, and defining exact output formats.
**Example**: User query: "Write a function to divide two numbers." Enhanced prompt: "Write a function `safe_divide` that takes two numbers. **Explicitly require it to handle division by zero by returning `None` and to return a float even for integer inputs.**"
**Why it works**: Models will often generate a naive solution that addresses only the obvious case from the user's description. By injecting precise, non-redundant requirements, you guide the model to consider the full scope of the problem, preventing common oversights.
