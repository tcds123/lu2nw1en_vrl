Define Mandatory Output Formatting and Documentation Constraints

**When to apply**: When the generated code must integrate into a larger codebase, adhere to a specific style guide, or include documentation for automated tools.
**What to do**: Specify the exact format of the output code block. Mandate the inclusion and style of docstrings (e.g., Google, NumPy). Define required sections (Parameters, Returns, Raises). Indicate if type hints, specific imports, or a particular code structure (e.g., a class with specific methods) are required.
**Example**: "Provide the complete Python code in a single code block. The function must include a Google-style docstring with `Args:` and `Returns:` sections. Use type hints for all parameters and the return value."
**Why it works**: Models often omit documentation or use inconsistent formatting unless explicitly instructed. This ensures the output is not just functionally correct but also meets project standards for maintainability and tooling compatibility (e.g., Sphinx autodoc).
