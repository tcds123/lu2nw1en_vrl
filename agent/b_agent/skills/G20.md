Pair Error-Handling with a Requirement for Correct Numerical Results

**When to apply**: When the task involves calculations or data processing where invalid inputs are possible, but the primary goal is to compute a correct result for valid data.
**What to do**: First, state the expected mathematical or logical outcome for standard, valid inputs. Then, specify how errors (e.g., invalid types, out-of-range values) should be handled, ensuring the instructions don't imply that error handling is the *only* requirement.
**Example**: "Implement a function `divide_safe(a: float, b: float) -> float:` that returns `a / b`. For valid inputs, it must return the correct floating-point quotient. If `b` is zero, raise a `ValueError` with the message 'Division by zero'."
**Why it works**: Models sometimes over-index on error-handling instructions and produce code that *only* validates inputs and raises errors, missing the core computation. This pairing ensures the model generates a fully functional solution, not just a input validator.
