Enforce Algorithmic Constraints with Explicit, Concise Rules

**When to apply**: When the solution must meet specific performance (O(n) time, O(1) space), style (no list comprehensions), or resource (no imports) constraints. Common in competitive programming, interview problems, or optimized core functions.

**What to do**: State constraints as clear, imperative rules. Use definitive language like "must," "cannot," "only." Specify the allowed operations, data structures, and complexity bounds. Place these rules before the implementation request.

**Example**: "You must solve this in O(n) time with O(1) extra space. You cannot use `sorted()` or any other function that creates a new list. You can only use a single loop and two integer variables to track state."

**Why it works**: Without explicit constraints, models will often generate the most straightforward or Pythonic solution, which may violate hidden requirements (e.g., using `collections.Counter` when imports are forbidden, or using slicing which creates O(n) space). This directive overrides the model's tendency to optimize for readability over efficiency or specific rules.
