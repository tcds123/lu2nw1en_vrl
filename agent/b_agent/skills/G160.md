Balance Strict Formatting with Syntactic Completeness

**When to apply**: When you need a very specific output format (e.g., for direct integration into a codebase or autograder) but also need to avoid truncated or nonsensical generation.
**What to do**: Pair a strict formatting command with a clear, non-negotiable requirement for syntactic and logical completeness. Emphasize that the formatting rule does not override the need for a fully implemented solution.
**Example**: "Output only the final function definition, with no additional text. However, the function definition must be complete, including its body, correct return statements, and all necessary internal logic. Do not output placeholder comments like `# your code here`."
**Why it works**: Models sometimes interpret "output only the function definition" as an instruction to output *just the signature* or to leave the body empty. By explicitly demanding completeness *within* the strict format, you prevent this common truncation error.
