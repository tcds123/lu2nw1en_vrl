Prioritize essential functional requirements over stylistic preferences, and place stylistic rules after the core task is established

**When to apply**: When both functional and stylistic rules are necessary, but functional correctness is paramount. This refines G31 by providing an ordering strategy.
**What to do**: Structure the prompt in two clear parts. Part 1: The command, function signature, core logic, and input/output rules. Part 2: A separate sentence or bullet with stylistic notes (e.g., "Follow PEP 8," "use descriptive variable names").
**Example**: "Write a function `count_vowels(text: str) -> int` that returns the number of vowels (a, e, i, o, u) in the input string, case-insensitively. After implementing the core logic, ensure the code adheres to PEP 8 guidelines."
**Why it works**: This sequential ordering mirrors how a developer thinks: solve the problem first, then clean up. It prevents the model from conflating style with function and potentially making a functional compromise to meet a stylistic rule mentioned early.
