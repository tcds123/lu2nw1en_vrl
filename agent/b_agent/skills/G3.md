Preserve Input Order Unless Explicitly Allowed to Sort

**When to apply**: When processing sequences where original order carries meaning (e.g., processing log entries, maintaining insertion order, implementing a cache). Often needed in tasks involving deduplication, filtering, or grouping where the naive approach is to sort.

**What to do**: Explicitly state that the original order of elements in the input must be preserved in the output. Forbid the use of operations that implicitly reorder, like `set()` (which has arbitrary order) or `sorted()`, unless they are explicitly required for an intermediate step and the final order is restored.

**Example**: "You must preserve the relative order of elements from the input list in the output list. Do not use `set()` or `sorted()` if they would destroy the original order. Duplicates should be removed so that the first occurrence is kept."

**Why it works**: Models frequently use `set()` for deduplication or `sorted()` for grouping without considering that these operations destroy order. This instruction forces the model to choose order-preserving algorithms (e.g., using a `dict` or `OrderedDict` as a seen-check).
