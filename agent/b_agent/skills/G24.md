Explicitly Define Input Mechanism and Output Format

**When to apply**: When the problem involves reading data (not just function parameters) or producing output for a judge/system (e.g., competitive programming, script tasks).
**What to do**: Precisely state how input is provided (e.g., "read from standard input", "passed as function argument `grid`") and the exact format of the output (e.g., "print the result as a single integer", "return a list of tuples").
**Example**: "Read an integer `N` from standard input, then read `N` lines of strings. For each string, print its length on a new line. Do not prompt for input."
**Why it works**: Models often default to a convenient but incorrect I/O method (e.g., using `input()` prompts in a non-interactive environment, returning instead of printing). Explicit alignment with the problem's functional I/O requirements is crucial for the solution to be usable.
