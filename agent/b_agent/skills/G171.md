Define Recursive Function Signatures and Structure Precisely

**When to apply**: When the problem requires a recursive solution (e.g., tree traversal, divide-and-conquer, generating sequences). When the prompt vaguely describes recursion, leading to implementations with incorrect base cases or parameter passing.
**What to do**: Explicitly state the function name, its parameters, and return type. Clearly describe the recursive case (how the problem breaks down) and the base case(s) (when recursion stops). Avoid mixing this structural definition with low-level implementation details like loop counters or temporary variables.
**Example**: Instead of: "Write a recursive function to calculate factorial. Think about how it calls itself with a smaller number." Use: "Write a recursive function `factorial(n: int) -> int`. The base case is `n <= 1`, which should return `1`. The recursive case should return `n * factorial(n-1)`."
**Why it works**: Models sometimes implement recursion incorrectly by modifying global state, missing base cases, or failing to propagate return values. A clear, declarative signature and structure guide the model to produce a textbook recursive implementation, reducing logical errors.
