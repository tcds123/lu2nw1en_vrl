Define Error Handling with Exact Output Strings or Exception Types

**When to apply**: When the problem requires raising exceptions or returning specific error messages for invalid inputs. Common in validation tasks or robust API design.
**What to do**: Explicitly state the exact exception type to raise (e.g., `ValueError`) or the exact string to return/print (e.g., `"Invalid input"`). Do not just say "handle errors" or "print an error message."
**Example**: "If the input `amount` is negative, raise a `ValueError` with the message `'Amount cannot be negative.'` If the input `currency` is not in the list `['USD', 'EUR']`, return the string `'Unsupported currency'`."
**Why it works**: Test cases often check for exact string matches or exception types. Vague instructions lead to inconsistent error handling (e.g., printing vs. raising, different message wording) that fails automated tests.
