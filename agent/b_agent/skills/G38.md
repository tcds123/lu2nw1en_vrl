Structure Prompts with a Concise Persona and Direct Standards

**When to apply**: For all code generation tasks to establish a consistent, high-quality output style and prevent the model from generating unnecessary boilerplate, contradictory instructions, or off-topic commentary.

**What to do**: Start the prompt with a brief, expert persona (e.g., "You are a senior software engineer."). Follow with a bulleted or numbered list of non-negotiable coding standards (e.g., readability, no external libraries, PEP 8 compliance). Ensure these standards are concise and do not conflict with each other or the core task.

**Example**: "You are a Python expert writing production-ready code. Adhere strictly to the following: 1. Write clean, readable code with descriptive variable names. 2. Use only the Python standard library; no external dependencies. 3. Include a Google-style docstring. 4. Ensure the function is efficient for typical use cases."

**Why it works**: Models can generate verbose, tutorial-style code with unnecessary prints or explanations if no persona is set. Conflicting instructions (e.g., "be concise" vs. "add extensive comments") cause confusion and erratic output. A clear persona and standards anchor the model's behavior.
