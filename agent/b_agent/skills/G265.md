Explicitly Prohibit Unwanted Behaviors Coherently

**When to apply**: When you need to guard against common model failures such as verbose explanations, extraneous output, use of banned libraries, or defensive code that isn't asked for.
**What to do**: Use clear, imperative language starting with "Do not". List prohibitions concisely. Ensure the prohibitions do not conflict with the core task. Phrase them as rules, not as part of a narrative.
**Example**: "Do not include any `print` statements, `input` prompts, or example usage in the function body. Do not import any external libraries. Do not add comments explaining the algorithm."
**Why it works**: Code generation models are trained on code with comments and examples, so they default to including them. Without explicit prohibition, the generated code is often cluttered and not suitable for direct integration into a larger, silent codebase.
