Ground Specifications in the Provided Problem Statement to Prevent Scope Creep

**When to apply**: When the user's request is detailed but the assistant might be tempted to add "helpful" features like logging, extra parameters, or different return formats that were not requested.
**What to do**: Explicitly instruct the model to implement **only** what is described in the prompt. Do not add functionality for error logging, user input, example usage, or extended features unless they are explicitly listed in the requirements.
**Example**: "Implement the function **exactly as described below**. Do not add any additional parameters, print statements, logging, or features not specified. Use only the inputs and produce only the output defined in the task."
**Why it works**: Models are trained to be "helpful" and may add common boilerplate or robustness features (like printing results) that violate the requirements of an automated testing system, which expects only the specified function signature and behavior.
