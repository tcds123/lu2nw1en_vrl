Mandate Complete, Executable Code, Not Stubs or Pseudocode

**When to apply**: For all code generation tasks unless explicitly asked for a skeleton or outline. Especially critical when the prompt is a high-level description that could be interpreted as a request for planning.
**What to do**: Use strong, unambiguous language requiring a full implementation. State that the code must run without additional definitions and must solve the problem as stated.
**Example**: "You must provide a complete, executable implementation. Do not output a function stub (`def solve(...): pass`) or pseudocode. The code you output should solve the problem fully and be ready to run."
**Why it works**: Models sometimes generate high-level plans or placeholder code when they are uncertain or when the prompt resembles a design question. This instruction forces a shift from planning to concrete implementation.
