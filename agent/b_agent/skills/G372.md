Align Prompt Specifications with the True Problem Statement

**When to apply**: When crafting prompts based on external problem descriptions (contest websites, internal tickets, user stories). This is critical to avoid solving a different, inferred problem.
**What to do**: Before finalizing the prompt, cross-check every attribute name, method signature, constant value, and logical rule (e.g., "greater than or equal to") against the authoritative source. Copy-paste key names and values directly. Do not paraphrase or summarize critical details that could change meaning.
**Example**: If the problem says: "The `Employee` class has an attribute `years_of_service`", the prompt must say: "The `Employee` class must have an attribute named `years_of_service`" and not "The `Employee` class must have an attribute for tenure."
**Why it works**: Models are highly literal. A slight deviation (e.g., `start_index` vs. `start`) or a misinterpreted inequality (">" vs. ">=") will cause the generated code to fail tests. This skill prevents "solving the wrong problem" due to prompt inaccuracy.
