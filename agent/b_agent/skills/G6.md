Mandate Exception Raising, Not Error String Returns

**When to apply**: When invalid inputs must be handled, and the required behavior is to raise a built-in exception (like `ValueError`, `TypeError`, `IndexError`) to signal an error.
**What to do**: Explicitly state the condition(s) that constitute invalid input and specify the exact exception type to be raised. Prohibit returning error messages, special values (like `-1`, `None`, or `"ERROR"`), or printing.
**Example**: "Implement `def sqrt_positive(x: float) -> float:`. If `x` is negative, raise a `ValueError` with the message `'x must be non-negative'`. Do not return a string or a sentinel value."
**Why it works**: Models frequently default to printing error messages or returning `None`/`-1` on invalid input, as this is common in simple scripts. Tests often check for specific exception types being raised. Without explicit instruction, the generated code will fail these tests.
