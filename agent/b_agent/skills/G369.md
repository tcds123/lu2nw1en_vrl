Specify Exact Method Signatures While Preserving Implementation Freedom

**When to apply**: When the problem requires a specific function or class interface, such as LeetCode-style coding challenges, library API definitions, or when integrating generated code into a larger codebase with fixed contracts.
**What to do**: In the prompt, explicitly state the required function name, the exact order and types of its parameters, and its return type. Use the target language's standard type hints or declarations. Avoid dictating the internal algorithm, variable names, or helper functions unless they are part of the core interface.
**Example**: "Implement a function `def find_duplicates(nums: List[int]) -> List[int]:` that takes a list of integers and returns a list of all integers that appear more than once. Do not modify the input list."
**Why it works**: Code generation models may default to common but incorrect signatures (e.g., `(arr)` instead of `(nums: List[int])`) or guess at return types. This precision ensures the generated code compiles and integrates correctly, while the lack of internal constraints allows the model to select the most efficient or appropriate algorithm.
