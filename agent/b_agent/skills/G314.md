Clearly define preprocessing scope and result mapping for string transformations

**When to apply**: When the problem requires transforming or analyzing an input string (e.g., palindrome check, anagram grouping, case-insensitive comparison) but the final output must reference or preserve the original string's format.
**What to do**: Explicitly separate the logic for analysis from the logic for presentation. First, instruct the model to create a processed version of the input for the core algorithm. Then, mandate that the function's return value (e.g., boolean, list of indices, transformed string) is based on the original, unprocessed input, not the intermediate representation.
**Example**: "Write a function `find_palindromic_words(sentence: str) -> List[str]`. For detection, consider only alphanumeric characters and ignore case. However, the returned list must contain the original words from the input `sentence` in their original casing and punctuation."
**Why it works**: Without this, models often conflate the cleaned data used for computation with the required output, returning lowercased strings or strings without punctuation, which is incorrect. This instruction enforces a clear separation of concerns.
