Explicitly Define Function Signature, Return Format, and Edge Cases

**When to apply**: For any function implementation task, especially when edge cases (empty input, invalid input, minimal values) could lead to errors or ambiguous outputs.
**What to do**: State the exact function name, its parameters with types (e.g., `def func(n: int, items: list[str])`), and the precise return type and format. Follow this with a clear "if-then" rule for each relevant edge case.
**Example**: "Write a function `find_primes(n: int) -> list[int]` that returns a list of all prime numbers less than `n`. If `n` is less than or equal to 2, return an empty list. The list should be in ascending order."
**Why it works**: Models often make implicit, incorrect assumptions about edge-case handling (e.g., returning `[2]` for `n=2`) or return formats (e.g., a generator vs. a list). This eliminates ambiguity and ensures the generated function's interface matches the expected test cases.
