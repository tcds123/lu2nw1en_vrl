Balance Behavioral Detail with Scope Boundaries

**When to apply**: When the problem requires specific validation, error handling, or output formatting, but the internal algorithm implementation is flexible. When unit tests are known to check for precise outputs or edge-case behaviors.
**What to do**: Over-specify the *external behavior*: validation rules, exact error messages, and output formatting. Under-specify the *internal implementation*: allow freedom in algorithm choice and data structures. Clearly state the function's signature and the contract it must fulfill for all given inputs.
**Example**: "Implement a function `clean_string(s: str) -> str`. It must remove all non-alphabetic characters and convert the result to lowercase. If the input string is empty or contains no alphabetic characters, return an empty string. Do not worry about performance; focus on correctness for all possible input strings."
**Why it works**: Models might implement a correct core algorithm but fail hidden unit tests due to missing validation or incorrect formatting. Over-specifying internals is harmless, but under-specifying behavior leads to solutions that are logically sound but fail on specific test cases.
