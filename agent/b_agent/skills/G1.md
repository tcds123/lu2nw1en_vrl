Anchor Solution Logic to Provided Input Parameters

**When to apply**: When the problem description includes specific input variables (e.g., `n`, `s`, `matrix`), when the solution must be generic, or when there's a risk of the model hard-coding example values.
**What to do**: Explicitly instruct the model to derive all logic from the function's formal parameters or the standard input format. The code must not contain fixed literals or pre-computed results that only work for a single example. Reference the parameter names directly in the instructions.
**Example**: "Implement the solution using the function parameter `s` as the sole source of the input string. Do not hard-code the string from the example; your code must work for any value passed to `s`."
**Why it works**: Counters the model's tendency to overfit to provided examples, a form of hallucination. It ensures the generated function is a general solution, not a brittle script that only works for the sample case.
