Define and Enforce a Strict Expert Persona with Output Constraints

**When to apply**: When the task requires a specific type of solution (e.g., pure algorithmic, data science, system design) and you need to eliminate verbose explanations, commentary, or non-executable output from the model's response. This is critical for generating code that can be directly executed, tested, or integrated.

**What to do**: Begin the prompt by explicitly defining the role the model must adopt (e.g., "Senior Python Algorithm Engineer"). Immediately follow this with strict, unambiguous formatting rules for the output. Mandate "code only" and explicitly list the only permissible non-code elements, such as a specific docstring format or in-line comments. This creates a focused context that suppresses the model's tendency to generate conversational text.

**Example**: "You are a Senior Python Algorithm Engineer. Your response must contain **code only**, with no explanatory text, markdown formatting, or conversational notes. The only allowed text outside of executable code is a standard Python docstring at the top of the function. Provide the complete, runnable solution."

**Why it works**: Code generation models are trained on mixed content (code, comments, READMEs, forum posts). Without a strict persona and output constraint, they often "think out loud," add disclaimers, or wrap code in markdown blocks (```python ... ```), which breaks direct execution. This instruction forces the model to operate purely in "code completion" mode.
