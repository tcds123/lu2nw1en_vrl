State Required Algorithm Concept, Not Step-by-Step Instructions

**When to apply**: For problems where a specific algorithm is known to be optimal (e.g., "use Dijkstra's algorithm," "apply Kadane's algorithm"). When you want to guide the model towards an efficient approach without scripting its every loop and variable.

**What to do**: Name the target algorithm or paradigm and its key performance characteristic. Describe *what* it should achieve at a high level, but avoid prescribing the *how* of low-level implementation details.

**Example**: Instead of "Initialize i=0. Loop while i < n. Check if condition...", write: "Solve this using a sliding window approach to achieve O(n) time complexity. Maintain a window that satisfies the constraint and update the result as you iterate."

**Why it works**: Overly prescriptive step-by-step instructions can be confusing, contain errors, or conflict with the model's own reasoning process. Specifying the algorithm concept gives the model a correct direction while allowing it to leverage its vast training on how to implement that concept correctly.
