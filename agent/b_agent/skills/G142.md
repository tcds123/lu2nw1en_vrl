Explicitly State Validation Rules and Error Handling Expectations

**When to apply**: When the function must enforce preconditions on its inputs or state, and the required behavior on violation is specific (e.g., raise a particular exception with a message, return a sentinel value).
**What to do**: List each invalid scenario and the exact response required. Use the pattern: "If [condition], then [action]." The action should be concrete: "raise a ValueError('mileage must not decrease')".
**Example**: "Implement `update_mileage(new_mileage)`. Validation: 1) `new_mileage` must be an integer. 2) `new_mileage` must be greater than the current mileage. If validation fails, raise a `ValueError` with a descriptive message."
**Why it works**: Without explicit validation rules, models often generate code that assumes ideal inputs or handles errors silently/inconsistently. This instruction ensures the generated code aligns with test suites that specifically check for these error conditions, preventing runtime failures in production-like scenarios.
