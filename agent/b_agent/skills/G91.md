Specify Concrete Algorithmic Constraints, Not Prescriptive Steps

**When to apply**: When the problem has specific performance requirements (time/space complexity), input scale limits, or mandatory algorithmic approaches (e.g., "use constant extra space"). Also for math problems with known efficient techniques.
**What to do**: Provide the key constraints and optimization goals that define a correct solution. Give concrete bounds (e.g., "n can be up to 10^6") and name critical optimizations (e.g., "must run in O(n log n) time"). Avoid dictating the exact sequence of code statements, which can conflict with valid implementations or stifle the model's ability to structure the code logically.
**Example**: "Implement a function to check if a number up to 10^12 is prime. The solution must efficiently handle the large upper bound. Hint: A common approach is to check divisibility only up to the square root and handle even numbers separately first."
**Why it works**: It gives the model the necessary guardrails for correctness and efficiency without over-constraining it. Prescribing steps can lead to syntactically invalid or contradictory code if the model's natural code generation flow differs from the prescribed order.
