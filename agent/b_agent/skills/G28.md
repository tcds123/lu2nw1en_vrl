Prioritize the Single Most Critical Non-Default Constraint

**When to apply**: When instructions contain multiple constraints, and one is highly specific, counter-intuitive, or likely to be overridden by the model's default patterns (e.g., preferring immutability, recursion, or a specific library).
**What to do**: Identify the one constraint that most strongly deviates from a standard solution. State it first, clearly, and in isolation. Use forceful language (e.g., "must," "critical," "override typical approaches") to signal its priority.
**Example**: "CRITICAL CONSTRAINT: You must modify the input list in-place. Do not allocate a new list for the result. After this constraint, implement a function that rotates the list `nums` by `k` steps to the right."
**Why it works**: Code models have strong priors for common patterns (e.g., returning new collections). Isolating the key exception forces it to override its default "solution template," preventing a functionally incorrect implementation that otherwise looks correct.
