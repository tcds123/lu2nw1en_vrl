Specify Concrete Validation and Error-Handling Rules Separately

**When to apply**: When the function has specific preconditions for its inputs (e.g., non-negative integers, non-empty lists, strings within a certain format) or needs to handle edge cases with explicit errors or return values. This is crucial for robust API or library functions.

**What to do**: Create a dedicated "Validation & Error Handling" section in the prompt. List each invalid input scenario and the exact exception to raise (including the error message text) or the specific value to return. Do not mix these rules with general advice about writing "clean code".

**Example**: "Validation & Error Handling: If the input `n` is less than 0, raise a `ValueError` with the message `'Input must be non-negative.'`. If the input `data_list` is empty, return an empty list `[]`."

**Why it works**: Models trained on diverse codebases see inconsistent error handling. Without explicit, separate instructions, they may omit validation entirely, handle errors inconsistently, or embed vague warnings in comments instead of raising proper exceptions, leading to fragile code.
