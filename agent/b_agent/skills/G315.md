State precise, non-contradictory algorithmic requirements

**When to apply**: When defining a problem's core constraints, such as time/space complexity, prohibited libraries, or specific algorithmic approaches (e.g., "in-place", "without division").
**What to do**: List requirements positively and explicitly. Avoid vague or negative phrasing (e.g., "don't use X"). If a constraint is critical, state it upfront. Crucially, review the prompt to ensure no instruction contradicts another (e.g., asking for O(1) space while also requiring a call stack for recursion).
**Example**: "Implement the function with O(n) time complexity and O(1) additional space, modifying the input list in-place. You may not use library functions that directly solve the problem (e.g., `sorted()`)."
**Why it works**: Models can fail silently on contradictions, often choosing one path arbitrarily. Vague constraints like "efficiently" are ignored. Explicit, coherent constraints guide the model toward a valid implementation space.
