Restate the Complete Core Task Accurately Before Implementation Details

**When to apply**: At the beginning of crafting any prompt. Before adding constraints, examples, or style guides, ensure the fundamental "user story" or requirement is captured in a single, unambiguous sentence. This acts as the north star for the entire prompt.

**What to do**: Start the prompt by explicitly restating the core task. This should include the primary action (write, create, implement), the artifact's name (function `foo`), its key inputs, and its expected output or effect. Frame it as the objective.

**Example**: "Core Task: Write a function named `flatten_nested_list` that takes a list potentially containing nested lists of integers and returns a single flattened list of all integers in depth-first order."

**Why it works**: If the core task is ambiguous, buried, or incorrect, every subsequent instruction builds on a faulty foundation. Models can perfectly implement misguided instructions. A clear, upfront restatement ensures both the prompt engineer and the model are aligned on the primary goal from the start.
