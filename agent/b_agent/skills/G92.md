State Performance Goals, Grant Implementation Flexibility

**When to apply**: When you care about the *what* (correctness, efficiency) and the *why* (key algorithmic insight) more than the *exact how* (specific variable names, loop structures, helper function organization).
**What to do**: Clearly articulate the performance objective (e.g., "O(n) time, O(1) space") and the core algorithmic concept required (e.g., "use a two-pointer technique"). Then, explicitly grant the model autonomy to structure the implementation, choose data structures, and name variables as it sees fit to meet those goals.
**Example**: "The solution must achieve O(n) time complexity by traversing the list only once. You should use a hash map to track seen elements for constant-time lookups. Determine the exact implementation structure and variable naming to fulfill this requirement."
**Why it works**: It focuses the model on the critical algorithmic challenge while avoiding micromanagement. This leads to more natural, idiomatic, and often more creative code that still satisfies all technical requirements, as the model isn't fighting against unnatural step-by-step directives.
