Define Complete Function Signature and Imports Before Implementation

**When to apply**: When the task requires a specific Python function, especially for library functions, API endpoints, or solutions to coding challenge problems. Also crucial when the required imports are non-standard or the return type is complex (e.g., `List[Tuple[int, str]]`).

**What to do**: At the very beginning of the prompt, explicitly state the full function signature, including parameter names, types, and the return type. List all required imports, even if they are standard (e.g., `from typing import List`). This creates a rigid template the model must follow before it begins thinking about logic.

**Example**: "Write a Python function. First, include the exact import: `from collections import defaultdict`. Then, define the function as `def find_common_elements(list1: List[int], list2: List[int]) -> Set[int]:`. Only after this signature, proceed with the implementation."

**Why it works**: Without this, models often generate code with incorrect function names, missing type hints, or import statements scattered throughout the logic or omitted entirely. This forces the model to structure the solution correctly from the outset, preventing refactoring errors and ensuring the generated code is immediately runnable in a context that expects that specific interface.
