Focus on Essential Task Requirements, Not Stylistic Preferences

**When to apply**: When defining the problem's success criteria. When tempted to include style guides (naming conventions, use of comprehensions) or to ban safe, standard language features.
**What to do**: Prioritize instructions on functional correctness, algorithmic complexity, and handling of specified edge cases. Only prohibit approaches that are fundamentally wrong for the task (e.g., "do not use a built-in sort function" for a custom sorting problem). Avoid banning generic constructs like `for` loops or `if` statements.
**Example**: "Implement the function to run in O(log n) time. It must correctly handle negative numbers as inputs. Do not use the `**` operator or `math.pow`." Instead of: "You must use a while loop and a variable named `low`."
**Why it works**: Models have strong stylistic priors. Fighting them on style (e.g., "never use list comprehensions") consumes prompt tokens and can introduce friction, potentially degrading performance on the core logic. Focusing on functional constraints aligns with the model's strength in problem-solving.
