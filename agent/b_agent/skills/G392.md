Prioritize Functional Correctness Over Verbose Style or Premature Optimization

**When to apply**: For straightforward algorithmic problems where the primary risk is logical error, not style. When the prompt is cluttered with secondary demands for perfect documentation, extreme performance, or elegant code that could distract from getting a correct solution first.

**What to do**: Lead with the requirement for a functionally correct solution that passes all typical test cases. De-emphasize or place after correctness any non-essential requests for extensive comments, perfect variable names, or micro-optimizations unless they are core to the problem.

**Example**: "First and foremost, ensure the function returns the correct result for all valid inputs, including edge cases. Code readability is important, but correctness is the top priority. A simple, clear, and correct solution is preferred over a complex but buggy one."

**Why it works**: Models can waste context and reasoning on optimizing or over-documenting a fundamentally flawed algorithm. This instruction focuses the model's "chain of thought" on the core logic and edge case handling, which is the hardest part.
