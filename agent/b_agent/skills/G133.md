Specify Exact Preprocessing and Complexity Constraints Up Front

**When to apply**: For data cleaning, parsing, or string manipulation tasks where the input format is messy (mixed case, punctuation) and the efficiency of the cleanup is part of the challenge. Also for problems where the obvious solution has poor complexity.
**What to do**: In the prompt, explicitly list the preprocessing steps (e.g., convert to lowercase, remove non-alphanumeric characters) as part of the function's contract. Simultaneously, state the required time/space complexity for the entire operation, including this preprocessing.
**Example**: "Write a function `is_palindrome(s)` that returns True if the string `s` is a palindrome, ignoring case and non-alphanumeric characters. The function must preprocess the string within the same O(n) time and O(1) additional space complexity (or O(n) space if necessary for immutability)."
**Why it works**: Without explicit preprocessing instructions, models may produce logic that is case-sensitive or fails on strings with spaces. Without the complexity constraint, they might use multiple passes or intermediate data structures that violate the efficiency goal, even if the core algorithm is correct.
