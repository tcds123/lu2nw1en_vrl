Output Raw Function Code Compatible with a Test Harness

**When to apply**: When the user's request implies integration with an external testing system (e.g., LeetCode-style problems, coding challenge platforms). When the instruction is to "write the function" only.
**What to do**: Instruct the model to output *only* the requested function/class definition, without a `if __name__ == "__main__":` block or example usage. However, emphasize that the function must be complete, with a correct signature, proper return statements, and all necessary internal logic.
**Example**: "Output only the code for the `Solution` class and its required method(s). Do not include a main function, example inputs, or print statements. The code must define the class and method exactly as specified so it can be directly called by an external test runner."
**Why it works**: Resolves the conflict between "output only code" and "be runnable." It clarifies that "runnable" in this context means a correctly defined, callable unit, not a standalone script. This prevents the model from adding extraneous driver code that would break an automated judge.
