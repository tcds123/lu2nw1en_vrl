Craft Clear, Non-Contradictory, and Concise Instructions

**When to apply**: When the prompt contains multiple "do not" statements, overly specific formatting rules, or instructions that conflict (e.g., "return a list" but also "print each element"). Also when the prompt is unnecessarily long, repeating the same requirement in different words.
**What to do**: Review the prompt and remove all instructions that do not directly impact the functional correctness or required output format of the code. Consolidate overlapping rules. Ensure all "must" and "must not" statements are logically consistent. Strip out meta-commentary about the prompt itself.
**Example**: Instead of: "Write a function that processes a list. Do not use list comprehensions. Do not use the `map` function. You must not modify the input. Ensure the output is sorted. Do not use the built-in `sorted` or `list.sort`. Also, please avoid using any external libraries. The function should be efficient. Return a new list." Use: "Write a function `process_list(lst)` that returns a new, sorted list derived from `lst` without modifying the input. Do not use Python's built-in sorting functions (`sorted` or `list.sort`)."
**Why it works**: Code generation models can be confused or overly constrained by contradictory or redundant rules, leading to syntax errors, logical flaws, or failure to generate any code. This simplification focuses the model on the core algorithmic constraint (no built-in sort) and the required output.
