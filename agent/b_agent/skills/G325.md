Use Simple, Unambiguous Output Format Instructions

**When to apply**: When the response must be machine-parsable, when only a specific part of the code is needed (e.g., just a function body), or when extraneous explanation would break an automated testing pipeline.
**What to do**: Give a single, clear command for the output format. Use positive directives (e.g., "output only...", "return only...") rather than a long list of "do nots." Avoid embedding format rules within complex negative statements.
**Example**: "Output only the final Python function definition, with no additional comments, print statements, or example usage."
**Why it works**: Models can misinterpret nested or negative instructions ("don't output X unless Y, but if Z then..."). A simple, positive format rule minimizes ambiguity, ensuring the output is directly usable in a code cell or test harness.
