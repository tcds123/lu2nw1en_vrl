Balance Specificity with Flexibility in Constraints

**When to apply**: When defining a function's behavior that has multiple valid implementation paths, or when you need to enforce coding standards (like no use of built-in functions) without dictating every line of code.
**What to do**: Specify the *what* (functional requirements, input/output behavior, key prohibitions) clearly, but avoid over-specifying the *how* (exact variable names for intermediate steps, specific loop structures) unless absolutely necessary for correctness.
**Example**: "Write a function `clean_string(s: str) -> str` that removes all non-alphanumeric characters and converts the result to lowercase. Do not use regular expressions (`re` module). The implementation must use a single pass over the string."
**Why it works**: Over-constraining (e.g., "use a `for` loop with index `i`") can confuse the model if its internal "reasoning" prefers a different valid pattern, leading to syntax errors or logical contradictions. This balance provides guardrails for correctness and style while leaving room for the model to generate fluent, idiomatic code.
