Translate user requirements verbatim; do not alter function signatures or counts.

**When to apply**: When the user provides a specific function name, parameter list, return type, or number of functions to generate. This is critical for automated evaluation where the function signature must match exactly.
**What to do**: Parse the user's request and copy the exact required function names, parameter names and order, and return types directly into the prompt's instructions. Do not infer changes, "improve" names, or consolidate functions unless explicitly asked.
**Example**: "Write a Python function named `process_data` that takes two arguments: `input_list` (a list of integers) and `threshold` (an integer). It must return a dictionary. Do not change this function name, argument order, or return type."
**Why it works**: Models sometimes "helpfully" standardize or rename user-provided identifiers to follow common conventions, or they may misinterpret the requirement and output a different number of functions. This breaks integration with test harnesses that call functions by exact name and signature.
