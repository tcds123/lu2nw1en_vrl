Enforce a Clear, Logical Code Structure

**When to apply**: When generating multiple classes, several helper functions, or a module with specific organizational standards. When the order of definitions matters for execution or readability (e.g., helper functions must be defined before the main function that uses them).
**What to do**: Explicitly state the order in which code elements should appear. Common patterns include: imports first, then constants, then helper classes/functions, then the main class/function, and finally the `if __name__ == "__main__"` block.
**Example**: "Structure your code as follows: 1. Necessary import statements. 2. Definition of the `Node` helper class. 3. Definition of the `Tree` main class with its methods. 4. The `if __name__ == '__main__':` block with example usage."
**Why it works**: Models can produce valid code in a haphazard order (e.g., defining a method that uses a helper class defined later), which may confuse human readers or, in some languages, cause reference errors. A structural guide ensures standard, readable, and often executable ordering.
