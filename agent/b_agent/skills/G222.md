Enforce Documentation and Complexity Constraints Clearly and Concisely

**When to apply**: When the solution requires a specific docstring format (Google, NumPy), explicit type hints, or must adhere to time/space complexity bounds.
**What to do**: State the documentation standard as a separate, succinct requirement after the core logic. For complexity, use Big O notation explicitly. Avoid embedding these rules in long, complex sentences.
**Example**: "Implement the function `def two_sum(nums: List[int], target: int) -> List[int]:` with O(n) time complexity. The function must include a complete Google-style docstring. Do not use nested loops."
**Why it works**: Verbose or garbled constraint phrasing (e.g., "make it fast" or "document well") is ignored or misinterpreted. Explicit, standalone instructions for docs and complexity are treated as first-class requirements, leading to compliant solutions.
