Prioritize Functional Correctness and Structure Over Low-Level Details

**When to apply**: When the core challenge is algorithmic logic or architectural design, not syntax minutiae. When the user starts specifying variable names or minor optimizations that could distract from the primary objective.
**What to do**: State the high-level goal and necessary structure first. Specify *what* needs to be achieved (e.g., "ensure thread-safety," "prevent duplicate entries") and the required components, but avoid dictating *how* to achieve it at the level of loop constructs or temporary variables unless it's critical.
**Example**: "Create a `TaskScheduler` class that can add tasks with priorities and execute the highest-priority task first. Focus on a correct priority queue implementation. Do not worry about the specific internal sorting method, as long as the `execute_next()` method always returns the correct task."
**Why it works**: Over-specification can confuse the model, causing it to focus on adhering to arbitrary syntax rules rather than solving the core problem. This gives the model the flexibility to choose a standard, efficient implementation (like `heapq`) that meets the functional goal.
