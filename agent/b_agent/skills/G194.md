Define Signature, Edge-Case Behavior, and Output Format Constraints

**When to apply**: When you need a complete, self-contained code snippet for direct execution or evaluation, particularly for functions where edge cases (empty input, `None`, single element) are meaningful and the delivery format is strict.

**What to do**: Specify the full function signature. Explicitly list the required behavior for each identified edge case. Finally, dictate the exact boundaries of the generated output (e.g., only the function in a code block).

**Example**: "Provide the Python function definition inside a single code block. Function: `get_last_element(lst: list) -> any`. If `lst` is empty or `None`, return `None`. Otherwise, return the last element. Do not include any examples, tests, or explanatory text."

**Why it works**: Models frequently add extra print statements, test code, or handle edge cases inconsistently (returning `0` vs. `None`). This triple specification (interface, logic, packaging) ensures the output is a directly usable, correct component that fits a predefined testing harness.
