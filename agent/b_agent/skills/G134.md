Balance Detail with Focus: Include Essential Edge Cases, Avoid Redundant Restatements

**When to apply**: When the problem description is long or contains background information, when edge cases are critical for correctness (e.g., empty inputs, boundary values, invalid data types), or when the model tends to paraphrase the problem in comments.
**What to do**: Explicitly list the key functional edge cases that must be handled in the solution. Simultaneously, instruct the model not to re-describe the general problem in code comments or docstrings. The docstring should document the function's interface and behavior, not the story.
**Example**: "Implement the function `clean_string(s: str) -> str`. Key requirements: 1) Remove all characters that are not letters or digits. 2) If the resulting string is empty, return the string `'<EMPTY>'`. 3) Handle `None` input by returning an empty string. Do not include comments that restate the general problem description from this prompt."
**Why it works**: Prevents the model from wasting tokens and mental focus on redundant narrative, which can crowd out the implementation of critical logic. It forces the model to allocate its "attention" to the hard parts (edge case handling) while keeping the code clean and professional.
