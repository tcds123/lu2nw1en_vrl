Prioritize Concise, Complete Task Specification Over Verbose Rules

**When to apply**: When the prompt is at risk of being truncated due to length, or when overly complex formatting instructions are obscuring the core algorithmic requirement.
**What to do**: Lead with a clear, one-sentence description of the core task. Then, add only the most critical constraints (signature, key edge cases). Avoid repeating the same requirement in different ways or adding extensive stylistic rules that don't affect functionality.
**Example**: "Create a function to find the longest common prefix among a list of strings. Function signature: `def longest_common_prefix(words: List[str]) -> str:`. Return an empty string if the list is empty or no common prefix exists."
**Why it works**: Long, repetitive prompts can cause models to miss key instructions due to information overload or truncation. A concise, front-loaded specification ensures the model's context window is focused on the essential problem logic, improving generation accuracy.
