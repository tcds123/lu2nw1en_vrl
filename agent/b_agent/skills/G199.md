Explicitly Define Function Signature and Edge-Case Behavior

**When to apply**: When the problem has non-obvious corner cases (empty inputs, null values, large numbers) or when the required output for invalid/edge inputs must differ from the main algorithm's logic.
**What to do**: In the prompt, define the exact function name, parameter names, and their expected types. For each edge case, specify the exact return value or behavior, leaving no room for the model to infer or default to a generic error.
**Example**: "Write a function `def clean_string(s: str) -> str:` that removes all non-alphabetic characters. If the input string `s` is empty or `None`, return an empty string `''`. Do not raise an exception for these cases."
**Why it works**: Models often handle common cases well but make arbitrary or inconsistent choices on edge cases (e.g., returning `None`, throwing an error, or returning an empty list). Explicit specification ensures deterministic behavior across all inputs, which is critical for robust unit testing.
