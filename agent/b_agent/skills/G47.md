Prioritize Precise Requirement Translation Over Generic Coding Standards

**When to apply**: When functional constraints (e.g., "do not use the built-in sort function") are more important than general best practices (e.g., "use descriptive variable names"). When the evaluation is based solely on correctness of the transformation logic.
**What to do**: Frame constraints directly in service of the problem's functional goals. If a coding standard (like a specific algorithm) is required, present it as a non-negotiable requirement for correctness, not as a stylistic suggestion.
**Example**: "You must implement the sorting logic manually using a bubble sort algorithm. The correctness of your solution depends on using this specific algorithm, not just on producing the correct sorted output. Do not use Python's `sorted()` or `.sort()` methods."
**Why it works**: Models are trained on general "good code" which may conflict with specific problem constraints. This instruction forces the model to prioritize the evaluator's definition of correctness (adherence to specified constraints) over its own learned stylistic preferences.
