Specify Exact Signature, Mutation Behavior, and Documentation

**When to apply**: For any function or class implementation, especially when mutation (in-place vs. new copy) is ambiguous, or when integration into a larger codebase requires specific documentation format.
**What to do**: Declare the exact function/class name, parameter types and names, return type, and whether inputs are mutated. Explicitly state if a docstring is required and its key sections (e.g., Args, Returns, Examples).
**Example**: "Implement `def normalize_vector(vec: List[float]) -> List[float]:`. Do not modify the input list; return a new list. Include a full Google-style docstring with `Args:`, `Returns:`, and a one-line `Example:`."
**Why it works**: Models often default to in-place modification or omit documentation if not explicitly told. Ambiguity leads to interface mismatches that break calling code. This eliminates guesswork about the contract the implementation must fulfill.
