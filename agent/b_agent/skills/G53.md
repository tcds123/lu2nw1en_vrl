Prioritize Essential Constraints to Prevent Over-Engineering

**When to apply**: When specifying input validation, error handling, or performance requirements. When the problem has clear functional boundaries that could be expanded upon unnecessarily.
**What to do**: Focus the prompt on the constraints that are critical for passing tests or meeting the core API contract. State necessary validations and error conditions concisely. Avoid adding detailed prescriptions for internal implementation, auxiliary functions, or defensive programming beyond what's required.
**Example**: "Implement `validate_and_process(data: list) -> int`. The function must raise a `ValueError` if `data` is empty or contains non-integer values. Otherwise, return the sum of positive integers. Do not add logging, type hints beyond the signature, or additional sanity checks."
**Why it works**: Models often over-interpret verbose or overly cautious instructions, generating extra layers of abstraction, unnecessary logging, or custom exception classes that deviate from the expected API and cause test failures.
