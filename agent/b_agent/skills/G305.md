Explicitly define mapping rules and case handling with concrete examples

**When to apply**: When the task involves data transformation, categorization, or processing with specific rules (e.g., converting status codes to messages, parsing commands, cleaning text, applying business logic). Also when edge cases or special inputs (like null, empty, invalid) must be handled distinctly.
**What to do**: Do not just state the rule abstractly. Provide a clear, bulleted or numbered list of input-output pairs or condition-action pairs. For edge cases, explicitly state what the output or behavior should be. Use a mini "lookup table" format within the prompt.
**Example**: "Write a function `categorize_age(age)` that returns a string category. Mapping rules: 0-12 -> 'Child', 13-19 -> 'Teenager', 20-64 -> 'Adult', 65+ -> 'Senior'. For invalid inputs (e.g., negative numbers), raise a `ValueError`."
**Why it works**: Code generation models may infer incorrect or inconsistent logic from vague descriptions (e.g., "handle young ages"). Concrete examples anchor the model's understanding, prevent off-by-one errors, and ensure all specified cases are covered in the implementation.
