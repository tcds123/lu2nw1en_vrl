Establish expert coding standards without over-specifying steps

**When to apply**: When code quality, readability, and maintainability are as important as correctness (e.g., production code, library functions, interview scenarios).
**What to do**: Define the quality bar in terms of outcomes: "include a docstring with Args/Returns," "follow PEP 8," "use descriptive variable names." Avoid step-by-step algorithmic instructions (e.g., "first, sort the list, then iterate with two pointers..."). Instead, state the goal (e.g., "find the pair with the smallest difference").
**Example**: "You are a staff engineer writing production-grade code. Implement a solution that is efficient, well-documented, and adheres to standard Python style guides. Include a comprehensive docstring and type hints. Focus on clarity and maintainability over clever one-liners."
**Why it works**: Telling the model *what* to achieve (clean code) rather than *how* to achieve it (a specific algorithm) leverages the model's vast training on optimal patterns. Over-specifying steps can bypass the model's better judgment and even introduce errors if the prescribed steps are suboptimal.
