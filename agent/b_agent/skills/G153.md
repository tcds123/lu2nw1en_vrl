Explicitly Require Algorithmic Efficiency Details

**When to apply**: When the problem implicitly requires an efficient solution (e.g., large input constraints, time limit mentions) or when a naive implementation is a common pitfall. Applicable to prime checks, factorization, searching sorted data, or avoiding nested loops.
**What to do**: Directly specify the key optimization technique within the problem constraints. Instead of just stating "make it efficient," embed the algorithmic hint as a non-negotiable part of the solution specification.
**Example**: "Implement `is_prime(n)` to return `True` if `n` is a prime number. For efficiency, you must only check divisibility up to and including the square root of `n`, and you should handle even numbers as a special case to avoid unnecessary checks."
**Why it works**: Without explicit guidance, models often default to the most straightforward, inefficient algorithm (e.g., checking divisibility up to `n-1`). By mandating the efficient approach, you steer the model away from this common failure and ensure the generated code meets performance expectations.
