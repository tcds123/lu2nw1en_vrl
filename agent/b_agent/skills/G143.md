Enforce Minimal Output: Code Only, No Explanations or Extra Features

**When to apply**: When the task is a straightforward coding challenge (e.g., LeetCode-style, unit-test-driven) where any extra output will cause submission failures. Also when the model has a known tendency to "think aloud" or add example usage.
**What to do**: Explicitly instruct the model to output *only* the final code solution. State that no explanations, comments (beyond minimal in-code ones), example invocations, or descriptive text are allowed. Frame this as a requirement for automated grading.
**Example**: "Your output must contain ONLY the requested function or class definition. Do not include any introductory text, explanations, example usage, or print statements. The code will be extracted and run directly against unit tests."
**Why it works**: Prevents scope drift where the model adds helper functions or test code not asked for, which can break automated test runners. It counters the model's training to be helpful and explanatory, forcing it to prioritize machine-executable output.
