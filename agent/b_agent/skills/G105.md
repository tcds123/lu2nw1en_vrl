Define Algorithm Approach Without Banning Valid Alternatives

**When to apply**: When a specific technique (e.g., recursion, dynamic programming, two-pointer) is pedagogically or performance-required, but multiple valid implementations of that technique exist.
**What to do**: Name the required high-level approach. Describe its key mechanism (e.g., "use memoization to store computed results"). Avoid low-level, overly restrictive commands (e.g., "use a `for` loop", "do not use `while`") that might force an unnatural or incorrect implementation of the core approach.
**Example**: "Solve this using a recursive approach with memoization. Ensure repeated subproblems are not recalculated. Do not mandate the exact structure of the memoization cache (e.g., dictionary vs. list) as long as the principle is followed."
**Why it works**: Guides the model towards the desired solution pattern while preserving its flexibility to generate syntactically correct and idiomatic code. Overly specific bans can lead to contorted code or violations of the ban due to the model's literal interpretation.
