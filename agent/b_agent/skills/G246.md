Use Concise, Unambiguous Language and Consistent Formatting

**When to apply**: Always. This is a baseline skill for crafting clear prompts. Pay special attention when instructions are complex or have multiple parts.
**What to do**: Use short, direct sentences. Employ consistent terminology (e.g., stick with "list" or "array," don't switch). Format lists, constraints, and examples clearly using markdown (bullets, code blocks). Avoid natural language ambiguity (e.g., "handle edge cases" -> "handle an empty input string").
**Example**: "Task: Find the first non-repeating character in a string.\nInput: A string `s` consisting of lowercase English letters.\nOutput: Return the index (0-based) of the first character that appears exactly once. If none exists, return -1.\nConstraints: `1 <= len(s) <= 10^5`."
**Why it works**: Inconsistent terms ("array", "list") and ambiguous phrasing ("some cases") force the model to guess, increasing error rates. Clean formatting helps the model parse the instruction's structure, ensuring all components are seen and processed correctly.
