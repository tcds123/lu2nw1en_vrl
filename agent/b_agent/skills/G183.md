Define Core Functional Requirements in a Structured List

**When to apply**: When the task has 2-5 discrete, non-negotiable rules that the code must follow (e.g., input validation rules, filtering criteria, case-handling). This is crucial for data cleaning, validation, and parsing tasks.
**What to do**: Present the core requirements as a concise, numbered or bulleted list. Use clear, affirmative language for each rule. Keep the list focused on *what* the code must achieve, not *how* it should be implemented.
**Example**: "The function must: 1. Convert all input text to lowercase. 2. Remove any character that is not alphanumeric or a space. 3. Collapse multiple consecutive spaces into a single space."
**Why it works**: Burying requirements in a paragraph increases the chance the model will miss one. A structured list acts as a clear checklist for the model's internal scoring, ensuring each discrete rule is addressed in the generated logic.
