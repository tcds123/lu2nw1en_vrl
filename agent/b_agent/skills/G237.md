Provide Specific Implementation Constraints Without Over-Specifying Syntax

**When to apply**: When the solution must meet certain non-functional requirements (e.g., time/space complexity, banned constructs, mandatory paradigms) but the exact code path should be left to the model.
**What to do**: State constraints in terms of requirements, not syntax. Use phrases like "must run in O(n) time", "do not use the built-in `sorted` function", or "use a recursive approach". Avoid dictating specific variable names or line-by-line logic.
**Example**: "Reverse the linked list in-place. You must use O(1) extra space and cannot create a new list. Modify the nodes' pointers directly."
**Why it works**: Over-specifying syntax (e.g., "use a `for` loop with index `i`") can conflict with the model's optimal solution path or produce unnatural code. Constraining the *what* (complexity, paradigm) rather than the *how* guides the model correctly while preserving its problem-solving flexibility.
