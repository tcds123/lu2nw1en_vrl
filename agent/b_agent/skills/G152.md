Separate Formatting Instructions from Solution Constraints

**When to apply**: When the prompt includes both a strict output format rule (e.g., "output only code") and a complex solution description. Also when previous generations have omitted necessary code blocks, imports, or function bodies while trying to comply with formatting rules.
**What to do**: Clearly distinguish between *what* the model should generate (the solution's logic and structure) and *how* it should be presented. Place formatting instructions in a dedicated section, often at the end, and ensure they do not contradict the requirement to produce complete, runnable code.
**Example**: "Your task is to write a complete Python solution. First, implement the logic described below. After your solution, ensure the final output contains only the code, with no explanatory text, markdown formatting, or comments outside the function body."
**Why it works**: Code generation models can over-index on phrases like "output only code" and may strip out essential parts of the implementation (like necessary `import` statements or closing braces) or fail to generate any code at all, producing only a confirmation message. This separation clarifies that "completeness" is a higher priority than the "only code" format.
