Maintain Coherent, Concise Instructions Without Contradiction or Redundancy

**When to apply**: When the prompt contains multiple implementation steps, complex logic, or a list of requirements that could be misinterpreted as contradictory. Also when refining a verbose or ambiguous user request.
**What to do**: Consolidate all requirements into a single, logically ordered flow. Remove any statements that repeat the same condition in different words. Actively check for and eliminate logical contradictions (e.g., "return a list" vs. "print a string").
**Example**: "Write a function `clean_data(data)` that takes a list of strings. Remove any leading/trailing whitespace from each string, filter out empty strings after trimming, and return the resulting list. Do not modify the original input list."
**Why it works**: Models can become confused or produce erratic code when instructions conflict. Redundancy wastes token budget and can accidentally introduce subtle variations in meaning. A single, clear statement of intent ensures the model focuses on a correct implementation.
