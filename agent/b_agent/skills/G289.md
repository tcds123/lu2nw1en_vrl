Define a Specific Persona and Coding Standards to Ensure Quality Output

**When to apply**: When generating production-ready code, library functions, or code that must adhere to team conventions. When the task is complex enough to benefit from a structured, professional approach.
**What to do**: Explicitly state the role the model should adopt (e.g., "Senior Python Developer"). Specify key coding standards: meaningful naming, use of docstrings, adherence to a style guide (PEP 8), and principles like DRY (Don't Repeat Yourself).
**Example**: "Act as an expert software engineer. Write a solution that is modular, efficient, and well-documented. Use descriptive variable names, include a docstring for the main function explaining parameters and return values, and follow PEP 8 conventions."
**Why it works**: Without a defined persona, models default to a generic, often minimalistic coding style. Explicit standards push the model beyond a "just working" solution towards maintainable, professional code and reduce the chance of sloppy or cryptic implementations.
