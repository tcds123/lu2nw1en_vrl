Balance Algorithmic Direction with Implementation Autonomy

**When to apply**: When the problem has a known efficient approach (e.g., "use a hash map," "apply depth-first search") or when specific style constraints (like functional vs. imperative) are important, but the exact code path isn't critical.
**What to do**: State the high-level algorithm or data structure to use. Specify any non-negotiable style constraints (e.g., "must be recursive," "must use list comprehension"). Then, explicitly grant freedom for the model to handle the specific implementation details, variable naming, and control flow.
**Example**: "Solve this using a stack to track opening brackets. The solution should be in an iterative style. You are free to choose the exact loop structure and variable names."
**Why it works**: Without this balance, models may either ignore the optimal algorithm (producing inefficient code) or become overly constrained by low-level details, reducing code quality and creativity in handling edge cases within the prescribed paradigm.
