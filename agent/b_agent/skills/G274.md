Provide Unambiguous Rules for Input Validation and Error Handling

**When to apply**: When the function must handle invalid or unexpected inputs. When the prompt mentions "robustness" or "defensive programming". Avoid vague terms like "handle errors gracefully".
**What to do**: Explicitly list the validation checks to perform (e.g., type, range, null). Specify the exact response for each invalid case: raise a specific exception (e.g., `ValueError('Input must be positive')`), return a sentinel value (e.g., `None`), or use a default. Do not leave the behavior open to interpretation.
**Example**: "Validate that `n` is an integer. If `n` is not an integer, raise a `TypeError`. If `n` is less than 0, raise a `ValueError` with the message `'n must be non-negative'`. Otherwise, compute and return the factorial."
**Why it works**: Vague instructions like "validate the input" lead to inconsistent or incomplete validation. The model might check for `None` but miss negative numbers, or it might print an error instead of raising an exception, causing the caller's code to break.
