Balance Structure with Flexibility to Avoid Syntax Breakdown

**When to apply**: When providing formatting rules (e.g., "put the code in a single markdown block"). When the model might over-index on minor stylistic demands at the expense of generating valid code.
**What to do**: Provide clear structural guidance but avoid absolute, syntax-breaking commands. Use phrases like "ensure the final output is..." or "the response should contain..." rather than rigid, step-by-step generation mandates.
**Example**: **Instead of**: "First output '```python', then the code, then exactly '```'. Do not write anything else." **Use**: "Provide the complete solution in a single Python code block. Do not include any explanatory text outside the code block."
**Why it works**: Overly rigid formatting commands can cause the model to fail if it missteps slightly, potentially resulting in no code or malformed markdown. Flexible yet clear instructions guide the output format while allowing the model to recover from minor deviations.
