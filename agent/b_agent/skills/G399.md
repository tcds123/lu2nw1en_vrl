Specify Core Algorithm or Data Structure Without Contradiction

**When to apply**: When the problem's solution must use a specific approach (e.g., "use a heap," "implement in O(log n) time") or when you need to guide the model away from a naive, incorrect, or inefficient default approach.
**What to do**: State the required algorithm, data structure, or complexity clearly at the start. Ensure all subsequent details (like allowed operations) are consistent with this core requirement. Avoid mixing in details that contradict it (e.g., asking for O(1) space while also requiring recursion on a list).
**Example**: "Implement a LRU cache class `LRUCache`. You must use a doubly linked list and a hash map (dictionary) to achieve O(1) time for both `get` and `put`. Do not use `collections.OrderedDict`."
**Why it works**: Without explicit guidance, models may choose a simpler, incorrect data structure (like a single list or a standard dict). A clear, non-contradictory mandate forces the model to recall and structure the correct implementation pattern.
