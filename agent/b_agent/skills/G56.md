Prioritize Functional Correctness Over Stylistic Perfection

**When to apply**: When the primary success criterion is passing functional tests, not achieving ideal code style, optimal performance, or adhering to a specific style guide (unless explicitly required).
**What to do**: Frame the prompt around the exact input-output behavior required by validation tests. If style or performance is not part of the test criteria, do not emphasize it. Direct the model's focus to correctness for the given constraints.
**Example**: "Implement `find_duplicate(nums: List[int]) -> int`. The list `nums` contains `n + 1` integers where each integer is in the range [1, n]. There is exactly one duplicate number. Find and return that duplicate. Focus on a correct solution; optimization for O(1) space is not required."
**Why it works**: Without this guidance, models may prioritize generating "beautiful" or "optimal" code (e.g., using list comprehensions, advanced libraries, or complex algorithms) that can introduce subtle bugs or deviate from the expected, simpler solution path that the tests are based on.
