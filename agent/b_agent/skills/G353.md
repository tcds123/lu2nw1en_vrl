Align Primary Logic Description Perfectly with the Intended Evaluation

**When to apply**: When the task involves precise mathematical or logical operations where similar-sounding concepts are distinct (e.g., mean vs. median, substring vs. subsequence, depth-first vs. breadth-first search).
**What to do**: Use precise, standard terminology for the core operation. Double-check that the description of the algorithm matches the exact required output. Do not use near-synonyms or hint at alternative tasks.
**Example**: "Write a function `median(nums: List[float]) -> float` that calculates the **median** value. For an odd-length list, it is the middle element when sorted. For an even-length list, it is the average of the two middle elements. Do not calculate the mean (average)."
**Why it works**: Models may treat related terms as interchangeable if not explicitly disambiguated. A precise definition prevents the model from implementing a common but incorrect alternative (like calculating the average when the median is required), which would fail hidden test cases.
