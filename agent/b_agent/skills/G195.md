Provide Essential Instructions, Avoid Redundant Over-Specification

**When to apply**: When a task requires specific tools or documentation standards but has multiple valid implementation paths. Use to gently guide the model towards idiomatic, well-documented code without locking it into an overly narrow solution.

**What to do**: Mandate the use of specific, high-level Python constructs if they are fundamental to a good solution (e.g., "use `collections.Counter`"). Require a docstring describing parameters and returns. Avoid dictating variable names, loop structures, or intermediate steps unless absolutely necessary.

**Example**: "Write a function `calculate_average(grades: list) -> float`. Use the built-in `sum()` and `len()` functions. Include a docstring that explains the function's purpose, the `grades` parameter, and the return value."

**Why it works**: Instructing "use `sum()` and `len()`" prevents the model from writing an unnecessary manual loop. Requiring a docstring ensures documentation. Avoiding further specification (like "name the variable `total`") prevents conflicts with the model's natural coding style, reducing the chance of syntax errors or odd constructs.
