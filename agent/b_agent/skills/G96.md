Specify Algorithm Requirements Without Logical Contradictions

**When to apply**: When defining algorithm properties that are mutually exclusive or highly unusual in combination (e.g., "in-place" but also "stable" for certain sorts, or "use recursion" with "constant space" for deep recursion).
**What to do**: Ensure the required algorithm properties are logically compatible. If they are not, prioritize the non-negotiable requirement and drop or adjust the contradictory one. For example, require "stable sort" and specify "you may use mergesort or timsort," not "use quicksort."
**Example**: "Implement a sorting function that is stable and operates in O(n log n) time. Do not require it to be in-place, as that would conflict with common stable sort implementations."
**Why it works**: Models trained on vast code corpora know that certain combinations are impossible or non-standard. Providing contradictory constraints can cause the model to generate nonsensical code, fail silently, or choose one constraint arbitrarily, likely not the one you intended.
