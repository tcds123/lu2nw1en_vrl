Balance Specificity and Conciseness in Expert Persona and Core Requirements

**When to apply**: When the prompt needs to define a role (e.g., "expert Python developer") and state key functional requirements without becoming a wall of text. This is crucial for complex tasks like implementing a custom data structure, a multi-step algorithm, or a class with specific methods.
**What to do**: Start the prompt by succinctly defining the expert persona relevant to the task. Then, list the core functional requirements in a clear, bulleted or numbered format. Avoid narrative explanations of *why* the requirements exist; just state *what* is needed. Omit redundant phrasing and tangential details.
**Example**: "You are an expert Python developer specializing in efficient algorithms. Your task is to write a function `find_median_sorted_arrays(nums1, nums2)` that returns the median of two sorted integer arrays. Core requirements: 1. Overall runtime complexity must be O(log (m+n)). 2. You cannot merge the arrays into a new sorted array. 3. Handle empty input arrays."
**Why it works**: Without this balance, models may generate verbose, instructional prose instead of code, or they may miss critical requirements buried in text. Overly terse prompts, conversely, lead to generic or incomplete implementations that don't assume the necessary expertise.
