Define Signature, Types, and Edge Cases Explicitly

**When to apply**: For robust function implementation, especially when edge cases (empty input, `None`, negative numbers, ties) are critical to correctness and likely to be overlooked.
**What to do**: After defining the function signature, include a dedicated "Edge Cases" section. List specific inputs and the expected output or behavior for each. Use the same format as your primary example.
**Example**: "`def find_winner(votes: dict[str, int]) -> str:` # Example: find_winner({'A':5, 'B':5, 'C':3}) returns 'A'. # Edge Cases: - If the dict is empty, return an empty string. - If there is a tie for highest votes, return the candidate whose name comes first alphabetically."
**Why it works**: Models tend to generate code that works for the happy path in the main example. Explicitly enumerating edge cases forces the model to consider and handle them, dramatically increasing the robustness and reliability of the generated code.
