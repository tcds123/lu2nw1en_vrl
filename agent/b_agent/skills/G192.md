Emphasize Core Constraints with Concise, Unambiguous Language

**When to apply**: When the solution has non-negotiable performance (time/space complexity), side-effect rules (in-place modification), or immutability requirements. Common in optimization problems, algorithm interviews, and systems programming.

**What to do**: State constraints using standard computer science terms ("O(n) time, O(1) extra space"). Use imperative language for critical rules: "must modify the input list in-place", "must not use division", "must preserve the relative order of elements".

**Example**: "Write a function `move_zeros(nums: List[int]) -> None`. It must move all zeros in `nums` to the end while maintaining the relative order of non-zero elements. Do this **in-place** with **O(1) extra memory**. Do not return a new list; modify `nums`."

**Why it works**: Without explicit constraints, models frequently generate suboptimal solutions (e.g., using extra space for an in-place problem). Concise, technical keywords activate the model's knowledge of canonical solutions that satisfy those constraints, leading to correct, efficient code.
