Balance Formatting Constraints to Ensure Valid Code Output

**When to apply**: When the required output format is strict (e.g., a single function), but you must avoid generating empty stubs or code missing essential parts like `return` statements. Also applies when banning verbose explanations.
**What to do**: Instruct the model to produce the complete, syntactically correct code structure (e.g., full function with signature and body) while explicitly prohibiting non-code text like comments, examples, or conversational explanations. Use positive framing ("output only the code") combined with a negative prohibition ("do not include any test cases or explanations").
**Example**: "Your output must contain only the Python function definition, complete and executable. Do not include any example usage, print statements, test code, or explanatory text outside the function body."
**Why it works**: Code generation models often default to adding conversational wrappers or example usage, which can break automated evaluation that expects only code. This instruction prevents malformed submissions by prioritizing the essential code structure while removing extraneous output.
