Ensure all technical specifications are consistent and avoid contradictory instructions

**When to apply**: When a prompt contains multiple constraints on implementation method, data structures, or libraries. Double-check when mixing concepts like "generator" and "return a list", or "use recursion" and "must be O(1) space".
**What to do**: Review the prompt for logical conflicts. If you require a specific approach (e.g., recursion), ensure other constraints (e.g., space complexity) are compatible. Remove or revise any contradictory requirements before generation.
**Example**: Instead of "Write a function that yields squares as a generator but returns a list," use the consistent "Write a function that returns a generator yielding squares of numbers." Or, "Write a function that returns a list of squares."
**Why it works**: Models try to satisfy all instructions and may produce bizarre, non-functional, or inefficient code when given contradictory goals. This often results in runtime errors or failed generations as the model cannot resolve the conflict.
