Explicitly Require Input Validation and `ValueError` for Invalid Ranges

**When to apply**: For functions involving numerical parameters with strict validity domains (e.g., mathematical bases, array indices, scaling factors). This is crucial for building robust, production-ready functions.
**What to do**: Directly instruct the model to validate the input parameter(s) against a specified valid range or set of conditions. Mandate that the function must raise a `ValueError` with a descriptive message if the input is invalid, before any other processing occurs.
**Example**: "The `base_convert` function must validate that the `base` parameter is an integer between 2 and 36, inclusive. If it is not, the function must immediately raise a `ValueError` with an appropriate message (e.g., 'Base must be between 2 and 36')."
**Why it works**: Without explicit instruction, models often generate code that assumes valid input, leading to silent errors or crashes. Mandating validation with a specific exception type enforces defensive programming and a clear API contract.
