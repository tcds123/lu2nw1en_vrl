Align Prompt Requirements Exactly with the Problem's Core Attributes and Methods

**When to apply**: When the problem statement defines a specific class name, method signatures, attributes, or a precise input/output format. This is crucial for LeetCode-style problems, coding challenge specifications, or API interface definitions.
**What to do**: Extract the exact class name, method names, parameter names (including order and types), return types, and required public attributes from the problem statement. List them verbatim in the prompt. Do not rename parameters for "clarity" or add helper methods unless explicitly required.
**Example**: "Implement a class `TicTacToe` with the following method: `def move(self, row: int, col: int, player: int) -> int:`. The constructor is `def __init__(self, n: int):`. The method must return the winning player's number (1 or 2) if the move causes a win, otherwise 0. Do not add any other public methods or attributes."
**Why it works**: Code generation models may hallucinate convenient but non-compliant interfaces (e.g., changing `player: int` to `player: str`), add unnecessary constructors, or omit a required attribute. This strict alignment ensures the generated code passes automated tests that check for exact signature matches.
