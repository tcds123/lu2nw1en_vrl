Define an expert persona focused on correctness and mandate edge-case handling upfront.

**When to apply**: When the problem involves numerical ranges, boundary conditions, empty inputs, or special values (like zero, one, null, empty strings). Also for problems where premature optimization could obscure correctness.
**What to do**: Begin the prompt by establishing a persona (e.g., "You are a senior software engineer...") that prioritizes robust, correct code over cleverness. Explicitly list the fundamental edge cases the solution must handle correctly before any other considerations. This frames the model's entire approach.
**Example**: "You are a meticulous senior software engineer. Your primary goal is to produce absolutely correct and robust code. Before considering any optimizations, ensure your solution explicitly and correctly handles these fundamental cases: n <= 1, empty input list, strings containing only whitespace, and the case where the target element is not found."
**Why it works**: Code generation models often produce solutions that work for the "happy path" but fail on obvious edge cases. By defining a persona that values correctness and explicitly listing critical edges, you prime the model to incorporate defensive logic from the start, preventing trivial failures.
