Enforce Minimalist Code-Only Output Formatting

**When to apply**: When the generated code will be directly executed, evaluated by an automated judge, or integrated into a larger codebase without manual extraction. Also crucial when the model has a tendency to add verbose explanations, markdown headers, or conversational text.

**What to do**: Issue a clear, direct command that the model's output must consist solely of the final, runnable code. Explicitly forbid all explanatory text, comments outside the solution, and conversational markdown. Specify that code formatting (like triple backticks for code blocks) must be perfectly balanced and not interfere with direct copying.

**Example**: "Your output must contain only the final, executable code. Do not include any explanatory text, comments outside the function/class body, markdown code fences (```), or conversational notes. The code must be ready to be copied and run directly."

**Why it works**: Code generation models often default to a conversational, tutorial-like output style, which breaks automated testing systems and requires manual cleanup. This instruction directly counteracts that default, forcing the model into a "raw code" mode.
