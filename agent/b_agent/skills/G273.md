Prescribe the Core Algorithm, Bounds, and Edge-Case Strategy

**When to apply**: For algorithmic problems where the solution space is large or a specific approach is required (e.g., "use a sieve", "apply two-pointer technique", "handle overflow"). Also crucial for problems with mathematical bounds or specific performance requirements.
**What to do**: Directly state the intended algorithm or algorithmic family. Specify any mathematical bounds (e.g., "results fit within a 32-bit signed integer"). Enumerate key edge cases (e.g., "handle empty input, single element, and duplicate values") and prescribe how to handle them.
**Example**: "Implement the solution using a sliding window approach. The input list length `n` is up to 10^5. Handle the case where the window size `k` is greater than `n` by returning an empty list. Ensure the time complexity is O(n)."
**Why it works**: Without this guidance, the model may select a suboptimal algorithm (e.g., O(n^2) instead of O(n)), fail to consider integer overflow, or ignore critical edge cases, resulting in a solution that is inefficient, incorrect, or fails on hidden test cases.
