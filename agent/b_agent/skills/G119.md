Define an Expert Persona Aligned with Core Evaluation Logic

**When to apply**: When you want to encourage high-quality, secure, or idiomatic code, but the problem has specific, non-standard evaluation rules (e.g., must use a particular inefficient algorithm, must not use a certain library).
**What to do**: First, establish the persona (e.g., "You are a senior software engineer"). Then, immediately state any non-negotiable logic or constraints that take precedence over general best practices. Use phrases like "even though" or "despite" to highlight the alignment.
**Example**: "You are an expert in writing clean, production-ready Python. However, for this specific problem, you must implement the O(n²) algorithm as described, even if more efficient alternatives exist, as this is what the evaluator will test."
**Why it works**: Without this, the model might apply its "expert" knowledge to "optimize" a solution, violating the problem's implicit requirements and failing tests. This explicitly reconciles the persona's goals with the problem's success criteria.
