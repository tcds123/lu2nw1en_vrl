Provide Clear Function Signatures While Avoiding Overly Rigid Implementation Steps

**When to apply**: When the task requires a specific function or method to be generated, especially for coding challenge solutions, API implementations, or when integrating with existing code that expects a precise interface.
**What to do**: Explicitly define the function name, its parameters (with types if applicable), and its return type. Describe *what* the function should do, but do not prescribe *how* it should do it step-by-step (e.g., avoid "first, initialize a variable i; then, create a while loop...").
**Example**: "Write a function `def max_profit(prices: list[int]) -> int:` that returns the maximum profit possible from a single buy and sell transaction given daily prices. The function must take a list of integers as input."
**Why it works**: Code generation models can fixate on literal, step-by-step instructions, leading to unnatural or inefficient code. This approach ensures the generated code has the correct interface for testing or integration while allowing the model to leverage its own patterns for the internal logic, which often yields more idiomatic solutions.
