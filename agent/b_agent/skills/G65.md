Define Precise Output Format and Edge Case Behavior

**When to apply**: When correctness hinges on exact output formatting (string case, spacing, delimiter) or when edge cases (empty input, zero, negative numbers, ties) have specific, non-intuitive handling rules.

**What to do**: Explicitly state the required return type and format. Use examples for normal and edge cases. Specify the exact return value for each edge case (e.g., `None`, empty list, specific error message, or raised exception).

**Example**: "The function `find_first_prime(arr: List[int]) -> Optional[int]` must return the first prime number found in the list, or `None` if no prime is found. Return the integer itself, not its index. For an empty input list, return `None`. Do not print anything."

**Why it works**: Models might make reasonable but incorrect assumptions, like returning `-1` for "not found," raising an exception, or printing the result instead of returning it. These subtle deviations cause hidden test failures even if the core logic is correct.
