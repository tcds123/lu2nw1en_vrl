Specify Key Constraints Explicitly but Minimally

**When to apply**: When certain tools or approaches are forbidden (e.g., "no external libraries"), or when a specific algorithm is required (e.g., "use binary search"). When constraints are critical to the problem's validity.
**What to do**: List essential bans or mandates in a dedicated "Constraints" section. Be specific about what is disallowed (library names) or required (algorithm names), but avoid adding unnecessary restrictions on code style or structure.
**Example**: "Constraints: Do not use the `datetime` module. You must implement the date logic manually. Time complexity must be O(log n)."
**Why it works**: Without explicit bans, models frequently default to using powerful built-in libraries (`itertools`, `datetime`, `numpy`) that might circumvent the intended challenge. Stating complexity requirements prevents brute-force solutions. Minimalism prevents the constraint list from becoming contradictory or overwhelming.
