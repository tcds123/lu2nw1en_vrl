Maintain Consistency in Formatting and Style Instructions

**When to apply**: When providing a multi-part prompt or when combining skills from a library. Inconsistencies often arise around docstrings, comments, type hints, and use of print statements.
**What to do**: Audit the full prompt for conflicting directives. Choose a consistent stance (e.g., "include docstrings" or "no comments") and apply it uniformly. Avoid saying "add comments" in one section and "output only code" in another.
**Example**: "Generate a complete Python function. **Include a brief docstring describing parameters and returns.** Do not add any other comments or print statements within the function body. The output should be the function definition only."
**Why it works**: Models are sensitive to conflicting signals and may become confused, resulting in a partial or erratic adherence to style rules (e.g., adding a docstring but then also adding explanatory `print` calls). Consistency removes this ambiguity, leading to cleaner, more predictable output.
