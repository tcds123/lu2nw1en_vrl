Explicitly Define Edge Case Handling with Exact Return Values

**When to apply**: When edge cases are not merely about validation but require specific, non-error return values as part of the business logic. This is a more specific application of G291.
**What to do**: For each identified edge case (empty input, zero, null, boundary values), state the *exact* value or object that must be returned. Do not leave it open-ended (e.g., "handle gracefully").
**Example**: "The function `average(grades: list[float]) -> float` should return the arithmetic mean. If the input list is empty, return `0.0`. If any grade in the list is negative, return `-1.0` to indicate invalid input."
**Why it works**: Vague instructions like "handle the empty case" lead to inconsistent model behavior—some may return `None`, `0`, `[]`, or raise an exception. Defining the exact expected output ensures deterministic, testable behavior across all scenarios.
