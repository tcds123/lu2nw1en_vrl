Emphasize Robust Error Handling and Standard Libraries Concisely

**When to apply**: When the problem involves operations that can clearly fail (I/O, parsing, division, key lookups); when you want to ensure the solution is practical and not just a contest-style snippet.
**What to do**: Instruct the model to handle specific, likely exceptions (e.g., `ValueError`, `KeyError`, `ZeroDivisionError`) and to use the standard library where appropriate. Bundle this into a single, succinct directive.
**Example**: "Implement `parse_config(filepath: str) -> Dict`. Use the `json` module. Include robust error handling using `try-except` to catch `FileNotFoundError` and `json.JSONDecodeError`, returning an empty dict `{}` in those cases."
**Why it works**: Without this nudge, models often generate brittle code that assumes ideal inputs. This concise instruction steers the model towards production-quality patterns without adding verbose, step-by-step error-handling logic that could clutter the main solution.
