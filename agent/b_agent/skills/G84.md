Explicitly Define the Expected Output Format and Scope

**When to apply**: When the evaluation context differs from typical interactive coding (e.g., requires a full runnable script, a single expression, or a specific function signature). Clarify to match the execution environment.
**What to do**: State clearly whether the output should be a standalone script, a function, a class, or a code snippet. If a function, specify its name and parameters to ensure correct invocation.
**Example**: "Output a complete Python script that reads from standard input, processes it, and prints the result to standard output. Do not wrap the logic inside a function."
**Why it works**: Assuming the wrong output type (function vs. script) is a common failure. This aligns the model's generation with how the evaluator will execute the code—whether by calling a function or running the script directly.
