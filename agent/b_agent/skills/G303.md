Guide Algorithmic Approach at a High Level

**When to apply**: When a specific algorithm or strategy is required for correctness or efficiency, but you want to avoid micromanaging the implementation details. Useful for teaching or when the model might otherwise choose a naive, inefficient approach.

**What to do**: Specify the algorithmic paradigm or key data structure to use (e.g., "use a sliding window", "implement a depth-first search", "use a min-heap for efficiency"). Avoid prescribing low-level details like specific variable names (`i`, `j`, `ptr`) or exact loop structures.

**Example**: "Solve this using a two-pointer technique starting from both ends of the sorted array. Do not use extra space for a hash map."

**Why it works**: It steers the model towards the correct solution space without being overly restrictive. This balances guidance with flexibility, allowing the model to generate idiomatic code while adhering to the necessary algorithmic constraint, preventing brute-force or memory-inefficient solutions.
