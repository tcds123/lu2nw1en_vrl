Specify the Exact Algorithm or Key Implementation Steps

**When to apply**: When the problem's correctness or efficiency hinges on a specific known algorithm (e.g., Sieve, Dijkstra's, Quickselect) or a non-obvious implementation trick.
**What to do**: Name the algorithm. Optionally, list 1-3 of its most critical, non-trivial steps that the model might get wrong. Do not re-derive the entire algorithm; assume knowledge of its standard form.
**Example**: "Generate all prime numbers up to `n`. Use the Sieve of Eratosthenes. Key steps: Initialize a boolean list of length n+1. Iterate `p` from 2 to sqrt(n). If `p` is prime, start marking multiples from `p*p`."
**Why it works**: Models can solve a problem many ways; naming the algorithm narrows the search space. Highlighting the tricky step (e.g., starting from `p*p`) prevents a common, less efficient implementation error, ensuring the generated code matches the intended performance characteristics.
