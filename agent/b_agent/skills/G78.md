Specify Serialization Format for Null/Missing Values

**When to apply**: When dealing with tree, graph, or linked list problems that require serialization/deserialization. When the input or output represents a hierarchical structure with potential null children.
**What to do**: Define the exact placeholder for null. Specify the order of serialization (e.g., level-order). State how trailing nulls are handled (often omitted).
**Example**: "Serialize the binary tree to a string using level-order traversal. Represent `null` nodes with the string `"null"`. Omit trailing `null`s from the serialized list. For example, a tree with root value 1 and a left child 2 should serialize to `[1,2,null]`, not `[1,2,null,null,null]`."
**Why it works**: Models frequently default to common but inconsistent conventions (e.g., `None`, `-1`, `'NULL'`, omitting nodes). Mismatched null representation is a major source of deserialization errors. An explicit format ensures the generated code matches the expected wire protocol.
