Explicitly List Required Signatures, Attributes, and Output Formats

**When to apply**: For any class definition task; when function names or parameter order are critical; when string output must match a test case exactly (e.g., spaces, newlines, rounding).
**What to do**: Provide the exact class name, method signatures (including parameter *names* and *types*), and return types. For output, specify the format verbatim, using examples if necessary. Treat this as the API contract.
**Example**: "Define a class `BankAccount` with `__init__(self, owner: str, balance: float = 0.0)`. It must have methods `deposit(self, amount: float) -> None` and `get_balance(self) -> str` that returns a string exactly like `'Owner: Alice, Balance: $50.00'`."
**Why it works**: Models can hallucinate minor differences in parameter names (`balance` vs `initial_balance`) or output formatting, causing test failures. This level of precision eliminates ambiguity and ensures the generated code interfaces correctly with the test harness.
