Focus on the "What": Declarative Requirements Over Prescriptive Steps

**When to apply**: When the prompt reads like a step-by-step tutorial, dictating the algorithm's inner workings. When the goal is to assess the model's problem-solving ability, not its ability to transcribe instructions.
**What to do**: Describe the task's objective, inputs, outputs, and any critical properties (e.g., time complexity, stability). Avoid phrases like "first, create a variable; then loop through; finally, return." Use declarative language: "The function must...", "It should return...", "Ensure the output satisfies...".
**Example**: Instead of: "First, initialize an empty dictionary. Then iterate through the string. For each character, check if it's in the dictionary and update its count. At the end, return the dictionary." Use: "Write a function `char_frequency(s: str) -> dict` that returns a dictionary where each key is a character from the string `s` and its value is the count of occurrences in `s`."
**Why it works**: Prescriptive instructions can lead to brittle, literal translations that fail on edge cases. Declarative requirements allow the model to reason about the problem space and choose an appropriate implementation strategy, often resulting in more robust and idiomatic code.
