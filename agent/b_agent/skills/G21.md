Verify and Include Precise Problem Specifications and Constraints

**When to apply**: When the task involves numerical thresholds (e.g., "discount rates over 15%"), business rules (e.g., "users must be over 13"), or algorithmic limits (e.g., "time complexity O(n log n)"). An incorrect or omitted specification renders the solution invalid, regardless of code quality.

**What to do**: Before finalizing the prompt, cross-check all numerical values, comparison operators (>, >=, <, <=), rates, limits, and edge-case definitions against the ground truth problem statement. Incorporate these verified constraints explicitly and verbatim into the prompt's requirements section.

**Example**: "Implement validation such that a `discount_percent` is considered valid only if it is a number between `0.0` and `50.0` (inclusive). Orders with a `total_weight_kg` greater than `30.0` must be flagged for manual review. The solution must handle up to `10^5` input items efficiently."

**Why it works**: Models will treat the prompt as the sole source of truth. If the prompt says "over 10," the model will implement `if x > 10:`. If the true requirement was "10 or over," the generated code will be subtly wrong. This skill prevents specification hallucination and ensures functional correctness.
