Ground Performance Goals in Reality, Avoid Hyperbole

**When to apply**: When giving performance benchmarks, especially relative to highly optimized built-in functions or libraries (e.g., Python's `sorted`, `numpy` operations, etc.).
**What to do**: Set realistic performance goals. Instead of "outperform the built-in sort," specify "aim for O(n log n) complexity" or "minimize memory allocations." Acknowledge that matching built-in performance is a worthy goal, but claiming to surpass it in a simple Python script is often unrealistic.
**Example**: "Implement an efficient function to concatenate a list of strings. The goal is to achieve O(n) total character copying, avoiding the common O(n^2) pitfall of repeated concatenation. Note that `''.join(list_of_strings)` is the built-in, optimal way to do this; your implementation should illustrate the efficient algorithm."
**Why it works**: It keeps the prompt credible and focused on achievable learning or demonstration objectives. Unrealistic claims can confuse the model or lead it to generate misleading code with false performance comments. It encourages the model to focus on sound algorithmic principles rather than impossible optimizations.
