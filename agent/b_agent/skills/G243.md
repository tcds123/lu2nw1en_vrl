Avoid Verbose Meta-Commentary and Contradictory Instructions

**When to apply**: When instructions are becoming long or nested. When you notice phrases like "make sure to also...", "on the other hand...", or "it is important to note that..." which add noise.
**What to do**: Strip out conversational asides, self-referential notes about the prompt itself, and redundant emphasis. Combine or remove overlapping directives. Ensure all remaining instructions are logically consistent (e.g., don't forbid loops but require O(n^2) complexity).
**Example**: Instead of: "You must use a hash map for efficiency. Actually, a set might work too. But don't use a brute force double loop because that's too slow. Also, remember to handle the empty input case." Use: "Implement a solution with O(n) average time complexity. Handle the empty input case by returning an empty list."
**Why it works**: Extra verbiage dilutes the signal, and contradictions create confusion, leading the model to either ignore critical parts or generate internally inconsistent code. Concise, consistent instructions maximize the probability of correct, coherent generation.
