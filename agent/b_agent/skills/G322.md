Structure prompt logically, prioritizing essential instructions

**When to apply**: For all prompts, especially complex ones with multiple requirements, examples, and edge cases.
**What to do**: Organize the prompt in a logical flow: 1) Persona & Task Summary, 2) Function Signature, 3) Core Requirements & Constraints, 4) Input/Output Examples, 5) Edge Cases, 6) Coding Standards. Use clear headings or separators. Place the most important information (signature, core task) first.
**Example**: "**Task Summary**: [1-sentence summary].\n**Function**: `def func(...) -> ...:`\n**Core Requirements**:\n- [Req 1]\n- [Req 2]\n**Examples**:\n>>> func(input1)\noutput1\n**Edge Cases**:\n- What if input is empty?\n- What if input contains duplicates?\n**Code Quality**: Include docstring and type hints."
**Why it works**: A logical structure mirrors how humans reason about problems and how models parse information. Prioritizing key data reduces the "recency bias" where models overweight the last thing they read. It makes the prompt easier to debug and iterate on.
