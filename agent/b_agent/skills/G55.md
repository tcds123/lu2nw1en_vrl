Balance Detail and Conciseness for Clear Model Interpretation

**When to apply**: When the problem has multiple requirements or edge cases. When it's necessary to be precise without writing an overly long, complex prompt that may confuse the model.
**What to do**: List requirements as bullet points or short, separate sentences. Include all essential details (e.g., input ranges, return types, specific edge-case behavior) but omit verbose explanations, motivational context, or restrictive phrasing about *how* to implement (e.g., "you must use a loop").
**Example**: "Write `def count_vowels(s: str) -> int`. Requirements: Count both uppercase and lowercase vowels (a, e, i, o, u). Return 0 for an empty string. The input will only contain alphabetic characters."
**Why it works**: Excessively long or complex prose can cause the model to miss key constraints. Conversely, being too terse can omit critical details. Structured, concise listing helps the model parse and adhere to all functional points without distraction.
