Guide with Concrete, Non-Leaky Algorithm Hints

**When to apply**: When the problem has a known trick or specific data structure that is key to the solution (e.g., Roman numerals, coin change greedy validity, monotonic stack). Use to point the model in the right direction without giving away the entire implementation.

**What to do**: Provide a concrete, declarative hint about the required data or algorithm structure. Reference specific, named entities (value-symbol pairs, adjacency list, parent pointer). Avoid abstract procedural descriptions ("check all possibilities and then combine results").

**Example**: "To convert an integer to a Roman numeral, use a descending list of tuples: `[(1000, 'M'), (900, 'CM'), ..., (1, 'I')]`. Iterate through this list, appending the symbol while subtracting the value from the input number."

**Why it works**: Abstract hints ("use a greedy approach") can be interpreted in multiple ways, leading to incorrect implementations. A concrete, data-centric hint ("descending list of value-symbol pairs") directly shapes the algorithm's core loop and data representation, dramatically increasing correctness.
