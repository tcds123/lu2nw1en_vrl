Enforce Algorithmic Constraints Concisely and Consistently

**When to apply**: When the core challenge is to implement an algorithm manually (e.g., custom sort, search) or to enforce functional programming principles (immutability). When the prompt's constraints are buried in verbose text.
**What to do**: State the core algorithmic prohibition clearly and upfront (e.g., "Do not use built-in sorting functions"). Pair it with any key behavioral requirements (e.g., "Do not modify the input argument"). Keep these constraints as simple, standalone statements without extra justification or repetition.
**Example**: Instead of: "You need to sort the list, but the point is to learn how sorting works, so don't just call .sort(), that's cheating. Make sure you don't change the original list either." Use: "Implement the function `custom_sort(lst: list) -> list` to return a new sorted list. You must not use Python's built-in `sorted` or `list.sort`. The input list `lst` must not be modified."
**Why it works**: Models can miss critical constraints if they are phrased as commentary. Clear, imperative prohibitions directly influence the model's token selection, making it far less likely to generate a disallowed built-in function or a side-effect-producing mutation.
