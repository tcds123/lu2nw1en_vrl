Specify Interface and Logic, Not Low-Level Implementation

**When to apply**: When defining a function, class, or API. When the prompt dives into specifics like "use a while loop with index `i`" or "name the accumulator variable `res`."
**What to do**: Clearly define the function signature (name, parameters with types, return type). Describe the core logical transformation or property the code must enforce. Explicitly state that implementation choices (data structures, loops, intermediate variables) are at the discretion of the solver.
**Example**: Instead of: "Create a function. Use two pointers, `left` and `right`. Move them towards the center and swap characters in a while loop to reverse the string." Use: "Implement a function `reverse_string(s: str) -> str` that returns the reverse of the input string `s`. Do not use `s[::-1]` or `reversed(s)`. The implementation must reverse the string in-place if the language supports it, or otherwise return a new reversed string."
**Why it works**: Over-specifying implementation details prevents the model from using potentially better or more idiomatic approaches (e.g., recursion, library functions). By defining the contract and key logical constraints, you test the model's problem-solving, not its ability to copy pseudocode.
