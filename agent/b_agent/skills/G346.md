Define the Exact Function Signature and Documentation Format

**When to apply**: When integrating generated code into a larger codebase with style guides, or when automated tools will parse the documentation. When the return type or parameter types are critical (e.g., for type hints or static analysis).
**What to do**: Specify the function name, parameter names and types, return type, and the exact docstring format (e.g., Google, NumPy, ReST). Include any raised exceptions in the signature or docstring.
**Example**: "Implement a function with this exact signature and docstring:
```python
def parse_config(file_path: str) -> dict[str, Any]:
    '''
    Parses a YAML configuration file.

    Args:
        file_path: Path to the .yaml configuration file.

    Returns:
        A dictionary containing the parsed configuration.

    Raises:
        FileNotFoundError: If `file_path` does not exist.
        yaml.YAMLError: If the file contains invalid YAML.
    '''
```
**Why it works**: Models may default to inconsistent naming, omit type hints, or use incorrect docstring formats, reducing code usability and maintainability. A precise specification ensures the generated code meets integration standards.
