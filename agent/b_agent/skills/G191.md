Clearly Define Signatures and Outputs, Not Implementation

**When to apply**: When the "what" is more important than the "how"—common in algorithm challenges, data transformations, or when evaluating multiple solution strategies. Use when you want to test the model's problem-solving ability within a fixed output format.

**What to do**: Provide the exact function signature (name, parameters with type hints, return type). Describe the required transformation or result in clear input-output terms. Avoid mentioning specific libraries, loops, or variables unless they are the *only* way to solve it.

**Example**: "Implement a function `find_missing_number(nums: List[int]) -> int`. Given a list `nums` containing `n` distinct numbers in the range `[0, n]`, return the single missing number. The function signature and described behavior are the only constraints."

**Why it works**: Telling a model *how* to solve a problem (e.g., "use Gauss' formula") can bypass the core challenge if the goal is to see if it knows the optimal method. This focuses the model on achieving the correct outcome, allowing it to select from its knowledge of valid algorithms (e.g., sum formula, XOR).
