Maintain clear, concise instructions without redundant formatting or verbosity

**When to apply**: When prompts become long and risk burying the core request in markdown, excessive explanations, or polite but unnecessary phrasing. Also when previous generation attempts produced correct logic but with unwanted commentary or formatting in the code.
**What to do**: Strip away any narrative setup, motivational language, or meta-commentary about the task's importance. Use imperative voice. Combine related constraints into single, dense sentences. Avoid bullet points for trivial items unless they improve clarity.
**Example**: Instead of "Hello, could you please write a function that, given a list of integers, computes their sum? It would be great if you could make sure it's efficient. Thanks!", use: "Write a function `sum_list(nums)` that returns the sum of all integers in the input list."
**Why it works**: Extra verbiage dilutes the signal-to-noise ratio for the model, increasing the chance it misinterprets a side comment as a core requirement or generates unnecessary code (like print statements for explanation). Concise prompts focus the model's attention.
