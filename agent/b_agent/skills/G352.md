Structure Requirements Logically and Avoid Syntactic Corruption

**When to apply**: When requirements are presented in a disordered list, contain grammatical errors, or include placeholder text like "[DESCRIBE HERE]" that breaks the instruction's flow.
**What to do**: Organize instructions in a logical sequence: 1) Function signature, 2) Core logic/algorithm, 3) Input validation/edge cases, 4) Output format. Proofread the prompt to ensure it is syntactically correct English (or the relevant language) with no broken clauses or mixed tokens.
**Example**: "Implement `calculate_tax(income: float) -> float`. The logic must apply a 10% tax to income up to 50,000 and 20% to any amount above. Validate that income is non-negative; raise a `ValueError` otherwise. Return the tax amount rounded to two decimal places."
**Why it works**: Models are sensitive to syntactic coherence. Logically structured, grammatically correct prompts are parsed more accurately, leading to code that correctly implements the sequence of operations. Broken syntax can cause the model to generate nonsensical or incomplete code.
