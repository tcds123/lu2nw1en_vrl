Balance Thoroughness with Conciseness in Requirements

**When to apply**: When the task has multiple, important facets (input validation, error handling, performance) but the prompt is becoming a long paragraph that risks the model overlooking key details.
**What to do**: Use bullet points or numbered lists to break down requirements. Each point should be a single, atomic instruction. Remove redundant words and narrative fluff. Group related constraints together.
**Example**: "Create a function that validates an email address. Requirements: 1. Check for presence of a single '@' symbol. 2. Ensure the domain part contains a '.'. 3. Return a boolean. 4. Time complexity should be O(n)."
**Why it works**: Verbose, prose-style prompts can cause models to miss critical instructions due to information overload. A concise, scannable list reduces noise, improves instruction fidelity, and makes it easier for both the user and model to verify that all points have been addressed.
