Specify Both Time and Space Complexity Requirements Explicitly

**When to apply**: For any algorithm where efficiency is a primary concern, especially in scenarios with large data (big O notation) or memory-constrained environments (space complexity). This is critical for problems involving caching, recursion, or large auxiliary data structures.
**What to do**: Clearly state the required or preferred time complexity (e.g., O(n)) and space complexity (e.g., O(1) auxiliary space). If a trade-off exists, indicate the priority (e.g., "optimize for time, then space").
**Example**: "Write a function `find_duplicate(nums)` where nums contains n+1 integers between 1 and n. The function must run in O(n) time, use only O(1) extra space, and cannot modify the input array."
**Why it works**: Models might default to a suboptimal solution (e.g., using a hash set for O(n) space when O(1) is possible) if not explicitly constrained. Stating both requirements forces consideration of algorithms like Floyd's Tortoise and Hare, which meet the specific dual constraints.
