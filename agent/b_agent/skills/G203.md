Clearly Specify Exact Signatures, Data Structures, and Error Types

**When to apply**: When designing classes, stateful objects, or APIs where the internal representation (like history logs) and exception contracts are as important as the functionality.
**What to do**: Detail the exact method signatures, the required internal data structure (type and format), and for errors, specify the exact exception type *and* the string message that should be raised.
**Example**: "Implement a `Calculator` class with an `add(x, y)` method and a `history` attribute. `history` must be a list of tuples, each like `('add', x, y, result)`. On division by zero, raise `ZeroDivisionError('Cannot divide by zero')`."
**Why it works**: Models often get the "shape" of data structures wrong (using a dict instead of a list of tuples) or raise generic `Exception` objects. Precise specification ensures the generated code matches the expected interface for downstream consumers and testing.
