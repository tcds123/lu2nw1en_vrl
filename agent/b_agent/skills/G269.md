List Required Methods with Precise Signatures

**When to apply**: When designing a class or an API with multiple interacting methods. Crucial to avoid ambiguity about which methods are needed and how they interface.
**What to do**: List each required method as a bullet point with its full signature (def name(self, param: type) -> return_type). Under each, briefly state its single responsibility. Do not mix behavioral instructions across methods.
**Example**: "Implement a `Calculator` class with: - `def add(self, a: float, b: float) -> float:` Returns the sum of a and b. - `def memory_store(self, value: float) -> None:` Stores the provided value in an instance variable. - `def memory_recall(self) -> float:` Returns the stored value."
**Why it works**: Ambiguous instructions like "the class should have methods to add and manage memory" lead to missing methods, incorrect signatures, or conflated responsibilities. Precise signatures act as a contract, ensuring the generated class has a correct and usable interface.
