Prioritize Functional Correctness Over Cosmetic Formatting Rules

**When to apply**: When the primary goal is a working algorithm, and exact docstring formats or comment styles are not evaluated. This focuses the model's capacity on logic.
**What to do**: Instruct the model to focus on writing correct, efficient code. If specific output (like a printed value) is needed, state that. De-emphasize or omit requirements for specific comment styles, docstring formats (e.g., reStructuredText), or markdown code fences unless they are part of the test.
**Example**: "Write a function that returns the kth largest element in an unsorted list. Do not worry about writing docstrings. Just ensure the function is correct and efficient."
**Why it works**: Models can waste tokens and attention on generating perfect docstrings or comments at the expense of buggy logic. This directive allocates the model's "thinking" to the problem-solving layer.
