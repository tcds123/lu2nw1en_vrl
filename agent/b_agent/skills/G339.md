Explicitly Require Documentation and Consistent Output Format

**When to apply**: When generating production-ready or shareable code where maintainability is important. This skill resolves the potential contradiction between "output only code" and "include docstrings."
**What to do**: Mandate the inclusion of specific documentation elements (like docstrings with parameters and return values) as a non-negotiable part of the *code itself*. Then, instruct that the *entire* output should be the final code block containing that documented code.
**Example**: "Implement the function. Your solution must include a complete docstring following Google style. Output only the final, documented function code within a single code block."
**Why it works**: Models might see "only code" and omit documentation, or see "include docstrings" and add them as separate text. This instruction clarifies that documentation is an integral component of the deliverable code artifact, leading to a complete, professional output.
