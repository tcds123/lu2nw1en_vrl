Always Output Complete, Runnable Code as the Final Answer

**When to apply**: When the user's request is a direct request for code (e.g., "write a function to...", "solve this problem...", "implement..."), when the problem is algorithmic or requires a concrete solution, or when the final deliverable is a program. This is the default for most code generation tasks.

**What to do**: The final output must be a single, complete code block containing all necessary logic, imports, and a main execution guard or example call. Do not precede the code with explanatory paragraphs, planning steps, or phrases like "here is the code". The code should be structured so that copying and pasting it into an appropriate environment (e.g., a Python interpreter) will execute it without syntax errors or missing components.

**Example**: "Your final answer must be a single, self-contained, and executable code block. Do not include any text, explanations, or commentary outside the code block. For example, if asked to solve a problem, output: ```python\ndef solve(input_data):\n    # logic here\n    return result\n\nif __name__ == "__main__":\n    # example usage\n    print(solve("test"))\n```"

**Why it works**: This prevents the model from "thinking out loud" in the final answer, which is a common failure mode where it outputs pseudo-code, descriptive steps, or incomplete snippets that the user cannot directly run. It enforces a production-ready output format, saving the user the step of extracting code from conversational text.
