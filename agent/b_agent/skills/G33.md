Define the Core Algorithmic Requirement Without Over-Specifying Steps

**When to apply**: For problems where the main challenge is translating a worded problem into a precise computational rule, particularly with sorting, counting, or string parsing.
**What to do**: Clearly state the rule or metric to be computed and any tie-breaking or formatting logic. Avoid detailing the implementation sequence (e.g., "first split, then count, then store in a list...").
**Example**: "Count the number of '/' characters to determine directory depth. If two paths have the same depth, break the tie by choosing the lexicographically smaller one."
**Why it works**: Models are proficient at implementing stated rules but can be led astray by unnecessary procedural constraints. This focuses the model on the *what* (the rule), freeing it to choose an efficient *how* (e.g., using `str.count` and `sorted` with a key function).
