Forbid Contradictions Between Prompt Body and Code Structure

**When to apply**: When the prompt contains both high-level requirements (in the body) and specific code formatting rules (often at the end). This prevents self-contradiction.
**What to do**: Actively review the prompt for conflicts. For example, if the prompt body says "write a concise solution without extra fluff," but a later rule requires "comprehensive docstrings," you must resolve this. Explicitly instruct the model on which rule takes precedence or clarify that docstrings are not considered "extra fluff" in this context.
**Example**: "The prompt asks for 'clean, minimal code.' Note that 'minimal' here refers to algorithmic simplicity, not the omission of documentation. You must still include the required docstrings and type hints as specified, as they are essential for production code."
**Why it works**: Models can become confused by contradictory instructions, leading to incomplete outputs (e.g., missing docstrings) or internal logical errors. Resolving the conflict explicitly provides a clear, single directive for the model to follow.
