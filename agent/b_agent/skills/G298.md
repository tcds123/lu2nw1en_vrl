Strictly Prohibit All Non-Code Output

**When to apply**: A stricter version of G250, used when even internal comments or docstrings might be problematic for an automated evaluator, or when the solution must be a single, unadorned block of code (common in competitive programming judges).

**What to do**: Command the model to output *only* the solution's code. This includes forbidding module-level docstrings, "if __name__ == '__main__'" blocks, and any comments that are not strictly necessary for the code's logic. The output should be a bare solution class or function.

**Example**: "Output only the code for the solution class/function. Do not include a 'if __name__ == '__main__':' block, any print statements for testing, or any comments outside the function body. The entire response must be the code."

**Why it works**: Some evaluators parse the exact submission and may fail on unexpected output. This instruction eliminates all potential noise, ensuring the model's entire response is consumable as the answer.
