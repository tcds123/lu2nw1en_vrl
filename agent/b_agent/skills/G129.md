Restrict Output to Core Functionality with No Extraneous Elements

**When to apply**: Always, unless the task explicitly asks for a full script with I/O. This is a baseline hygiene skill to ensure the generated code is directly usable as a library function or a solution to an online judge problem, which typically requires only a specific function/class.
**What to do**: Include a clear, direct instruction that forbids any code outside the requested scope. Explicitly ban common extras: input collection (`input()`), print statements for debugging, unnecessary imports (like `sys` for a pure math function), and example usage.
**Example**: "Implement the requested function only. Do not include any import statements, input/output operations, or example usage. The output should be a single, runnable function definition."
**Why it works**: Models are often trained on code snippets from tutorials that include example usage and I/O. Without this restriction, they frequently add `print()` statements or `input()` calls, making the code non-portable and failing automated testing systems that expect only the function.
