Prescribe the *What*, Not the *How*, to Leverage Model Capabilities

**When to apply**: When the user's prompt starts to micromanage implementation details (e.g., "use a for loop with index i", "name the variable `tmp`"). When you want the model to find the most efficient or idiomatic solution.
**What to do**: Frame all instructions as requirements on the function's external behavior, inputs, outputs, and constraints. Avoid mandating specific algorithms, data structures, variable names, or control flow structures unless absolutely necessary.
**Example**: *Instead of* "Use a hash map to store characters and a while loop to iterate," *say* "The function should determine if the input string has all unique characters, with a time complexity better than O(n^2)."
**Why it works**: Modern code models are trained on vast corpora of idiomatic solutions. Over-prescription stifles this knowledge, leading to unnatural, less efficient code. Specifying the goal allows the model to select the most appropriate implementation from its learned patterns.
