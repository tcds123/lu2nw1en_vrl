Clarify Types and Behavior with Concrete Input/Output Examples

**When to apply**: When the problem statement is abstract or easily misinterpreted. When the output format is complex (nested structures, specific classes). This is a complement to G290.
**What to do**: After defining the signature, provide 2-3 concrete pairs of example inputs and their corresponding expected outputs. These examples should cover a normal case and at least one non-trivial case.
**Example**: "`def parse_range(s: str) -> tuple[int, int]:` Parse a string like `'a-b'` into a tuple of integers (a, b). Example: `parse_range('10-20')` should return `(10, 20)`. `parse_range('5-5')` should return `(5, 5)`."
**Why it works**: Examples serve as executable specifications. They resolve ambiguity in the text description (e.g., what "parse" means) and provide the model with a direct pattern to generalize from, dramatically increasing the accuracy of the generated code.
