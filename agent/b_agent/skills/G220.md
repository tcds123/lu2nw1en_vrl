Structure Prompt as Signature, Technical Approach, Style Rules

**When to apply**: For problems where both the algorithm and implementation style are important (e.g., using a specific library, following a design pattern). This is a refined version of G216.
**What to do**: 1) Define the function signature and objective. 2) Specify the technical approach or required libraries. 3) Finally, list simple, discrete style rules. Keep each section distinct.
**Example**: "1. Define: `def parse_log_line(line: str) -> dict:`. Its objective is to extract timestamp, log level, and message into a dictionary. 2. Use the `re` module with `re.compile` for parsing. 3. Follow PEP 8, use a docstring, and name the compiled regex pattern `LOG_PATTERN`."
**Why it works**: This logical flow mirrors how a developer thinks: *what* is needed, *how* to do it, then *how* to polish it. It prevents style rules from being mistaken for core logic and ensures the model selects the correct tools.
