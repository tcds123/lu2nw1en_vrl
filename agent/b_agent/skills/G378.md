Explicitly State Core Algorithmic Requirements in a Direct, Simple Sentence

**When to apply**: When the problem's solution fundamentally depends on a specific programming paradigm (e.g., recursion, iteration), a specific data structure (e.g., use a stack, use a hash map), or a specific algorithmic pattern (e.g., two-pointer, depth-first search). Also apply when the user's request implicitly requires a specific approach that the model might otherwise miss.

**What to do**: Isolate the single most critical implementation constraint. State it as a clear, standalone instruction at the beginning of the implementation requirements, using imperative language. Avoid burying it within other details or using conditional phrasing like "you can use...".

**Example**: "Implementation Requirement: You must use a recursive function to solve this problem. Do not use iterative loops." or "Core Algorithm: The solution must employ a hash map (dictionary) to achieve O(n) average time complexity for lookups."

**Why it works**: Code generation models often default to common or iterative solutions. Without an explicit, high-priority directive, they may ignore a specified paradigm (like recursion) in favor of a simpler loop, or choose a suboptimal data structure, failing the core requirement even if the output is functionally similar.
