Explicitly Mandate Case Normalization for Case-Insensitive Operations

**When to apply**: Whenever the problem involves string comparison, sorting, or lookup where case should be ignored (e.g., username validation, dictionary keys, search functions).
**What to do**: In the prompt, explicitly state that the operation is case-insensitive. Instruct the model to implement this by normalizing strings (e.g., using `.lower()` or `.casefold()`) before comparison. Also require that the function's docstring or comments reflect this behavior.
**Example**: "Implement a function `is_palindrome(s: str) -> bool` that returns `True` if the string is a palindrome, ignoring case and non-alphanumeric characters. The implementation must convert the string to lowercase (using `.lower()`) for comparison. Document this case-insensitive behavior in the function docstring."
**Why it works**: Without explicit instruction, models may generate case-sensitive logic or use methods like `str.equalsIgnoreCase()` (Java) without the corresponding normalization in Python, leading to logical errors. Mandating the specific normalization step ensures consistent, correct behavior.
