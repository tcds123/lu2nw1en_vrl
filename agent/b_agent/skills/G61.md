Enforce Exact Implementation Constraints for Test Compatibility

**When to apply**: When the problem includes hidden unit tests, a specific grading script, or requires integration with existing code. Also when the problem statement mentions "you must implement the following class/method" or provides a function signature in a code stub.

**What to do**: Explicitly restate all mandatory interface elements from the problem statement. Specify the exact class name, method names, their parameters (including order and default values), and return types. Mandate the use of a specific core data structure if provided (e.g., "you must store data in a `list` named `self.items`").

**Example**: "You must implement a class named `MedianFinder` with the following exact methods: `def __init__(self):` initializes an empty data structure, `def addNum(self, num: int) -> None:` adds the integer, and `def findMedian(self) -> float:` returns the median. Do not change these names, signatures, or return types. Your code will be tested by an automated suite that calls these methods directly."

**Why it works**: Code generation models may invent convenient helper methods or slightly alter signatures (e.g., `find_median` vs `findMedian`), causing immediate test failure due to `AttributeError`. This constraint ensures the generated code's public API matches the test runner's expectations exactly.
