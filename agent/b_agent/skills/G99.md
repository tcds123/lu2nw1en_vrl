Mandate the Exact Function Signature for Evaluation

**When to apply**: For every coding task, especially when integrating with automated testing systems, unit tests, or competition judging environments. This is non-negotiable for functions, class methods, and constructors.

**What to do**: Provide the exact function name, the order and data types of all parameters (including `self` for methods), and the exact return type. If the function is a method within a class, specify the class name. Do not leave room for interpretation on naming or parameter order.

**Example**: "Write a Python function named `calculate_median` that takes a single parameter, `numbers`, which is a list of floats, and returns a float. The function signature must be exactly: `def calculate_median(numbers: list[float]) -> float:`"

**Why it works**: Automated test suites call functions by exact name and pass arguments in a specific order. If the model generates `def find_median(data):` or `def calculate_median(nums, sorted=False):`, the tests will fail immediately, resulting in a score of zero regardless of the algorithm's correctness. This skill eliminates this trivial but catastrophic failure mode by enforcing interface compliance.
