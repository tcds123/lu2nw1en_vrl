Precisely Define Function Signature and Critical Logic

**When to apply**: For mathematical calculations, API interfaces, or when specific formatting of the output (like rounding) is a core requirement; when ambiguous instructions could lead to multiple valid but differing implementations.
**What to do**: Specify the exact function name, its parameters and their types, and the return type. For the core logic, state the required formula, algorithm name, or processing rule verbatim. Explicitly define any output formatting rules, such as rounding to a specific number of decimal places.
**Example**: "Write a function `calculate_compound_interest(principal: float, rate: float, time: int) -> float`. Use the formula `A = P * (1 + r/100)**t`. The returned amount must be rounded to two decimal places using `round()`."
**Why it works**: Models may default to different rounding strategies (floor, ceiling, banker's rounding), misinterpret parameter order, or use a mathematically equivalent but structurally different formula. This precision eliminates variance, ensuring the generated code meets exact functional specifications.
