Define Precise Output Formatting and Signature Requirements

**When to apply**: When the generated code must adhere to specific project standards, API contracts, or testing frameworks. This includes specifying function names, parameter order and types, return types, and documentation style.
**What to do**: Define the exact function signature (name, parameters, return type). Specify the style and required sections for the docstring (e.g., Args, Returns). Reiterate that only this final formatted code block should be output.
**Example**: "Implement a function with the signature `def calculate_statistics(data: list[float]) -> dict[str, float]:`. Include a PEP 257 docstring with 'Args:' and 'Returns:' sections. Output only this final function code in a single Python code block."
**Why it works**: Models might generate functionally correct code with wrong names, parameter orders, or missing documentation, breaking integration. This level of precision ensures the output is a drop-in replacement, meeting both functional and stylistic contracts.
