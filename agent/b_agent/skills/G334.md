Explicitly Forbid Incorrect Approaches and Mandate Correct Ones

**When to apply**: When certain common shortcuts or library functions would trivialize the learning objective or violate explicit constraints (e.g., interview practice, educational tasks, implementing a specific algorithm from scratch).
**What to do**: Clearly state what is *not* allowed using direct prohibitive language (e.g., "Do not use..."). Immediately pair this with a positive instruction stating the required technique or algorithm by its common name or description.
**Example**: "Do not use Python's `sorted()` function or the `.sort()` method. You must implement the merge sort algorithm manually, which involves recursively splitting the list and then merging the sorted halves."
**Why it works**: Models are trained on code that heavily uses standard libraries. Without an explicit ban, they will default to the simplest, most common solution. The positive mandate provides a clear alternative path, guiding the model toward the intended implementation.
