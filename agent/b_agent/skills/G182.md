Maintain Structural Clarity with Consistent Formatting

**When to apply**: For complex prompts with multiple requirements, constraints, and output rules; when a prompt's own syntax is messy, which can cause the model to misinterpret or overlook parts of the instruction.
**What to do**: Organize the prompt using clear sections with headings (e.g., `## Task`, `## Input Format`, `## Constraints`, `## Output Format`). Use complete, grammatically correct sentences. Avoid bullet points with inconsistent symbols, excessive markdown, or run-on sentences.
**Example**: "## Task: Normalize a list of website URLs.\n## Input Format: A list of strings.\n## Constraints: Handle missing `http://` prefixes and trailing slashes.\n## Output Format: Return a list of normalized, full URLs."
**Why it works**: Models parse prompts as sequences of tokens. Disorganized prompts with syntactic noise (like mixed symbols, incomplete phrases) can lead to parts of the instruction being weighted incorrectly or ignored, resulting in incomplete or misaligned code.
