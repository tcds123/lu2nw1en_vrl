Explicitly Instruct Edge Case Handling Aligned with Tests

**When to apply**: When the problem implies but does not explicitly state handling for empty inputs, invalid data, boundary values, or special conditions. When you are aware of specific test cases the solution must pass.
**What to do**: After stating the core logic, add a dedicated instruction for edge cases. Enumerate them concretely (e.g., "handle empty list", "input string may contain leading/trailing spaces"). Directly state the expected behavior for each case.
**Example**: "Core logic: Reverse the words in a given string. Edge cases: If the input is an empty string `''`, return an empty string. If the input contains multiple spaces between words, reduce them to a single space in the output. The function should not raise an error for any valid string input."
**Why it works**: Models often optimize for the "happy path" and neglect edge cases unless explicitly prompted. This instruction forces consideration of boundary conditions that are commonly tested, preventing solutions that fail on hidden tests.
