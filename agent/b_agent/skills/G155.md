Mandate Modular Structure with Exact Core Interface

**When to apply**: For problems where logic can be naturally decomposed (e.g., a main solver that uses a helper for validation, recursion with memoization, or complex class methods). Essential when test suites will call a specific function signature.
**What to do**: Instruct the model to create helper/utility functions for distinct sub-tasks, while unambiguously stating the name, parameters, and return type of the primary function that must be present for the solution to be evaluated.
**Example**: "Implement the solution by writing a helper function `is_valid(config)` that checks constraints. Your primary function must be named `solve(configuration: list) -> int` and should call the helper. Ensure `solve` returns the required integer result."
**Why it works**: Models might inline all logic into one monolithic function, making code hard to read and test. This instruction enforces separation of concerns. Explicitly naming the core function prevents the model from exporting only the helper or using a different function name, which would cause autograder failures.
