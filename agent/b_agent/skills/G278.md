Outline Clear Algorithmic Steps Without Over-Specifying Syntax

**When to apply**: For problems where the logical sequence of steps is more important than the exact syntax. This guides the model's reasoning process without micromanaging its code style.
**What to do**: Break down the solution into 3-5 high-level, language-agnostic steps. Describe the *what* (e.g., "initialize a hash map to count frequencies") and the *why* (e.g., "to identify duplicates"), but not the *how* (e.g., avoid dict comprehension syntax).
**Example**: "Algorithm: 1) Initialize an empty result list. 2) Iterate through the input list. 3) For each element, check if it meets the condition (e.g., is even). 4) If it does, append it to the result list. 5) After the loop, return the result list."
**Why it works**: It provides a roadmap for the model's logic, reducing the chance of missing a step or implementing steps in the wrong order. By avoiding syntax details, it allows the model to use its optimal coding style for the given language, resulting in more natural and idiomatic code.
