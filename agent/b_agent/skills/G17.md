Include explicit test cases in the prompt to align with evaluation.

**When to apply**: When the problem involves nuanced behavior that might be under-specified or easily misinterpreted (case sensitivity, treatment of duplicates, handling of null/empty, specific error conditions). When you want to "lock in" the expected behavior for critical scenarios.
**What to do**: Embed 1-3 concrete, illustrative test cases directly in the prompt. Frame them as requirements: "Your solution must pass the following test cases:" or "Ensure your function behaves as shown in these examples." Include edge cases that are essential for correctness.
**Example**: "Write a function `count_unique_words(text: str) -> int`. It should treat words case-insensitively and ignore punctuation. For example, for input 'Apple apple, banana.', the function must return 2 (apple and banana). For an empty string, it must return 0."
**Why it works**: Models can generate code that passes a vague requirement but fails on specific interpretations. Providing concrete examples disambiguates intent. It also serves as a mini-integration test, guiding the model to implement logic that produces the exact outputs you've specified.
