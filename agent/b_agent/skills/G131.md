Prohibit Disallowed Methods/Libraries While Allowing Necessary Built-ins

**When to apply**: When the problem's hidden test or learning objective requires implementing logic manually rather than using a high-level library function (e.g., implementing sort, search, or a data structure from scratch).
**What to do**: Identify the specific "shortcut" functions or libraries that would trivialize the problem. Explicitly forbid them using clear language like "You may not use...". Conversely, affirm that standard built-ins (like `len()`, `range()`) are permitted.
**Example**: "Implement a function `my_atoi(s)` to convert a string to a 32-bit integer, mimicking the behavior of `int(s)`. You may not use `int()`, `strip()`, or regular expression libraries directly for the core conversion logic. Standard string indexing and `ord()` are allowed."
**Why it works**: Models heavily rely on their training distribution, which includes many solutions using built-in shortcuts. Without an explicit prohibition, they will almost certainly use `int()` or `sorted()`, bypassing the algorithmic challenge entirely and producing an invalid solution for the intended task.
