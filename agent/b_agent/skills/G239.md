Define Required Approach and Docstring Without Revealing Logic

**When to apply**: When the solution must follow a specific paradigm (recursion/iteration) and include documentation, but the internal algorithm should be discovered by the model.
**What to do**: Mandate the approach (recursive/iterative) and require a docstring that describes *what* the function does, its parameters, and return value. Do not describe the step-by-step logic *inside* the function.
**Example**: "Implement a binary search function `search(nums: list[int], target: int) -> int` using an iterative approach. Include a docstring that summarizes the function, describes the parameters `nums` (sorted list) and `target`, and states that it returns the index or -1 if not found."
**Why it works**: This prevents the prompt from being a restatement of the solution code itself. It ensures the model generates the correct structure and documentation while still exercising its ability to implement the core algorithm correctly.
