Structure Prompts Logically: Task, Interface, then Constraints

**When to apply**: For all non-trivial coding tasks. Especially important when the problem has multiple components (e.g., input parsing, core algorithm, output formatting).
**What to do**: Organize the prompt into three clear sections: 1) A one-sentence task summary. 2) The exact function/class signature and I/O format. 3) A bulleted or numbered list of key algorithmic, performance, and edge-case constraints. Keep formatting rules separate.
**Example**: "Task: Validate if a Sudoku board is valid. Interface: `def is_valid_sudoku(board: List[List[str]]) -> bool:`. Constraints: 1. Check each row for duplicates 1-9. 2. Check each column. 3. Check each of the 9 3x3 sub-boxes. 4. Empty cells are marked '.'."
**Why it works**: Models process information sequentially. A logical flow mirrors how a programmer thinks: what's the goal, what's the interface, what are the rules. Mixing these (e.g., putting a formatting rule between algorithmic steps) causes the model to misprioritize or forget requirements.
