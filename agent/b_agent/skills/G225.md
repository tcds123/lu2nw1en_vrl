Specify Regex Patterns with Concrete Matching and Non-Matching Examples

**When to apply**: For any task involving pattern matching, validation, or string parsing (e.g., email validation, log parsing, data extraction). Essential when the pattern has subtle boundaries (e.g., must match `cat` but not `catalog`).

**What to do**: Do not just describe the pattern in words. Provide the exact regex string to use. Immediately follow it with clear, bulleted examples of strings that MUST match the pattern and strings that MUST NOT match. This acts as test cases embedded in the prompt.

**Example**: "Use the regex pattern `r'^\d{3}-\d{2}-\d{4}$'`. For example, it should match `'123-45-6789'`. It must NOT match `'123-456-789'` (too many digits in middle group) or `'123-45-6789a'` (trailing character)."

**Why it works**: Models are prone to misinterpreting textual descriptions of patterns (e.g., "a three-digit area code" might lead to `\d\d\d` instead of `\d{3}`). Providing the exact pattern eliminates guesswork. The examples serve as immediate validation anchors, preventing off-by-one errors and incorrect boundary handling in the generated logic.
