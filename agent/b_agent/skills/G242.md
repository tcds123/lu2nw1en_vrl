State Core Algorithmic Requirement First in Simple Language

**When to apply**: When the problem involves a non-trivial transformation, selection, or computation (e.g., deduplication, sorting by a custom key, finding a path). When secondary constraints (like time complexity or memory limits) exist.
**What to do**: Before listing constraints or examples, articulate the primary logic goal in a single, simple sentence. Use plain language that defines the *what*, not the *how*. This sentence should be the anchor for all subsequent details.
**Example**: "Core requirement: Transform the input list so that all even numbers appear before odd numbers, preserving the relative order of evens and odds among themselves. Additional constraints: Do it in O(n) time and O(1) extra space."
**Why it works**: Models can get distracted by edge cases, performance notes, or input/output formats and miss the fundamental logic. Leading with the core algorithm ensures the model's primary focus is correct before optimizing or handling details, reducing logical errors.
