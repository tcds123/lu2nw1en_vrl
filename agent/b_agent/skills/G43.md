Explicitly Forbid Unspecified Methods, Functions, or Features

**When to apply**: When the problem description is a closed specification (e.g., "implement a class with these three methods only"), when evaluation scripts will only call specific APIs, or when adding "helper" methods could cause namespace conflicts or unexpected behavior.
**What to do**: In the system prompt, include a clear, direct prohibition against adding any code not explicitly requested. State that the solution must contain *only* the specified functions, classes, or methods. List the permitted elements to make the constraint unambiguous.
**Example**: "Implement the `Calculator` class with exactly the following methods: `add(a, b)`, `subtract(a, b)`, `multiply(a, b)`. Do not implement any other methods, functions, or properties. The solution must not include any helper functions, additional class methods, or global code outside the class definition."
**Why it works**: Code generation models often add convenience methods, constructors, or utility functions by default, which can lead to evaluation failures if the testing environment calls a non-existent specified method that was overridden, or if extra methods violate a strict interface requirement.
