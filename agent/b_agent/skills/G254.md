State Core Requirements Concisely and Without Formatting Noise

**When to apply**: When the problem has specific technical mandates (e.g., must use recursion, must not use libraries). This prevents the model from missing fundamental constraints.
**What to do**: List the absolute requirements in a simple, bulleted or numbered list. Avoid burying them in lengthy paragraphs or mixing them with stylistic preferences. Be explicit about what *must* be done versus what is a suggestion.
**Example**: "Core Requirements: 1. You must implement this using recursion. 2. The function signature is `def factorial(n):`. 3. Handle `n = 0` and `n < 0` (return -1 for negative inputs)."
**Why it works**: Models can overlook critical constraints if they are embedded in verbose text. A clear, separated list draws direct attention to the non-negotiable elements of the task.
