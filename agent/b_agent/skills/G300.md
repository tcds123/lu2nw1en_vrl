Specify Implementation Constraints Concisely and Coherently

**When to apply**: When certain libraries, language features, or built-in functions are disallowed to test algorithmic understanding (e.g., "no use of `itertools.combinations`") or required for consistency (e.g., "must use `collections.deque`").

**What to do**: List allowed or disallowed methods in a single, clear statement. Avoid scattering these constraints throughout the prompt. Be specific about the ban's scope (e.g., "Do not use the built-in `sum()` function" vs. "Do not use any built-in aggregation functions").

**Example**: "Implementation constraint: You may not use any built-in functions that directly solve the problem, such as `str.count()` or `collections.Counter`. You must implement the counting logic manually using basic loops and dictionaries."

**Why it works**: Fragmented or implied constraints can be missed. A consolidated, explicit list focuses the model's solution search on the permitted toolset, preventing it from taking shortcuts that bypass the intended learning or evaluation objective.
