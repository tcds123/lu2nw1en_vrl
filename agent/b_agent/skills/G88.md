Specify Concrete Complexity Constraints and Critical Edge Cases

**When to apply**: For algorithmic problems where asymptotic complexity (time/space) is a strict requirement, or where specific edge cases (empty input, single element, large values) are known failure points.
**What to do**: Explicitly list the required big-O complexity (e.g., O(n) time, O(1) extra space). Enumerate the critical edge cases the solution must handle. Integrate these into the problem statement as non-negotiable requirements.
**Example**: "Implement the solution in O(n) time and O(1) additional space. Ensure it correctly handles an empty input list, a list of all identical elements, and a strictly decreasing price series."
**Why it works**: Without explicit constraints, models may choose a simpler but quadratic solution, or neglect edge cases that are not in the example. This grounds the model's design choices in the evaluator's performance and correctness criteria.
