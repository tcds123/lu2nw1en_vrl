Eliminate Logical Contradictions in Output Specifications

**When to apply**: When the prompt mixes I/O actions (e.g., "print" vs. "return"), specifies conflicting data types, or gives ambiguous success criteria. A clear red flag is the use of both "print" and "return" for the primary output.
**What to do**: Audit the prompt for any pair of instructions that cannot both be true. Choose one primary output method (almost always `return` for a callable function). Ensure the described output type (list, integer, string) matches the operation.
**Example**: Instead of: "The function should calculate the sum and print it. Then return the sum as a string." Use: "The function `calculate_sum(a, b)` should return the sum as an integer." Or, if printing is truly required: "The function `calculate_and_print_sum(a, b)` should print the sum and return `None`."
**Why it works**: Contradictions cause models to produce code that tries to satisfy both demands, resulting in runtime errors or outputs that fail automated testing. A single, unambiguous output directive ensures the generated code has a clear and testable interface.
