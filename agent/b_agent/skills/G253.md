Balance Algorithmic Guidance with Coding Best Practices

**When to apply**: For complex problems where both correct logic and maintainable code are valued. This is key for interview-style problems or production-like code generation.
**What to do**: First, provide the core algorithmic requirement (e.g., "use a depth-first search"). Then, add non-restrictive guidelines for code quality, such as suggesting meaningful variable names, handling obvious edge cases (e.g., empty input), and keeping functions focused. Avoid mandating a single, overly specific implementation path.
**Example**: "Find the shortest path using BFS. Ensure your code is readable and handles cases where the start and end nodes are the same or disconnected. You are free to structure the BFS traversal as you see fit, but the solution should be modular."
**Why it works**: Over-constraining implementation can stifle the model's ability to find a valid solution. This balance ensures correctness while encouraging clean, adaptable code that isn't brittle.
