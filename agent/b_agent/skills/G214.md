Clean Formatting and Eliminate Delimiter Contradictions

**When to apply**: When the prompt contains markdown formatting errors, stray characters, or conflicting instructions about how to present the code (e.g., "surround code with triple backticks" vs. "code only"). This ensures the model's output is pristine and directly usable.

**What to do**: Use clean, standard markdown. Avoid broken code fences (``` ```). If you mandate "code only" in the Persona/Output section (G206), do not later ask for code in backticks. Remove any garbled text, placeholder text like `[TODO]`, or inconsistent formatting that could confuse the model's output parser.

**Example**: (Problematic) "Write the code... ```python def func(): pass ``` Remember, output should just be the raw code without any backticks." (Corrected) "Your output must be raw code without any markdown backticks or formatting. Implement the following function: `def func(): pass`"

**Why it works**: Models are pattern matchers. If they see triple backticks in the prompt, they are strongly inclined to replicate them in the output, even if text elsewhere says not to. Contradictory formatting instructions can cause the model to produce a garbled mix of code and markdown, making the output unusable until manually cleaned.
