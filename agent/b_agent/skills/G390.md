Ensure Unambiguous Task Description Matching the True Problem

**When to apply**: When paraphrasing a problem from a source (like a coding challenge website). When the initial prompt contains vague language, internal contradictions, or misstates the objective (e.g., "find the minimum" vs. "find the maximum").

**What to do**: Rephrase the problem description in your own words, then verify it against the original. Remove ambiguous terms like "optimal," "efficient," or "handle appropriately" unless clearly defined. State the primary objective in one clear, simple sentence.

**Example**: Instead of "Process the data stream to find the most frequent elements efficiently," write: "Given a stream of integers, implement a class that, when asked, returns a list of the **top k most frequent** elements in the stream **seen so far**."

**Why it works**: Models latch onto keywords. Ambiguity leads to plausible but incorrect interpretations (e.g., "most frequent" vs. "top k frequent," "ever" vs. "so far"). A precise description aligns the model's goal with the actual test cases.
