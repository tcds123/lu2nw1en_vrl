Enforce Strict Output Formatting with Mandatory Docstring and No Extraneous Text

**When to apply**: When the generated code must be directly integrated into a larger codebase, when automated testing or documentation generation is required, or when the model consistently adds verbose explanations, imports, or markdown formatting.
**What to do**: Explicitly instruct the model to output only a single, syntactically correct code block. Mandate that the function includes a docstring formatted with `:param` and `:return` tags. Prohibit any text, comments, or code outside this block, including imports unless they are part of the core solution.
**Example**: "Output a single Python code block containing only the function. The function must have a docstring using `:param <name>:` and `:return:` tags. Do not include any explanatory text, `import` statements, or comments outside the function body."
**Why it works**: Code generation models often "think aloud" by adding natural language explanations or unnecessary boilerplate, which breaks direct execution. This instruction forces a pure, production-ready output format, preventing truncation in contexts where only code is accepted.
