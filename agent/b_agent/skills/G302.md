Clarify Function Signature, Return Type, and Edge Cases Simply

**When to apply**: For all function implementation tasks, especially when edge cases (empty input, null values, extreme values) are critical to correctness. This is a foundational skill for ensuring the generated code has the right interface.

**What to do**: Define the function signature (name, parameters, types) and return type unambiguously. In simple language, state how the function should behave for specific edge cases (e.g., "If the input list is empty, return 0"). Avoid legalistic or complex phrasing.

**Example**: "Write a function `find_max_gap(nums: List[int]) -> float`. It returns the maximum difference between consecutive numbers in the sorted version of `nums`. If the list has fewer than 2 elements, return 0.0."

**Why it works**: Ambiguity in the interface is a common source of incorrect code. A simple, direct definition of the contract—including edge behavior—leaves no room for interpretation, ensuring the model generates a function that can be integrated and tested directly.
