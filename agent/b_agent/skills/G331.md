Explicitly Prohibit Disallowed Methods or Syntax

**When to apply**: When the learning objective is to implement logic manually, when certain built-in functions would trivialize the problem, or when working in a constrained environment (e.g., embedded systems, specific interviews).
**What to do**: Provide a clear, list-like prohibition of specific functions, operators, or language features. Be exhaustive for the common shortcuts.
**Example**: "Do not use the built-in `reversed()`, string slicing with `[::-1]`, or `join()` method. Implement the string reversal logic manually using loops or recursion."
**Why it works**: Models strongly favor the most idiomatic and concise solutions, which often use powerful built-ins. Without an explicit ban, they will almost certainly use the forbidden shortcut. A direct prohibition forces the model to access lower-level implementation patterns.
