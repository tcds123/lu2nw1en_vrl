Focus on Functional Requirements Over Stylistic or Domain Commentary

**When to apply**: When the prompt includes extensive background story, business context, or stylistic preferences (naming conventions, comment frequency) that are secondary to the core logic.
**What to do**: Extract and prioritize the immutable functional specs: the exact method signature, the transformation of inputs to outputs, and the handling of edge cases. De-emphasize or remove verbose domain explanations that do not affect the code's logic.
**Example**: **Verbose Prompt (to condense):** "In the context of our e-commerce platform's inventory system, which uses microservices, we need a utility to safely update stock. It's crucial for thread safety. Please write a carefully crafted function..." **Improved Prompt:** "Write a function `update_stock(current: int, change: int) -> int` that adds `change` (which can be negative) to `current`. Return the new stock. If the result would be negative, raise an `InventoryError`. Assume this function will be called in a multi-threaded environment."
**Why it works**: Extraneous text dilutes the signal of the core requirements. Models might waste context on understanding the domain story instead of the precise function logic, or they might incorrectly implement the business context as code.
