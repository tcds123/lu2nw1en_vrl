Define a Clear Expert Persona and Concise Requirements

**When to apply**: For complex tasks requiring specialized knowledge (e.g., cryptography, concurrency, algorithm optimization) or when the prompt is becoming a long list of disjointed instructions.
**What to do**: Start by establishing a relevant expert role for the model (e.g., "You are a senior software engineer specializing in memory-efficient algorithms"). Then, structure requirements under clear, non-repetitive headings like "Functional Requirements," "Performance Constraints," and "Edge Cases to Handle."
**Example**: "You are an expert in graph theory algorithms. Write a function that finds the shortest path in a weighted, directed graph. Requirements: 1. Correctness: Handle positive edge weights. 2. Efficiency: Aim for O((V+E) log V) time complexity. 3. Edge Cases: Graph may be disconnected; return a sentinel value if no path exists."
**Why it works**: The persona primes the model for a specific domain, improving conceptual accuracy. Concise, categorized requirements reduce cognitive load for the model, preventing it from missing key points buried in verbose text or generating contradictory logic.
