Specify Exact Method and Parameter Names for Test Compatibility

**When to apply**: For any task requiring a specific function/class interface, such as implementing a solution for an automated testing suite (e.g., unit tests that call `function_name(arg1, arg2)`).
**What to do**: Explicitly state the exact, case-sensitive names for the required function(s), class(es), methods, and their parameters. Use code-style formatting. Avoid descriptive placeholders like "a method to calculate" or "parameters for the input".
**Example**: "Create a class `Circle` with an `__init__(self, radius: float)` method and an instance method `area(self) -> float`. Do not rename these methods or add extra required parameters."
**Why it works**: Automated test runners call functions and methods by exact name. Ambiguous descriptions like "a function that takes the radius" can lead the model to generate `def calculate_area(radius):` instead of the required `def area(self):`, causing `AttributeError` or `NameError` during testing.
