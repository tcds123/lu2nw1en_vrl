Provide Clear, Concise, and Structured Edge-Case Rules

**When to apply**: When the problem involves decision logic with potential ambiguities, such as handling missing data, tie-breaking, empty inputs, or boundary conditions. When verbosity in the prompt could obscure the main rules.
**What to do**: State the primary requirement concisely, then use a bulleted or numbered sub-list for edge cases and rules. Be explicit about behaviors like returns for invalid input, sort orders, or equality handling.
**Example**: "Write a function `find_winner(vote_list)` that returns the candidate with the most votes. Requirements: - Return the candidate name as a string. - If multiple candidates tie for the highest votes, return the one whose name appears first in the original list. - If the input list is empty, return `None`."
**Why it works**: Without explicit edge-case rules, models often make arbitrary or inconsistent assumptions, leading to code that fails hidden test cases. Structured rules act as a direct specification for conditional branches in the code.
