Explicitly List Required Class and Method Signatures from Examples

**When to apply**: When the task involves implementing a class with specific attributes and methods, especially for object-oriented design problems, data structure implementations (e.g., LinkedList, Trie), or system design simulations.

**What to do**: Extract the exact class name, method names, their parameters (including `self`), and return types directly from the example usage provided in the problem. List them explicitly as a contract the implementation must fulfill.

**Example**: "Implement the `MyHashMap` class with the following methods exactly as specified:
    - `__init__(self)`: Initializes the object with an empty map.
    - `put(self, key: int, value: int) -> None`: Inserts a (key, value) pair.
    - `get(self, key: int) -> int`: Returns the value or `-1` if not found.
    - `remove(self, key: int) -> None`: Removes the key and its value."
**Why it works**: Models might infer incorrect method signatures (wrong parameter order, missing `self`, different return types) from a narrative description, causing instant test failures. A explicit list acts as an unambiguous API specification.
