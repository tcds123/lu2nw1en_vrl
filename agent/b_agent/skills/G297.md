Articulate Core Requirements and Constraints Concisely

**When to apply**: When the problem involves specific performance requirements (O(n) time), memory limits, or behavioral rules (e.g., "handle duplicates by keeping the first occurrence"). Essential for algorithmic challenges and system design tasks.

**What to do**: State the essential functional goals and non-negotiable constraints in a single, coherent list. Avoid embedding these details in narrative paragraphs. Use bullet points or a clear "Constraints:" section. Do not repeat the same constraint in different words.

**Example**: "Constraints: 1. Time complexity must be O(n log k). 2. Do not use built-in sorting functions. 3. If the input list is empty, return an empty list. 4. Preserve the relative order of elements that are not removed."

**Why it works**: Models can miss or misinterpret constraints buried in prose. A consolidated, unambiguous list ensures the model prioritizes these requirements during its reasoning and code generation, preventing solutions that are functionally correct but violate key rules.
