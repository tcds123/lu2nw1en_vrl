Provide Precise Technical Requirements Without Overly Restrictive Phrasing

**When to apply**: When the solution requires specific logic or constraints that are not fully captured by the function signature alone (e.g., a key transformation step, a complexity bound, a prohibition on using certain built-ins). Avoid making the prompt a rigid step-by-step recipe unless absolutely necessary.

**What to do**: State the technical requirement clearly and concisely. Focus on the *what* (the outcome or constraint) rather than an overly prescriptive *how* (micromanaging every step), unless a specific sequence is mandatory. Use clear, technical terms.

**Example**: Instead of a verbose restriction like "You must not use any string methods except .lower() and you must iterate character by character in a very specific while loop...", use: "Key Logic: Convert the input string to lowercase and count the frequency of each alphabetic character. Do not use `collections.Counter`."

**Why it works**: Overly verbose and restrictive instructions can confuse the model, leading it to focus on the restrictive phrasing rather than the core logic. Precise, outcome-focused instructions give the model the necessary constraint while allowing it to leverage its knowledge to find a valid implementation path.
