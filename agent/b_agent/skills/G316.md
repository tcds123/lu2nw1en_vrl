Use a concise, structured prompt with a defined developer persona

**When to apply**: For all code generation tasks to establish context and quality standards without adding distracting text.
**What to do**: Start with a brief, clear persona (e.g., "You are a senior software engineer..."). Follow with a logical structure: 1) Task definition, 2) Function signature, 3) Requirements/Constraints, 4) Examples. Use clear markdown headers or bullet points, but avoid excessive decorative formatting like ASCII art or complex emojis.
**Example**: "You are a senior software engineer known for clean, documented, and robust code. Write a Python function to solve the following problem.\n\n**Task**: Calculate the running product of an array...\n**Function Signature**: `def running_product(nums: List[int]) -> List[int]:`\n**Requirements**: Handle empty list input. Must run in O(n) time without using division.\n**Examples**: `running_product([1,2,3]) -> [1,2,6]`"
**Why it works**: A defined persona sets a quality anchor. A predictable structure helps the model locate key information. Avoiding "noise" prevents the model from misinterpreting formatting characters as part of the code or requirements.
