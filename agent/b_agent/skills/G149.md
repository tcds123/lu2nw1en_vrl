Specify Exact Error Handling Behavior for Invalid Inputs

**When to apply**: When the problem description includes input validation requirements and the expected response to bad input is a specific exception or return value.
**What to do**: Instead of saying "validate the input," prescribe the exact action: which exception to raise (with what message) or what sentinel value to return. Include the condition that triggers it.
**Example**: "If the input list is empty, your function must raise a `ValueError` with the message `'Input list cannot be empty'`. If any element in the list is not a positive integer, raise a `TypeError`."
**Why it works**: Vague instructions like "handle invalid input" lead to inconsistent behavior: the model might print a message, return `None`, raise a generic `Exception`, or silently ignore. Specifying the exact contract ensures the generated code matches the test suite's expectations.
