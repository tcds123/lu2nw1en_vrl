Prioritize Conciseness to Reserve Model Capacity for Code Generation

**When to apply**: When the problem description is inherently long (e.g., complex business rules, multi-step algorithms). When you notice the prompt approaching the model's context window limits.
**What to do**: Ruthlessly eliminate redundant words, repetitive examples, and motivational phrasing. Use abbreviations where clear (e.g., "O(n)" instead of "linear time complexity"). Combine related constraints into single sentences. The goal is to pack maximum instructional signal into minimum tokens.
**Example**: Instead of: "We need a function that, given a list of numbers, will find the two numbers that add up to a specific target. You must ensure the solution is efficient and does not use a naive double-loop approach. Consider cases where the input might be empty or have only one element." Use: "Implement `two_sum(nums: List[int], target: int) -> List[int]` to return indices of two numbers that sum to `target`. Assume exactly one solution exists. O(n) time complexity required."
**Why it works**: Language models have limited context windows. Verbose prompts use tokens that could otherwise be allocated to the generated code itself. A concise prompt reduces the risk of truncation, keeps the core task prominent in the model's attention, and often leads to more focused and accurate code.
