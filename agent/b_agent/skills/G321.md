Provide specific, non-buried implementation constraints

**When to apply**: When the problem has critical limitations that must be respected (e.g., no built-in sort, constant space, recursive vs. iterative).
**What to do**: Place key constraints in a dedicated, bulleted section (e.g., "**Constraints:**"). State them positively and precisely. Avoid embedding constraints in long paragraphs of explanatory text. Use clear terminology (O(n), in-place, immutable).
**Example**: "**Constraints:**\n- Time Complexity: Must be O(n log k) where n is total elements and k is number of lists.\n- Space Complexity: Can use O(k) extra space beyond the output.\n- Do not use `heapq.merge`."
**Why it works**: Constraints buried in prose are often overlooked by the model. A dedicated, clearly formatted section draws the model's attention to these critical requirements, drastically increasing the chance they are obeyed in the generated solution.
