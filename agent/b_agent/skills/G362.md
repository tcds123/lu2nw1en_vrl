Provide Essential Constraints Without Over-Specifying

**When to apply**: When the solution must operate within a specific environment (e.g., no network access, specific Python version) or when certain tools are disallowed, but the implementation approach should be creative.
**What to do**: State *what* is prohibited or required (e.g., "Do not use external libraries," "Must be thread-safe") but avoid dictating *how* to achieve it (e.g., "Use a for loop here," "Implement a bubble sort").
**Example**: "Implement a function to sort a list of integers. Constraint: You may not use Python's built-in `sorted()` function or the `list.sort()` method. The implementation details are up to you."
**Why it works**: Overly prescriptive prompts stifle the model's ability to generate optimal or idiomatic solutions. By stating the "what" not the "how," you enforce necessary boundaries while leveraging the model's full problem-solving capability, leading to more robust and interesting code.
