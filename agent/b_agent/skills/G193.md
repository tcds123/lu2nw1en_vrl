Eliminate Contradictions, Formatting Demands, and Obscuring Verbosity

**When to apply**: For any prompt, but especially when combining requirements from multiple sources or adding "helpful" notes. Always review prompts for internal conflict and noise before generation.

**What to do**: Read the prompt as a spec. Remove any instructions about code formatting (indentation, comment style) unless it's the actual task. Delete redundant explanations. Ensure no two requirements conflict (e.g., "return a list" and "print the values"). Use simple, direct sentences.

**Example**: **Bad (Noisy):** "Please write beautiful, clean code. The function should take a string, maybe use a loop, but actually recursion is better. Remember to add docstrings and type hints. Oh, and it must return a reversed string, but don't use `[::-1]` because that's cheating. Print it nicely."  
**Good (Clean):** "Write a function `recursive_reverse(s: str) -> str` that returns the reverse of `s` using recursion."

**Why it works**: Contradictory or excessive instructions confuse the model's priority weighting, often causing it to fulfill a minor formatting request at the expense of core logic or to generate broken code trying to satisfy incompatible goals. A clean prompt reduces cognitive load on the model, focusing its capacity on the essential task.
