Ensure I/O Format Alignment with Hidden Problem Specifications

**When to apply**: When the problem involves reading from stdin/writing to stdout, especially with multiple test cases, interactive input, or specific delimiters. Also when example interactions are provided in the problem statement.
**What to do**: Analyze the hidden problem's I/O format, not just the visible description. Explicitly state the exact input source (e.g., `sys.stdin`) and output destination (e.g., `print()` to stdout). Specify how to handle multiple lines, spaces, and the end-of-input condition. If examples are given, instruct the model to validate its logic against the provided input/output pairs.
**Example**: "Read all input from standard input (`sys.stdin`). The input consists of multiple test cases. The first line contains an integer T. For each of the next T lines, process a single integer N. For each test case, output the result on its own line. Your output must exactly match the format shown in the sample interaction."
**Why it works**: Code generation models often make incorrect assumptions about input parsing (e.g., reading a single line vs. all lines) or output formatting (e.g., extra spaces), leading to "Wrong Answer" on platforms with strict I/O checking. This prevents format mismatches.
