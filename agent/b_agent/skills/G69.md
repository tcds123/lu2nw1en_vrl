Define the Exact Interface and Prohibit Extraneous I/O

**When to apply**: When the solution must be a library-style component (function/class) and not a standalone script. Crucial for problems on competitive programming or automated grading sites where the solution is tested via function calls, not standard input.

**What to do**: Explicitly list the functions/classes to implement. State that the solution should not include any interactive input prompts (`input()`) or print statements unless explicitly required for debugging in a protected block. Specify that the code should rely on parameters and return values.

**Example**: "Implement only the `Solution` class with the method `def twoSum(self, nums: List[int], target: int) -> List[int]:`. Do not write a `main` function or read from `sys.stdin`. The judging system will instantiate this class and call the method."

**Why it works**: Models often generate code for a local, interactive environment, adding `input()` statements or `print()` calls for demonstration. This causes runtime errors in automated testers that call the function directly and provide input via arguments, not stdin.
