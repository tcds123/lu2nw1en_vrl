Prioritize Functional Correctness Over Stylistic Preferences

**When to apply**: When there is a potential conflict between a stylistic instruction (e.g., "use a list comprehension") and the most straightforward path to a correct, efficient solution. Correctness is always paramount.
**What to do**: Instruct the model that if a stylistic constraint (like a ban on certain language features or a demand for a specific syntax) would lead to incorrect, overly complex, or significantly less efficient code, the model should prioritize correctness and clarity. The goal is working code first, elegant code second.
**Example**: "Generate a solution that is first and foremost functionally correct for all inputs. If a suggested constraint (like avoiding a `for` loop) would make the code incorrect or much harder to understand, disregard that constraint in favor of a correct and clear implementation."
**Why it works**: Overly rigid stylistic rules can force models into producing convoluted or buggy code. This guideline empowers the model to use the most appropriate language constructs to solve the problem correctly, which is the user's primary need.
