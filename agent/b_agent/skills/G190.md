Precisely Specify Input Validation and Error Handling

**When to apply**: When function robustness is critical, especially for user-facing APIs, data processing utilities, or when edge cases (negative numbers, empty strings, wrong types) must be handled explicitly and consistently.

**What to do**: For each parameter, define the valid domain or conditions. State the exact exception type (`TypeError`, `ValueError`, etc.) and the precise condition that triggers it. Use clear, conditional language (e.g., "if not isinstance(x, int)...").

**Example**: "Write a function `divide_numbers(a: int, b: int) -> float`. Validate that both `a` and `b` are integers. If not, raise a `TypeError`. If `b` is zero, raise a `ValueError` with the message 'Divisor cannot be zero'. Return the result of `a / b`."

**Why it works**: Models often generate generic error handling (`raise Exception("error")`) or omit validation entirely. Explicit instruction ensures production-ready code that fails predictably, which is crucial for debugging and system integration.
