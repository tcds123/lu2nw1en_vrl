Balance Expert Persona with Direct Requirements

**When to apply**: When the task requires specialized knowledge (e.g., cryptography, graph theory, system design) but the prompt risks becoming overly academic, vague, or stylistically inconsistent.
**What to do**: Establish a concise, relevant persona (e.g., "You are a senior software engineer specializing in optimization") in one sentence. Immediately follow with direct, imperative instructions for the concrete task. Avoid mixing the persona's voice into the logic specifications.
**Example**: "You are an expert in concurrent data structures. Implement a thread-safe LRU cache. The class must be named `ThreadSafeLRUCache` and support `get(key)` and `put(key, value)` with O(1) average time complexity. Use a mutex for synchronization."
**Why it works**: Prevents the model from generating verbose explanations, theoretical tangents, or adopting an inconsistent tone that buries the functional code. It anchors the response in expertise while keeping the output focused on executable requirements.
