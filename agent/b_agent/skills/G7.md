Eliminate Internal Contradictions in Specifications

**When to apply**: When reviewing or refining a prompt that contains conflicting instructions, especially between docstrings/type hints and described behavior, or between examples and rules.

**What to do**: Carefully cross-check all parts of the prompt: function signature return type (`-> int`), docstring description ("returns -1"), and behavioral instructions ("raise ValueError"). Align them. Ensure examples match the stated rules.

**Example**: Fix the contradiction: Instead of "The function `get_index(item)` should return the index if found, or `None` otherwise. Its signature is `def get_index(item) -> int:`", write: "The function `def get_index(item) -> Optional[int]:` should return the index as an integer if found, or `None` if the item is not present."

**Why it works**: Contradictions confuse the model, leading to unpredictable outputs. It may follow the type hint and always return an integer (e.g., -1), violating the `None` requirement, or vice-versa. This causes type errors or logical failures in the test suite.
