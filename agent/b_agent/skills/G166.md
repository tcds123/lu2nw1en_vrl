Require a specific docstring style and restrict output to code only.

**When to apply**: When code readability, documentation, or integration into a larger codebase is important. When the evaluation may check for the presence and format of documentation.
**What to do**: Explicitly instruct the model to include a docstring following a named style (e.g., Google, NumPy, reStructuredText) within the function. Reiterate that the output must be *only* the code block containing the function(s) and docstring.
**Example**: "Your solution must include a Google-style docstring for the function. The docstring should describe the parameters, return value, and any exceptions raised. Output only the complete Python code block with the function and its docstring, and nothing else."
**Why it works**: Models often omit documentation unless explicitly told. Specifying a style ensures consistency. The reinforcement to output "only code" prevents the model from describing the docstring externally instead of writing it, which is a common failure mode.
