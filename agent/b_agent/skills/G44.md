Specify Exact Return Type and Format for Each Required Method

**When to apply**: For every function or method definition in the requirements, especially when outputs could be confused with side-effects (e.g., returning vs. printing), or when the format (list vs. tuple, integer vs. string) is critical for automated evaluation.
**What to do**: For each required method, explicitly state its name, parameters, and the precise nature of its output. Clarify if it should `return` a value or produce output via `print`. Specify the exact type (e.g., `list of integers`, `boolean`, `string without a newline`).
**Example**: "Implement the function `find_max(nums: List[int]) -> int`. It must *return* the maximum integer value from the list. Do not print the result. If the list is empty, return `None`."
**Why it works**: Models may default to printing results for console-based problems or return types that are logically correct but syntactically different (e.g., a generator instead of a list). This precision ensures the output matches the evaluator's expected signature exactly.
