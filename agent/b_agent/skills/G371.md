Prioritize Functional Correctness and Error Handling Over Formatting

**When to apply**: When the generated code must be robust in production-like scenarios, handle invalid inputs, or manage resources, rather than just pass a narrow set of unit tests.
**What to do**: Explicitly instruct the model on what constitutes an error and how to handle it (raise a specific exception, return a sentinel value, log a message). Mention critical behaviors like closing files or connections. De-prioritize instructions about code style, comment formatting, or docstring templates unless they are a strict requirement.
**Example**: "If the input file path does not exist, raise a `FileNotFoundError`. If the file is not valid JSON, raise a `json.JSONDecodeError`. Ensure the file is properly closed after reading, even if an error occurs."
**Why it works**: Models often prioritize generating syntactically perfect, well-commented code that fails silently on edge cases. Explicit error-handling instructions shift the focus to robustness, which is often the real evaluation criteria beyond basic functionality.
