Explicitly State Exact Function Name and Signature

**When to apply**: Always, but especially when the problem is abstract or when similar functions exist (e.g., `calculate` vs `compute`). Critical for automated testing where the evaluator calls a specific function.
**What to do**: Declare the required function name, its parameter names and types, and its return type with unambiguous language. Place this requirement at the beginning of the implementation instructions.
**Example**: "You must implement a function with the exact signature: `def find_median(arr: list[float]) -> float:`. The function takes a list of floats and returns a float."
**Why it works**: Code models may generate correct logic but inside a function named `median`, `calculate_median`, or `findMedian`, leading to `NameError` during evaluation. This explicit instruction aligns the model's output with the external calling contract.
