Specify Algorithmic Goals, Not Step-by-Step Prescriptions

**When to apply**: When you want to guide the model toward an efficient or specific algorithm (e.g., O(n log n) sort, memoization, two-pointer technique) without micromanaging variable names or control flow. Use when the problem has known optimal solutions.

**What to do**: State the high-level algorithmic requirement or property. Specify the goal (e.g., "achieve O(1) time complexity for `push` and `pop`") or the name of the technique/algorithm to use. Avoid dictating the exact sequence of operations or internal variable names.

**Example**: "Implement a stack that supports retrieving the minimum element in constant time. Use an auxiliary stack to track minimums. The class must be named `MinStack` and have methods `push`, `pop`, `top`, and `getMin`."

**Why it works**: Overly prescriptive instructions ("create a variable `i`, loop from 0 to n, then check if...") can confuse the model if the prescribed steps are incomplete or conflict with its optimal solution path. Providing the goal allows the model to leverage its training to produce a correct and idiomatic implementation of that algorithm.
