Clearly State Core Logic Before Formatting or Style

**When to apply**: When the prompt contains both a functional transformation (e.g., data conversion, calculation, filtering) and secondary concerns like output formatting, error handling, or style rules.
**What to do**: First, articulate the primary input-to-output transformation in one clear, imperative sentence. This sentence should focus solely on the logic, using plain terms like "convert," "find," "filter," or "calculate." Only after this core is stated, introduce additional constraints like "return the result as a formatted string" or "use a list comprehension."
**Example**: "Core logic: Calculate the sum of squares of all positive integers in the given list. Then, format the result as a string with the prefix 'Result: '."
**Why it works**: Code generation models often get distracted by secondary constraints and may produce code that perfectly formats an incorrect result. By isolating the core logic, you anchor the model's primary reasoning, ensuring the fundamental algorithm is correct before layering on presentation.
