Define Edge Cases Unambiguously and Consistently

**When to apply**: For any problem where boundary conditions are critical (empty inputs, zero, negative numbers, single-element lists, overflow, etc.). Essential for robust function and algorithm design.
**What to do**: Explicitly list the edge cases the implementation must handle. Ensure these cases are logically consistent with the core problem statement. Avoid vague terms like "handle edge cases"; instead, specify them concretely (e.g., "handle an empty input string by returning an empty list").
**Example**: "Write a function `parse_range(s)` that takes a string like '1-5' and returns the list `[1,2,3,4,5]`. Ensure it handles: 1) single numbers like '7' (return `[7]`), 2) malformed strings like '5-1' (raise a `ValueError`), and 3) strings with extra spaces like ' 10 - 15 '."
**Why it works**: Models may assume standard libraries handle edge cases or may define them inconsistently. Explicit, concrete enumeration removes ambiguity, ensuring the generated code is robust and behaves predictably across all specified inputs, matching the true problem requirements.
