Maintain coherent structure and consistent formatting

**When to apply**: Always, as a foundational skill to ensure prompt clarity and prevent model confusion.
**What to do**: Use consistent naming for variables and concepts throughout the prompt. Ensure all list items follow the same format (e.g., all bullets or all numbered). Proofread the prompt for typos, markdown corruption (e.g., broken code fences ` ``` `), or stray characters from copy-pasting. Use a plain, readable font in your prompt editor.
**Example**: (A coherent prompt avoids issues like): "`def process(data:List):` # Requirement: input is a list of ints. * Edge case: the data could be a tuple. Please handle. Also, the output format should be a dict keyed by string." (Corrected): "`def process(data: List[int]) -> Dict[str, int]:`\n- Input `data` is a list of integers.\n- If `data` is empty, return an empty dict.\n- The output dictionary should have string keys derived from the integers."
**Why it works**: Inconsistent formatting (mixing `List` and `list`) can confuse the model's type hint generation. Corrupted text or contradictory statements force the model to guess your intent, often leading to buggy or incomplete code.
