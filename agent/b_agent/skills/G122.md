Command "Output Only Final Code" Paired with a Strong Task Definition

**When to apply**: When the model persistently prefixes its code with explanations, markdown blocks, or conversational text, and you need clean, directly executable output.
**What to do**: First, give a complete and unambiguous problem definition. *Then*, as a separate, final instruction, explicitly state the output format. The strength of the first part gives the model confidence to obey the second.
**Example**: "Task: Implement the quicksort algorithm in-place for a list of integers. The function `quicksort(arr: List[int]) -> None` must sort the input list. Your solution must be the complete, runnable Python code for this function. Output only the final code solution, with no additional text, explanations, or markdown formatting."
**Why it works**: A weak task definition followed by "output only code" can cause the model to generate nothing or very low-confidence code. A strong, clear task first satisfies the model's need to "understand," making it more willing to comply with the strict output filter.
