Require Strict Output Formatting: No Extraneous Characters

**When to apply**: When the output will be piped directly into a compiler/interpreter or a strict validation script that is sensitive to extra characters, newlines, or markdown formatting.
**What to do**: Command the model to output *exactly* the required code block, with no leading/trailing backticks, no file headers, and no surrounding text. Specify that even comments inside the code should be minimal or omitted unless necessary for clarity.
**Example**: "Output ONLY the raw code for the function. Do not wrap it in markdown code blocks (```), do not add any introductory sentences, and do not include 'Here is the solution:'. The first line of your output must be `def function_name(...):`."
**Why it works**: Automated systems often expect a pristine code file. Extra text or markdown can cause parsing errors, syntax errors, or test failures. This eliminates all formatting noise.
