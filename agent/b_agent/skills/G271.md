Ensure All Internal Instructions are Logically Consistent

**When to apply**: In any prompt, but especially when combining multiple requirements (e.g., input validation, return type, error handling). Always review the prompt for contradictions before finalizing it.
**What to do**: Systematically check the prompt for conflicting statements. Verify that the described return type matches the task's goal, that constraints on input modification don't contradict required operations, and that any referenced examples or variables actually exist in the prompt context.
**Example**: *Inconsistent*: "The function must not return anything. It should return the computed sum as an integer." *Consistent*: "The function must compute the sum and return it as an integer. It should not print the result."
**Why it works**: Models attempt to satisfy all instructions simultaneously. When instructions conflict, the model may produce code that is logically incoherent, fails to compile, or arbitrarily chooses one instruction over another, leading to an incorrect solution.
