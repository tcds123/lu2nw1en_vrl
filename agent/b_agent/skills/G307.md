Specify exact function signature and output format requirements

**When to apply**: For any code generation task where integration with existing code, testing frameworks, or specific APIs is required. Essential when the function name, parameter order/types, and return type are non-negotiable.
**What to do**: State the function name, each parameter with its expected type (using language-specific type hints if possible), and the exact return type. If the output should be a printed string, a specific data structure (list, dict, generator), or a side effect, state it explicitly.
**Example**: "Write a Python function with signature `def filter_by_prefix(strings: List[str], prefix: str) -> List[str]:`. It must return a new list containing only strings from `strings` that start with `prefix`, preserving original order."
**Why it works**: Models often default to common patterns or names (e.g., `arr` instead of `strings`). Without an explicit signature, generated code may be functionally correct but unusable in the intended context, causing integration failures.
