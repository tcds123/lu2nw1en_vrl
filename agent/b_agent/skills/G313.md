Prioritize concrete implementation details (function name, parameter types, return type, error conditions) over philosophical descriptions of code quality.

**When to apply**: When prompts use vague quality attributes ("elegant", "robust", "production-ready", "clean") without defining what they mean concretely in the context of the task.
**What to do**: Replace abstract quality goals with specific, verifiable instructions. Instead of "write robust code," say "validate all function parameters and raise appropriate exceptions for invalid inputs." Define "efficient" as a time/space complexity target.
**Example**: Instead of "Write a clean, efficient function to find duplicates," use: "Write a function `find_duplicates(items: List) -> Set` that returns a set of all items appearing more than once in the list. It should run in O(n) average time complexity."
**Why it works**: Models have no shared concrete understanding of terms like "clean" or "production-ready." These can lead to unpredictable or insufficient outputs. Concrete details provide unambiguous criteria for the model to satisfy, leading to more reliable and useful code generation.
