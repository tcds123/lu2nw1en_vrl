Define Clear Function Signature and Return Behavior Without Over-Restriction

**When to apply**: When the function's interface is the primary requirement, but you want to avoid instructions like "do not use any loops" or "do not import any modules" that might make the problem unsolvable for the model.
**What to do**: State the signature and what the return value represents in the problem domain. Avoid banning specific, common programming constructs unless they are fundamentally incompatible with the required algorithm.
**Example**: "Write a function `merge_intervals(intervals: List[Tuple[int, int]]) -> List[Tuple[int, int]]` that merges all overlapping intervals and returns a new list sorted by start time. Focus on a correct and efficient algorithm."
**Why it works**: Excessively restrictive output instructions (e.g., "no imports", "no helper functions") can paralyze the model, leading to low-confidence generations or refusal. This provides a clear target while leaving reasonable implementation paths open.
