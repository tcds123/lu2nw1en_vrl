Provide Correct, Unambiguous Algorithm Steps

**When to apply**: When the problem requires a specific, non-trivial algorithm (e.g., dynamic programming, backtracking, a particular sorting algorithm, graph traversal).
**What to do**: Outline the key algorithmic steps at a high level. Focus on defining state (e.g., "Let `dp[i]` represent..."), iteration order (e.g., "iterate from the bottom-right to top-left"), and transition logic. Avoid mandating specific variable names or low-level syntax.
**Example**: "Algorithm: Use dynamic programming. State: `dp[i][j]` is the minimum path sum to cell (i, j). Transition: `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`. Iteration: Process rows from top to bottom, and within each row, columns from left to right."
**Why it works**: Simply naming an algorithm ("use DP") is insufficient; models often choose incorrect state representations or iteration orders. Providing the correct key steps guides the model's structural reasoning without stifling its ability to write the correct boilerplate and syntax.
