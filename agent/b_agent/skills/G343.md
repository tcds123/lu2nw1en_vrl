Ensure Prompt is Syntactically Clean and Free of Corruption

**When to apply**: Always, but especially when copying text from PDFs, web pages, or formatted documents. When the prompt contains odd characters, markdown artifacts, or inconsistent indentation.
**What to do**: Before submitting, review the prompt in plain text. Remove any stray characters, fix broken indentation, and ensure code snippets within the prompt are properly demarcated. Use a simple, consistent format.
**Example**: A corrupted prompt: "Write a function to reverse a string. Theƒunction should be named `revStr` & handle unicode." Cleaned version: "Write a function named `reverse_string` that takes a string as input and returns its reverse. The function should correctly handle Unicode characters."
**Why it works**: Models are sensitive to tokenization; stray characters (like 'ƒ' instead of 'f') can be interpreted as part of the requirement, leading to syntactically invalid code or misnamed functions. Clean input leads to clean, compilable output.
