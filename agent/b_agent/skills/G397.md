Prioritize Explicit Functional Requirements Over Stylistic Prescriptions

**When to apply**: When the primary goal is a correct, functional implementation. Avoid this when code style (e.g., for a textbook example) is an explicit, separate requirement.
**What to do**: Focus the prompt on the *what* (the function's job) and the *how* (the core algorithm or data structure constraint). Omit subjective style advice like "write clean code" or "use descriptive variable names." Instead, mandate specific functional behaviors.
**Example**: "Implement `def find_duplicate(nums: List[int]) -> int:`. You must use constant extra space, not modify the array, and the runtime complexity must be better than O(n²). The array contains integers from 1 to n, with one duplicate."
**Why it works**: Vague stylistic instructions add noise and consume context window without improving functional correctness. Models can infer reasonable style; they often fail on complex algorithmic constraints. This focuses the model's "attention" on the hard requirements.
