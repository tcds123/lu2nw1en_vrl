Prioritize Problem Interface Adherence Over General Best Practices

**When to apply**: When standard coding best practices (e.g., using private attributes, adding getter/setter methods, validating all inputs) would conflict with the expected interface defined in the problem statement or test suite.
**What to do**: Explicitly instruct the model to match the provided interface exactly, even if it means using public attributes, omitting input validation for guaranteed inputs, or using a specified non-standard method name. Treat the problem's API as a contract.
**Example**: "The problem states the `Stack` class must have a public list attribute `items`. Implement the `push` and `pop` methods to modify `self.items` directly. Do not make `items` private or rename it to `_items`, even though that is a common best practice."
**Why it works**: Models trained on general code may "correct" a given interface to follow common conventions, causing test failures because the test cases call `obj.items` directly. This instruction overrides that tendency.
