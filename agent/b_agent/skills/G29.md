Provide Clear, Feasible Formatting Instructions That Guide Without Restricting

**When to apply**: When the output format is critical (e.g., for API compatibility, test suite validation, or specific display needs). When a user asks for code to be "formatted" in a certain way.
**What to do**: Specify the *what* of formatting (e.g., "return a JSON object", "print each result on a new line") rather than the *how* (e.g., "use an f-string with exactly three spaces"). Ensure the requested format is logically possible given the function's other constraints.
**Example**: "The function must return a dictionary with two keys: `'status'` (a boolean) and `'result'` (the computed integer)."
**Why it works**: Overly rigid formatting commands (e.g., "use a `while` loop, not a `for` loop") can conflict with the model's optimal solution path, leading to forced, suboptimal code or refusal to generate. Clear outcome-based formatting gives the model necessary structure without handcuffing its implementation.
