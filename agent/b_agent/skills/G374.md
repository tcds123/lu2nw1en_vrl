Avoid Overly Restrictive Output Formatting Commands

**When to apply**: In most general code generation tasks, especially those embedded in a conversational context or requiring explanation. Only restrict output if you are 100% certain the downstream system will parse *only* code blocks and discard all other text.
**What to do**: Use instructions like "Provide the complete code solution" or "Generate the implementation." Avoid commands like "Output only the code, no explanations," "Do not say anything else," or "No text outside the code block," unless you have validated that the model's role is purely a code emitter.
**Example**: "Please provide a Python implementation for the function described below."
**Why it works**: Aggressive suppression commands can confuse the model's conversational flow, sometimes causing it to output nothing, truncate the code, or produce malformed output in an attempt to obey the "no text" rule. This is especially problematic for models fine-tuned on instructional data.
