Explicitly State Edge Cases and Expected Outputs

**When to apply**: For any function where boundary conditions (empty input, extreme values, invalid input) are likely or where the "obvious" behavior might be ambiguous.
**What to do**: List edge cases as concrete input-output pairs. Use the format "If input is X, return/output Y." Include handling for invalid inputs if required.
**Example**: "Write a function `clamp(value, min_val, max_val)`. Edge cases: If `value < min_val`, return `min_val`. If `value > max_val`, return `max_val`. If `min_val > max_val`, raise a `ValueError`."
**Why it works**: Models often handle the "happy path" well but may make arbitrary or inconsistent choices on edge cases. Providing explicit expectations eliminates this ambiguity and leads to robust, testable code from the first generation.
