Mandate a Modular Design with Helper Functions for Complex Tasks

**When to apply**: When the requested functionality is complex, involves multiple logical steps, or would result in a long, monolithic function. When code readability and reusability are explicit goals.
**What to do**: Instruct the model to decompose the problem. Explicitly ask for a main function that orchestrates the logic and separate, well-named helper/utility functions for distinct sub-tasks. Emphasize separation of concerns.
**Example**: "Implement a `process_report(data_file)` function. Structure your solution modularly: create a helper function `_parse_line(line)` to handle raw line parsing, another `_validate_record(record)` for data validation, and have `process_report` coordinate reading the file, calling these helpers, and aggregating results."
**Why it works**: Without this guidance, models tend to produce a single, dense block of code that is harder to debug, test, and understand. Enforcing modularity leads to more maintainable, testable, and conceptually clear code that mirrors professional software engineering practices.
