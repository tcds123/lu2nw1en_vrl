Prioritize Concise, Unambiguous Instructions Over Verbose or Contradictory Rules

**When to apply**: When the prompt is becoming long, contains stylistic commentary not relevant to the core function, or includes multiple rules that could conflict (e.g., "be efficient" vs. "use no extra memory").
**What to do**: Strip away all non-essential commentary, domain explanations, and secondary stylistic preferences. Consolidate the core functional requirements into a single, logically ordered list. Ensure no two requirements contradict each other (e.g., "must be O(n)" and "must use nested loops" for an n² algorithm).
**Example**: "Write a function `clean_string(s: str) -> str` that removes all non-alphabetic characters and converts the result to lowercase. Do not use regular expressions. The function must handle empty strings and should return an empty string if the result would be empty."
**Why it works**: Code generation models can be distracted by verbose formatting and may latch onto contradictory or low-priority instructions, leading to incorrect logic or ignored core requirements. Concise, unambiguous instructions reduce the chance of misinterpretation.
