Prioritize Concise, Unambiguous Behavioral Requirements

**When to apply**: Always. This is a foundational skill for writing clear prompts. It is most critical when the problem is complex or has many subtle rules.
**What to do**: Frame every instruction as a testable requirement. Use precise, action-oriented language (e.g., "must raise a ValueError", "returns -1 if not found"). Eliminate subjective style advice (e.g., "write elegant code") that doesn't affect functionality.
**Example**: "The function `find_index(arr, target)` must return the first index where `target` appears in `arr`. If `target` is not found, return `-1`. If `arr` is `None` or not a list, raise a `TypeError`. The time complexity must be O(n)."
**Why it works**: Vague or stylistic instructions introduce ambiguity, leading the model to guess at what's important. Clear, behavioral requirements map directly to test cases, guiding the model to generate code that passes specific, objective checks for correctness.
