Provide Clear, Concise Algorithmic Requirements

**When to apply**: When describing the logic or steps the code must implement, especially for custom algorithms, specific data manipulations, or when a particular implementation strategy is required (e.g., in-place modification, iterative vs. recursive).
**What to do**: Describe the algorithm's core steps in a simple, linear, and unambiguous way. Use imperative language focused on the *what* (the transformation) and the *how* (the high-level procedure). Avoid verbose narratives, contradictory options, or abstract descriptions.
**Example**: "To reverse the linked list, iterate through the nodes. For each node, point its `next` pointer to the previous node, then move forward. You will need to track the previous, current, and next nodes during iteration."
**Why it works**: Vague or wordy instructions lead to misinterpretation. Models perform better with direct, stepwise logic that mirrors the structure of the code they need to generate. This reduces the chance of the model inventing an incorrect or overcomplicated approach.
