Remove Redundant and Overly Restrictive Constraints

**When to apply**: When the problem statement or initial prompt contains rules that are irrelevant to the core logic, contradictory, or artificially limit valid solutions (e.g., banning built-in functions without reason, specifying unnecessary steps).

**What to do**: Critically review all constraints. Retain only those that are essential for correctness, performance (Big O), or interface (function signature). Strip out rules that are ambiguous, stylistic preferences presented as requirements, or restrictions that don't affect the problem's fundamental challenge.

**Example**: Instead of "Do not use any built-in functions or libraries. Implement your own sorting algorithm. Do not use extra space. Ensure the function name is `solve`," write: "Implement a function `solve(nums)` that sorts the list `nums` in-place and returns it. Aim for O(n log n) time complexity."

**Why it works**: Extraneous rules confuse the model, causing it to focus on arbitrary restrictions instead of the core algorithm. This can lead to incorrect logic, inefficient code, or failure to use perfectly valid and idiomatic language features.
