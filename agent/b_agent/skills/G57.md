Enforce Strict API Adherence by Prohibiting Unsolicited Additions

**When to apply**: When designing a class or module with a strict public interface, or when solving problems where test suites are sensitive to extra methods or attributes.
**What to do**: Explicitly instruct the model to implement *only* the specified methods and attributes. Use a prohibitive statement to block the addition of other public methods, properties, or required constructor parameters not listed in the requirements.
**Example**: "Create a `BankAccount` class with `__init__(self, balance: float)` and `deposit(self, amount: float) -> None`. Do not add any other public methods or instance variables. The class must not have a `withdraw` method."
**Why it works**: Models often "helpfully" add common-sense methods (like getters/setters, `__str__`, or validation helpers) which can conflict with test suites that iterate over expected methods or check for the absence of certain functionalities.
