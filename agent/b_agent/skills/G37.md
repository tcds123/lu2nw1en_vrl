Define Algorithmic Constraints and Edge Cases, Not Steps

**When to apply**: For optimization problems, system design with resource limits, or when the problem statement implicitly requires a specific performance class (e.g., "in-place", "without extra space", "linear time").
**What to do**: State the required time and space complexity (e.g., O(n log n) time, O(1) auxiliary space). Enumerate critical edge cases to handle (empty input, large values, duplicates). Crucially, do not describe a specific algorithm like "use a hash map" or "sort the array," as this can conflict with the model's optimal solution path.
**Example**: "Write a solution that runs in O(n) time and uses O(1) extra space beyond the input list. Handle edge cases: an empty list, a list with one element, and a list where all elements are identical."
**Why it works**: Models often understand complexity constraints and can derive appropriate algorithms (two-pointers, bit manipulation, etc.). Prescribing a specific algorithm can cause the model to force-fit an inferior implementation or generate contradictory code if the prescribed steps don't meet the stated constraints.
