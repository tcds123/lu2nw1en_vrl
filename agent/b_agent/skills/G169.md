State core task concisely upfront before secondary details.

**When to apply**: For all tasks, but especially complex ones with multiple requirements. This ensures the model understands the primary objective before getting bogged down in formatting, style, or edge cases.
**What to do**: In the first 1-2 sentences of the prompt, declare the essential task: the function name, its parameters and return type, and the single most important constraint (e.g., "using recursion", "in O(1) space"). Then, in subsequent sentences, add other requirements.
**Example**: "Implement a recursive function `fib(n: int) -> int` that returns the nth Fibonacci number. The function must use recursion and handle n=0 and n=1 correctly. Additionally, include a Google-style docstring and ensure the output is a complete code block."
**Why it works**: Models process prompts sequentially. Leading with the core task anchors the model's high-level plan. If secondary details like docstring style are mentioned first, the model may prioritize them and produce a well-documented but algorithmically incorrect function.
