Specify the Core Algorithmic Approach or Constraint, Not Syntax

**When to apply**: When a specific algorithm, data structure, or complexity constraint is non-negotiable for correctness or performance, but its implementation can vary. When you need to guide the model away from an obvious but incorrect brute-force solution.
**What to do**: State the required approach as a constraint on the solution's logic or performance, using plain English to describe the mechanism. Avoid language that dictates specific syntax (e.g., "use a for loop").
**Example**: "Remove duplicates from the input list while preserving the original order of first appearance. You must achieve this with O(n) average time complexity, typically by using a hash set to track seen items."
**Why it works**: It steers the model towards the correct algorithmic family (e.g., hash-based deduplication) without locking it into a potentially suboptimal implementation detail. This prevents the model from using O(n²) nested loops or other inefficient but logically correct methods.
