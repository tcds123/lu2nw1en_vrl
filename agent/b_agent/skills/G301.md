Prioritize Functional Correctness and Clean Structure Over Style

**When to apply**: When the primary goal is a working, efficient solution, not code golf or adherence to a specific style guide (like PEP 8 line length). Useful for algorithmic core development where internal structure matters more than formatting.

**What to do**: Emphasize that the solution must be functionally correct, efficient, and have a clear logical structure (e.g., well-named helper functions, separation of concerns). De-emphasize or omit strict rules about formatting, variable naming conventions, or comment density unless they are critical.

**Example**: "Focus on delivering a correct and optimally efficient solution. Clean, readable code structure is important, but minor style issues like line length are not a priority. Do not sacrifice clarity for overly concise 'clever' code."

**Why it works**: Models can get distracted by secondary style requirements, potentially over-optimizing for format at the expense of algorithm or bug-free logic. This instruction re-centers the objective on the core engineering task.
