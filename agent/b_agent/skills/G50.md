Mandate Verifiable Correctness Against Stated Transformation Logic

**When to apply**: For all problems where the evaluation is based on a specific input-output transformation. This shifts focus from code style to functional correctness.
**What to do**: Instruct the model that the solution will be judged by applying the stated logic to test cases. Emphasize that the code must produce outputs that are verifiably correct according to that logic, not just be well-structured.
**Example**: "Your solution will be evaluated by testing if, for given inputs, it produces outputs that exactly match the results defined by the transformation rule above. Correctness is determined solely by this functional verification."
**Why it works**: This counteracts the model's tendency to produce plausible, well-commented code that may have subtle logical bugs. It focuses the model's objective on the exact mapping between inputs and required outputs.
