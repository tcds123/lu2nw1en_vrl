Specify Algorithmic Constraints, Not Implementation Details

**When to apply**: When the problem has critical performance (time/space complexity) or resource (no network calls) requirements, but the implementation path should be left open to the model's reasoning.
**What to do**: State the required algorithmic constraints clearly (e.g., O(n) time, O(1) extra space). Avoid banning specific language features (e.g., "don't use `sorted`") unless they directly violate the core constraint. Allow the model to choose appropriate data structures and constructs.
**Example**: "Implement a solution that runs in O(n log n) time and uses at most O(n) extra space. You may use any standard Python libraries and constructs that meet these complexity requirements."
**Why it works**: Over-prescribing (e.g., "use a while loop, not a for loop") can limit the model's ability to generate an optimal or idiomatic solution. Stating the goal (complexity) focuses the model on the *what* and *why*, letting it figure out the *how*, which often yields more robust code.
