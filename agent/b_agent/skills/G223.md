Maintain Prompt Coherence to Prevent Gibberish or Invalid Code

**When to apply**: When editing or combining prompts, or when a prompt has become long and complex. If previous generations have produced corrupted outputs (e.g., mixed languages, broken markdown).
**What to do**: Before finalizing the prompt, read it for internal consistency. Ensure all instructions are in the same language and logical order. Remove any fragments, placeholder text, or conflicting commands. Verify that formatting rules are possible to follow.
**Example**: **Corrupted Prompt**: "Write a function to... [INSERT LOGIC HERE] ...and make sure to use f-strings. Oh also don't forget imports. ```python code only plz." **Coherent Prompt**: "Write a Python function `format_greeting(name: str) -> str:` that returns `f'Hello, {name}!'`. The solution must be in a single Python code block."
**Why it works**: Models are highly sensitive to prompt structure. Gibberish, placeholders, or contradictory formatting rules can cause the model to replicate the corruption in its output or fail to generate any valid code at all.
