Define the Exact Function Signature and Demand Strict Adherence

**When to apply**: When the function's interface (name, parameters, return type) is critical for integration, testing, or API consistency. This is always important but especially for library functions, solutions to coding challenge platforms, or when mimicking a specific existing API.

**What to do**: Explicitly provide the exact function signature, including parameter names, types (if applicable), default values, and return type annotation. State unequivocally that the generated code must match this signature exactly, with no alterations.

**Example**: "Function Signature: `def calculate_discount(price: float, discount_rate: float = 0.1) -> float:` The generated code must implement this exact signature. Do not change parameter names, order, default values, or the return type annotation."

**Why it works**: Models may "correct" what they perceive as suboptimal names, reorder parameters, or omit type hints/defaults if not explicitly bound to the signature. This causes integration failures where the calling code cannot find the function with the expected interface.
