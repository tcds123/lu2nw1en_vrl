Explicitly Forbid Explanations-Only and Demand Code Deliverable

**When to apply**: When the prompt is a direct request for implementation (e.g., "write a function that...", "implement an algorithm for..."). This skill reinforces G9 by explicitly stating the prohibition.
**What to do**: State clearly that the output must be executable code, not just an explanation or a plan. Use strong directive language like "never output just an explanation" or "the deliverable is code, not a description." This closes the loophole where a model might provide a correct algorithmic description but no code.
**Example**: "The deliverable is executable code. Never respond with only an explanation of how you would solve it or a step-by-step plan without providing the actual implementation."
**Why it works**: It prevents a common model behavior: providing a correct textual solution that is useless to a developer who needs to copy-paste and run code. It aligns the model's output format with the user's implicit need for a working program.
