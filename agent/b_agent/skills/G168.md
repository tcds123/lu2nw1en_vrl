Define and enforce the required output format strictly.

**When to apply**: When the downstream use case requires a specific format—e.g., code only for direct execution, or code with inline comments for education, or a separate explanation block for review.
**What to do**: State the format requirement upfront and at the end for emphasis. Be precise: "Output only the code", "Output the code first, then a brief explanation in a separate paragraph", or "Include detailed comments within the code explaining each step."
**Example**: "You must output two distinct sections: 1) A complete Python code block containing the solution. 2) A brief explanation of the algorithm's time and space complexity, outside the code block. Do not mix explanation into the code block."
**Why it works**: Models default to patterns from their training data, which often mix code and explanation. Without explicit format instructions, the output is unpredictable and may not fit the intended pipeline (e.g., an auto-grader expecting pure code will fail if explanations are present).
