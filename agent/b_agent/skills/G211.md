Explicitly Forbid Specific Problematic Approaches or Constructs

**When to apply**: When certain standard library functions, imports, or simplistic solutions would trivialize the problem or violate its educational/assessment intent (e.g., "implement sorting without using `sorted()`"). Also useful to prevent known anti-patterns or inefficient methods.

**What to do**: Clearly list the disallowed functions, modules, or techniques. Use a positive tone by framing it as part of the challenge. Optionally, suggest the category of solution that is expected (e.g., "implement your own binary search").

**Example**: "Implement the function `calculate_mean(numbers: List[float]) -> float` **without using the `sum()` built-in function or importing the `statistics` module.** You must manually iterate through the list to compute the total and count."

**Why it works**: Models heavily rely on common shortcuts and built-in abstractions. If `sum()` is allowed, the model will almost certainly use it. An explicit prohibition forces the model to decompose the problem and generate the underlying logic, which is often the actual learning or testing objective.
