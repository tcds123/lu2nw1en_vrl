Clearly Define and Harmonize Edge-Case Behavior

**When to apply**: When the problem involves boundary conditions (empty input, null values, large numbers, invalid arguments) or when previous model outputs have been inconsistent in handling these cases.
**What to do**: Explicitly list the edge cases that must be considered. For each, define the *exact* expected behavior (return value, exception, etc.). Review the prompt to ensure no other part contradicts this behavior.
**Example**: "Write a function `safe_divide(a, b)`. Edge Cases: 1. If `b == 0`, return `None`. 2. If either `a` or `b` is not a number (int/float), raise a `TypeError`. 3. Ensure the function works correctly for very large floating-point numbers."
**Why it works**: Models can make arbitrary or inconsistent decisions on edge cases if not guided, leading to buggy code. A single, unambiguous specification acts as a source of truth, ensuring the generated logic is coherent and reliable across all scenarios.
