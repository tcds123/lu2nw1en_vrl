Provide Specific, Actionable Requirements in a Prioritized List

**When to apply**: When the task is complex or has multiple distinct components (e.g., "build a data parser and a summarizer"), when there are critical constraints (e.g., "must run in O(n) time"), or when the user's initial request is vague or narrative-based.
**What to do**: Break down the request into a simple, numbered list of concrete requirements. Prioritize the most critical functional elements first. Each item should specify a function name, a key algorithm to use, or a structural constraint (e.g., "must implement class X").
**Example**: "Please write Python code with the following requirements, in order of priority: 1. A function named `calculate_entropy(data_list)` that computes Shannon entropy. 2. Use `collections.Counter` for frequency calculation. 3. The function must handle empty lists by returning 0. 4. Include a `main()` function that demonstrates usage with a sample list."
**Why it works**: Code generation models can misinterpret prose descriptions, leading to missing features or incorrect function names. A clear list directly maps to the structure of the generated code, ensuring all specified points are addressed in the output.
