Clearly define the core task and expected output format in simple, unambiguous language before adding any constraints

**When to apply**: For all tasks, but especially complex ones with multiple steps or constraints. This is the foundational structure of a good prompt.
**What to do**: Start the prompt with a single, direct sentence that states what to generate and the primary output. Use the simplest possible language. Only after this clear "headline" should you add details, edge cases, performance requirements, or stylistic rules.
**Example**: "Write a Python function that reverses a string. The function should be called `reverse_string`. It must handle empty strings and use recursion. Do not use built-in `reversed` or `[::-1]`."
**Why it works**: Models process the beginning of a prompt with higher attention. A muddy opening can lead to the model missing the primary goal entirely. This structure ensures the model latches onto the correct objective before layering on complexity.
