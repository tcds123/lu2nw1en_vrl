Set Uncontradictory Coding-Style Expectations

**When to apply**: When the generated code should follow specific conventions like PEP 8, use modular design, or include specific types of comments, without creating internal conflicts in the instructions.
**What to do**: State style expectations positively as part of the code's requirements. Frame them as attributes of the final code block, not as separate output items. Avoid pairing a style demand with an instruction that would negate it.
**Example**: "Write the solution adhering to PEP 8 guidelines. The final code should be modular, with a clear separation of concerns, and include informative docstrings and inline comments where complex logic exists. Output the complete script in a single code block."
**Why it works**: Contradictory instructions (e.g., "include comments" and "output only code") cause confusion, often resulting in the model ignoring one requirement. By integrating style into the code specification, you ensure a consistent, high-quality output that meets all criteria.
