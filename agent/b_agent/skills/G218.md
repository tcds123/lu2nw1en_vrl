State Core Algorithmic Constraints Before Stylistic Rules

**When to apply**: When the solution must employ a specific technique (e.g., recursion, a particular data structure, a regex pattern) or adhere to a hard constraint (e.g., O(n) time, O(1) space, no imports).
**What to do**: Immediately after the function signature, state the non-negotiable technical constraint using imperative language. Separate this from general coding style or formatting preferences.
**Example**: "Define `def is_valid_ip(ip: str) -> bool:`. You must validate the IP using a single compiled regex pattern that checks for four octets in the range 0-255. After this logic is correct, ensure the function has a Google-style docstring."
**Why it works**: Models can prioritize later, more verbose instructions (like docstring rules) over earlier, subtler ones. By front-loading the algorithmic constraint, you ensure it is treated as a primary requirement, not an optional suggestion.
