Enforce Interface Adherence Over Stylistic Conventions

**When to apply**: When the generated code will be assessed by an automated test suite that checks method names, parameter order, and return types, but not necessarily code style (e.g., most online judges, unit test integrations).
**What to do**: In the prompt, stress that the public interface (class/function names, method signatures, public member visibility) must match exactly. State that internal style (docstring format, variable naming conventions, use of f-strings) is secondary and can follow the model's standard practices for the language.
**Example**: "The public API must be exactly as specified. Internal implementation details, including the format of docstrings and choice of variable names, are less important than correct functionality."
**Why it works**: Models sometimes waste tokens or generate awkward code trying to satisfy conflicting stylistic demands (e.g., a specific docstring format that clashes with the language's norms), which can distract from or even break the core functional logic.
