Balance Detail with Clarity: Specify Complexity, Avoid Contradictory Suggestions

**When to apply**: When algorithmic efficiency (time/space complexity) is a stated requirement. When providing implementation hints that must not conflict with the primary constraints.
**What to do**: Clearly state the required complexity (e.g., O(n) time, O(1) extra space) as a direct constraint. Avoid adding secondary, vague suggestions (e.g., "make it fast") that could contradict the primary complexity goal or ordering needs.
**Example**: "Implement a solution that runs in O(n) time and uses O(1) additional space, not counting the input and output storage. The order of elements in the output must match the requirement specified above."
**Why it works**: Vague instructions like "optimize for speed" can lead to premature optimization or choices (like using a hash map for O(1) lookups) that violate an explicit O(1) space requirement. Clear, singular complexity targets guide the model to select appropriate algorithms.
