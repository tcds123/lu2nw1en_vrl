Mandate Specific Error Handling and Exception Messages

**When to apply**: When the function must fail loudly and predictably under specific invalid inputs (e.g., negative numbers, malformed strings, missing keys). This is crucial for creating robust, debuggable APIs and passing unit tests that check for exact exception types and messages.

**What to do**: Explicitly state the condition that should trigger an exception, the exact exception type (e.g., `ValueError`, `TypeError`, `KeyError`), and, if required, the precise string content of the exception message. Treat the error message as a functional requirement.

**Example**: "If the input `json_string` is not a valid JSON format, the function must raise a `ValueError`. The error message must be exactly: `'Input string is not valid JSON.'` If the parsed JSON does not contain the required key `'data'`, raise a `KeyError` with the message `'Missing \"data\" key.'`"

**Why it works**: Without explicit instruction, models often implement generic error handling (`raise Exception("Error")`) or simply return `None`. This leads to inconsistent and non-idiomatic error reporting. Specifying the exact exception type and message ensures the generated code behaves predictably in failure modes, which is a key aspect of professional code.
