Balance Constraints: State Goals, Not Mandatory Methods

**When to apply**: When a problem has clear objectives (efficiency, readability, specific behavior) but multiple valid implementation strategies exist. When over-specification could lead to suboptimal or convoluted code.
**What to do**: Clearly state the *goals* (e.g., "must be non-mutating," "must be thread-safe," "must use constant memory") and the *constraints* (e.g., "O(n) time"). Avoid mandating specific techniques (e.g., "use a for loop," "use recursion") unless they are the explicit learning objective.
**Example**: "Provide a solution that modifies the input list in-place and uses O(1) extra memory. You may use any approach that meets these two requirements."
**Why it works**: If you mandate a method (e.g., "use recursion"), the model might force an inappropriate pattern where a simpler iterative solution exists. Stating the goal allows the model to select the most suitable tool from its knowledge, leading to more natural and often better code.
