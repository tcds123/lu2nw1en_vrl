Explicitly Constrain Output Format with Direct, Emphatic Phrasing

**When to apply**: When you need a specific, isolated component (like a single function or class) and not a full program, test suite, or explanation. This is crucial for tasks like competitive programming solutions, LeetCode-style function implementations, API endpoint stubs, or when integrating generated code into a larger codebase.

**What to do**: Use imperative, unambiguous language at the end of your prompt to dictate the exact boundaries of the output. Specify not only what *to* include, but also what *not* to include. Phrase it as a non-negotiable command, not a suggestion. Repeat the core constraint for emphasis.

**Example**: "Implement the `merge_sort` function according to the docstring. Your output must contain **only** the Python function definition. Do not include any example usage, test cases, print statements, or explanatory comments outside the function body. Output ONLY the function."

**Why it works**: Code generation models are often trained on code repositories that include accompanying tests, driver code, and documentation. Without explicit constraints, they default to this "complete example" pattern, which adds superfluous code that must be manually removed. This instruction directly overrides that tendency, yielding clean, copy-paste ready output.
