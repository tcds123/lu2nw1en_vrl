Mandate a Clean Output Format and Forbid Extraneous Content

**When to apply**: When the response must be integrated directly into a larger codebase or when automated testing will evaluate the raw output; to prevent the model from adding its own test cases, explanations, or example usage which would break a parser.
**What to do**: Explicitly state the exact format of the expected output. Command the model to return *only* that content (e.g., the function, the class). Prohibit common extras like example calls, `print` statements, or narrative explanations.
**Example**: "Return only the final Python function with a docstring. Do not include any example usage, test cases, or `print` statements in the code block."
**Why it works**: Models are trained to be helpful and often demonstrate their code with examples. For programmatic use, this extra content is noise and will cause errors if the output is evaluated directly. This instruction streamlines the output for direct consumption.
