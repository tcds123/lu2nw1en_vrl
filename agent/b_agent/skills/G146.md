Prioritize Functional Correctness and Edge Cases Over Code Style

**When to apply**: When the primary success criterion is passing a battery of unit tests, especially those with tricky edge cases (empty inputs, large values, invalid data). When stylistic nitpicking could distract from core logic.
**What to do**: Explicitly instruct the model that working, correct code is the absolute priority. Direct it to consider edge cases (zero, null, duplicates, overflow) and ensure the logic handles them. De-emphasize formatting preferences like variable naming conventions unless specified.
**Example**: "Focus entirely on functional correctness. Ensure your solution handles all edge cases mentioned and implied (e.g., empty list, single element, negative numbers). Do not worry about code style, formatting, or variable names as long as the code is correct and readable."
**Why it works**: Models might waste tokens on perfecting style or writing extensive docstrings while missing a critical boundary condition that causes test failures. This instruction aligns the model's priority with the evaluator's (test suite).
