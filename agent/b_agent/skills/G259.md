Enforce Output Purity by Prohibiting Extraneous Print Statements and Comments

**When to apply**: When the solution must be a pure function or class, and any printed output or instructional comments will interfere with the test harness. Essential for functions that are graded by return value alone.
**What to do**: Explicitly forbid the use of `print()` statements for debugging or explanatory purposes within the solution code. Also, prohibit the generation of instructional comments meant for the user (e.g., "# Now we calculate the sum..."). Only necessary imports are allowed.
**Example**: "Implement the function `calculate_average`. Your solution must not contain any `print()` statements. Do not add comments that explain the algorithm to a human reader. Only import modules that are strictly necessary for the logic."
**Why it works**: Stray print output can corrupt the test runner's interpretation of the program's output. Excessive commenting adds noise and can sometimes lead the model to generate incorrect pseudo-code instead of executable code.
