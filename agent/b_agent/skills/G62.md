Prioritize Clear, Concise, and Contradiction-Free Functional Requirements

**When to apply**: When the initial prompt is wordy, contains generic platitudes (e.g., "write efficient, clean code"), or mixes high-level goals with low-level steps in a confusing way. Essential for refactoring vague user requests.

**What to do**: Strip away verbose explanations and meta-commentary. Consolidate the core task into 1-2 sentences stating the primary goal. List structural and functional requirements as bullet points, removing any advice that conflicts with another part of the prompt.

**Example**: Instead of a long paragraph, use: "Write a function `format_duration(seconds: int) -> str` that converts a number of seconds into a human-readable string (e.g., '1 hour, 2 minutes and 3 seconds'). Requirements: Handle pluralization correctly, return 'now' if seconds is 0, use the units year, day, hour, minute, second, and combine components with commas and 'and' as in the example."

**Why it works**: Models can be distracted by superfluous text, potentially over-optimizing for mentioned but non-essential qualities (like "clean") at the expense of correctness. Contradictions (e.g., "use recursion" and "avoid deep recursion") cause confusion and inconsistent outputs.
