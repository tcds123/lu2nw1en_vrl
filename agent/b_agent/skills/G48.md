Always Explicitly Name the Target Function and Its Exact Signature

**When to apply**: At the start of every prompt that asks for a function or class implementation. This is non-negotiable for avoiding misinterpretation of the task's entry point.
**What to do**: State the exact name of the primary function/class and its full signature, including parameter names, types (if applicable), and return type, before any other implementation details.
**Example**: "Write a Python function with the signature `def is_palindrome(s: str) -> bool:` that determines if a string reads the same forwards and backwards."
**Why it works**: Models might infer an incorrect function name (e.g., `check_palindrome`) or signature (e.g., accepting a list) from the problem description, resulting in code that cannot be called by the evaluation harness, causing immediate failure.
