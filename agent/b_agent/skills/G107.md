Prioritize Functional Correctness and Clarity Over Conflicting Stylistic Rules

**When to apply**: When the prompt contains multiple, potentially contradictory stylistic requirements (e.g., "write detailed comments" but also "keep the code concise"), or when stylistic rules are so rigid they risk causing the model to produce no code at all.
**What to do**: Explicitly instruct the model to focus on delivering a working, correct solution first. State that clarity and correctness are the primary goals, and that any provided stylistic guidelines should be followed only if they do not compromise the core logic or prevent a valid solution from being generated.
**Example**: "Your primary objective is to produce a functionally correct and clear solution. Adhere to the provided style guidelines (like modularity and comments) only insofar as they support this goal. Do not let stylistic concerns prevent you from outputting complete, executable code."
**Why it works**: Code generation models can become "paralyzed" when trying to satisfy conflicting or overly strict non-functional requirements, leading to incomplete outputs or refusal. This instruction anchors the model on the most critical objective: a working program.
