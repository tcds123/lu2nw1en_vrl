Provide Exact Constraints While Avoiding Redundant Verbiage

**When to apply**: When input/output boundaries, base cases, or performance limits are critical to correctness. Common in problems with numerical limits, string length constraints, or specific edge cases.
**What to do**: State constraints precisely once, using numbers and clear conditions. For example, "`1 <= n <= 10^5`" or "The input list may be empty." Do not rephrase the same constraint multiple times in different ways.
**Example**: "Given an integer `n` where `0 <= n <= 100`, generate all valid combinations of `n` pairs of parentheses. An empty list should be returned for `n = 0`."
**Why it works**: Repetition can confuse the model or cause it to over-index on minor details, potentially distorting the core logic. Precise, single-statement constraints are unambiguous and easier for the model to incorporate.
