Unambiguously Specify Class and Method Signatures

**When to apply**: For object-oriented design problems, LeetCode-style class implementations, or any task where a class with specific methods must be instantiated and called by an external tester.
**What to do**: Provide the exact class name, and for each method, its name, parameters (with types if possible), and return type. Specify if a method is public/private (e.g., using underscore) and what the constructor (`__init__`) should do.
**Example**: "Create a class named `Trie`. It must have an `__init__(self)` method that initializes the root. It must have an `insert(self, word: str) -> None` method. It must have a `search(self, word: str) -> bool` method."
**Why it works**: Without this precision, models may generate methods with slightly different names (`add` vs `insert`) or missing parameters, causing instant test failure when the grader tries to call the defined interface.
