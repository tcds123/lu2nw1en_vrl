State Technical Constraints Without Prescribing Algorithmic Details

**When to apply**: When the problem requires efficient solutions (e.g., "optimal solution," "large inputs") or has specific resource limits. When you need to guide the model's complexity choice without dictating its internal structure.
**What to do**: Clearly specify the required time and/or space complexity (e.g., O(n log n), O(1) extra space). Avoid naming specific algorithms (e.g., "use quicksort") or data structures (e.g., "use a heap") unless absolutely necessary. Frame the constraint as a requirement for the solution's performance.
**Example**: "The solution must run in O(n) time and use O(1) additional space, not counting the output. Do not describe how to achieve this; just ensure the implemented code meets these constraints."
**Why it works**: Provides a clear optimization target for the model's reasoning without over-constraining its implementation path. This prevents confusion where the model might output a description of the algorithm instead of the code, or might reject valid alternative approaches that also meet the complexity bounds.
