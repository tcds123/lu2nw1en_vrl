Give Concrete Instructions on Core Logic and Edge Cases

**When to apply**: When the problem has subtle failure points, specific input domains (empty lists, negative numbers, single-character strings), or non-obvious core operations that must be handled.
**What to do**: Directly state the key logical operation and enumerate the critical edge cases to handle. Use plain language and avoid abstract metaphors (e.g., don't say "navigate the data landscape").
**Example**: "The core logic should convert each character to its ordinal value and sum them. Handle the edge cases of an empty input string (return 0) and very long strings efficiently."
**Why it works**: Models can generate code that passes for common cases but fails on boundaries. Explicitly mentioning edge cases primes the model to include necessary conditionals (e.g., `if not s: return 0`). Concrete language prevents misinterpretation of vague requirements.
