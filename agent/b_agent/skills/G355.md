Explicitly State Algorithm, Validation, and Error-Handling Requirements

**When to apply**: For algorithmic functions where the approach, robustness, or failure mode is critical. This is essential for recursion, specific time/space complexity, or strict input validation.
**What to do**: Directly command the model to use a specific algorithmic approach (e.g., "use a recursive divide-and-conquer method"). List all validation rules (e.g., "check that n is a positive integer"). Specify how to handle invalid input (e.g., "raise a ValueError with a descriptive message").
**Example**: "Implement `binary_search(arr, target)` using an **iterative** approach (not recursive). Validate that `arr` is sorted in ascending order; if not, raise a `ValueError`. If `target` is not found, return `-1`."
**Why it works**: Without explicit guidance, models default to common, often simpler, implementations that may not meet unstated constraints (like avoiding recursion). Clear validation and error-handling rules prevent the generation of brittle code that crashes on edge cases.
