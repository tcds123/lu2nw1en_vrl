Explicitly State Edge Case Handling Rules

**When to apply**: When the problem has known, tricky boundary conditions (e.g., empty input, maximum/minimum values, special dates like midnight, singular/plural rules). When the "obvious" or common-sense handling is incorrect.

**What to do**: Do not assume the model will infer edge cases. List them explicitly as rules. Use "if/then" statements or a mapping from specific input to specific output. Treat these rules as part of the core specification.

**Example**: "Handle these time conversion edge cases explicitly: `00:00` must become `'12:00 AM'`. `12:00` must become `'12:00 PM'`. `11:59` -> `'11:59 AM'`. `13:00` -> `'1:00 PM'`."

**Why it works**: Models reason from common patterns in their training data, which may not align with specific domain rules (e.g., 12-hour clock conventions). Without explicit instruction, they will apply a statistically common but incorrect transformation to edge cases, leading to subtle bugs that are hard to detect.
