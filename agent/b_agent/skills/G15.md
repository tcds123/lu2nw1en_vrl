Operationalize Constraints with Exact Transformation Steps

**When to apply**: When a problem's core logic depends on a specific normalization, comparison, or preprocessing step that is easy to overlook or implement inconsistently (e.g., case-insensitive comparison, ignoring punctuation).
**What to do**: Translate abstract requirements into concrete, actionable steps within the prompt. Specify the exact method or function to use for the transformation and where to apply it.
**Example**: "Before checking for duplicate words, normalize each word by converting it to lowercase using `.lower()` and stripping leading/trailing whitespace with `.strip()`. Comparisons should be made on these normalized forms."
**Why it works**: Models might understand the requirement ("case-insensitive") but implement it incorrectly or inconsistently (e.g., using `casefold()` in one place and `lower()` in another). Providing the exact operational step ensures uniformity and prevents subtle bugs.
