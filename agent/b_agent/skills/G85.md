Prioritize Functional Correctness and Test Passing Over Minor Optimizations

**When to apply**: When the primary goal is to pass a set of test cases (especially hidden ones), and stylistic preferences or micro-optimizations are secondary. Use to prevent the model from over-engineering a brittle solution.
**What to do**: Instruct the model to focus on correctness for all specified edge cases. State that readability and minor performance improvements are acceptable only if they do not risk failing the tests.
**Example**: "Your solution must correctly handle all edge cases, including an empty input list and a list of length one. Prioritize a correct, straightforward solution over an overly clever or complex one that might be error-prone."
**Why it works**: Models sometimes produce "clever" one-liners or atypical algorithms that are efficient but fail on edge cases. This instruction steers the model toward robust, testable logic as the primary objective.
