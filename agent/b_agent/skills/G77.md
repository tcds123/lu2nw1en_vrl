Maintain a Single Source of Truth for Core Requirements

**When to apply**: When the prompt contains multiple sections (e.g., background, examples, instructions). When there's a risk of repeating a requirement with slight variations.
**What to do**: State the core requirement once, clearly and authoritatively. If you need to elaborate, refer back to that single statement (e.g., "as specified above"). Do not rephrase key specs in different parts of the prompt unless you are providing an example.
**Example**: "Core Requirement: The function `merge(a, b)` must return a new sorted list containing all elements from both input lists `a` and `b`, which are themselves sorted. [Later in prompt] Remember, as per the core requirement, the inputs are guaranteed to be sorted, so your algorithm should leverage this."
**Why it works**: Models can detect inconsistencies. If a requirement is stated differently in two places (e.g., "sorted list" vs. "ascending order"), the model may become confused about which to prioritize, potentially leading to logic that tries to satisfy a non-existent, conflated requirement.
