Focus on Core Functionality, Not Example Usage

**When to apply**: When the prompt starts describing sample inputs/outputs in a way that could be misinterpreted as part of the function's *implementation* (e.g., "print the result").
**What to do**: Specify the function's signature, its core transformation logic, and its return value. If you must give an example, label it clearly as "Example I/O" and separate it from the implementation instructions.
**Example**: "Write a function `count_vowels(s: str) -> int` that returns the number of vowels (a, e, i, o, u) in the input string, case-insensitively. [Example: For input `'Hello'`, the function should return `2`.]"
**Why it works**: Models can literally incorporate example formatting (like `print(2)`) into the code. By isolating the example as a specification of behavior rather than an implementation step, you guide the model to produce a clean, reusable function that returns a value, as opposed to a script that prints a specific case.
