Ensure System Prompt Specification Matches Original User Requirements Exactly

**When to apply**: When you are acting as a translator or refiner of a user's problem statement. This is a meta-skill for prompt construction to prevent introducing errors at the source.
**What to do**: Compare the final system prompt line-by-line with the original user requirements. Remove any constraints, examples, or assumptions you added that are not present in the original. Ensure the core task is preserved without contradiction.
**Example**: (Original User Request: "Write a function to add two numbers.") The system prompt should be: "Write a function `add(a, b)` that takes two numbers `a` and `b` and returns their sum." It should NOT be: "Write a function `add(a, b)` that takes two integers and returns their sum, and also prints a log message." (The type restriction and logging were added).
**Why it works**: Prompt engineers often unconsciously add "helpful" constraints or elaborations. This can change the problem, leading the model to solve a different, harder, or incorrect task than the user intended, causing solution rejection.
