Forbid Common, Subtle Implementation Pitfalls

**When to apply**: When the required approach has well-known, easy-to-make mistakes that would break the solution (e.g., mutable default arguments, shallow copies, integer overflow, off-by-one errors in a specific pattern).
**What to do**: Identify the one or two most critical pitfalls specific to the problem and approach. Issue a clear, direct prohibition against them. Reference the exact erroneous pattern to avoid.
**Example**: "When implementing the memoization dictionary, pass it as an argument or use a closure. Do not use a mutable default argument (e.g., `def f(n, memo={})`), as this leads to incorrect behavior across multiple calls."
**Why it works**: Models can reproduce common bug patterns seen in training data. Explicitly calling out these "anti-patterns" acts as a strong negative signal, steering the model away from a correct-in-logic but flawed-in-practice implementation that would fail subtle tests.
