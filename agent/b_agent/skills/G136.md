Specify Functional Requirements, Not Implementation Steps

**When to apply**: When the problem has specific behavioral constraints (e.g., case-insensitivity, sorting order, treatment of special values) but the implementation approach should be left to the model's reasoning.
**What to do**: Clearly state *what* the function must do in terms of inputs, outputs, and rules. Use phrases like "must handle", "should ignore", "is considered invalid". Avoid phrases like "use a loop to...", "implement a stack", or "first check for X, then do Y".
**Example**: "Write a function `is_anagram(s1: str, s2: str) -> bool`. The comparison must be case-insensitive and must ignore any whitespace characters. An empty string is only an anagram of another empty string."
**Why it works**: Over-prescribing the algorithm can lead to suboptimal or incorrect code if the model misinterprets a step. By stating the "what", you allow the model to select the most appropriate and idiomatic implementation, leading to more robust and creative solutions.
