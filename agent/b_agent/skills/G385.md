Mandate a Simple, Explicit Example in the Docstring

**When to apply**: For all function-generation tasks. A concrete input-output example in the docstring is the most effective way to communicate expected behavior, especially for functions with complex logic, edge cases, or non-obvious transformations.

**What to do**: Require that the generated function's docstring includes a `>>>` (doctest) example or a simple `Example:` section. Specify the exact example input and the expected output. This grounds the abstract requirement in a concrete test case.

**Example**: "The function's docstring must include a simple example demonstrating its use. For example: `>>> capitalize_alternating('hello world')` `'HeLlO WoRlD'`"

**Why it works**: Models understand concrete examples better than abstract descriptions. Providing an example in the prompt and requiring its inclusion in the output forces the model to internalize the correct behavior. It also serves as immediate, inline documentation and a basic test for anyone using the generated code.
