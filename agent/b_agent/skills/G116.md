Balance Detail with Brevity to Prevent Distraction and Drop-off

**When to apply**: When the problem description is long or has many edge cases; when initial model responses are verbose or include irrelevant commentary; when you need to specify constraints without writing a novel.
**What to do**: Prioritize the core logic, inputs, and outputs. State constraints as bullet points or short clauses, not as narrative. Omit obvious implementation steps (e.g., "iterate through the list") unless the algorithm itself is the requirement.
**Example**: "Write a function `find_duplicate(nums: List[int]) -> int`. Constraints: `nums` has `n+1` integers from 1 to `n` (inclusive), exactly one duplicate. Must use O(1) extra space and less than O(n²) time. Do not modify `nums`. Return the duplicate value."
**Why it works**: Code generation models can get lost in verbose instructions, leading to partial generations or off-topic code. This focuses the model's attention on the critical, non-negotiable aspects of the solution, reducing cognitive load and generation errors.
