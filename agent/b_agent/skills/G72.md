Mirror Original Problem Features Faithfully

**When to apply**: For any problem restatement. Especially critical for nuanced features like "non-negative integers" (including zero), "distinct" elements, or "up to k times."
**What to do**: Copy key phrases from the original problem statement verbatim when describing functional requirements. Do not paraphrase conditions that affect logic. Double-check that all nouns, adjectives, and numerical bounds are preserved exactly.
**Example**: "Given an array of integers `nums` and an integer `k`, return `true` if there are two *distinct* indices `i` and `j` such that `nums[i] == nums[j]` and `abs(i - j) <= k`. The original problem states *distinct indices* and *less than or equal to k*."
**Why it works**: Models are sensitive to wording. Changing "distinct indices" to "two positions" might allow `i == j`. Changing "less than n" to "up to n" changes inclusivity. Faithful copying prevents introducing subtle logical errors through misinterpretation.
