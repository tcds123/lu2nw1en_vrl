Define Representation for Empty Structures

**When to apply**: For problems involving optional or potentially empty inputs like trees, graphs, or lists. When the base case is a critical part of the algorithm.
**What to do**: Explicitly state the valid representation for "empty". For functions, specify the return value for empty input. Use the same terminology as the problem's likely test harness.
**Example**: "The input `root` may represent an empty tree. In this context, an empty tree is represented by `None`. Your function should handle `root = None` by returning an empty list `[]`. Do not assume the input will be an empty list `[]`."
**Why it works**: Without this, a model might write code that assumes a non-empty structure, leading to `AttributeError` (e.g., `root.val`) when `root` is `None`. Or it might treat `[]` and `None` interchangeably, causing type errors or incorrect logic for the empty case.
