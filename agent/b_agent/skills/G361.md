Output Only the Function Definition with Docstring

**When to apply**: When the generated code needs to be integrated into a larger codebase or when test suites/example usage provided by the model create clutter and potential syntax errors.
**What to do**: Explicitly instruct the model to exclude all supporting code, test cases, and narrative explanations. Specify that the output should be a single, self-contained function or class definition, including a descriptive docstring, and nothing else.
**Example**: "Write the `calculate_statistics(data)` function. Your output must be *only* the Python function definition, including its docstring. Do not include any example calls, print statements, test data, or explanatory text."
**Why it works**: Models often "show their work" by generating driver code to demonstrate functionality. This instruction filters out that demonstration layer, delivering the precise artifact needed for development, reducing copy-paste errors and extraneous output.
