Mandate a Clean Output and Prohibit Extraneous Elements

**When to apply**: When the required output is a specific data structure (e.g., a list, an integer, a string) and not a full program, or when any additional printing or logging would corrupt the result for an automated judge.
**What to do**: Command the model to return or output *only* the final result. Explicitly forbid common extraneous elements like debug prints, progress logs, or interactive input prompts. Do not specify how to compute the result.
**Example**: "The function must return only the longest palindromic substring as a string. Do not include any `print()` statements or request user input within the function."
**Why it works**: Code generation models, especially when trained on tutorial code, often include illustrative prints or input statements. A direct prohibition prevents this, ensuring the function's output is pure and testable.
