Provide Optimization Direction While Preserving Implementation Flexibility

**When to apply**: Similar to G126, but broader. Use when you need to guide the model's problem-solving approach—such as suggesting a two-pointer technique, dynamic programming, or a specific mathematical insight—without dictating the exact loop structure or state management.
**What to do**: Give a high-level strategic hint that points toward an efficient solution family. Use phrases like "consider using...", "aim for an approach that...", or "the solution should leverage...". Avoid imperative sequences like "first declare a hash map, then iterate...".
**Example**: "Write a function `max_area(height)` to solve the 'Container With Most Water' problem. The solution should use a two-pointer approach to achieve O(n) time complexity. Do not use a brute-force O(n^2) check of all pairs."
**Why it works**: Overly prescriptive instructions can confuse the model's code generation, causing it to mismatch variable names or logic flow. Providing directional guidance aligns the model's internal knowledge with the desired solution pattern, resulting in correct and efficient code that still feels natural.
