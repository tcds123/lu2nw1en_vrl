Precisely Restate Boundary Conditions

**When to apply**: When the problem involves numerical ranges, array indices, or inclusive/exclusive bounds (e.g., "0 <= i < n", "positive integer", "up to and including").
**What to do**: Identify all boundary-related phrases in the original statement. Restate them using identical mathematical or logical terms. Pay special attention to "less than" vs. "less than or equal to" and the handling of empty collections or zero values.
**Example**: "The original problem says: 'for indices i where 0 <= i < len(arr)'. This means the starting index is 0 and the last valid index is `len(arr)-1`. Ensure your loop uses `< len(arr)` and not `<= len(arr)`."
**Why it works**: Code generation models can produce off-by-one errors if boundary language is imprecise. A model might interpret "up to n" as `range(n)` (exclusive) or `range(n+1)` (inclusive) based on subtle cues. Precise restatement eliminates this ambiguity.
