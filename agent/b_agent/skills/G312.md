State core functional requirements (e.g., use recursion, validate inputs, handle base cases) as direct, concise bullet points or short sentences, not buried in abstract prose.

**When to apply**: When the task has 2-5 critical, non-negotiable implementation details that are easy for a model to overlook if phrased narratively.
**What to do**: After the initial command, list the key requirements using a dash (`-`), asterisk (`*`), or numbered list. Keep each point to one line. Avoid embedding them in paragraphs of explanation.
**Example**: "Write a recursive function `fibonacci(n)`.
- Validate that `n` is a non-negative integer; raise `ValueError` otherwise.
- Implement the base cases: F(0) = 0, F(1) = 1.
- For n > 1, return F(n-1) + F(n-2)."
**Why it works**: Models are adept at parsing list structures and interpreting each item as a separate requirement to fulfill. Burying requirements in prose increases the risk of the model missing one, as it might summarize or rephrase the paragraph instead of extracting all discrete commands.
