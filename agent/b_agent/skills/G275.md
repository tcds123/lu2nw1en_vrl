State Core Task and I/O Behavior First, Before Constraints

**When to apply**: For all prompts. This establishes the primary objective before layering on additional rules, making the prompt easier for the model to parse.
**What to do**: Begin the prompt with a simple, declarative sentence that summarizes the function's job. Immediately follow with the expected input parameters and output type/format. Only after this foundation is set should you add constraints, performance requirements, or stylistic notes.
**Example**: "Write a function `flatten_dict` that takes a nested dictionary and returns a flattened version. Input: a dictionary where values may be other dictionaries or primitives. Output: a single-level dictionary with composite keys. Now, add the following constraints: use a dot '.' as the separator for keys, and do not mutate the original dictionary."
**Why it works**: Models process prompts sequentially. Leading with the core task anchors the model's understanding. If you start with constraints (e.g., "don't use recursion"), the model may struggle to infer what the actual goal is, leading to a solution that meets the constraints but solves the wrong problem.
