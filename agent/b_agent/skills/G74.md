Explicitly Prohibit Unrequested Functionality

**When to apply**: When the solution should be a pure function or a specific module. When extra print statements, logging, input prompts, or feature creep (like adding a counter or a GUI) would break automated grading.
**What to do**: Give a direct, imperative instruction to implement *only* what is asked. List common types of unrequested additions to avoid. Command the model not to create any additional helper functions, classes, or output unless explicitly required.
**Example**: "Implement only the `calculate_score(data)` function. Do not add any `print()` statements, input solicitation (`input()`), logging, or visualization. Do not create additional functions like `main()` or helper classes unless the logic absolutely requires it for clarity within the single function."
**Why it works**: Models often default to creating executable scripts with `if __name__ == '__main__':` blocks or add debug prints, which can cause grading systems to misinterpret the output. An explicit prohibition anchors the model to a minimal, correct implementation.
