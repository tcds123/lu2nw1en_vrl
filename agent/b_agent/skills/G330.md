Prioritize Concise, Testable Instructions Over Abstract Framing

**When to apply**: When prompts become wordy, philosophical, or sound like a lesson plan rather than a specification. This is crucial for getting direct, functional code.
**What to do**: Strip out pedagogical language ("imagine you are...", "the goal is to understand..."), abstract metaphors, and verbose justifications. State requirements as clear, testable assertions.
**Example**: Instead of: "Embark on a journey to explore the tree of knowledge, carefully contemplating each node to extract its essence..." use: "Perform an in-order traversal of the binary tree and return a list of node values."
**Why it works**: Ornate or abstract language dilutes the signal. Models respond best to direct, imperative statements that resemble function docstrings or problem statements from competitive programming sites, which are heavily represented in their training data.
