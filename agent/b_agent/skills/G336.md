Provide Clear Algorithmic Constraints, Not Low-Level Specifications

**When to apply**: When the solution must meet performance guarantees (O-notation) or work within resource boundaries (memory), but the exact implementation details are flexible.
**What to do**: State the required time and/or space complexity. Define the allowed input boundaries and any key implementation constraints (e.g., "in-place", "use constant extra space"). Avoid prescribing variable names, loop types (for/while), or other minutiae.
**Example**: "Find the duplicate number in an array of integers where numbers are in the range [1, n]. The solution must run in O(n) time, use only O(1) extra space, and must not modify the original array."
**Why it works**: Overspecifying low-level details is restrictive and can lead to unnatural code. By focusing on constraints, you guide the model toward the correct algorithmic family (e.g., Floyd's Tortoise and Hare for the above) while allowing it the flexibility to generate idiomatic, well-structured code within those bounds.
