Prioritize correctness constraints over unspecified stylistic preferences.

**When to apply**: When the problem statement specifies functional requirements (input/output, immutability, time/space complexity) but does not mandate specific styles (e.g., using list comprehensions, avoiding loops, specific variable naming beyond clarity).
**What to do**: In the prompt, explicitly list the non-negotiable constraints first (e.g., "must not modify the input list", "O(n log n) time complexity"). Avoid adding subjective style rules like "use a lambda here" or "make it a one-liner" unless they are part of the original problem.
**Example**: "The solution must handle duplicate values correctly and must run in O(n) time with O(1) extra space. Do not modify the input array. Prioritize meeting these constraints over any particular coding style or idiom."
**Why it works**: Models can over-index on common stylistic patterns seen in training (like always using list comprehensions), which can sometimes violate core constraints (e.g., by creating a new list when in-place modification is required). This instruction aligns the model's priority with the evaluator's.
