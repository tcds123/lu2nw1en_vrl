Ensure Absolute Consistency Between Core Requirements and Examples

**When to apply**: When providing example inputs/outputs, docstring templates, or test cases. When the problem description includes specific formatting or edge-case behavior that must be mirrored exactly.
**What to do**: First, state the core functional requirement in plain language. Then, ensure every provided example, test case, or docstring template strictly adheres to that requirement. If examples show a specific output format (e.g., returning a list vs. a tuple), explicitly state that the function must match that format.
**Example**: "Write a function `clean_string(s)` that removes all non-alphabetic characters and converts the result to lowercase. For example, `clean_string('He12llo, Wo_rld!')` must return exactly `'helloworld'` (a single string, no spaces). Your implementation must produce identical output for the same logic."
**Why it works**: Code generation models often treat examples as loose illustrations rather than strict specifications. This prevents the model from generating code that meets the abstract goal but deviates in the exact output format or edge-case handling shown in the examples.
