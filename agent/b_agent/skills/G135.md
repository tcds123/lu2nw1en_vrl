Forbid Extra Output: Strictly Limit Output to the Requested Function Code

**When to apply**: For all code-generation tasks where the output will be directly evaluated, tested, or integrated into a larger codebase. Especially critical for automated testing pipelines.
**What to do**: Issue an explicit, unconditional command that the model's response must contain ONLY the final code block (e.g., a function or class definition). Prohibit any print statements for demonstration, example usage, explanatory text before/after the code, or markdown formatting like ```python.
**Example**: "Output only the final, executable Python code for the requested function. Do NOT include any print statements, example calls, 'here is the solution' text, or markdown code fences. The entire response should be the code itself."
**Why it works**: Code generation models are often trained on instructional data that includes examples and explanations. Without this strict instruction, they frequently add "helper" text or demonstration code, which breaks automated evaluation scripts and requires manual extraction of the solution.
