Separate Coding Standards from Demonstration Steps

**When to apply**: When you require production-quality code (with docs, error handling) but also need to specify how the function will be validated or demonstrated in the prompt itself.
**What to do**: First, define the coding standards (e.g., "Include a Google-style docstring," "Validate all input parameters," "Make functions modular"). Then, in a separate section, specify any demonstration or validation steps, if absolutely necessary.
**Example**: "Coding Standards: 1. Include a comprehensive docstring with Args/Returns. 2. Raise `ValueError` for invalid inputs. 3. Write helper functions if logic becomes complex. Task: Now, implement a function to factorize a number into its prime components."
**Why it works**: Intermixing standards with logic (e.g., "validate input, then calculate, then print for the example of 15") leads the model to hardcode the demonstration. Separating them establishes the standards as global, invariant rules for the code's structure, resulting in a clean, professional implementation independent of any test case.
