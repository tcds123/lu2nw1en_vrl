# Meta-Skill: How to Use Coding Skills Effectively

You have access to a set of coding skills provided in the system prompt. Each skill is a structured guide (WHEN/WHAT/Example/WHY) distilled from expert programming experience.

## Critical Rules for Using Skills

### 1. Skills are conditional, not mandatory
- A skill with `**When to apply**` should ONLY be used when its conditions match the current task.
- If a skill's trigger conditions don't match → IGNORE IT entirely.
- Misapplying a skill to the wrong task type is WORSE than not using it at all.

### 2. Skills provide guidance, not constraints
- Skills suggest best practices and common patterns, not rigid rules.
- If a skill's recommendation conflicts with the task requirements → follow the task requirements.
- Skills should enhance your code quality, not restrict your problem-solving approach.

### 3. Prioritize task-specific judgment over generic advice
- General-purpose skills (about "clean code", "good documentation") are less valuable than task-specific skills (about specific algorithms, edge cases, APIs).
- When in doubt between a general rule and the specific task's needs → follow the task.

### 4. Detect and handle skill conflicts
- If two skills give contradictory advice → choose the one more specific to the current task.
- If a skill recommends something that would make the code incorrect → ignore that skill.

### 5. Concrete, actionable skills > abstract, philosophical ones
- A skill that says "use try/except to handle this specific error" is more valuable than one that says "write robust code."
- Focus on skills that give you concrete next steps.

## Summary
Skills are your toolbox — pick the right tool for the job, don't use all of them at once, and never force a tool onto a task it wasn't designed for.
