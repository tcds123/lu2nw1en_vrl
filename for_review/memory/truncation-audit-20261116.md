# 截断样本审计: 24/557 的真面目 (2026-11-16)

> issue #71 · 数据: `for_review/outputs/paired_five_arm_20261113/run1/` (30 题 × k=20 × 2 seed × 5 臂 = 6000 样本, errors=0)
> 工具: `for_review/code/tools/audit_truncation.py` (零 API), `replay.py` / `pareto.py`

## 起因

用户追问「直接统计所有截断的情况, 看是否和正确答案一致, 不就知道是否能够推断截断一定错了」。按字面做: **557 条截断, 其中 pred == 真值 24 条 = 4.31%**。数字准确。

## 为什么这个 4.31% 不能读成"截断却答对"

`eval_aime24_multiseed.py:108-111` `extract_int_answer` 的第 3 级兜底 = **全文最后一个整数**。截断 = 答案没写出来 → 兜底只能抓推理中间的小整数。

| 证据 | 数值 | 说明 |
|---|---|---|
| 截断样本 pred 集中于小整数 | \|n\|≤20 占 56.9%~75.0% (各臂) | 未截断样本几乎不发生 |
| 同题对照 `aime24:78` | 未截断 pred 181/182 = **23**; 截断 pred 众数 = **1** (7 次) | 抽取路径改变 |
| 同题对照 `aime24:88` | 未截断 145/159 = **127**; 截断众数 = **3** (7 次) | 同上 |
| 同题对照 `aime24:89` | 未截断 189/193 = **902**; 截断众数 = **902** (3 次) | 短答案题 → 兜底必然撞值 |
| 合成文本 `"Case 1: n=1 gives 4. Case 2: n=2 gives 9. Case 3: n=3"` | 抽出 **1** | 兜底行为确认 |

## 结论

- 「截断一定错」**经现有数据检验后仍成立**, 但它**从未被单独测量过**: 一直成立是因为兜底很少撞上真值。
- 24 条中真正的"截断前已交付答案"必须靠**显式标记**判 (`<answer>` / `\boxed` / 尾窗 1200 字内 `Answer: N`), 不能用"抽到的数恰好等于真值"。
- 我此前说"4.31% 是口径产物"**用词过强**: 数字不假, "答对"才是误读。

## 三态判读口径 (后续实验统一)

| 类 | 判据 | 含义 |
|---|---|---|
| A | 截断前有显式答案标记且 pred==真值 | 真"提前交付", 唯一算"截断却答对"的类别 |
| B | 无任何显式标记 | 含兜底假阳性 (当前 44~64 条/臂) |
| C | 残文里连真值都没有 | 纯无产出 |

零 API 初筛 (无全文, 只能代理): A 候选 0~3 条/臂, B 44~64 条/臂, C 0 条/臂。**硬结论待阶段 1 落全文 + `extract_strict()`。**

## 教训

1. "和正确答案一致" 必须先证明答案**从哪里来**; 抽取器松时, 一致性检验系统性偏乐观。
2. 判读任何指标前看**同题分布**: 截断 pred 众数 ≠ 未截断众数 = 抽取路径变了。
3. 用户的"直接统计"思路正确, 只差一步 —— 统计**有显式标记**的截断样本。
