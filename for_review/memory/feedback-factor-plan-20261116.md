## 二、零 API 回放 (5 臂 6000 样本, 严格计分) 的关键数字

- 相对 none_seed1 (逐题配对, 题级 bootstrap 4000):
  - d1 +6.17pp [+1.2,+11.7], **净答对长度 +471 tok [+124,+839]** (显著变长)
  - d2 (s1) +8.50pp [+3.3,+14.7], 长度 +405 [−83,+1064]
  - s0 (s1) +4.50pp [+0.8,+8.8], **长度 +557 [+65,+1203]** (显著变长)
  - d3 长度 −127~−264 tok (唯一压长度), 但 pass +1.8~2.0pp CI 含 0
- 纯长度变化题 (FL) 5~11 题/臂; 纯截断变化但 pass 不变 (TR_pass) 仅 0~2 题/臂。
- 结论: 池里**没有**「又准又短」的现成候选; 现有 skill 走的是「更长的对」。

## 三、设计决定 (含模拟证据)

1. **否掉** λ 加权与学分制: 假学分 d=+1 可伪造 +0.147 delta, 真 optimum +0.367 → 空转技能白拿 40%。
2. **采用** 逐样本三态 (PASS_CLEAN / FAIL_CLEAN / BUDGET) + 逐题预算指示器 1/0.5/0 + **两道硬门**:
   - 门1 正确率非劣 (δ_acc = −1pp, 同 k / 同 cap / 同 prompt);
   - 门2 效率改进 (共同 PASS_CLEAN 子集, 配对净长度 CI 上界 <0 且点估计 ≤ −15%)。
   双门同时成立 → ACCEPT; 单门 → 进 Pareto 池 (多样性来源, 留 ≥2 点)。
3. 循环 (`tail_loop≥5`,`cycle_reps≥5`) 作**准入判据 + 分诊标签**, 不作得分项。
4. 记账 6 个数永不合成: strict_pass / trunc_rate / clean_pass_tokens_p50 / clean_fail_tokens_p50 / loop_rate / n_B_calls (输入+输出, 认领 skill 长度成本)。

## 六、待用户裁定的 4 个决策点

1. δ 取值: 建议 acc ≥ −1pp 且长度 ≤ −15% (备选 −0.5pp/−20%、0/−30%)。
2. 主战场: 建议 AIME24+25 60 题 pilot → 判否转 MBPP Pro 150; 备选直接上 MBPP Pro。
3. 是否现在就改 `run_one` / `paired_five_arm_v1.py` 的严格计分 (历史数字变化 ≤0.6pp, 需重算 5 臂与 cap 扫描表)。
4. 阶段 2 进化轮数: 2 轮 (≈1800) vs 4 轮 (≈3600)。
