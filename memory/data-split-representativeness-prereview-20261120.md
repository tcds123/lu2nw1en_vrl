# 数据划分代表性预审 (Train 80 / Val 100 / Test 2765) — 2026-11-20

用户提出研究设计风险: 80 训练题 → Skill 学习 → 2765 独立测试题, 训练规模与代表性是否足够未经论证。
本篇 = **审计第 0 步 (静态数据, 0 API)**, 主 run 继续不中断。完整审计脚本化见"后续"。

## 事实 (已核实, 不含推断)

### 口径与来源

| 口径 | 实际数量 | 来源 |
|------|---------|------|
| 原始训练集 | **80** | `appsplus_capped_seed42/train/items.json` = seed42 ratio-split train 790 题的**前 80 个**(`split_manifest.json` note) |
| 原始验证集 | **395** (非 100) | `val/items.json`; 脚本/训练取 val 前 **100** 题做候选选择 |
| 训练池 (实际参与 Evolver) | **27** | `train_s0_cache.json`: 80 题 S₀ hard=53/80 → fail pool 27 题 (trainer 取前 27) |
| 测试集 | 2765 | = seed42 ratio-split test **全集** (7000 题中 70%) |

- seed42 官方划分 2:1:7 (790/395/2765), 三者 **ID 交集全 0**, 同源 `APPS_Plus/data/v1`。
- 测试集不是"从 7000 里另抽 2765"而是 test 全集 → 测试集规模本身不是设计缺陷 (用户第 3 点同意)。
- 切分方式差异: train/val 是 train 池的**前 N 个**(按 ID 顺序截断), test 是随机划分的**全集**。

### 分布对比

| 维度 | Train 80 | Train fail 27 | Val 395 (用 100) | Test 2765 |
|------|---------|---------------|------------------|-----------|
| difficulty | interview 100% | 100% | 100% | 100% (无区分度) |
| stdin | 72.5% | 44.4% | 76.5% | **77.2%** |
| func (裸函数) | 17.5% | **25.9%** | 12.2% | **13.4%** |
| class Solution | 10.0% | **29.6%** | 11.4% | **9.4%** |

- fail pool 中 class 题 8/27 全失败 (S₀ 对 class 题通过率 0/8), 而 test 中 class 仅 9.4% → 训练信号大量集中在测试中占比最小的题型。
- 关键词粗分类 (粗糙, 仅作量级参考): DP 1.0–3.7%、greedy 0.7–1.3%、graph 5.8–7.5%, train/val/test 大致一致;
  fail 27 中 binary-search 类占 11% vs test 1.5% (小样本, 不稳健)。
- 题面长度中位数 (字符): train 1621 / val 1531 / test 1627; raw_solution 中位数 533/495/493 → size 维度一致。

### 重复与近重复

- 精确重复 (id、题面规范化): 0 (三划分内与跨划分)。
- 近重复: 抽样核验 120 个 quick_ratio>0.9 的候选, 7 个真重复 (real ratio>0.8), **全部指向同一 train 题 3953**:
  CodeChef 文档不完整时**同一题面文本配不同 sample I/O** 被当成多题入库 (3953 vs test 6464 等)。

  不是"独立新题泛化"; 报告措辞需相应限定。全量近重复计数待脚本化 (451 个候选未全核验)。

### 统计可行性 (关键)

以 test 全量 n=2765 检测净增益率 3pp ≈ 83 题 (δ=0.03) 的配对功效:
- 假设总不一致对比例 25% (乐观) 需 n≈425; **保守 5% (Arm1 vs S₀ 实测: 16/300≈5.3%) 需 n≈2480**。
- 当前 300 题主结果的 CI 宽约 ±10pp, 正是该原因的必然结果 → **补 2765 有实质必要, 当前 run 应继续**。
- 子组功效 (3pp, 乐观假设): 需 stdin≈3000 (有 2134)、class≈1360 (有 260)、func≈1670 (有 370) →
  **按题型子组分析不可行**; 子组最多做描述性报告。

### 验证集

- 100/395 题: 单次配对比较 3pp 位移的检出概率约 10% (乐观不一致率假设) → **多轮 Skill 选择几乎无分辨力**,
  候选选择受抽样噪声支配 (与 Arm1/Arm3 val delta 0.04–0.11 的抖动形态一致)。
- 但 Skill 作用于测试是**固定文本**、不按通过率选择 → val 噪声不影响 test 指标无偏性, 只影响"选出的是��运气还是好 skill"。

## 判读 (供用户决策, 不含夸大)

1. 用户质疑成立: 27 道有效失败反馈题 (其中 8 题 class) 支撑 2765 题泛化结论, 代表性未论证。
2. 但补 2765 是正确且必要的: 即使 Evolver 无增益, 需要 2765 才能以 δ=3pp 判无增益; 当前 run 继续。
3. 训练规模扩展实验 (80/160/320) 需先决定分型: 等方差 (8 题/次) 还是等臂 (27 题/次, 1 次扫 3 个规模)。
4. 3500 级候选池 (790 train + 395 val) 中有效题仅 185 道 S₀ 失败, class 失败题约 8+11=19 →
   class 方向的天花板很低 (test class 260 题, 增益上限 ~6% 总通过率, 现实得多)。
