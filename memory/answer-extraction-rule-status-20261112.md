# 答案抽取规则 候选测试 (2026-11-12, 未采纳)

## 背景
`extract_int_answer` 先取最后一个 `\boxed{}` (含思考中试算), 再取最后 `<answer>`, 最后全文末整数。
问题: flash 常在思考里写 "\boxed{23} ... 再想想, \boxed{371}" 或先错后对; "最后一个 boxed" 不一定是收尾答案。

## 候选: 末尾窗口内取最大 0~999 整数
在 `/tmp/efl_demo2` 的 26 条完整 trace 上离线比对 (gold 来自 aime24.jsonl):

| 策略 | S0 cache (14题) | baseline (12题) |
|---|---|---|
| 当前规则 (last boxed/answer/末整数) | 8/14 | 7/12 |
| 末尾窗口取最大 ≤999 整数 | 2/14 | 4/12 |

→ **拒绝**. 思考中的大数/试错值远多于真实答案, 该启发式显著更差 (同时会把部分错答"蒙对")。
本轮文本尾显式标记规则 ("Final answer: N") 优于纯末整数兜底 (修复前 74 题被抽错), 保留。

## 待办

  若模型不遵守, 归因到"未按格式收尾"这一行为 facet, 由 evolver 迭代出规则, 而非评测器猜测。
