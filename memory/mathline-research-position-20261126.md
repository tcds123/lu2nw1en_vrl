# 数学线研究定位根本修正（2026-11-26 用户）

## 核心定位 (用户确定)

**论文主要目标 = "Skill 自动进化带来的任务性能提升"**。
推理能力变化、规则可解释性、跨任务泛化 = 不同层次的**补充**研究问题, 非门槛。

## 被纠正的根本错误

我此前把 meta-option 当成"需要排除的问题", 反复要求 LiveMath 证明"去掉捷径后依然有效"——这**偏离了研究核心目标**。

**Why:** 研究是 training-free Skill 自进化。核心问题: Evolver 能否在无人指定优化规则下, 自主发现提高目标模型任务表现的 Skill? meta-option 规则若是 Evolver 自主发现(非人工预埋), 就是**有效的自动优化结果**。事后发现它可用简单字符串匹配实现, **不意味着自动发现它没研究价值**。规则简单 ≠ 自动发现能力简单。

**How to apply:**
- LiveMath **不需要**以"去掉 meta-option 后依然有效"作成功必要条件
- trivial baseline (rule_meta_guess) 回答的是"人类能否手写更好规则", 不是"自动系统能否发现规则"——别用前者否后者
- over S₀ 的真实可重复增益 = 正向结果, 不管来自 meta 还是 not_meta

## 三个结论的区分 (用户)

1. **Skill 自动进化有效** — 若 Evolver 自主找到规律并独立评测稳定增益, 完全构成方法有效性证据。✅ 这是论文主结论
2. **模型数学推理能力提高** — 不能仅由 meta 增益推出, 但**我们不一定需要证明它**。补充问题
3. **Evolver 跨任务泛化能力** — 需其他数据集证据, 不该要求 LiveMath 单独承担。补充问题

## 数学线研究重点 (重排)

**不再问**: 增益是否"真正属于数学推理"?
**改问**:
1. 旧 evolver +16.1pp, 为什么新机制移植后 10 候选 0 晋升? ← **最优先**
2. 新机制是否生成了有效候选却被统计门控拒绝? ← **最优先**
3. 新旧机制同预算下谁更稳定发现/保留有效 Skill?
4. 自动发现能力能否在 AIME/代码任务以其他形式体现?

**关键**: 若新 evolver 生成有益候选却被门控拒绝, 该修的是**评估和选择过程**, 不是要求它放弃 meta 规律。

## 决定性发现 (2026-11-26 零 API, 回答用户问题#2)

**新机制 smoke 候选被拒根因 = 候选效应太小(+0.023), 而 LiveMath 噪声大(σ≈0.114)**, 非"门控过严"。

从 smoke 实际数据反推:
- iter1 Option Comparison: val_delta=+0.023, val_ci=−0.0035, **n=71 总体(含meta, 非子集)**
- 反推 σ_题级 ≈ **0.114** (LiveMath), 是 AIME(0.044) 的 **2.6 倍**
- CI>0 需效应 > +0.0265; +0.023 power 仅 **40%** → 注定跨零

**新旧对比真正落差**:
| | 旧 evolver | 新机制 smoke |
|---|---|---|
| 效应 | +0.161 (+16.1pp) | +0.023 (+2.3pp) |
| power (n=71,σ=0.114) | ≈100%→过门 | ≈40%→跨零被拒 |

旧 evolver 过门因 meta 规律效应**大**(+0.161>>+0.0265检出下限)。新机制候选效应**小一个数量级**, 淹没在 LiveMath 高噪声。**不是门控拒绝有效候选, 是新机制候选效应不足**。门控阈值+0.027 对 +0.161 宽松。真问题=新机制为何没发现大效应候选——smoke 只2轮+train_n=18 不能定论, 需完整 run。

注: "not_meta=27不够"约束只对纯非捷径增益成立。按新定位(含meta), 总体n=71充足, 检出下限+0.027, 旧+0.161轻松过。问题不在n, 在候选效应大小。

## 三处统计判断核实 (2026-11-26, 用户纠偏后零 API 复核)

### 点1: 40% power ≠ "注定跨零" (我此前表述错误, 用户纠正对)
正确含义: 若真实效应=+0.023, 有 **40% 概率过门、60% 概率跨零**。smoke 落在 60% 侧, 但**不能证候选真实效应就是+0.023** — +0.023 是点估计, 真实效应可能更高(+0.04 power=84%), 只是这次抽样偏低。"小效应检出功效不足"成立, "已证候选效应=+0.023"不成立。

### 点2: σ/门槛口径已核实 — 独立单位=题数n=71, 非rollout
bootstrap_ci_lower (tf_global_v2_math.py:719): 先每题 `sum(v)/len(v)` 取题级均值 (per_item[qid]=[d] 单元素, L447) → 在**题级均值**上 bootstrap 1000次 → 2.5分位。eval_k=8 多次采样在进 bootstrap 前已被 `pass_rate=n_pass/k` 均值化 → **未把rollout当独立题** (用户担心没发生)。
- σ=0.114 从单候选单次paired eval反推 (mean=+0.023,ci=−0.0035 → SE=0.0135 → σ=0.0135×√71=0.114)
- 门槛: n=71→+0.0265, n=10→+0.071, n=80→+0.025 (用户算术全对)
- **σ本身有不确定性**: 单次估计, 真实σ可能在0.08~0.15。稳估需多候选per-item, **但per-item未落盘=真实缺口**

### 点3: 新旧+0.161 vs +0.023 不可直接比 (我此前过强, 用户纠正对)
- 旧+0.161: 完整run, in-sample, 旧机制(无paired_rescore)
- 新+0.023: 2轮smoke, 单候选点估计, 新机制, 1个facet
- 评估集/作用范围/指标/预算都不对齐。**只能判"新smoke尚未观察到同等规模收益", 不能认定"新机制候选生成质量下降一个数量级"**。

## 完整run的科学价值 (用户强调)
不取决于是否再达+0.161。复现成功→新机制完整正向证据; 复现失败→只要设计公平+轨迹完整, 同样可定位差异来源(候选生成/搜索空间/数据利用/选择策略)。**不因2轮smoke的0晋升再停这条线**。

## 仍需确认的 (底线)

- 规则确由 Evolver 自主产生, 非人工预埋 (防起点污染, 见 run1 教训)
- 无评测数据泄漏
- 区分优化集增益 vs 独立测试增益 (+16.1pp 是 in-sample 正向信号, 独立泛化需单独确认)
