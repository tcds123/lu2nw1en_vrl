# budget focus 天花板分析 (2026-11-19, run_20261119_140908 复核)

**发现**: run3 budget focus 4 轮命中 3 次但候选全 admitted=false (CI≤0), 根因不是渲染质量 (issue #87 增量 B), 而是**截断信号天花板**。

## 定量 (天花板 = 截断率 × 题数)

- tr = 5.6% × 30 题 = **~1.67 题截断**
- 即使 budget section 救回所有截断题, 可恢复 pass 上限 = +1.67/30 = **+0.056**
- 这与 iter3 budget 候选 delta 峰值 **+0.056 几乎完全吻合** — 机制在 iter3 已触及天花板
- iter4 退回 -0.022 是天花板下的采样噪声 (1-2 题救回与否的硬币翻转)

## 推论

- 天花板 +0.056 在 n=30 下 CI 跨 0 (iter3 下界 -0.033) → **永远过不了 CI>0 门控, 无论渲染多好**
- 截断题多为最难题 (最长 CoT), "早提交"未必答对 → 实际可恢复 < +0.056, 更难显著
- **瓶颈是信号量 (tr 太低 → 天花板太低 → CI 太宽), 非渲染质量**

## 对下一步的修正 (相对 [[trunc-efl-bgt-dual-evolve-launch-20261118]] 已列 2 方向)

- **方向 2 (增强 patcher 截断渲染, #87 增量 B)** 改善候选质量, 但**打不破 tr=5.6% 设的天花板** — 投入产出比存疑
- **更高杠杆: 降 cap 提高截断率**。cap-sweep (2026-11-13, flash): cap=8192 tr~10-12%, **cap=4096 tr~20-22%**。V3.2 在 8192 仅 5.6% (比 flash 紧凑), 4096 待测但必 >5.6%。tr=20% → 可恢复上限 +6/30=**+0.20**, 天花板抬高 ~3.6 倍, budget focus 有更多 failure 累积, budget section 改进更易统计显著
- 或 **增 n** (更多题) 收窄 CI, 让既有 +0.056 变显著 — 但天花板不变, 仍卡在 +0.056 附近

## 建议 (仅建议, 不改代码)

1. 先验证方向 1 (Quantity Parsing +0.100 的 AIME25 跨集泛化) — 这是论文基线是否成立的前提, CI+0.011 较薄, held-out 是真正判据
2. 若决定推进防截断自进化: **优先降 cap 到 4096 (V3.2) 而非先改渲染** — 抬高天花板是解除 CI 门控绑定约束的直接手段, 渲染优化留到信号充足后再做
