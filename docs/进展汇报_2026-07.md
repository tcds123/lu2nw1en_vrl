## 一、研究定位与总体框架

研究主题为 Training-Free GRPO 与提示词及技能（Skill）优化的融合方案，面向代码与数学生成任务的系统提示词优化。核心流水线始终保持不变：A 模型（Qwen3-4B，经 GRPO 训练）生成系统提示词或技能，交由 B 模型（DeepSeek-V3.2 API，冻结）生成代码或解答，再由 C 模型（DeepSeek-V4-Flash，冻结）结合单元测试进行评判打分，所得奖励信号驱动 A 模型更新。其中 A 模型为 Qwen3-4B-Instruct-2507，基于 verl 框架在 8 张 GPU 上训练，输入为问题、参考解与示例，输出为系统提示词或技能；B 模型在第二阶段已升级为具备自进化能力的 BAgent 框架；C 模型的奖励定义为 70% 单元测试通过率与 30% LLM 评判的加权。

研究方向已由"参数空间优化"转向"上下文空间进化"，即在不对模型参数进行梯度更新的前提下，通过优化上下文空间（提示词、技能、记忆的组合）引导模型行为。七月的工作围绕这一转向展开：先在代码域完成严格的判别实验，继而确立方法创新点，最后转向数学试验场，并经历了一次由假阳性到诊断修复再到真实增益确认的关键波折。

### 2.2 代码域的严格判别（07-13 至 07-21）

本阶段的核心是以严格实验否定一个看似可行的方向，为后续转向扫清障碍。全面体检（07-13）显示，从 GRPO 轨迹蒸馏的 402 条技能全部 ATE=0、使用计数为 0，P1 剪枝表明其中 21/30 有害，GRPO 训练停留在 step 637 已两周未推进。Step 1 验证进一步得到双阴性结果：BigCodeBench（n=57）得 p=0.349，MBPP_pro 五组（n=100）全部 p>0.19，技能注入对通过率无收益。在采用 LLM 作为选择器挑选三条技能的 Focused-3 方案中，相对基线仍为 p=0.828 的全阴性结果，由此判定问题不在于挑选策略，而在于技能池质量本身，注入侧的改进空间至此穷尽。

在排除数据污染（LCB 分层显示已见样本 0.708 对未见样本 0.427，信号集中于 hard 题 0.54 对 0.18）后，无污染条件下技能优化仍出现 test −0.7 至 −1.4pp 的过拟合，hard 题零收益，代码单函数域由此判定不可行。值得强调的是，综合调研表明"技能对代码无用"的结论是错误的——综述中 SWE 类工作及 SkillComposer（LCB v6 +2.5）、SePO（MBPP 91.2 至 96.2）等均有正先例。本项目负结果的根因在于通用提示词文本技能、stdin 竞赛题与全量注入三者的组合，而非技能范式本身失效，这一修正为后续在数学域取得正结果提供了方法校准。

### 2.3 创新点确立：GRPO 优化初始技能 S₀（07-21 至 07-22）

经代码域判别，本项目的差异化创新点得以明确：A 模型通过 GRPO 学习改写初始技能 S₀，奖励信号取 delta pass-rate（即 skill_pass 与 s0_pass 之差），以此隔离技能的真实贡献。S₀ 为手写的初始技能文本（如 LCB 版竞赛编程启发式，约 1796 字符），是 B 模型系统提示词的一段，是被优化的对象而非优化器。完整流水线为：A 模型输入 S₀ 与问题，输出改写后的技能；B 模型以改写技能生成代码；C 模型与单元测评判；奖励取改写技能通过率与 S₀ 通过率之差；GRPO 据此更新 A 模型。采用 delta 奖励的原因在于，绝对通过率会被题目难度污染，而 delta 仅衡量技能带来的增量，与 D2Skill 的双 rollout、SkillComposer 的 delta pass-rate 思路一致。为防止 A 模型走捷径原样复制 S₀（delta=0 无负奖励），引入相似度退化检测，当改写结果与 S₀ 相似度高于 0.95 时直接施加下限惩罚，迫使 A 模型进行实质改写。

与同类工作相比，本项目的差异在于优化器与信号形式（见表 2）。SkillOpt 采用 LLM 启发式 rollout-reflect 与绝对通过率，SkillComposer 采用 rejection sampling 与 delta 通过率（非 RL），SePO 采用进化搜索与 LLM 评判相似度（非 RL）；本项目则采用 GRPO 梯度信号与 delta pass-rate，以 S₀ 为起点。即现有工作多用启发式、进化搜索或 rejection sampling，本项目以 GRPO 梯度信号训练 A 模型改写技能，构成核心差异。

**表 2　本项目与同类工作的方法差异**

| 方法 | 优化器 | 信号 | 起点 |
|---|---|---|---|
| SkillOpt | LLM 启发式 rollout-reflect | 绝对 pass | S₀ |
| SkillComposer | rejection sampling（非 RL） | delta pass | per-task |
| SePO | 进化搜索（非 RL） | LLM-judge 相似度 | S₀ |
| 本项目 | GRPO（RL 梯度） | delta pass-rate | S₀ |

07-22 完成端到端冒烟验证：本机单卡 Qwen3-0.6B 上 verl 单步训练完整贯通，A 模型改写技能、B 模型生成代码、LCB 单测、delta 奖励、GRPO 更新全链路打通；hard 题 abc380_g 的 S₀ 通过率为 0，A 模型改写后 B 模型全对，delta>0 成立。过程中修复五个阻塞缺陷，涉及 S₀ 后端、奖励键、提示词过长、test_code 截断以保 delta 可比、以及 return_dict 等。

### 2.5 免训练优化器 v2 与评测噪声问题（07-27 至 07-28）

本节是本月最具方法论价值的部分，记录了一个看似强正的结果如何被复测推翻，又如何经诊断修复后得到真实但更小的正结果。

**v2 优化器的建立。** 07-24 的 TF-global 数学版 test 与 S₀ 持平，被判定阴性。代码级诊断发现 v1 存在六个结构性缺陷：经验池完全卡死（三轮合并输出等于输入）、蒸馏信号为提示词措辞技巧而非失败模式、rewriter 从未见到真实错误、定理与草稿字段未被利用、合成仅为 S₀ 的表层改写、val 门控过弱。其本质是优化器未产出任何 S₀ 尚未包含的信息，致使全局技能退化为 S₀ 的表层改写，强模型表现严格不优于 S₀。此外发现数学域从未建立 trace2skill 基础，现有 402 条经验池为代码域产物，对数学选择题完全无用。据此建立两条互补的免训练全局路径（均与代码域池物理隔离）：路径 A 为离线 trace2skill，新建 `extractor_math.py`，经生成轨迹、按题蒸馏失败模式、跨题合并、追加式合成四阶段，核心设计是反转泛化规则，拒绝提示词措辞技巧与单题答案，仅保留可泛化的数学诊断程序；路径 B 为在线闭环 v2，修复 v1 全部六个缺陷，关键改进为追加式合成（S₀ 原样保留并追加失败模式节，不重写 S₀ 以避免干扰强模型）与 bootstrap CI 门控（95% CI 下界大于 0 才接受，不再接受单题翻转噪声）。07-27 首次结果（test=124）显示，离线 trace2skill 为 0.3548（+2.4pp），TF-global v2 为 0.4839（+15.3pp），SkillOpt-best 上界对照为 0.5161（+18.6pp），当时据此宣布推翻 7-24 关于"global 对强模型无效"的结论。

**表 4　TF-global v2 首次结果与对照（test=124，07-27）**

| 方法 | test acc | Δ vs S₀ |
|---|---|---|
| trace2skill-math（路径 A，离线） | 0.3548 | +2.4pp |
| TF-global v2（路径 B，在线闭环） | 0.4839 | +15.3pp |
| SkillOpt-best（上界对照） | 0.5161 | +18.6pp |

**复测推翻 +15.3pp。** 鉴于项目历史多次出现小样本假阳性（APPS_Plus 07-17 +6pp 至 07-18 全量 −2.1pp），对 +15.3pp 进行三种子复测。结果显示三个种子全部被 CI 门控拒绝，最优技能退回 S₀，+15.3pp 无法重现。

**诊断：两个评测设计缺陷。** 关键证据是四个 run 的 baseline_val（S₀ 现场重跑 val）在 4/18、6/18、7/18 之间波动，而评测端本不应波动。其一为 temp=0 非确定性：DeepSeek-V3.2 网关的 vLLM 后端在 temp=0 下，因 batch 大小变化、并发请求与浮点累加顺序不同，输出不完全可复现，v2 以 8 线程并发跑 val，同一 S₀ 跑出不同结果，delta 混入 ±2 至 3 题的纯评测噪声。其二为 baseline 与 candidate 评测不对称：baseline 单次采样（passes=1），candidate 两次取平均（passes=2），baseline 撞到偏低采样形成虚假低基线，+15.3pp 大概率源于此采样偏差而非真实增益。附带发现 `llm()` 的 temperature 形参从未传入，rewriter、distill、merge 实际均在 temp=0.0 运行，缺乏采样多样性。

**修复。** 采取五项措施：每题采样 k 次投票（EVAL_TEMP=0.3），通过率取通过次数除以 k 为连续值以降噪声；precompute_s0 同样采用 k 投票以与 candidate 对称；baseline 改用 s0_cache 固定快照、不现场重跑，base_delta 置零以消除采样偏差；rewriter 以 GEN_TEMP=0.8 真采样恢复多样性；数据划分改为 1:3:6（train=18，val=53，test=106），val 由 18 扩至 53 使 bootstrap CI 功效约提升三倍，单题翻转影响由 0.056 降至 0.019。

**修复后真实结果。** 07-28 在 test=106、同条件 k=5 投票下，S₀ 为 0.2906，v2 最优技能为 0.3604，增益 +7.0pp。val 端三轮全部接受且单调递增（+0.079、+0.083、+0.098），bootstrap 95% CI 下界分别为 +0.042、+0.045、+0.053，均为正；test 端 +7.0pp，泛化成立（val +9.8pp 至 test +7.0pp，方向与显著性一致）。最优技能为 S₀ 追加八条具体数学诊断条目（量词依赖、逻辑完备性、组件清单、元选项、字面常量、主客体对齐、正则性层级、附加条件），均为 S₀ 原未包含的数学内容，非表层改写。

**表 5　修复后 v2 真实结果（test=106，07-28）**

| 方法 | test pass | Δ vs S₀ |
|---|---|---|
| S₀（seed） | 0.2906 | 0 |
| v2 best skill | 0.3604 | +7.0pp |

**最终定论。** +15.3pp 系评测噪声（baseline 采样偏差）导致的假阳性；修正评测后真实增益为 test +7.0pp，统计显著且可复现。方法本身（TF-global v2 的失败模式蒸馏、追加式合成、CI 门控）有效，训练侧信号能够泛化。对比尤为鲜明：同一方法同一数据，修正前三种子全拒、最优技能退回 S₀，修正后三轮全接受且递增，差异仅源于评测的修正。

### 2.6 当前结论与状态

当前进展可概括如下。其一，A-B-C 流水线与 BAgent 自进化框架已完整。其二，创新点（GRPO 优化 S₀，delta pass-rate 信号）已端到端打通（单卡 0.6B 冒烟，hard 题 delta>0）。其三，免训练 TF-global v2 在数学基准上取得 test +7.0pp 的可复现、统计显著正结果，为当前最扎实的正结果。其四，离线 trace2skill 数学域基础池首次建立（test +2.4pp），与代码域物理隔离。后续待推进的工作包括：修复后 test +7.0pp 的多种子复测、超参扫描与消融；8 卡 4B 正式 GRPO 训练暂缓，当前坚持免训练与 global 形态先行取得效果。此外，API 28 RPM 全局硬限约束实验须串行进行，密钥多次失效待集中管理。

本月最核心的方法论教训在于：两次大反转（07-18 APPS_Plus、07-28 +15.3pp）均源于以非同条件或含噪声的 baseline 进行比较。绝对值必须以同密钥、同模型、同采样重测，delta 信号必须基于同条件对称 baseline，且评测端须以多次投票降低噪声。这一教训已沉淀为后续所有实验的前置规范。

## 三、文献综述与相关工作

依据 Ding et al. (2026) 综述 *Agent Skill Evaluation and Evolution: Frameworks and Benchmarks*（arXiv:2606.11435）及对若干关键论文的精读，梳理如下。

### 3.1 Agent Skill 的形式化与四大进化范式

综述将 Agent Skill 形式化为 S = (C, π, T, R)，即触发条件 C、执行策略 π、终止准则 T、可复用接口 R，具备完整的过程边界。其核心主张是：技能领域正经历从"孤立创建"到"评估驱动的自动化进化"的范式转变，评估与进化是同一持续学习过程的两个面。按学习信号的来源与粒度，进化分为四大范式（见表 6）：执行反馈（步骤级，从执行失败中学习并重写技能）、轨迹蒸馏（序列级，从多条轨迹蒸馏可复用模式）、压缩与增强（库级，消除冗余、合并冲突、探索未覆盖区）、强化学习（任务级，以 RL 优化技能的跨任务复用性）。两条关键设计原则贯穿各范式：批量蒸馏优于单轨迹蒸馏，因需比较多条轨迹方能区分可复用模式与任务特定噪声；持续蒸馏优于一次性蒸馏，技能应作为不断更新的进化记忆体。

**表 6　技能进化四大范式**

| 范式 | 信号源 | 粒度 | 核心思想 | 代表工作 |
|---|---|---|---|---|
| 执行反馈 | 单次运行步骤级 | Step-level | 从执行失败中学习，重写技能 | SkillForge, CoEvoSkills, Skills-Coach |
| 轨迹蒸馏 | 多次运行序列级 | Sequence-level | 从多条轨迹蒸馏可复用模式 | SPARK, Trace2Skill, Memento-Skills, XSkill |
| 压缩与增强 | 库级别结构 | Library-level | 消除冗余、合并冲突、探索未覆盖区 | SkillNet, SkillX, SkillReducer, SkillFoundry |
| 强化学习 | 任务级奖励 | Task-level | 以 RL 优化技能的跨任务复用性 | D2Skill, SkillRL, SkillOS, Skill1 |

### 3.2 关键方法精读与对接点

**Skills-Coach：Training-Free GRPO。** 该方法与本项目最为相关，不依赖 C 模型或梯度更新，将 GRPO 的群组相对思想迁移至技能文本层面：对技能指令生成多个变体，在合成测试集上比较执行得分，选组内相对最优作为下一轮基线。其优势在于信号干净、无需 C 模型、分钟级收敛；劣势在于依赖合成测试质量（可能过拟合合成案例），且仅优化已有技能、不学习"如何生成好技能"的能力。本项目可将其作为前置精炼（合成测试快测）或 C 模型不可用时的降级方案。

**SkillComposer（通义实验室）：create / improve / merge 与 delta pass-rate。** 该方法将技能构建分解为创建、改进、合并三个可训练操作，以 delta pass-rate rejection sampling 训练（阈值 ϵ=0.4，仅采用真正提升通过率的技能入训练集）。关键发现是合并为最重要操作（+3.7），在线优于混合优于离线（在线精炼带来最大提升），但强模型在离线通用库上收益有限——这与本项目"TF per-task +8.4pp 而 TF-global 对强模型无效"的观察完全一致。其 delta pass-rate 入库门槛、合并去重、改进精炼三操作正是本项目 experience 模块的升级方向。

**SePO：自指涉提示词优化。** 该方法是最直接的提示词优化对应工作，将提示词 agent 自身的系统提示词也作为优化变量，同一优化程序同时作用于任务提示词与提示词 agent 提示词，采用两阶段训练（多任务预训练以进化优化器自身，再单任务微调）。其在 AIME、ARC、GPQA、MBPP、Sudoku 上平均提升 +4.49，跨模型泛化 +2.13pp。该方法与本项目互补：SePO 为文本级进化（不更新参数），本项目为参数级进化（GRPO 真更新），可用 SePO 式快速搜索寻找良好提示词起点，再进入 GRPO 精细优化。

**D2Skill、SkillOS、Skill1：强化学习驱动进化的信号设计。** D2Skill 的 paired rollout（同任务同时运行有技能与无技能，以差距作为 hindsight utility）即综述反复强调的双 rollout 评估协议，是验证技能贡献、剥离"agent 变强与技能变好"噪声的标准做法，可直接用于本项目的 custom_reward.py。SkillOS 将评估嵌入训练循环（冻结 executor 与可训练 curator，复合奖励含 latency、token cost），对应本项目"C 模型评判嵌入训练"与复合奖励的升级方向。Skill1 以频域分解 credit（低频归因于选择、高频归因于蒸馏）将单一奖励拆分给两种能力，避免多奖励源冲突，为统一策略归因提供思路。

**ARISE 与 SAGE：强化学习驱动的技能创建。** ARISE 技术最为丰富，包括策略驱动的技能选择（让策略自身学习选择技能而非依赖外部检索器）、层级化奖励（解错为 0、解对但未用技能为 1、解对且用技能为 2）、OG+1 专用技能生成 rollout、双层库（Cache 10 与 Reservoir 100）；消融显示去除层级化奖励后技能利用率从 73% 降至 31%。SAGE 采用 Sequential Rollout（以任务链为 rollout 单位，q₂ 使用 q₁ 技能的成功信号回传至 q₁），场景全成功率达 +8.9pp，平均 token 减少 59%。这两项工作为解决本项目"C 模型区分度不足""触发词精度等同于随机"等问题提供了直接可借鉴的奖励设计与选择机制。

### 3.3 基准体系与缺陷

综述将技能专属基准分为六大类：Utility（SkillsBench 表明 curated skills 平均提升 16% 通过率）、Generation、Retrieval & Routing、Safety（Skill-Inject 等八类攻击）、SWE、Real-world，并指出三大结构性缺陷。其一为缺乏纵向评估，所有基准仅测单次快照，未追踪技能在多轮反馈中是否真正改进；其二为指标过于二元，绝大多数采用 pass/fail，忽略 token cost、latency、错误类型、恢复率等操作性因素；其三为覆盖不均衡，跨领域 curator 泛化未被作为评估目标。这三大缺陷恰好对应本项目待补方向：纵向评估（追踪多轮迭代改进曲线，本项目已在做 val 三轮递增追踪）、复合奖励（已实现 70% 单测加 30% 评判，可加入 latency 与 token）、跨域泛化（数学主试验场加代码对照）。

### 3.4 本项目在全景中的差异化定位

本项目在综述全景中的对应关系如表 7 所示。核心结论是：本项目的 A-B-C 加 GRPO 架构与综述的强化学习驱动进化范式高度对齐，差异化体现在三点——其一，以 GRPO 梯度信号（而非启发式、进化搜索或 rejection sampling）训练 A 模型改写技能；其二，以 delta pass-rate 信号隔离技能真实贡献；其三，以 trace 蒸馏创建与池化检索补全技能生命周期。Skills-Coach 的 Training-Free GRPO、D2Skill 的双 rollout、SkillComposer 的三操作与 delta 门槛，是三个可直接引入的技术增强点。

**表 7　本项目在综述全景中的定位**

| 综述全景模块 | 本项目对应与定位 |

| Skill Retrieval / Routing | BAgent ContextBuilder（检索精度待提升） |

## 四、工程与理论相结合

为验证上下文空间进化方法在真实场景的有效性，我们将论文中的技能优化方法迁移到一个工业工程任务上，即对工业机器人控制器运转中产生的报错日志进行根因诊断。该任务由一个诊断 Agent 执行，其行为由一组诊断技能（系统提示词、路由规则、故障模式库、停止条件）引导；优化目标是在不重训模型的前提下，通过改写这些技能提升诊断的根因覆盖率与定位精度。该工程数据集规模较小（约 24 个真实诊断 case），但每个 case 均带有完整工具调用轨迹与业务方标注的参考根因，适合作为小样本技能进化的试验场。

### 4.1 方法迁移：从论文范式到工程流水线

我们没有直接套用现成框架，而是自研了一条轻量技能优化流水线，其骨架融合了综述与论文中三个方法的方法论（见表 8）：借鉴 Trace2Skill 的多轨迹并行 patch 提案与分层合并归纳，从诊断轨迹蒸馏失败模式并合并为无冲突的技能补丁；借鉴 SkillOpt 的 held-out gate 验证，采用 practice/gate 分层划分，gate 集绝不参与补丁生成以防小样本过拟合；借鉴 Skills-Coach 的小样本收敛与组内相对优势理念，24 个 case 不扩充，每个 case 重复采样以补样本数，候选技能与当前技能组内对比。优化对象是内置的诊断技能（记为 S₀），通过外置目录加载机制在不重新打包发行版的前提下让 Agent 运行改写后的版本，形成自进化闭环：由 S₀ 出发，用诊断轨迹蒸馏补丁，合并为候选技能 S'，经 held-out gate 验证，若接受则 S' 成为新基线并进入下一轮。这与论文"评估驱动的自动化进化"范式（创建、使用、评估、进化的闭环）完全同构。

**表 8　论文方法到工程流水线的迁移**

| 论文方法 | 借鉴的方法论 | 工程落地 |
|---|---|---|
| Trace2Skill（轨迹蒸馏） | 多轨迹并行 patch 提案与分层合并归纳 | 从诊断轨迹蒸馏失败模式，合并为无冲突的技能补丁 |
| SkillOpt（训练范式） | held-out gate 验证才接受编辑 | practice/gate 分层划分，gate 集绝不参与补丁生成，防小样本过拟合 |
| Skills-Coach（Training-Free GRPO） | 小样本几十条即收敛、组内相对优势 | 24 case 不扩充，每 case 重复采样补样本数，候选技能与当前技能组内对比 |

### 4.2 缺陷归因与优化切入点

对现有轨迹的量化诊断暴露了诊断技能的三类系统性缺陷，均可在不重训模型的前提下通过改写技能修复。其一为证据引导失灵，技能的"优先读取"引导未能将 Agent 引导至关键证据文件，导致根因覆盖率偏低；其二为故障模式库覆盖不足，内置模式条目过少，Agent 不掌握多数实际根因的判定路径；其三为停止条件失灵，同任务下取证工具调用数两极分化（过度取证与过早误判结束并存），覆盖率却未提升。这三类缺陷分别对应路由技能、知识库技能、控制技能三个可独立进化的上下文组件，印证了论文"上下文组件独立进化、独立评分"的设计理念。

### 4.3 双信号奖励与评估可靠性

工程任务中业务方提供的参考根因本身是模糊、不精确的，这与论文七月经历的"评测噪声导致假阳性"教训直接呼应，即评估可靠性是进化方法成立的前置条件。为此，奖励设计采用双信号双门槛而非单一加权。主信号为盲评 judge，由异模型在不喂真值的前提下，仅依据诊断轨迹按逻辑自洽性、证据链完整性、定位精度（最好到文件与行号）、探索适度四维盲评，逼近"诊断质量"本身，并允许技能做出真值未标注但逻辑更自洽的探索性改进。护栏信号为根因字段命中率，作为相对可信的真值字段，仅作"不退步"下限，防止为形式美观而牺牲根因命中。接受条件为两门槛同时满足（盲评质量提升且根因命中不大幅退步），并对每条轨迹多次盲评取中位数以抵抗 LLM 评分抖动。这一设计本质上是论文"客观执行信号加 LLM 评判"复合奖励在真值不可靠场景下的工程强化版。

### 4.4 初步进展与理论印证

目前已完成阶段 0 的闭环验证。盲评 judge 在不依赖真值的前提下，能够自主区分不同质量的诊断轨迹（如识别出过度取证、结论与证据脱节、因果时序不成立等过程性缺陷），并稳定产出可操作的优化方向；完整的"轨迹到补丁到 gate"闭环在 smoke case 上贯通，候选技能的盲评质量显著优于当前基线并通过双门槛被接受。该工程实践从三个层面印证了论文的理论框架：其一，在不对模型参数进行梯度更新时，优化上下文组件确实能够引导模型行为，上下文空间进化在真实工程数据上成立；其二，轨迹蒸馏加 held-out gate 的小样本闭环可产出可验证的技能改进，与论文数学基准上 test +7.0pp 的可复现增益同源；其三，当真值或评测不可靠时，盲评 judge 加软护栏的双信号设计是保住进化方向可信度的关键，这与论文七月"修正评测噪声后真实增益才浮现"的结论一致，构成工程与理论的相互印证。

## 五、下一步计划

**短期（立即推进）。** 其一，确认修复后的 +7.0pp：对修复后的 v2 进行多种子复测（评测端已有 k 投票降噪声，应较修复前稳定），量化方法方差。其二，消融与归因：以 trace2skill 基础池作为 v2 冷启动经验注入（基础与优化归因），设置纯 rewriter 与有池对照，并扫描 v2 超参（iters、g、eval_k）。其三，跨任务泛化验证：构建 AIME24 适配器（路径 C，作为非筛选 val 的真泛化检验）。

**中期（一个月内）。** 其一，在数学基准上跑通 GRPO 优化技能方法：将 custom_reward 迁移至 `<answer>` 标签验证器，同条件对位 S₀、GRPO 改写、TF-global、TF-per-task。其二，8 卡 4B 正式 GRPO 训练（托管平台）：先以单迭代冒烟确认无 OOM 且奖励流通，再推进至 max_iter=5，以 check_delta_health.py 监控 agent_ok%、degen%、mean_delta 衰减。其三，控制变量诊断（一次一变量对照 SkillOpt 基线）：rollout 方式、表示方式、优化信号（GRPO+ATE 对 val-gate，为论文 Step1 核心）、技能来源。其四，C 模型 defect-injection 审计，作为启用任何技能退休或删除操作的前置。

**长期与论文级。** 其一，论文叙事：从"参数空间到上下文空间"，创新点为 GRPO 训练 A 改写 S₀（delta pass-rate）加 trace 蒸馏创建加池化检索，以数学为主试验场，代码阴性结果作为"模型饱和需 agent 架构"的过渡证据。其二，泛化验证（单 agent 有效后）：smolagents 或 LangGraph 多 agent 适配器，验证跨 agent ATE 排序一致性。其三，工程化：以 ACP 协议标准化 A/B/C 通信，集中管理 API 密钥，并以 SkillsBench 作终极验证。依训练线与免训练线的对比，可能出现三种可发表结果形态：GRPO-4B 显著优于 TF（表明训练值得）、TF 与 GRPO-4B 相当（表明免训练足够）、TF 优于 GRPO-4B（作为小模型 RL 优化提示词的诚实负结果）。
