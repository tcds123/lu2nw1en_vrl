# 论文进展汇报 — Facet-Tree Skill 进化

> 2026-08-25 | 数学 skill 优化方向

---

## 一句话结论

新方法（Facet-Tree 树状进化 + 分支交叉）**已通过 Stage 0 验证，显著打破旧天花板，方向被证明有效；目前尚未追上最强基线 skillopt，差距明确且测得稳定，下一步开多代冲这个差距。**

---

## 一、做什么

**目标**：优化一个数学题系统提示词（skill），让生成模型做选择题时正确率更高。

**老办法卡在哪**：之前一直用"单条线反复改同一个 skill"（单 lineage），反复优化在验证集上能涨，但一换到测试集就不涨了——四个不同机制全卡在 **0.46** 左右同一个天花板，说明问题出在搜索结构本身，不是优化维度不够。

**新办法（Facet-Tree）**：把 skill 按 `## ` 段切成几个独立模块（facet），例如：

- Option Comparison（选项比对）
- Theorem-Level Precision（定理级精度）
- Hypotheses（假设分析）
- Final Answer（最终答案，冻结不动）

每个分支**只许动自己那一段**，各分支往不同方向专精；分支之间还能**交叉**（取父本 A 的某段 + 父本 B 的某段拼成子代）。

> 本质变化：从"单条线优化"升级成"种群 + 选择 + 交叉"的遗传算法。**注意**：当前这 4 段 facet 轴是**人工按 `## ` 段预设的**（Stage 0 跑 `--no_emergence`），不是"自动涌现"出来的——"涌现"是下一个阶段（终局 C 组）要验证的目标，尚未兑现（详见第六节）。

### 用什么算法（原理）

**遗传算法（GA）三要素**，缺一不可：**种群**（多个体并存）＋ **选择压力**（按适应度保留）＋ **交叉/重组**（两个父本拼出新子代）。单 lineage 反复改 = 只有变异 + 保留最优，是爬山（hill-climbing），不是真 GA——这正是老办法卡天花板的结构病根。

Facet-Tree 怎么落到三要素上：

| GA 要素 | Facet-Tree 对应 | 落在哪条线 |
|---|---|---|
| **种群** | 每个 facet 分支独立演化，弱变体不删（archive 保留输家） | DarwinX 的 archive 树 |
| **选择压力** | 全局准确率（EM pass_rate）作为统一适应度 | 沿用现有 evolver 评估链路，零新评估器 |
| **交叉** | 2-parent facet 组合：取父本 A 的强段 + 父本 B 的强段，合成连贯子代 | DIVE 的 2-parent Recombination 换到 slot 粒度 |

**相比老办法，换了两样东西**（均坐实 val→test 脱节的诊断）：

1. **换搜索结构**：单 lineage → 树。archive 保留多 lineage 含输家，避免"局部最优被 winner-takes-all 固化"，这是 DarwinX §5.1 对 val→test 的直接诊断。
2. **换自由度结构**：单一目标 → facet 分支。不同分支专攻不同侧面，让树天然长出 specialists，而非逼出单一局部最优。

**关键的诚实边界（"预设 vs 涌现"）**：

- **现在这套（Stage 0）= 预设轴**：4 个 `## ` 段是人工切的，每个分支只能动自己那段的自由度由 `facet_edit_guard` 护栏硬编码。**这不是"涌现"**，是"人工预设"。
- **"涌现"是设计目标，还没兑现**：设计里希望 facet 轴能像多头注意力的 head specialization 一样，由进化自己长出来（而不是人手切 4 段）。这要靠终局 C 组（多代 + 开涌现 + K=3 门控）去验证，判据是 `Common Failure Modes` 第 5 段能否**从零长出**且有因果贡献。
- **为什么不能现在就说"像多头注意力"**：真正 attention 的 head 是**没有任何人事先指定哪个 head 学什么语义**的，完全靠 loss 逼出来；而 Stage 0 的 4 段是**人提前写死标题和语义**的。二者差着一整个"预设 → 涌现"的距离，不能类比。

> 参考论文（>均为 EA 调研全文核实）：DIVE（多种群 + 2-parent skill 重组 + 三分）、DarwinX（archive 树 + preserve-and-extend）、EvoPrompt（教科书真 GA）、PromptBreeder（fitness sharing 多样性维持）、EvoAgent（多基因配置 crossover）。

## 二、冒烟测试通过了吗

**通过了。** 经历一次 bug 修复后，Stage 0 入场判据 **5/5 全绿**。

时间线：

| 日期 | 事件 | 结果 |
|---|---|---|
| 08-21 | Stage 0 正式 2 代进化 + 测试集复评 | **GO**，破判据线 |
| 08-24 | 多代 smoke 发现交叉算子"触发了但被拒" | 找到根因 |
| 08-24 晚 | 修复后重跑 smoke | **5/5 全过，交叉真生效** |

**那个 bug 是什么**：交叉时让 LLM"合并重复段落"的指令，和"段不能增删"的结构守卫互相矛盾——LLM 被夹在中间，一合并就丢段头被拒。修复方式是**改指令去对齐守卫**（不是放宽守卫），交叉产物这次真正被采纳（`crossover_fired:1`，增益 +0.189）。

## 三、核心结果

测试集 = 106 题，4 个 seed 平均（eval_k=3），8-21 官方 run：

| 方法 | 测试集 4-seed 均值 | 相对基线 |
|---|---|---|
| s0（基线，不优化） | 0.2877 | — |
| **Facet-Tree（2 代）** | **0.4953** | **+0.2075** |
| skillopt（最强基线） | 0.5629 | +0.2752 |

**破天花板线 = 0.4654**（老办法反复打不破的天花板）。

→ **0.4953 > 0.4654，破天花板**，机制值得继续开多代。这条线**已达成、已退役**——当前 test 终评真正要追的是闭合 skillopt 的判据线 0.5464（见第四节、附）。

**多代 smoke（08-24）证明不是噪声**：
- 主轴（Option Comparison）两代单调上升，**换不同随机种子重跑也能复现**（+0.156 → +0.344）
- 次轴先涨后触顶回撤，接受准则自动拦住退化（防止掉分）

### ⚠️ 关于"val 还是 test"的重要说明

evolver 内部跑的是**验证集**（val，用来选 best skill）；**测试集（test=106）要单独人工跑脚本**，evolver 不会自动跑。所以同一批实验可能出现"val 测了、test 没测"的情况。报告中的三批 run 状态如下：

| run | 日期 | best skill | val（选 skill 用） | test（绝对水平） | 用途 |
|---|---|---|---|---|---|
| run_20260821_153252 | 08-21 | `abb71de55a` | val +0.294 | ✅ **test 0.4953** | **本报告的核心数字** |
| run_20260824_153302 | 08-24 | `1dbbb821c3` | val +0.344 | ❌ 未测 | smoke 收敛版 |
| run_20260824_183940 | 08-24 | `2c33e2f5fc` | val +0.194 | ❌ 未测 | **修交叉 bug 后版** |

**所以**：
- 报告里 **0.4953 是 8-21 修复交叉 bug 前的测试集结果**（val +0.294 → test 0.4953）。
- 8-24 那几个 smoke 里的数字（+0.344、+0.194）是 **val 上的提升幅度**，不是测试集绝对通过率。
- 8-24 **修复交叉 bug 后的新版 best skill，只测了 val，test 还没测** → 这就是"下一步 test 终评"的由来：测的是"修 bug 之后"的 test 水平，回答①是否比旧的 0.4953 更好、②能否追上 skillopt 0.5629。

> 简言之：**0.4953 = 修 bug 前的 test 水平；test 终评 = 要测修 bug 后的 test 水平**，两者是不同版本的 skill。

## 四、对比 skillopt 怎么样

**还差一截，但差距测得非常稳。**

- Facet-Tree **0.4953** vs skillopt **0.5629**，落后 **0.0676**（约 6.8 个百分点）
- 经过统计功效分析钉死：**判据差距 = 0.0511 = 5.88 个标准误**（0.4953 对上判据线 0.5464），属于"超稳"，方向板上钉钉
- 诚实注：第 4 个 seed 单跑 0.4623 略低于判据线，是靠 4-seed 均值跨过去的

**含义**：树 + 交叉已经**显著打破单 lineage 天花板**，证明机制方向对；但**还没追上 skillopt 绝对水平**——这是下一步多代终局要去闭合的目标。

## 五、诚实记录的负面发现

**DIVE bootstrap（想靠切不同题目子集造异构环境）没真正起作用。**

- 三个分支的失败类型 **100% 都是 meta-option**（元选项类），没有一个分支专有的失败类型
- 也就是说：分支的"专精"目前**只来自 facet 段冻结这个物理约束**，不是来自环境差异
- 根因：这批数学题的失败模式本身高度同质，切分后各子集还是被同一类失败主导

> 不影响 Stage 0 通过，但说明"靠环境差异造分支分化"这条路在当前数据上空转，终局若要靠它，得先换题源或改切分策略。

## 六、两个待补的理论薄弱点（诚实记录现状）

当前结果有两处**设计层面**的薄弱点，已在设计文档 v4 里落成待办，这里简要说明现状：

### 1. facet 轴现在是「预设」，还不是「涌现」

**现状**：Stage 0 跑的是 `--no_emergence`，facet 轴 = 人工按 `## ` 段预设的 4 个固定段（Option Comparison / Theorem-Level Precision / Hypotheses / Final Answer），每个分支只能动的自由度由 `facet_edit_guard` 护栏硬编码锁死。

**含义**：设计里「facet 轴自动涌现（类比多头注意力 specialization）」的主张**尚未兑现**——这是 novelty 的最大风险点。当前 2 代的 +0.2075 证明了「树 + 交叉 + 单 slot 变异」这个机制有效，但**没证明「涌现」本身有效**。涌现的兑现点 = 终局 C 组（多代 + 开涌现 + K=3 门控），判据是 `Common Failure Modes` 第 5 段能否从零长出且有因果贡献。

### 2. 起点只有单 S₀，缺多样性初始化

**现状**：Stage 0 起点钉死单 S₀（4 段），没有做多样性化。

**含义**：单 S₀ 起步是单 lineage 时代的遗产。进入真 GA 后，基因多样性是有效性的源泉（EvoPrompt 手工+LLM 混合初始种群、PromptBreeder fitness sharing、DIVE bootstrap 子集起步都支持这点）。**且做「S₀ → 多样性扰动 → 异质初始种群」不违反公平性**——只要每个个体的祖先都是同一 S₀，就仍然公平（SkillOpt 也是从 S₀ 起步）。这是一处可补的改进点，很可能就是提升上限的那一步。

> 这两点都指向同一根：当前实现还带着「单 lineage + 人工模板」的残余，没真正进入「种群随机化 + 轴涌现」的 GA 形态。**不是 bug，是阶段性问题**；但诚实记录清楚，避免把「预设」说成「涌现」、把「单起点」说成「多样性充足」。
