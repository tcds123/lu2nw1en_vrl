# 论文研究进展汇报

**汇报时间：** 2026年11月13日  
**汇报范围：** 2026年7月9日至2026年11月13日  
**汇报对象：** 导师及课题组

## 一、研究工作概述

自2026年7月以来，研究工作主要围绕大语言模型的 Skill 自动优化与进化方法展开，重点研究如何利用模型生成过程中的错误反馈，迭代改进 Skill，并评估其在不同任务和数据集上的有效性。

研究过程中，整体技术路线经历了三个阶段：

1. **代码生成任务上的有效性验证（7月）：** 对现有 Skill 注入与优化方法进行系统评估，发现纯文本 Skill 在部分代码生成基准上难以获得稳定的测试集收益，因此调整研究方向。
2. **数学任务上的进化算法研究（7—9月）：** 设计免训练的 Skill 优化方法，并进一步引入基于 Facet-Tree 的遗传搜索机制，在 LiveMathBench 上取得了较为稳定的性能提升。
3. **强模型条件下的优化机制与条件路由研究（10—11月）：** 将实验模型切换为 DeepSeek-V4-Flash，重新评估 Skill 优化在代码生成任务上的有效性，并在 APPS_Plus 上发现不同题目对 Skill 注入存在差异化响应。在此基础上，进一步设计条件路由机制。

目前，研究重点逐渐由单纯优化 Skill 文本转向研究 Skill 的适用条件及其与基础模型之间的协同机制。

## 二、代码生成任务上的初期实验

### 2.1 现有 Skill 系统评估

研究初期，首先对已有的 Skill 经验池及其注入机制进行了评估。

主要实验结果如下：

| 实验内容 | 实验结果 | 结论 |
|---|---|---|
| 历史经验池（402条） | 平均处理效应 ATE 均为0，使用计数为0 | 历史经验未形成有效优化信号 |
| BigCodeBench 注入实验 | n=57，p=0.349 | 未观察到显著提升 |
| MBPP_pro 注入实验 | 5组实验均 p>0.19 | 未观察到显著提升 |
| Focused-3 策略 | n=100，准确率由28%提升至48%，p=0.83 | 当前样本下不具有统计显著性 |

上述结果表明，初期经验池中的 Skill 缺乏有效的错误归纳信息，仅调整 Skill 的选择策略难以解决这一问题。

### 2.2 代码生成基准上的优化实验

随后，使用 SkillOpt 在 MBPP Pro、APPS_Plus 和 LiveCodeBench（LCB）上开展优化实验。

| 数据集 | 实验结果 | 分析 |
|---|---|---|
| MBPP Pro | 最优测试集准确率0.4604，低于无 Skill 基线0.4679 | 验证集优化未能迁移至测试集 |
| APPS_Plus | 最优测试集准确率0.6351，低于无 Skill 基线0.6564 | 小样本实验中的正向结果未在完整测试集上复现 |
| LCB NEW | 验证集提升约15个百分点，测试集下降0.7—1.4个百分点 | 验证集与测试集表现存在明显差异 |

综合上述实验，初期采用的纯文本 Skill 优化方式未能在代码生成任务上获得稳定的测试集增益。

需要说明的是，该结论仅针对当前模型、任务设置及 Skill 注入方式，不能据此推断 Skill 优化方法在所有代码任务上均无效。

### 2.3 GRPO 训练路线调整

研究初期还尝试利用 GRPO 训练独立的 Skill 改写模型，以任务正确率变化作为奖励信号。

实验完成了基本流程验证，包括 Skill 改写、代码生成、单元测试及奖励计算等环节。由于正式训练需要较多计算资源，同时免训练优化方法已取得初步实验结果，因此后续停止了该训练路线。

此后，研究重点转向不更新模型参数的 Skill 自动进化方法。

## 三、免训练 Skill 优化方法研究

### 3.1 数学任务作为实验平台

由于初期代码生成任务上的优化效果不稳定，研究转向数学选择题任务，以便更直接地分析 Skill 对模型决策过程的影响。

在 LiveMathBench 上进行初始对比实验，结果如下：

| 方法 | 测试集准确率 | 相对 S₀ 的变化 |
|---|---:|---:|
| 无 Skill | 29.0% | -3.9个百分点 |
| 初始 Skill（S₀） | 33.1% | — |
| SkillOpt-best | 51.6% | +18.6个百分点 |

实验表明，数学任务上存在较为明显的 Skill 优化空间，因此将其作为后续算法研究的主要实验平台。

### 3.2 免训练优化器迭代

首先实现 TF-global 优化器，并针对其经验池利用、错误反馈和候选生成等问题进行了改进。

初期 v2 版本在测试集上取得0.4839的准确率，相较初始版本提升15.3个百分点。但后续多 Seed 复测未能复现这一结果。

进一步检查发现，原评测流程存在两项问题：

- Baseline 与 Candidate 的采样次数不一致；
- 温度设置及采样结果缺乏统一管理。

修复后，采用固定 Baseline 缓存、投票评估及扩大验证集等措施，最终获得约7.0个百分点的提升。

这一阶段明确了评测一致性对 Skill 优化实验的重要影响。

### 3.3 Evolver 迭代优化

在此基础上，进一步实现 Evolver，将错误分析、候选 Skill 生成和迭代筛选整合为自动优化流程。

主要结果如下：

| 实验 | 测试集结果 | 说明 |
|---|---|---|
| 初始 S₀ | 0.305 | 基线 |
| Evolver | 0.378—0.478 | 不同版本表现存在差异 |
| 多 Seed 复测 | 提升6.6—16.1个百分点 | 不同随机种子下均观察到正向变化 |
| 10轮迭代 | 0.438 | 未超过较早版本的最优结果 |

消融实验表明，种群选择机制和基于失败样例的补丁生成机制具有显著贡献，分别带来约10.5和7.8个百分点的提升。

但在 AIME24 上，Evolver 仅提升1.9个百分点，统计检验 p=0.70，未表现出显著的跨任务迁移能力。

因此，当前方法的有效性主要体现在特定数学选择题任务上。

## 四、Facet-Tree 遗传搜索算法

### 4.1 方法设计

单条 Skill 持续迭代的实验中，多种不同优化机制最终收敛于约0.4654的测试集准确率，表明仅依靠局部文本修改难以继续获得稳定提升。

为扩大搜索空间，进一步提出 Facet-Tree 遗传搜索方法。

该方法将 Skill 划分为多个相对独立的功能模块，各分支分别优化对应模块，并通过双亲交叉实现不同优化结果的组合。

初始实验采用人工预设的 Facet 划分方式，主要包括：

- Option Comparison；
- Theorem-Level Precision；
- Hypotheses；
- Final Answer。

通过 `facet_edit_guard` 限制各分支的修改范围，降低不同优化方向之间的相互干扰。

### 4.2 实验结果

| 实验阶段 | 测试集准确率 | 说明 |
|---|---:|---|
| 初始 S₀ | 0.2877 | 基线 |
| Stage 0 | 0.4953 | 首次超过单分支迭代结果 |
| 交叉机制修复后 | 0.5220 | 进一步提升 |
| Overlay 算子修复后 | 0.5354 | 改善不同模块之间的组合效果 |
| 后续版本 | 0.5472—0.5542 | 不同版本间存在一定差异 |

其中，0.5354版本相较初始 S₀ 提升23.4个百分点。

实验中还发现，多个模块分别获得的性能改进并不能直接叠加。原有实现中，最终最优结果往往仅保留单个模块的最优修改，而未能有效组合其他模块的改进。

针对这一问题，进一步设计 Overlay 算子，改善跨模块修改的保留与组合方式。

### 4.3 与 SkillOpt 的对比

为评估 Facet-Tree 方法的实际效果，开展了8-Seed 对照实验。

| 方法 | 测试集准确率 |
|---|---:|
| Evolver | 0.5212 |
| SkillOpt | 0.5503 |

Evolver 相较 SkillOpt 低2.91个百分点，且8个 Seed 的比较结果均未显示 Evolver 优势。

因此，尽管 Facet-Tree 相较早期 Evolver 有较大改善，但尚未超过 SkillOpt 基线。

进一步分析发现，原有 `facet_edit` 算子主要支持局部内容修改，无法有效增加新的功能模块。这限制了搜索空间，也使得部分优化结果难以通过交叉操作保留。

### 4.4 Expand 算子及机制验证

为解决功能模块无法扩展的问题，进一步设计 Expand 算子。

实验结果显示：

- Expand v1 测试集准确率为0.4654，较此前结果下降约7个百分点。
- Expand v2 整体提升约为负2.1个百分点，未达到统计显著性。
- 在不包含 meta 结构的17道题目上，观察到15.7个百分点的提升，p=0.0235。

该结果说明 Expand 算子可能对特定题目子集有效，但尚不能证明其能够改善整体性能。

此外，对自动分支生成机制进行了验证。由于失败样例之间缺少足够重复的错误类型，基于聚类结果自动生成分支的实验未能形成有效搜索结构。

## 五、LiveMathBench 数据集结构与优化机制分析

### 5.1 数据集结构特征

在对 LiveMathBench 的实验结果进行进一步分析时，发现数据集存在两项值得关注的结构特征。

第一，训练集、验证集和测试集中的正确选项均为 A。

第二，部分题目包含较为明显的 meta 语义信息。例如，题目中出现“a stronger result can be proven”这一表述时，测试集对应的46道题目全部选择了正确答案。

这些特征来自原始数据集的选项组织方式和题目语义结构，而非 Skill 优化过程中人为添加的规则。

### 5.2 位置偏置与语义规则实验

为区分 Skill 学习到的规则与数据集位置分布之间的关系，开展了以下实验：

| 实验 | 方法 | 结果 |
|---|---|---|
| 选项位置打乱 | 对选项顺序进行确定性打乱，并同步调整正确答案 | 位置相关规则的效果发生变化 |
| 位置偏置因果实验 | 将 Skill 中的“option A”替换为“option C”，其他内容保持不变 | 偏置峰由 A 迁移至 C |
| 干净重训 | 在打乱后的数据集上重新训练 | OFF：54.1%；ON：52.2% |
| Meta 规则分析 | 对相关 Skill 条目进行删除和干扰实验 | 删除特定规则后，其触发行为消失 |

实验表明，部分优化结果与正确选项的位置分布有关，而另一部分结果来自对题目语义结构的学习。

在后续版本中，位置相关规则通过训练集打乱实验得到识别，并在候选筛选过程中被移除。

因此，后续研究将重点放在语义规则的形成机制及其适用范围上。

### 5.3 研究意义

上述实验表明，Skill 优化算法能够从任务反馈中提取与数据集结构相关的规则，并将其写入 Skill。

但这类规则的有效性具有一定的数据分布依赖性。当训练集与测试集在结构特征上存在差异时，规则的迁移效果可能受到影响。

因此，后续需要在结构特征不同的任务上进一步验证 Skill 优化方法的泛化能力。

## 六、AIME 数值竞赛任务上的泛化实验

### 6.1 初始泛化实验

为验证在 LiveMathBench 上得到的优化方法能否迁移到数值竞赛题，进一步在 AIME 数据集上开展实验。

主要结果如下：

| 方法 | AIME25 测试结果 |
|---|---:|
| S₀ | 0.4963 |
| Evolver | 0.5000 |
| SkillOpt | 0.5074 |

Evolver 和 SkillOpt 相较 S₀ 均未获得统计显著的提升。

其中，Evolver 在10轮迭代、50次算子操作后，未产生有效晋升候选。

### 6.2 Skill 结构与生成范式实验

针对 AIME 任务的特点，进一步尝试缩减初始 Skill，并采用不同的代码执行范式。

实验发现：

- 将初始 Skill 压缩至797个字符后，held-out 准确率达到0.5185，高于 S₀ 的0.4741，但多 Seed 结果未达到统计显著性。
- ReAct 工具循环使 S₀ 和 Evolver 的表现分别下降7.4和13个百分点。
- CodeAgent 采用 Program-of-Thought（PoT）方式，通过生成 Python 代码完成计算，使 S₀ 提升14.8个百分点，p=0.0007。

上述结果说明，对于数值竞赛题，执行代码进行计算可能比增加工具交互步骤更有效。

### 6.3 优化算法问题诊断

在后续实验中，发现 Evolver 主要存在以下问题：

1. 原有失败类型识别依赖关键词匹配，难以准确识别几何题等复杂错误类型。
2. 部分候选 Skill 的生成方向与实际错误类型不匹配。
3. Skill 更新门控缺少充分的统计约束，容易接受验证集上的偶然提升。

针对这些问题，尝试引入 EFL 方法，通过语义分类识别错误类型，并根据失败数据动态生成 Facet。

但后续实验发现，即使改善候选筛选机制，几何类补丁仍难以获得稳定提升。

这表明当前优化方法的主要限制并不完全来自候选筛选，而是与候选 Skill 的生成质量有关。

### 6.4 评测流程修复

2026年10月中旬，对评测流程进行了系统检查，并修复了多个影响实验可靠性的问题。

| 编号 | 问题 | 修复措施 | 结果 |
|---|---|---|---|
| F6 | Baseline 缓存不固定 | 固定 AIME 评测清单并复用缓存 | 减少重复调用，保证基线一致 |
| F2 | 分组救援逻辑无法触发 | 增加 `--rescue_on_reject` | 救援机制能够正常执行 |
| F1 | 30道题、k=3 的评测分辨率不足 | 增加至 k=8，并引入配对评估 | 评测丢题率由68%降至0—3% |
| C2 | 不同轮次采样噪声影响结果 | 采用配对重评分 | 降低候选与基线之间的采样差异 |

修复后，AIME 实验中仅有 run#6d 的 iter2 获得了符合当前统计判据的晋升结果，提升4.2个百分点，置信区间下界为0.4个百分点。

### 6.5 噪声校准与算法瓶颈分析

进一步采用相同协议对 S₀ 进行15次重复评估，发现准确率估计的标准误约为0.018—0.025。

在当前样本规模和评测条件下，稳定识别的性能提升幅度约为10个百分点。

而此前大多数候选 Skill 的提升幅度低于5个百分点，因此难以与采样波动区分。

此外，算法生成的有效文本修改数量较少：

- Evolver 历史最优版本仅增加约106个字符。
- SkillOpt 共执行68条编辑操作，其中仅合并2条，最终增加约2148个字符。

这些结果表明，当前优化算法的限制不仅体现在候选选择上，也体现在有效修改内容的生成能力上。

## 七、更强模型条件下的实验研究

### 7.1 模型切换及实验动机

2026年11月，研究将实验模型切换为 DeepSeek-V4-Flash。

主要考虑是：此前 V3.2 模型在部分任务上存在错误类型分散、难以形成有效优化方向的问题。通过更换能力更强的模型，进一步检验模型能力与 Skill 优化效果之间的关系。

### 7.2 AIME 实验

Flash 在 AIME24 上的初始准确率达到0.854，其中30道题目中有21道全部答对；AIME25 上准确率达到0.838。

在此基础上开展 Skill 自动进化实验，结果如下：

| 实验 | 结果 | 结论 |
|---|---|---|
| Flash S₀ | AIME24：0.854 | 当前任务表现较高 |
| Evolver 自进化 | In-sample 提升7.8个百分点，置信区间下界为1.1个百分点 | 训练样本上取得显著提升 |
| Held-out 评估 | 提升1.67个百分点，置信区间跨越0 | 未验证跨分布迁移效果 |
| Skill 蒸馏实验 | 部分蒸馏版本准确率明显下降 | Skill 可能对输出长度及推理过程产生不利影响 |

实验表明，更强模型条件下，Skill 优化可以在训练样本上取得一定效果，但其泛化能力仍需进一步验证。

### 7.3 LiveCodeBench 实验

在 LCB 上，Flash 模型的初始性能明显高于此前使用的 V3.2。

进一步使用 SkillOpt 进行优化，结果如下：

| 难度 | 题目数量 | Flash S₀ | V3.2 S₀ | SkillOpt 提升 |
|---|---:|---:|---:|---:|
| Easy | 34 | 0.9706 | 0.941 | +2.9个百分点 |
| Medium | 26 | 0.7692 | 0.577 | +3.9个百分点 |
| Hard | 83 | 0.5542 | 0.193 | +6.0个百分点 |
| 合计 | 143 | 0.4685* | 0.4406 | +4.9个百分点 |

注：合计行中的0.4685为 SkillOpt 内部评测基线，与独立 S₀ 评测口径不同。SkillOpt 优化后的结果为0.5175，best step为0.5315。

相比此前 V3.2 上未能获得正向提升的结果，Flash 上的实验呈现出更明显的优化收益。

这说明模型能力变化可能影响 Skill 优化的有效性，但仍需进一步开展同协议对照实验。

### 7.4 ClassEval 实验

在 ClassEval 上，首先采用原有 SkillOpt 方法进行优化，但由于部分候选被强制接受，最终导致 Skill 长度增长至8273个字符，测试集性能下降4.3个百分点。

随后恢复门控机制，拒绝所有不符合条件的候选，测试集性能基本保持不变。

进一步尝试调整门控粒度及初始 Skill 结构，均未获得稳定提升。

最后，将代码生成流程改为两轮执行反馈机制：

1. 第一轮生成代码；
2. 执行 doctest，获取运行结果；
3. 第二轮根据执行反馈修改代码。

实验发现，仅改变生成流程就使 S₀ 增加12道正确题目，提升17.1个百分点。

但不同 Skill 版本之间的差异仍然较小，主要原因是验证集仅包含10道题目，难以区分不同 Skill 的实际效果。

因此，后续将 APPS_Plus 作为主要代码实验数据集。

## 八、APPS_Plus 上的条件路由方法

### 8.1 整体 Skill 注入实验

在 APPS_Plus 上，使用 Flash 模型进行 SkillOpt 优化。

实验结果如下：

| 方法 | 测试集准确率 |
|---|---:|
| 初始模型及 S₀ | 0.6933 |
| SkillOpt 优化后 | 0.7033 |

整体提升1.0个百分点，共增加3道正确题目，McNemar 检验 p=0.72，未达到统计显著性。

单纯采用整体 Skill 注入，未能获得稳定的测试集收益。

### 8.2 分层分析

进一步按照基础模型在每道题目上的表现，将测试样本分为两类：

- 基础模型未能正确回答的题目；
- 基础模型已经正确回答的题目。

分析发现，Skill 注入存在明显的双向效应：

| 变化类型 | 题目数量 | 说明 |
|---|---:|---|
| 正向变化 | 17 | 原本错误的题目在注入 Skill 后得到正确答案 |
| 负向变化 | 14 | 原本正确的题目在注入 Skill 后变为错误 |
| 净变化 | +3 | 与整体准确率提升3题一致 |

其中，17道得到改善的题目中，有13道原始模型的 soft score 为0。

这一结果表明，整体性能提升有限并不意味着 Skill 完全无效，而是正向收益与负向影响在整体评估中发生了抵消。

### 8.3 条件路由机制设计

针对上述问题，提出按题目动态选择是否注入 Skill 的条件路由方法。

具体流程如下：

1. 第一轮由基础模型 S₀ 独立完成题目。
2. 判断第一轮输出是否正确。
3. 对基础模型未能正确回答的题目，第二轮注入优化后的 Skill。
4. 对比两轮输出，保留表现更好的结果。

该方法不再要求所有题目统一使用 Skill，而是根据基础模型在当前题目上的表现决定是否进行 Skill 增强。

### 8.4 条件路由实验结果

在 APPS_Plus 测试集300道题目上进行了初步实验。

<text><strong>主要结果：</strong></text>

| 指标 | 实验结果 |
|---|---:|
| 基础模型正确题目数 | 208 |
| 条件路由正确题目数 | 228 |
| 新增正确题目 | 20 |
| 条件路由准确率 | 76.00% |
| 准确率提升 | 6.67个百分点 |
| Rescue | 20 |
| Regression | 0 |
| McNemar 检验 | p=1.9×10⁻⁶ |

条件路由结果显著优于整体 Skill 注入方案，配对检验 p=0.0033。

在此基础上，将条件路由机制整合至 Evolver，完成了初步流程验证。当前版本在300道测试题上达到229道正确，较基础模型增加21道，p=9.5×10⁻⁷。

正式的三轮迭代实验已于11月13日启动。第一轮验证集路由准确率提升4.67个百分点，并通过当前接受判据；第二轮仍在运行。

### 8.5 阶段性分析

APPS_Plus 实验说明，Skill 的有效性可能具有题目依赖性。

对于基础模型已经能够正确处理的题目，额外注入 Skill 可能引入不必要的约束，导致原有正确结果发生变化。

对于基础模型无法正确处理的题目，Skill 则可能提供额外的推理策略和问题解决信息。

因此，相较于单纯优化 Skill 文本，研究 Skill 与基础模型之间的条件协同机制具有进一步探索价值。

目前的条件路由结果属于初步实验，仍需通过独立实验和多轮迭代验证其稳定性。

## 九、主要实验结论与研究方法演进

### 9.1 主要实验结论

结合7月至11月的实验结果，目前可以得到以下阶段性结论：

**（1）Skill 优化效果与任务类型及模型能力有关。**

初期在代码生成任务上，纯文本 Skill 注入未能获得稳定提升；在 LiveMathBench 上，免训练优化方法取得了较明显的性能改善。更换 Flash 模型后，LCB 上也观察到了正向优化效果。

**（2）搜索结构影响 Skill 优化效果。**

单分支迭代容易受到局部修改空间的限制。Facet-Tree 通过模块化搜索、交叉和组合操作扩大了候选空间，但目前尚未在公平对照中超过 SkillOpt。

**（3）评测协议是算法研究的重要基础。**

AIME 实验中发现的缓存漂移、采样不一致、评测分辨率不足等问题，均可能影响优化效果的判断。配对评估、固定基线和噪声校准有助于提高实验结论的可靠性。

**（4）Skill 的有效性具有题目依赖性。**

APPS_Plus 上的分层分析表明，Skill 注入可能同时产生正向和负向影响。条件路由能够在初步实验中减少负向影响，并取得更高的整体准确率。

**（5）执行反馈能够改善代码生成效果。**

ClassEval 实验中，两轮代码生成与执行反馈机制使基础模型准确率提升17.1个百分点。这说明模型生成、执行与修正之间的交互过程值得进一步研究。

### 9.2 方法演进过程

| 阶段 | 方法 | 主要研究内容 |
|---|---|---|
| 第一阶段 | BAgent 与经验池注入 | 验证历史经验对模型生成能力的影响 |
| 第二阶段 | GRPO 训练尝试 | 探索通过强化学习优化 Skill |
| 第三阶段 | 免训练优化器 | 基于错误反馈生成并筛选候选 Skill |
| 第四阶段 | Evolver | 引入迭代优化、种群选择及失败驱动修改 |
| 第五阶段 | Facet-Tree GA | 引入模块化搜索、交叉及 Overlay |
| 第六阶段 | 评测机制改进 | 引入固定基线、配对评估及噪声校准 |
| 第七阶段 | 条件路由 | 根据题目特征决定是否注入 Skill |

## 十一、总结

过去四个月的研究工作主要完成了 Skill 自动优化方法的设计、迭代及多任务验证，并逐步将研究重点由 Skill 文本本身的优化扩展到 Skill 与基础模型之间的协同机制。

在 LiveMathBench 上，Facet-Tree 方法取得了较明显的性能提升；在 AIME 上，实验揭示了当前优化方法在数值竞赛任务中的局限；在更强模型条件下，LCB 实验重新观察到正向优化效果。进一步地，APPS_Plus 上的实验发现，Skill 对不同题目的影响并不一致，条件路由在初步实验中取得了20道题目的净增益。

下一阶段的主要任务是完成 APPS_Plus 正式迭代实验及相关消融研究，进一步验证条件路由机制的稳定性，并结合跨数据集实验明确方法的适用范围。

**当前研究重点：从单纯的 Skill 优化转向 Skill 的条件化使用及其与基础模型的协同优化。**
