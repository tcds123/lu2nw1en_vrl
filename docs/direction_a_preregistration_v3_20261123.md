## 2. RQ1 — 固定 Skill 的推理生成稳定性 (k=3)

### 2.1 定义
"同一 Skill、同一题集、同一生成配置下, 三次独立生成的结果是否一致", **不是** Evolver 训练过程的可复现性。

### 2.2 设计 (D1 = 整轮批推进)
- 260 题 × 3 轮, 顺序 **r1 全 260 → r2 全 260 → r3 全 260**。每轮均为从零生成的全新调用, 不复用任何缓存; **不因前两轮结果调整 r3 的时间、题序或配置**。
- 每轮结果独立评测 (`_evaluate_d5`), 产出 hard / soft / pass_rate / fail_reason / 完整 stderr / 结构向量。
- 题序在轮内按冻结的 260 ID 清单顺序固定 (并行 8, 但 ID 清单与轮次之间不重排)。

### 2.3 R1a — 点估计复现程度 (正式报告部分①)
参照: **P_A = 132/260 = 0.5077**。

每轮 r ∈ {r1, r2, r3} 报告:
| 项 | 定义 |
|---|---|
| `P_r` | 该轮 260 题中 hard=1 的占比, 附 Clopper-Pearson 95% 区间 (**单样本 CP, k=n_pass, n=260, 双侧 α=0.05**; 不得用下面的条件区间函数) |
| `Δ_r` | `P_r − P_A` (单位: 率) |
| 净变化题数 | `g_r = #{r 轮 pass 且 P4-A fail} − #{r 轮 fail 且 P4-A pass}` |
| `D_r` | 该轮与 Phase 4-A 的**不一致对数** (逐题配对: 一侧 pass 一侧 fail) |
| `CI(Δ_r)` | 条件精确区间: 条件于 `D_r`, 对 rescue/D_r 取 Clopper-Pearson, 再按 `(2p̂−1)·D_r/260` 仿射 (harness `paired_net_gain_ci`, 与 Phase 4-A 同法) |
| 点估计容忍判定 | **是否满足 `|260·Δ_r| ≤ 13`** (即 13 道题以内) |

**实现约束 (2026-11-23, 0 API 核对, `docs/phase2_issues_202611.md` #112):** harness 的 `paired_net_gain_ci` 是**条件**区间函数 — 它在 `rescue / D` 上取 CP 再仿射, 当 g=0 (`rescue=regress`) 时返回退化到点估计的区间 (实测 `paired_net_gain_ci(132, 0, 260)` → `[0.4797, 0.5077]`, 而单样本 CP 为 `[0.4452, 0.5700]`, Wilson 为 `[0.4473, 0.5679]`)。
→ `P_r` 的区间**必须**用独立实现的单样本 CP (`scipy.stats.beta.ppf(α/2, k, n−k+1)` / `beta.ppf(1−α/2, k+1, n−k)`), 不得复用 `paired_net_gain_ci`。
→ 已实现并通过: `eva/direction_a_cp.py::uncond_cp` (0 API)。单测 (i) 132/260 复现 `[0.4452, 0.5700]`; (ii) 0/260 与 260/260 端点; (iii) 与 `beta.ppf` 手算一致 (1e-9); (iv) 与 harness `_clopper_pearson` 交叉一致; (v) 负对照 `paired_net_gain_ci(132,0,260)` 宽度 2.8pp vs 单样本 CP 12.5pp。**运行方式 `python eva/direction_a_cp.py`, 须在 E0 之前通过。**

- `|260Δ_r| ≤ 13` 是**点估计容忍界**, 只描述"观察到的净增益接近历史值", **不称为统计等效证明**, 不替代正式等效检验。
- `D_r ≤ 26` 只作为**该轮区间能否判定的可行性指标**报告, **不作为判定条件** (D≤26 不保证区间落入等效界)。

### 2.4 正式等效检验 (D2 + D4, 保留 v2 §2.4 原式)
逐轮要求:
```
CI(Δ_r) ⊆ [−0.05, +0.05]     r = r1, r2, r3
```
**三轮全部满足, 才判定与 Phase 4-A 历史结果达到预注册的等效标准。**
不使用三轮平均值替代任何一轮; 不用"三轮平均落在 ±5pp 内"推出"三轮分别等效"。

### 2.4.1 区间族与多重性 (v3 新增, 回应"§2.5 是否控制三重检验")

两个判定方向的多重性性质不同, 分开规定:

**(i) "等效支持" — 交集 (intersection) 方向, 不需要 Bonferroni。**
要判"支持等效"必须三轮**都**满足; 每轮单独用 α=0.05 时, 即使每个区间各错 5%, 三轮同时错的概率也只 ≤ 5%,
所以合取方向的家族错误率天然受控。**但代价是单轮区间不宽于 2ε**: 用 CP 区间, 260 题的半宽在 P≈0.5 时约 6.2pp,
已超过 5pp → **在 n=260 下"等效支持"基本不可能出现**。这是 §2.5 第三类"证据不足"成为预期结果的原因, 不是规则失效。

**(ii) "存在偏离证据" — 并集 (union) 方向, 需要控制。**

> **已裁定 (2026-11-23, 用户正式裁定): 采用方案 A。** 写入 protocol.json `multiplicity_scheme = "A"`。
> 只允许 A, 不在看到结果后切换; 不再保留 B 作为备选 (B 的 Bonferroni 加宽区间**不用于**任何判定)。
> 裁定理由 (记录在案): Direction A 的核心是正式等效检验; A 保留单轮区间的解释能力, 且避免 Bonferroni 把本来已宽于 2ε 的区间进一步加宽。

**方案 A 规则 (冻结值):** 三轮判定统一使用**各轮 95% 双侧名义区间** (即 §2.3 的条件精确区间, α=0.05), 不做 Bonferroni。

**强制边界条款 (写入正文与 protocol.json):**
- **等效支持**仍按交集判定: 三轮区间**全部**完整落入 [−0.05,+0.05], 不因三轮重复而放宽标准。
- **偏离证据**只作为**名义单轮证据 (nominal per-round evidence)** 报告, **不构成三轮整体的家族错误率控制声明**。正文固定措辞: "family-wise error not controlled across 3 rounds; interpreted as nominal per-round evidence"。
- **禁止**把 A 下的偏离判定写成"正式的整体偏离检验"或"至少在某一轮发生偏离"这类家族结论。若未来研究需要正式声明三轮中至少一轮偏离, 须另立协议并使用方案 B (Bonferroni α′ = 0.05/3) 或其他多重性控制, 不得在本协议上追加。
- R1a 的 `|260Δ_r| ≤ 13` 容忍界与任何区间是两个尺度, 不得混用。

### 2.5 最终判定 (三类, 互斥且穷尽)
| 结果 | 判定 |
|---|---|
| 三轮 `CI(Δ_r)` 均完整落入 [−0.05, +0.05] (各轮 95% 区间, 方案 A) | **等效支持** |
| 至少一轮 `CI(Δ_r)` 完整落在等效界之外 (即整段区间 ∩ [−5pp,+5pp] = ∅) | **存在偏离证据 — 名义单轮证据** (规程: "family-wise error not controlled across 3 rounds; interpreted as nominal per-round evidence"; 不得表述为三轮整体偏离) |
| 其他 (某轮区间部分重叠或整体覆盖等效界但未完整落入) | **证据不足** |

- 区间宽 → "证据不足", **不称"不稳定"**, **不称"等效"**, **不降低等效标准**。
- 判定只在数据落盘后按本表机械执行; 不允许事后新增口径、事后选轮、事后改 ε。
- 预期算术提示 (写进 protocol.json, 防止事后惊讶): 三轮间 `D_r ≤ 26` 的条件区间半宽约 ≤ 2pp, 原则上可判, 但实际 `D` 由生成噪声决定, 若 `D` 接近 Phase 4-A 量级 (≥100) 则必然落"证据不足"。

### 2.6 R1b — 重复生成一致性 (正式报告部分②)
| 指标 | 定义 |
|---|---|
| 3/3 pass / 3/3 fail / mixed | 三轮逐题计数 + 一致性比例 `(3pass + 3fail)/260` |
| 三轮通过率及区间 | `P_r1, P_r2, P_r3` 及各自 CP 区间; 是否两两重叠 |
| 两两配对 | `Δ_r1r2, Δ_r1r3, Δ_r2r3`: 净增益题数、不一致对数、条件精确区间 |

R1b 回答"固定 Skill 在独立生成中的输出一致性", 与 R1a 的"复现 Phase 4-A"是两个问题, **分别报告, 不合成单一分数**。

**R1b 的可推断性边界 (v3 新增):**
- 三轮通过率的 CP 区间**重叠 ≠ 两轮无差异检验**; 正文只能写"区间重叠 / 不重叠", 不得写"通过率无显著差异"。
- 两两配对 (r1–r2, r1–r3, r2–r3) 在**同一题**上的结果: 报告净差题数 (pass→fail 减 fail→pass)、条件精确区间, 并附精确 McNemar 检验 `p = min(1, 2·Σ_{i≤min(a,b)} C(a+b,i) / 2^{a+b})` (a/b = 两方向不一致对数)。
- **R1b 只作描述性报告, 不作显著性筛选**: 三组两两检验不作 Bonferroni, 也不据此下"三轮一致 / 不一致"的判定; 正文须写明 "descriptive only; no multiplicity-adjusted inference across the three pairwise comparisons".
- R1b **不是**第二个等效判定标准, 不得用 R1b 的结果改写 §2.5 的判定。

## 4. RQ3 — 算法主体变化 (body diff, 探索性)

### 4.1 可比较范围 (先于任何 diff 计算确定, 不得事后扩大; D5 = 不追加基线生成)
对某题某轮, 若**同时**有 (i) Arm1 该轮抽取代码, (ii) S₀ 抽取代码, (iii) 两者 `class_defined ∧ method_defined ∧ parse_ok` 为真 → 可比较。

**已知覆盖 (v3 订正)**: `s0_cache_test_d5.json` 300 条中有 **26 道 class 题**带完整 response+code; 与 Arm1-only 81 子集交集 **10 道** (均 Arm1 pass); 与"Arm1 ∧ SkillOpt 均 pass"交集 3 道。
→ 预期可比较子集 **≤ 10** 题, 且**新生成的 Arm1 response 不能补齐历史基线 response**。
→ 本方向 A2 **不追加任何基线生成**; RQ3 结论只能为"不可判定"或用 ≤10 道做描述性示例, **不得外推**。

### 4.2 分类规则
比较单位: `class Solution` 内每个**方法体**; 基线有而 Arm1 无 / 反之, 记"结构变化"。
有序规则 (只取第一条命中):

| 类 | 名称 | 规则 |
|---|---|---|
| C0 | 无变化 | 方法体 AST 归一化后完全相同 (忽略注释/空行/文档字符串) |
| C1 | 包装变化 | 方法体 (去 docstring) **逐语句相同**、参数仅多出/去掉 `self`, 而函数所在容器不同 (顶层函数 ↔ `class Solution` 方法); 容器之外的内容不参与判定 |
| C2 | 签名变化 | 方法名相同, 参数名/默认值/注解不同, 方法体 C0 |
| C3 | 局部语法变化 | 方法体 AST 有差异但**语句类型多重集、复合语句嵌套骨架、If 条件与 for 迭代表达式 (alpha 归一化后) 全部相同**; 典型为变量重命名、`list()`↔`[]`、等价表达式改写 |
| C4 | 核心算法逻辑变化 | 其余一切 (语句增删 / 控制流结构不同 / 条件或迭代表达式改变 / 数据结构替换 / 复杂度级不同) |

- 不可判定的记 `C?`, **不得**强行归入 C0 或 C4; 不强制分类没有历史 response 的题。
- **双轨复核 (D6)**: 脚本初判 + **双人独立复核**; 复核不一致由**固定第三人仲裁**, 分歧全部记录在案。复核范围: 全部 C0/C1 + 20% 随机 C3/C4。
- 仅对 Arm1 pass 的题做 diff 会产生幸存者偏差 → 见 §4.4 扩展表。

### 4.3 分类示例与判定原则

**总原则 (v3 新增, 写入 protocol.json 与复核记录模板):**
1. 分类依据是**可观察到的代码差异**, **不得**根据 pass/fail 结果倒推代码变化类型。
2. 双人独立复核时**先各自分类**, 再交第三人仲裁; 分类前不得接触该题的通过/失败结果与 Arm1 相对基线的胜负。
3. 任一题在两个维度同时变化时, 按 §4.2 的有序规则取**第一条命中**, 并在复核记录中注明"多重差异"。

**统一记录结构 (每类每格必须七项齐全, 缺一项不得冻结):**
`最小原始代码 / 最小生成代码 / 变化点 / 预期类别 / 判定依据 / 边界说明 / 单元测试`

全部用例实现于 **`eva/direction_a_bodydiff.py`** 的 `CASES` 表, 用例名与下表一一对应;
`python eva/direction_a_bodydiff.py` 必须输出 `18 ok, 0 failed; boundary asserts passed`。
**通过该脚本只说明分类规则的实现符合本节预期, 不能替代 D6 两名独立复核人 (Reviewer 1 / Reviewer 2) 的人工一致性检查。**

| 边界说明 | ① 仅注释/空白/格式 → **不得**判 C4 (归 C0); ② 仅标识符改名 → **不得**判 C4 (归 C3); ③ 方法集合变化 (基线有而 Arm1 无 / 反之) 亦按 C4 处理并标注"结构变化" (§4.2) |
| 单元测试 | `C4 正例: 暴力 -> 哈希表`; `C4 反例: 仅注释扰动 -> C0 (不得 C4)` |

| 最小生成代码 | `class Solution: … return [` (语法错误); 或删除 `class Solution` 的顶层 `def twoSum(...)` |
| 变化点 | 代码不完整 / 无法解析 / 无法与基线对齐方法 |
| 预期类别 | **C?** |
| 判定依据 | 解析失败; 新代码无 `class Solution` 或无任何方法; 基线与新代码均无可用对齐单元; 两侧方法都不止一个且无同名交集 |
| 边界说明 | **C? 与 C4 不得混淆**: 无法分类只表示**证据不足**, 不表示算法逻辑发生变化; **禁止**把 C? 并入 C4 或 C0; 省略体 (`...`) 也不得判 C0 |
| 单元测试 | `C? 正例: 无法解析`; `C? 反例: 缺 class Solution 不得归 C0`; `C? 边界: 基线既无类也无顶层函数`; 显式断言 `省略体 ( ... ) 不得判为 C0` |

**判定的舞台范围**: 只比较 `class Solution` 内方法 (或基线为顶层函数时的同名/单函数对齐); 模块级导入、辅助类、`if __name__ == "__main__"` 块不参与分类, 但若其差异导致无法对齐, 记 C?。

**分类边界覆盖审查 (用户要求步骤②, 2026-11-23):**

| 边界 | 结论 | 保障 |
|---|---|---|
| C0 / C3 | 改名既非"完全不变"也非"局部语法修复之外" | 规则 C0 只做去 docstring, **不做** alpha 重命名 → 改名必落到 C3 |
| C1 / C2 | 补壳会改变参数列表 (加 `self`), 但**不是**签名变化 | C1 先于 C2, 且在 `wrapper_kind` 中显式扣除 `self` 后再比较其余签名位 |
| C1 / C4 | 补壳同时改方法体 | `wrapper_kind` 要求方法体逐语句相同, 否则返回 None → 落到 C0–C4 规则 |
| C2 / C3 | 签名与改名同时发生 | 取 C2 (更高类); 参数名不计入签名键 |
| C3 / C4 | 表面差异大但结构同 → C3; 语句增删/迭代范围变 → C4 | `structure_key` 三重比较 (多重集 / 骨架 / 条件与迭代表达式) |
| C4 / C? | 不可判定不得算作算法变化 | `classify` 所有异常与对齐失败分支一律返回 C?; 永不返回 C4 |
| C? / C0 | 解析失败或省略体不得当作"无变化" | 显式断言 `...` 不等于 BASE |

**已知遗漏 (已记录, 冻结前由 D6 复核人重点核验):**
1. **数据结构替换但语句结构不变** (例: `seen = {}` → `seen = []` + `seen.index(...)`): 规则判 C4 依赖语句多重集变化; 若替换后语句种类与数量恰好一致, 脚本可能判 C3。人工复核须以"关键数据结构的语义"为准; 脚本不得作为最终裁决。
2. **`while` 循环头不比较**: for→while 改写时 `while` 的条件未纳入 `structure_key` (其语句增删已足以判 C4), 但若出现"零增删的 while 改写"会落到 C3 — 此类情况在复核记录中标"多重差异"。
3. **嵌套函数/闭包内部的语句** 会进入多重集统计, 定义位置迁移可能被计为语句增删 → C4; 该保守偏差记录在案, 不修正 (宁可高估为 C4 而非低估)。

### 4.4 分析表 (v3 扩展: 纳入 Arm1 fail 的题)
| Arm1 该轮最终结果 | Diff 分类 | 解释 |
|---|---|---|
| pass | C0/C1/C2 | 入口或包装变化后通过 |
| pass | C3/C4 | 存在局部或算法主体变化 |
| **fail** | **C0/C1/C2** | **代码结构变化不足以解决问题 (补壳了仍 fail)** |
| fail | C3/C4 | 算法主体变化仍未带来通过 |
| 任意 | C? | 证据不足, 不强制归因 |

### 4.5 判定 (预注册)
- **探索性机制分析**, 不升级为正式算法逻辑因果检验。
- 可比较子集 < 20 题 → 结论一律写 **"不可判定 (insufficient comparable responses)"**, 不做比例推断。
- 不做不对称 diff: 不得因 Arm1 response 完整而基线缺 response, 就与基线缓存代码直接 diff 后推断"变化来自 Evolver"。

## 5. 统计单位、主分析集与缺失处理 (v3 全面改写)

### 5.1 统计单位
**题** (n = 260)。重复轮次以配对方式处理; **不把 260×3 当独立样本**。

### 5.2 主分析集 = 全部 260 道 (固定, 不筛选)
| 结果类型 | 主分析处理 |
|---|---|
| evaluable, 最终通过 | pass |
| evaluable, 最终失败 | fail |
| `gen_empty` | L0 failure (fail) |
| NameError / 缺少 `Solution` | 接口失败 (fail, **不排除**; RQ2 单列层级) |
| 其他模型执行错误 | 按对应漏斗层级记录, **不排除** |
| `infra_fail` (重试后仍无响应) | **缺失**, 逐题披露 |

- **不使用 all-3-valid 作为主分析集**。理由: 127/260 类题三臂全 fail; `agent_ok=False` 既包含 infra, 也包含"模型自己写不出 `Solution`"——后者正是 RQ2 的观测对象, 不能以"valid"名义删除。
- 门控规则 (替代 valid): 只有 §7.1 定义的 `infra_fail` 才进入缺失; 所有 `evaluable` / `gen_empty` / 模型侧错误一律留在 260 内。

### 5.3 三种报告口径 (固定, 同时呈现)
1. **主报告**: 全部 260 题, 逐题列出最终状态; 报告 pass 数 / fail 数 / infra 缺失数 (每轮)。
2. **保守下界**: 未解决的 infra 缺失按 fail 处理, 计算协议级通过率下界。
3. **条件性敏感性**: 仅在 evaluable-only 子集上计算通过率, 明确标注 `evaluable-only`, 不作为主结论。

### 5.4 配对统计中的缺失 (v3 新增: 完整计算定义)

记本轮 (新生成的 Arm1 第 r 轮) 与参照 (Phase 4-A Arm1 归档) 的每题状态:
`pass` / `fail` / `infra_missing`。对每个题 i, 配对单元为 `(new_i, ref_i)`。

**1) 分类 (互斥, 5 类 + 2 类缺失)**

| 单元类型 | 条件 | 是否进净增益 |
|---|---|---|
| `both_pass` | new=pass, ref=pass | 分母, 贡献 0 |
| `both_fail` | new=fail, ref=fail | 分母, 贡献 0 |
| `rescue` | new=pass, ref=fail | 分母, 贡献 +1 |
| `regress` | new=fail, ref=pass | 分母, 贡献 −1 |
| `missing` | new=infra_missing, ref ∈ {pass,fail} (或反向) | **不进** |
| `both_missing` | new=infra_missing, ref=infra_missing | **不进** |
| `ref_unrecorded` | ref 无归档记录 | **不进** |

- `rescue + regress` 即 §2.3 的 `D_r` 的基础; 但**只有无缺失的题才参与** `D_r` 与条件区间计算。
- `missing` / `both_missing` / `ref_unrecorded` 一律**不得**计为 discordant pair。

**2) 三种口径的公式 (写明分母, 不允许静默换分母)**

| 口径 | 净增益 `g` | 率 | 区间 | 分母 |
|---|---|---|---|---|
| **主口径** (complete-pair) | `g_main = n_rescue − n_regress` | `g_main / n_complete` | 条件精确区间 (CP on rescue/(rescue+regress), 再仿射) | `n_complete = n_total − n_missing − n_both_missing − n_ref_unrecorded` |
| **保守下界** | `g_cons = n_rescue − n_regress − #{new=infra_missing ∧ ref=pass}` (new 侧缺失按 fail 计) | `g_cons / 260` | 只报点估计 + 区间端点连同口径变化, **不另造区间** | 固定 260 |
| **evaluable-only** | `g_eval = n_rescue − n_regress` (= `g_main`); ref 无归档 (或 itself infra) 的题**既不进分子也不进分母** | `g_eval / n_complete` | 条件精确区间 (与主口径同法) | `n_complete` (双方均有可评测结果) |
| (参考) **全 260 分母** | `g_main` | `g_main / 260` | 仅报点估计, 不加区间 | 固定 260 |

- 三种口径**同时呈现**, 主结论用主口径, 保守下界/evaluable-only 作为敏感性; 不得只报有利的一个。
- **保守口径的净增益** `Δ_r^cons = g_cons / 260` (见上表行 2): new 侧缺失且 ref=pass 的题被计为 regress (最不利假设)。
  正式等效检验 (§2.4) 只对**主口径**的 `CI(Δ_r)` 做; 保守口径只作敏感性, 不改变 §2.5 判定。
- 由于 Phase 4-A 归档覆盖全部 260 题, 正常情况下 `n_ref_unrecorded = 0`; 若不为 0, 说明归档不完整, 须在报告中单列并在 §11 复核。
- 若 `n_complete / 260 < 0.9`, 主口径的结论须加脚注 ">10% items missing; interpret with caution", 且不得以主口径单独下"等效支持"。
  (2026-11-23 用户裁定: dry-run 已关闭, 但本条**保留为强制约束** — 缺失比例警示不能省略, 不得仅凭完整配对样本得出等效支持。)
- `g_cons` **只是保守敏感性分析**: 不得替代主分析的统计推断, 不得用于 §2.5 判定, **也不得反向改变** §2.5 的判定结果 (即不得因 `g_cons` 更不利而把"等效支持"改判)。

**3) 闭合断言 (每轮强制)**
```
n_complete + n_missing + n_both_missing + n_ref_unrecorded == 260
pass_r + fail_r + infra_missing_r == 260        # 与 5.3 口径一致
n_rescue + n_regress + n_both_pass + n_both_fail == n_complete
```
- **两侧都缺失** (`both_missing`) 单列计数, 既不计 pass 也不计 fail, 并在正文点名题号。
- `ref_unrecorded` 指 Phase 4-A 该题没有归档结果; 这类题不参与 RQ1 的 Δ 计算, 但仍在 260 主报告中出现。
- 完整性: 不许删题; 除 §7.1 的 infra 规则外不得剔除任何题。

## 6. 预算估算 (估算, **非授权**; D8 暂不授权)

**单位口径 (2026-11-23 用户裁定): 864 = 全部 HTTP 请求的硬上限, 不是 864 次成功生成。**

| 项 | 计算 | HTTP 请求数 |
|---|---|---|
| Arm1 生成 (初始请求) | 260 题 × 3 轮 | 780 |
| C 模型评判 | 不调用 (harness 直接判) | 0 |
| 离线重判 | 本地子进程 | 0 API |
| E0 冒烟 (D7) | 3 题 × 2 轮, 独立检查 | 6 |
| 重试预留 | 每题每轮最多 1 次重试 (§7.1), 上限即 780 × 0.1 | ≤ 78 |
| **合计硬上限** | 初始 + 冒烟 + **全部重试** | **≤ 864 次 HTTP 请求** |

- **864 是请求上限**: 重试预留的 78 次与初始 780 次、冒烟 6 次共用同一池, 重试**不得**突破该池。
- **达到 864 立即停止**; **不自动追加额度**, 不因实验未完成、结果不理想或重试需要而突破上限。未完成的题按 §7.1 计为 infra 缺失, 并在报告中点名题号, 不得补跑、不得因缺题而改变分母。
- 若实际需要的请求数 (780 + 6 + 实际重试) 逼近 864, 须在运行日志中预警并停止新增轮次, **不得**以"再补一点额度"的方式继续。
- 计费记录: 每次请求记录输入/输出 token 与耗时; 若按 token 计费, 保留可核算的费用公式 `费用 = Σ_t (in_t × 输入单价 + out_t × 输出单价)`, 单价由用户授权时提供, 写入 `protocol.json`。
- 冒烟 6 次**不进入主分析**, 结果只用于核对 E0 指纹与实际生效参数。
- **预算上限 ≠ 实际需要 ≠ 执行授权**; 未获授权前 0 调用。864 在授权前一律标注为**估算**, 核对后经用户书面确认方可成为执行预算。

## 7. 执行协议: 异常、重试、计费、落盘 (v3 修订 §7.1 / §7.3)

### 7.1 调用失败分类与重试计数 (统一为一套)
| 类 | 判据 | 处理 | 计入 fail |
|---|---|---|---|
| `infra_retryable` | 网络错误 / HTTP 5xx / 429 / 超时 / **空 response** | 重试 **至多 1 次** (见下) | 否 |
| `infra_fail` | 重试后仍失败 | 记录, 该题该轮标缺失 (不是 fail) | 否 |
| `gen_empty` | 有 response 但 `extract_code` 为空 | 记为 L0 失败 | **是** |
| `evaluable` | 有可解析代码 | 正常评测 | 视结果 |

**重试计数口径 (v3 订正)**: "每题每轮最多 1 次重试" = **首次请求之外最多再发 1 次**, 即该题该轮最多 **2 次 HTTP 请求**。
- 运行入口须把 harness `eval_independent` 的 `infra_retries` 显式置 **0**, 由协议层统一执行"首次 + 1 次重试"; 不得两层叠加成最多 3 次。
- protocol.json 记 `retry_policy = {max_attempts_per_item_round: 2, infra_retries_in_harness: 0}`, 并在 logs 记录每次尝试。
- **禁止**因评测结果不好而重试; 重试只针对 infra。
- 重试产生的新生成**覆盖**首次失败结果 (不保留"两次都算"), 同时保留首次失败记录在 logs (不应答选择)。

### 7.2 重复生成
- K=3 = 每轮从零生成; 不允许 best-of-k。
- 每轮落盘完整 original response (未截断), 不依赖 fail_reason 的 -200 尾部 (issue #108)。

### 7.3 落盘格式 (`runs/<ts>/`)
```
protocol.json               # E0 指纹 + 实际生效参数 + retry_policy + 命令 + 时间 + 两份 ID 清单 hash
responses/r{k}/{id}.json    # 元数据 (model id, 请求时间, usage, finish_reason, attempt 次数)
                            # + raw response + extracted code + ast ok + 结构向量 + 完整 stderr
results/r{k}/results.json   # hard/soft/pass_rate/fail_reason/route/input_form_hash/L0-L2 指标/状态
results/r{k}/e0_check.json  # 该轮启动前重算的 E0 指纹
logs/run.log                # 全程日志 (含每次调用的 attempt 与失败原因)
analysis/                   # RQ1 (R1a/R1b/正式等效检验) / RQ2 / RQ3 表 + 图
```
- `stderr` 存**完整**文本 + harness 路由 (`fn_call` / `stdin`) + 截断版 test_code hash。
- 不含 API key; key 只从环境变量 `QWEN_CHAT_API_KEY` 读取, 不写盘、不打印。

### 7.4 断点续跑
- 每题每轮独立文件; 启动时扫描已有结果, 跳过已完成项; **已完成的 infra_fail 不自动重跑** (否则等于改变样本), 除非整轮重启。
- 续跑前核验 E0 指纹一致, 不一致拒绝续跑。
