## 2. RQ1 — 固定 Skill 的推理生成稳定性 (k=3)

### 2.1 定义
**这是"同一 Skill、同一题集、同一生成配置下, 三次独立生成之间结果是否一致"**, 不是 Evolver 训练过程的可复现性。

### 2.2 设计
- 260 题 × 3 次独立生成 (r1, r2, r3), 顺序: 逐题串行推进 (题 1 的 r1,r2,r3 → 题 2 的 r1,r2,r3 …, 或按轮次整批推进? **决策项 D1**), 每次均为全新调用, 不复用任何缓存。
- 每次生成的结果独立评测 (`_evaluate_d5`), 产出 hard / pass_rate / fail_reason / 结构特征 / 完整 stderr。

### 2.3 指标 (统计单位 = 题, n=260)
| 指标 | 定义 |
|---|---|
| `P_r` = 第 r 次 class 通过率 | 260 题中 hard=1 占比, 附 Clopper-Pearson 95% 区间 |
| 三轮一致性 | 三轮都 pass / 三轮都 fail / 混合 的题数; 一致性比例 = (都是 + 都fail)/260 |
| `Δ_r1r2, Δ_r1r3, Δ_r2r3` | 逐题配对净增益 (r_i pass 且 r_j fail 数 − 反之数), 及其条件精确区间 (与 Phase 4-A 同法: 条件化于不一致对数 d 的 CP 再仿射) |
| 与 Phase 4-A 的一致性 | 各轮 vs Phase 4-A Arm1 原结果的配对净增益及区间 |

### 2.4 判定 (预注册)
- **通过**: 三个 Δ 的 95% 区间均落在 §6 预注册等效界 `[−ε, +ε]` 内, **且** 三轮 `P_r` 的点估计与 Phase 4-A Arm1 class 通过率 (132/260 = 50.8%) 的差异均不超过 ε。
- **不通过**: 任一 Δ 区间整体越出等效界, 或以任一方向跨出 ε。
- **未决**: 区间跨出等效界但覆盖 0 → 报告为"生成噪声不可排除, 未达预注册稳定性标准", 不追加重复以凑结论。
- **不因 RQ1 不通过而推翻 Phase 4-A**: Phase 4-A 结论独立成立, 新结果单独报告 (见 §8)。
- ε: **决策项 D2**, 建议 5pp (= 13 道题)。

### 2.5 禁止
- 不因前两轮结果好而加做第四轮; 不在看到部分结果后调整 k、ε 或抽样。
- 不做"最好一轮"式的择优报告; 三轮全部呈现。

## 3. RQ2 — 接口修复归因 (三级指标)

### 3.1 指标 (每题每次生成, 统计单位 = 题 × 重复)
| 级 | 指标 | 判定规则 (离线计算, 复用 harness 同源函数) |
|---|---|---|
| L0 可解析 | `parse_ok` | `_skillopt_extract_code(response)` 返回非空 **且** `ast.parse` 成功 |
| L1a 接口定义 | `class_defined` | 解析出的 AST 中存在 `class Solution` (含 `pass` 空类也算定义) |
| L1b 方法可用 | `method_defined` | `class Solution` 中有名为 `fn_name` 的方法; `fn_name` 来自 `_d5_extract_sig(question)` (与 harness 完全同源) |
| L1c 入口可执行 | `instantiation_ok` | 单对隔离子进程: `sol = Solution(); sol.<fn>(*args)` 不抛异常 (代表对 = 每卷第 1 对) |
| L2 最终通过 | `hard` | harness 原判: 全对通过为 1 |

层级是有序的: 未达 L1a 不可能达 L1c; 逐级报告绝对数与条件比例 (条件于上一级)。
另报告 `extract_sig` 失败题数 (harness 记 `NoSignature`, 这类题不进入 L1b/L1c 口径)。

### 3.2 逐题结构 diff (回答"是否只是补了壳")
对每 (题, r) 记录代码结构向量: `Solution` 是否存在、方法列表、方法签名 (参名/默认值)、是否含 `__main__` / `input()` / `sys.stdin`、顶层可执行语句数。
与 S₀ / SkillOpt 的**逐题**记录 (有 response 时) 对比; 无 response 时只报告 Arm1 侧结构分布。

### 3.3 判定 (预注册)
- **入口修复主导**: 在 S₀ 与 SkillOpt 均 fail 的 81 题 (Phase 4-A 分组 R_O) 中, 三轮合并 (或以 r1 为主报告) 的 `class_defined ∧ method_defined` 比例 ≥ π0 (**决策项 D3**, 建议 π0 = 0.8), 且 L0 未通过 (无法解析) 的比例 ≤ 5%。
- **报告要求**: L0→L1c 逐级漏斗图 + 条件比例; 任何一级的大幅流失都必须单独说明。

## 4. RQ3 — 算法主体变化 (body diff)

### 4.1 可比较范围 (先于任何 diff 计算确定, 不得事后扩大)
对某题某轮, 若**同时**有 (i) Arm1 该轮的抽取代码, (ii) S₀ 的抽取代码, (iii) 两者的 `class_defined ∧ method_defined ∧ parse_ok` 均为真 → 可比较。
**已知覆盖**: 现有 S₀ response 仅 `s0_cache_test_d5.json` 中 300 题 (其中 class 题 2 道)。
→ **RQ3 的预期可比较子集 ≈ 2 题, 基本不可用**。这是本协议的**已知限制**, 不是待解决的工程问题。
若用户在定稿时愿意为 S₀/SkillOpt 追加同协议生成 (**决策项 D5**, 会显著增加预算, 且会计入新调用), 可比较子集才扩大; 不批准则 RQ3 结论只能为"不可判定", 不得用 18 道抽样外推。

### 4.2 分类规则 (冻结前需在 doc 中给出示例, 见 §4.3)
比较单位: `class Solution` 内每个**方法体**; 基线有而 Arm1 无 / 反之, 单独记为"结构变化"。
逐方法按以下**有序**规则判定 (只取第一条命中):

| 类 | 名称 | 规则 |
|---|---|---|
| C0 | 无变化 | 方法体 AST 归一化后完全相同 (忽略注释/空行/文档字符串) |
| C1 | 包装变化 | 方法体仅在 `self.` 调用名别名、`Solution()` 外部包装、类定义位置/导入语句上不同; 函数体顶层语句序列不变 |
| C2 | 签名变化 | 方法名相同但参数名/默认值/注解不同, 方法体 C0 |
| C3 | 局部语法变化 | 方法体 AST 有差异, 但归约后 (去掉变量重命名/解包至多一层) 与基线等价: 差异 = 变量重命名、`list()`↔`[]`、条件写法、循环改写且控制流图相同 |
| C4 | 核心算法逻辑变化 | 其余一切方法体差异 (控制流图不同 / 语句增删 / 数据结构替换 / 复杂度级不同) |

- **不可归一化判定的**: 记为 `C?` (待核), **不得**强行归入 C0 或 C4。
- 分类由**脚本 + 人工复核双轨**: 脚本出初判, 人工对全部 C0/C1 与 20% 随机 C3/C4 复核; 复核不一致的记录在案并由固定第三人裁定 (**决策项 D6**: 谁做复核)。
- 只回答"是否变化", **不回答"变化对不对"**。

### 4.3 冻结前必须写入的示例 (占位)
- [ ] C0 正例 (同一算法不同变量名 → 应为 C3 反例)
- [ ] C1 正例 (仅补 `class Solution` 壳而方法体原样)
- [ ] C3 正例 (for 改 while, 控制流相同)
- [ ] C4 正例 (把暴力改成 DP)
- [ ] C? 例 (注释掉一半逻辑导致 AST 缺语句但语义不明)

### 4.4 判定 (预注册)
- 描述性为主: 报告 C0–C4 分布及其与"通过/不通过"的交叉表。
- 若可比较子集 < 20 题: 结论一律写 **"不可判定 (insufficient comparable responses)"**, 不做任何比例推断。

## 7. 执行协议: 异常、重试、计费、落盘

### 7.1 调用失败分类
| 类 | 判据 | 处理 | 是否计入 fail |
|---|---|---|---|
| `infra_retryable` | 网络错误 / HTTP 5xx / 429 / 超时 / 空 response | 立即重试, **每题每轮最多 1 次**; 再失败 → `infra_fail` | 否 |
| `infra_fail` | 重试后仍失败 | 记录, 该题该轮排除于主分析集 | 否 |
| `gen_empty` | 有 response 但 `extract_code` 为空 | 记为 L0 失败 | **是** (属模型行为, 不是 infra) |
| `evaluable` | 有可解析代码 | 正常评测 | 是/否视结果 |

- **禁止** 因评测结果不好而重试; 重试只针对 infra。
- 重试产生的新生成必须**覆盖**首次失败的结果, 不保留"两次都算" (避免选择性报告); 同时记录重试次数。

### 7.2 重复生成
- "K=3 独立生成"指每轮从零生成; 不允许多采几次取最好 (best-of-k) —— 那会把 RQ1 变成"best-of-3 稳定性", 语义不同。
- 每轮落盘完整 original response (未截断), 不依赖 fail_reason 的 -200 尾部 (issue #108)。

### 7.3 落盘格式 (`runs/<ts>/`)
```
protocol.json           # E0 全部指纹 + 代码 sha + 命令 + 时间
responses/r{k}/{id}.json  # 元数据 + raw response + extracted code + ast ok + 结构向量 + 完整 stderr
results/r{k}/results.json # 每题 hard/soft/pass_rate/fail_reason/route/input_form_hash/L0-L2 指标
logs/run.log              # 全程日志 (含每次调用的重试)
analysis/                 # 离线分析产物: RQ1/RQ2/RQ3 表 + 图
```
- `stderr` 存**完整**文本 (不截断) + harness 侧记录的路由 (`fn_call` / `stdin`) 与截断版 test_code hash。
- 不含 API key; key 只从环境变量读取 (`QWEN_CHAT_API_KEY`), 不写盘、不打印 (安全约束)。

### 7.4 断点续跑
- 每题每轮结果独立文件; 启动时扫描已有结果, 跳过已完成项。
- 重跑前必须核验 `protocol.json` 的 E0 指纹与本轮一致, 不一致拒绝续跑。
