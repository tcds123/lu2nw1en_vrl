## 一、候选池准入（pool_filter）：从设计到受控对照

### 1.1 设计动机

9/14 末定位 val→test 负迁移的上游缺陷：非 LOST 候选无差别 full-keep 入 archive，无质量/多样性把关，导致劣质与有毒候选混入池，被下游晋升、交叉、pop 采样反复复用（方向E 毒段放大即此链条）。pool_filter 设三关，全部 gate `archive.append`：

| 关 | 机制 | 语义 |
|---|---|---|
| ① 质量关 | `child_delta ≥ −eps`（eps=0.02≈1σ） | 候选相对父不显著恶化 |
| ② 5峰尖峰关 | ∃某维 bootstrap CI 下界>0 | 候选在某一关注点维度有可信尖峰信号 |
| ③ git-diff 多样性关 | 与已有池成员文本相似度 <0.95 | 候选与池中文本差异足够 |

8 维分峰方案（纯题目特性，meta 仅全无内容关键词时回退）：[0] implication 14 / [1] existence 21 / [2] quantifier 17 / [3] regularity 5 / [4] sharp 0 / [5] meta 9 / [6] domain 2 / [7] classification 3，最终归并为 5 峰（4 内容维 + 1 结构维）+ 2 几何信号。

### 1.2 单 run 方向性达成（9/15）与勘误（9/16）

9/15 pool_filter 上线 run（PID 38894，8 iter）best val Δ+0.343，4-seed test mean=**0.5645**，略越 theo_iter6 0.5542（+0.0103）、skillopt 0.5629（+0.0016）。但 9/16 核查 `evolver_log.json` 推翻此前记忆的两个前提：**非续跑 theo_iter6，而是从 S₀ 从零独立 run**（`init_skill_hash=68571cb2a6`=S₀）；**非唯一变量**（`expand_every` 1 vs 2 + 期间代码大改）。三份记忆就地加更正框。算法方向性正确（两条独立从零轨迹都 ≥0.5542），但 pool_filter 净效应**待受控对照坐实**。

### 1.3 严格受控对照（9/16-17）：ON +15.6pp 显著

为坐实净效应，9/16 18:18 两臂从同一 S₀ + 同一现场重生成 cache 并行起跑，argv 完全相同（iters8 K4 eval_k3 n_diag8 train_n35 facet_tree expand），**唯一变量 ON 多 `--pool_filter`**。各 ~8h evolver → 4-seed test（test=106, k=3, seeds=4）→ ON−OFF 配对 bootstrap CI。

**val 层面**：ON best_val_delta=+0.408（CI+0.310）几乎为 OFF +0.211（CI+0.131）的 2×，skill 更精炼（2610 vs 3503 chars）。

**test 层面**（未打乱评测下，数字真实）：

| | OFF | ON |
|---|---|---|
| evolver mean_pass | 0.4308 [0.440,0.425,0.409,0.450] | **0.5873** [0.616,0.594,0.572,0.566] |
| ΔvsS0 | +0.1281 | +0.2925 |

**配对统计**：ON−OFF mean Δ=**+0.1564**，bootstrap 95% CI=[+0.1297,+0.1730] 下界>0 显著，paired t=11.50 p=0.0014，Δ(ΔvsS0) 扣 s0 基线 +0.1643 CI[+0.142,+0.188] 仍显著，4/4 seed ON>OFF 一致。

看似一次干净的算法胜利。**但这个结论当天就被推翻——见下节。**

### 1.3.1 ON/OFF 变量到底差在哪——两份 skill 逐段对照（9/22 核查补录）

§1.3 的"+15.6pp"看起来是"开关一拨就涨"，但 pool_filter 没改 skill 模板，改的是"哪些段能进 archive → 哪些段被选中 → 最终进化出的 skill 终态"。三关压制劣质段进池，使两臂**殊途收敛到不同的 skill 文本**。这才是 ON/OFF 的实质差别。

**实验变量层**：两臂 argv 完全相同（iters8 K4 eval_k3 n_diag8 train_n35 facet_tree expand，同一份 S₀ cache 双臂共享），唯一差别 = ON 开 `--pool_filter`（质量关 + 5峰尖峰关 + git-diff 多样性关，eps=0.02），OFF 关。**两臂都跑完整 evolver、都进化出 skill**，不是 ON 有 skill / OFF 没 skill。

**skill 内容层**（两份 `best_skill_evolved.md` 逐行核对，ON=2629B/hash fa63335e，OFF=3519B/hash e24d3538a3）：

| 段 | ON 臂（开 pool_filter） | OFF 臂（关 pool_filter） |
|---|---|---|
| L1 标题 | `# Live Mathematical MCQ Heuristics` | 同 |
| L3-5 Option Comparison（meta 规则） | **祈使断言式**："...this option **should be selected**"（应被选中）→ 模型读到倾向直接选 | **审慎条件式**："...this is a meta-statement that **must be evaluated** by checking if any other option is both correct and maximal"（必须验证）→ 模型先判断再选 |
| L6-8 Theorem-Level Precision | 2 条（弱化/过强） | 3 条（多第 3 条：strict subset + sharp → 选 meta） |
| L10-12 Hypotheses | 2 条 | 3 条（多第 3 条：alert for strictly stronger → 选 meta） |
| **L16-23 第五段（分歧所在）** | **`## Implication Direction Check`** — biconditional 双向蕴含测试（iff ⇔ vs 单向 ⇒），末句锚句 "**only option A survives this two-way test**"（诊断范例 H(n,m) 的结论，非通则） | **`## Quantifier Order and Parameter Dependence`** — 量词序（∀∃ vs ∃∀）+ 相变 phase transition，末句讲 "uniform claim ... is incorrect"（无任何 option-X 字样） |
| meta 措辞总条数 | 1 处（L4） | **3 处**（L4 + L9 + L13） |

**两个核心分歧（这才是 +15.6pp 的文本根因，而非开关本身）**：

1. **meta 处置强度——ON 激进，OFF 审慎**。同一个 meta 信号，ON L4 进化成"见 meta 就选"（"should be selected"），OFF L4 进化成"见 meta 还得验证"（"must be evaluated"）。这就是此前记忆的"ON 写'选 meta' +0.300，OFF 只写'需检查 meta' +0.127"的文本出处——同一题面的两种 LLM 改写轨迹，在未打乱评测下直接拉开 +15.6pp。
2. **第五段是两条完全不同的数学路径**。ON 收敛到"双向测试"并留下一个带 "option A" 的锚句（即 §2.3 核查的 +0.1392 位置偏置来源，软性 anchor 非"教选 A"）；OFF 收敛到"量词序/相变"，无任何字母锚句（故 OFF A-vs-BCDE=−0.0228，无位置偏置）。两段都来自 val 集（val=training set）题面蒸馏，但内容完全不同。
3. **反直觉点**：OFF 的 skill 更长（3519B vs 2629B）、meta 措辞更多（3 处 vs 1 处），但 test 分数更低。因为 OFF 措辞是"需验证"而非"应选"，未打乱评测下不如 ON 的"应选"果断。pool_filter 压制冗余段进池，ON 反而更精炼、更激进地押 meta。

**为什么这反证 +15.6pp 不能归因 pool_filter**：两臂差不只"有没有三关"，而是"因为有没有三关 → 进化出不同 skill → 不同 skill 在 buggy 评测下得分不同"。ON 赢 OFF 主要赢在 **iter1 一次 LLM 改写把 meta 写成了"should be selected"**（运气成分），而非开关本身。shuffle 打乱后"选 meta"优势仍在（meta 检测 shuffle 不变，合法语义信号），但"选 A 位置捷径"失效，故 +15.6pp 坍缩到 +1.8pp（见 §2.3）。

## 二、评测捷径暴露：GPT review P0/P1 与 shuffle 重测

### 2.1 P0：评测存在两条捷径，主提升来自数据集伪影

9/17 外部 GPT review 以零 API 只读脚本独立复现（只读 split items.json + evaluator，不调模型）：

| split | n | gold=A | meta 选项题数 | meta 选项正确数 |
|-------|---|-------|--------------|----------------|
| train | 18 | 18/18 | 12 | 12 |
| val | 53 | 53/53 | 27 | 27 |
| test | 106 | 106/106 | 46 | 46 |

- **答案全是 A、选项没打乱**（全 100% gold=A）。**机制（9/22 原始源数据坐实）**：源数据 `livemath_raw/*/qa_*_final.json`（4 月份共 177 题）里正确答案被**单独存放在 `correct_choice` 字段**（dict，label 恒 "A" + 正文），4 个干扰项放 `choices`、label 恒 `('B','C','D','E')`，正确答案文本 **0/177 次出现在 choices 里**——正确答案与干扰项分离存放。split 构建器把正确答案拼到 choices 第一位标 A、干扰项顺移 B-E（用 `(month,no)` 联合键核对 test 106/106 命中），**未打乱顺序**。即"gold 全 A"是存储格式副作用（正确答案被独立字段存放且构建未打乱），非题目真的都选 A——正确答案**内容**各题不同，只是被统一贴了标签 "A"。`tf_global_v2_math.py:177 load_split` 直接 `json.load` 读这个未打乱的 items.json，绕过 dataloader 的 `shuffle_choices=True`。
- **meta 选项 100% 正确**：出现即正确答案。meta 占比 train 66.7% > val 50.9% > test 43.4%，单调递减；且 meta 选项恒在 A 位置、恒 == gold（split 构建置顶正确答案的副产物）。
- ON 的 +0.2925 提升约 **77% 来自这 46 道 meta 题**；OFF 的 +0.1281 约 **99% 来自这 46 题**，其余 60 题 OFF 几乎零提升。
- 无模型规则基线"有 meta 就选，否则 5 选 1 乱猜"= **0.547**（正好落在 README 记录的 ~0.55–0.57 天花板）；"有 meta 就选否则照 S₀ 答"≈0.677，**高于所有演化产物**。

**代码根因**：`tf_global_v2_math.py:177` `load_split` 直接 `json.load(open(.../split/items.json))`，绕过 `skillopt/envs/livemathmaticianbench/dataloader.py` 的 `shuffle_choices=True`（默认开，`_shuffle_item_choices` 用 `sha256(seed:item_id)` 确定性打乱 + remap `correct_choice.label`）。`evaluator.py:41-43` 按 `predicted_label == correct_label` 判分 → gold 恒 A 时模型只要倾向选 A 或选 meta 选项即命中。

### 2.2 P1："+15.6pp 归因 pool_filter"不成立

- pool_filter 在 ON run **只拒过 1 个候选**（Hypotheses 分支 CI<0），而被拒节点本就因 `val_ci>0` 被 donor 选择跳过 → filter 开关在此次 run 无任何作用路径。filter 只 gate `archive.append`（`skill_evolver_math.py:2719-2726`），promotion/TREE-BEST 用未过滤 survivors，crossover/overlay/expand 全绕过 filter。
- ON/OFF 真正差距在 **iter1 LLM 改写运气**：ON 写"选 meta 选项" +0.300，OFF 只写"需检查 meta" +0.127。同配置两次运行可差 ~15pp。
- 4 个 seed 只测评测噪声（sd≈0.014），每臂只 1 次演化，运行间方差 ~0.15 → 统计单位选错，"4-seed 配对"只坐实评测稳定性，不坐实算法效应。

### 2.3 阶段 A shuffle 重测（9/17，4-seed 坐实）

复用 dataloader `_shuffle_item_choices` 注入 evolver eval 路径，使 gold 不再恒 A、meta 位置随机化，"选 A"位置捷径失效。5 臂（s0/ON/OFF/theo_iter6/skillopt 原样不删段）+ 规则基线，分层报告 46 meta 题 vs 60 其余题：

| 臂 | 4-seed mean | meta_46 | other_60 |
|----|------------|---------|----------|
| s0 | 0.3215 | 0.201 | 0.414 |
| on | 0.4458 | 0.538 | 0.375 |
| off | 0.4277 | 0.447 | 0.413 |
| **skillopt** | **0.5613** | 0.788 | 0.388 |
| rule_meta_guess | 0.5189 | 1.000 | 0.150 |

四个核心发现（4-seed sd 全部 ≤0.024，跨 seed 稳定）：

1. **🚨 pool_filter +15.6pp 效应死亡**：on 4-seed mean=0.4458，off=0.4277，Δ(on−off)=**+0.0181**，per-seed Δ=0.003/0.022/0.028/0.019 均 ≪ 未打乱的 +0.1564，统计不可分。独立坐实 P1。
2. **🚨 平凡规则击败 on/off 两条演化臂**：rule 0.5189 > on 0.4458 / off 0.4277。零 API 规则"见 meta 就选否则乱猜"严格占优。ON 的"+0.2925 算法效应"在 on/off 两条 run 上不成立。
3. **✅ skillopt 是唯一击败规则基线的 artifact**：0.5613 > rule 0.5189（+4.2pp，3/4 seed 一致）。机制：meta_46=0.788（学得比 on/off 好但仍 < rule 1.0）且 other_60=0.388（> rule 0.150，保留真数学能力）。干净分解：skillopt other_60≈s0 other_60（略退 −0.026）→ skillopt ≈ s0 +（学到的 meta 规则），非 meta 能力没增（略减）。
4. **✅ meta 规则是 shuffle-invariant 的合法算法产物**：on/skillopt shuffle 后 meta_46 仍 >0.5（on 0.538、skillopt 0.788），证明抓的是文本语义信号而非位置。但 on/off 学的 meta 规则不够好（< rule 1.0），被平凡规则占优。

**关于 ON skill 内容的辨析（用户正确，已核查纠正）**：ON 产物 L16-20 `## Implication Direction Check` 段是 val 题 `202602:12` 内容（定理 H(n,m) abelianization），但其定理在 test 106 题出现 0 次 → **不是 test 泄漏**（对 test 分数贡献=0）；L4 `## Option Comparison` 的 meta 规则按选项文本触发、shuffle-invariant，是算法自主发现的合法产物。**故阶段 A 不删 ON skill 任何内容**，用原样 ON 跑 shuffle——shuffle 本身即去捷径（gold 不再恒 A、meta 位置随机化）。真正的去捷径是 shuffle，而非删算法产物。

**ON skill 位置偏置来源核查（9/22，用户二轮质疑后）**：用户质疑"若 skill 真教选 A，test（gold 全 A）应≈100%，但 ON 只有 ~0.59"——**此推理正确，证伪了"显式选 A 指令"假设**。读 ON skill 全文（`on_arm/run/best_skill_evolved.md`, 20 行/2629B, hash `fa63335e` = §8 实验所用），全文无任何"选 A"位置指令，grep "option A" 只命中 L20 末句 "In the diagnostic, only option A survives this two-way test."（描述某个诊断示例的结论，非通用规则）。§8 五位置数据证实 ON 在 pos0(A)=**0.6038 ≠ 1.0** → 模型没"无脑选 A"，只是对 A 有 ~13pp 轻微偏好。关键对照：**OFF skill 没有 L20 这句 anchor**（OFF 用 "Quantifier Order" 段替代 "Implication Direction Check" 段），而 OFF 的 A-vs-BCDE=−0.0228（无偏置）→ **ON 独有 anchor 句 ↔ ON 独有位置偏置**（最强 correlational 证据）。同时排除三个机械假象：evaluator 无默认-A（`parse_choice_label` 解析失败返回原 label/空串，不默认 A）、prompt 模板无 A 锚定（choices 平等列出 `{label}. {text}`）、非显式指令（那样会 ~100% 非 60%）。**最佳解释**：+0.1392 是 **L20 锚定句的软性位置泄漏**——skill 写了一个以 "only option A survives" 收尾的诊断范例，模型把示例结论软性泛化为"A 更可能对"的弱先验，在 gold 恰好全 A 的原评测上被放大 +13pp，shuffle 打乱后该先验失效（ON other_60 在 A=0.5278 vs B-E≈0.39，shuffle 后塌到与 s0 持平）。**判定：review 没判错**（位置偏置 +0.1392 实测、6× 量级独此一家），但"位置捷径"≠"明文教选 A"——是隐式 anchor 而非显式指令，量级 +13pp 而非 +100pp，论文叙事须写清是"范例锚定导致的软性位置先验"。**开放缺口**：上述 "L20 anchor → 位置先验" 是 correlational（ON 有 anchor 有偏置 / OFF 无 anchor 无偏置），非因果证明；严格因果须把 L20 末句 "option A" 改成 "option C" 重跑五位置看偏置是否迁移到 C（~2h API，待用户决定是否补）。这也为 §7 删段升 +8.4pp 补了一层解释：删 anchor 句不仅提升信噪比，还移除了位置先验源。

## 四、§10.1 多 run 方差（review #1 决定性实验）— run 级不可分 ✅

### 4.1 实验设计

回答 RF §2.2 / CF F10 的核心质疑：4-seed 只测评测噪声（sd≈0.014），运行间方差 ~0.15，单 run 能否判定"算法 A 优于算法 B"？把统计单位从"固定产物多 seed"改为"多 run"。

- on/off 两臂各 **N=2 独立演化**（facet-tree GA，iters=4），仅 `--pool_filter` 不同，其余配置同。evolver 无显式 seed → LLM 采样随机性产生 run 间方差（这正是要测的）。
- 每产物测 2 个 shuffle seed（k=3, EVAL_TEMP=0.3）→ run-level mean = 2-seed 均值。
- **统计单位 = 演化运行**（2 vs 2）。检验：Welch t + CI95 + 置换精确 C(4,2)=6 + 分层 bootstrap(2000)。N≤2 主判据 = **Welch CI95 是否跨 0 + 方向**（置换 p 结构性 ≥0.333 永不显著，仅辅证）。
- 三指标：overall（含 meta 位置捷径，上界）/ meta_46（位置捷径）/ **other_60（非 meta，真算法贡献主指标）**。
- 数据：LiveMathematicianBench split_1-3-6_seed42, n_test=106, n_meta=46。

### 4.2 各 run 三指标数值（2-seed run_mean）

| run | overall | meta_46 | other_60 | val Δ(iter4) |
|-----|---------|---------|----------|---------------|
| on1 | 0.4387 | 0.4420 | 0.4361 | +0.2535 |
| on2 | 0.3915 | 0.4058 | 0.3806 | +0.263 |
| off1 | 0.4104 | 0.4348 | 0.3917 | +0.1362 |
| off2 | 0.6022 | 0.8841 | 0.3861 | (死skill) |

### 4.3 run 级统计检验（主指标 other_60）

| 指标 | on_mean±sd | off_mean±sd | Δ(on−off) | Welch CI95 | perm p |
|------|------------|-------------|-----------|------------|--------|
| other_60 | 0.4083±0.0393 | 0.3889±0.0039 | **+0.0194** | [−0.3192, +0.3581] **跨 0** | 1.000 |
| overall | 0.4151±0.0334 | 0.5063±0.1356 | −0.0912 | [−1.068, +0.886] 跨 0 | 0.667 |
| meta_46 | 0.4239±0.0256 | 0.6594±0.3177 | −0.2355 | [−3.014, +2.543] 跨 0 | 0.667 |

### 4.4 最终 verdict

**other_60 on/off run 级不可分**：Δ=+0.0194（仅 +1.94pp，远小于此前单 run 测出的 +15.6pp），CI 跨 0，perm p=1.000。

判定依据链（三重证据一致，非统计功效不足所致）：
1. 单 run 的 +15.6pp（shuffled）是 LLM 改写运气 + 评测噪声，非 pool_filter 算法效应。
2. run 间方差（on sd=0.0393）吞没了 on/off Δ（0.0194）。
3. OFF 是死 skill（off1 四 iter 字节全同，off2 other_60 与 off1 几乎相同）→ pool_filter 在 OFF 路径无作用（只拒本就被跳过的候选）。

**对 "+15.6pp = pool_filter 净效应" 叙事的判定：叙事终结。** 2 个 on run 的 other_60 {0.4361, 0.3806} 与 2 个 off run {0.3917, 0.3861} 高度重叠，Δ 仅 +1.94pp 且不显著。pool_filter 无可重复的算法贡献信号。

### 4.5 两个尖锐的补充发现

**①指标选择会翻转表观胜者**：看 overall，on_mean=0.4151 vs off_mean=0.5063，**Δ=−0.0912，OFF 反而胜 ON**；看 other_60，Δ=+0.0194，ON 微胜 OFF。翻转根源是 off2：meta_46=0.8841（off1 仅 0.4348，学到极强位置捷径）把 overall 拉到 0.6022，但 other_60=0.3861 反而最低 → **overall 被 meta 捷径污染，绝不能作算法效应指标**，印证 review #1 对 meta 捷径的批评，也坐实 §三 Phase B 主指标改 non-meta delta 的决策。

**②val 不能预测 test（选 best-by-val 有过拟合 val 风险）**：on1/on2 的 val Δ 几乎相同（+0.2535 vs +0.263，差 0.01）但 test other_60 差 0.0556 → val/test generalization gap 本身有 run 间方差，单 run 选 best-by-val 不可靠。这为 §10.3「val≠training」实验提供了动机。
