## 三、跨轴叠加算子（overlay，算子E）机制

### 它要解决的问题：单轴隔离（改进无法跨轴累积）

先说清 overlay 为什么存在。核心算子 `facet_edit` 受 `facet_edit_guard` 物理约束：每次编辑**只能改一个命名段（slot）、其余段逐字不变、最多改一个 bullet**。这保证了一条进化线的全部修改都集中在一个轴内。副作用是：**各轴的改进彼此隔离、无法累积**。纯单轴进化的 best 必然长这样——

```
[某轴最优段] + [S0 其余所有段]
```

各轴的改进分别住在不同的 skill 里，彼此永不相遇。具体到出 8238b5e8 的 826 run：Option Comparison 轴进化到 `val_delta=0.3394`，但即便 Theorem / Hypotheses 轴各自也产出过正向 CI 的改进段，它们也无法与 Option 的改进并存于同一 skill——best 永远是 `Option-best + S0-Theorem + S0-Hypotheses`。这就是 `memory/facet-tree-no-cumulative-20260825` 记录的「单轴改进永不叠加」结构性失效。overlay（算子E，代码 `--overlay`，默认开启）即针对此缺陷设计：每代末把各轴历史最优段抽出来拼进同一 skill，只组装 + 竞争 best，不动单轴变异与 guard。

### 算法（`skill_evolver_math.py:1356-1400`，每代末执行）

下面用 826 run 的真实数字走一遍。四个轴：Option Comparison / Theorem-Level Precision / Hypotheses / Final Answer（Final Answer 冻结，不参与变异）。

**第 1 步 · donor 选取**（`select_axis_donors`，L952-982）

对每个进化轴，从 archive（keep-losers 归档，含历史全部叶）里挑出「该轴历史上最优的一个叶」作为 donor。一个叶要成为某轴 donor，须**同时过三道门槛**——

- **门槛 (i) `facet_label ∈ branch_axes`**：只取单轴叶。archive 里也有 overlay / crossover 自己生成的复合节点，它们没有单一「本轴」，不能当 donor，否则 donor 选取会自引用（overlay 选自己昨天的产物）。
- **门槛 (ii) `val_ci > 0`**：该叶的 bootstrap CI 下界为正，即改进统计上可信、不是噪声。这跟单轴 best 选取（L1293 `cd > best_val_delta and cl > 0`）口径完全一致——overlay 不另搞一套 donor 逻辑。
- **门槛 (iii) 本轴段 md5 ≠ root 段 md5**：该叶在这一轴的 slot 文本必须**真的被改过**，而不是还停在 S0 原文。这条最关键也最易被忽略：根叶（init_skill 本身）的 `val_delta` 记的是「init_skill 整体相对 S0 的增益」，不是「这一轴段的改进」。当 init_skill ≠ S0（如 826 run 从 1dbbb821 续跑，init 本身已带 +0.29 delta）时，4 个根叶会**全部白嫖这个整体增益**而过门槛 (ii)。若不设 (iii)，overlay 会把 S0 原文段当成「改进」叠进去，造成 `n_axes_combined` 虚高 + 把没动过的 S0 文本当改进的语义污染。md5 比对可靠，因为 facet 往返逐字节无损（L696 `_facet_roundtrip_assert`）。

通过三门槛的叶中按 `val_delta` 取最大。**没有 donor 的轴怎么办**——隐式回落到 `root_slots[ax]`（即 S0 / init_skill 该轴原文），不用做任何事。

> 826 iter0 实测：donors 选出 3 个轴（Option / Theorem / Hypotheses），`n_axes_combined=3`。

**第 2 步 · 组装**（L1362-1366）

```
overlay_slots = copy(root_slots)          # 从 init_skill 的全套段起步
for 每个轴 ax_key, donor dn:
    overlay_slots[ax_key] = dn.slots[ax_key]   # 用 donor 的该轴段覆写
# freeze 段不动（L1364 跳过 ax_key == freeze）
overlay_skill = facet_compose(title, overlay_slots)   # 拼回完整 skill
```

直观说：拿 init_skill 当底版，把每个 donor 贡献的那一段「换腿」式替换进去，其余段（含冻结段）保持 init 原样。没有 donor 的轴因为没被覆写，自然停留在 init 原文。

**第 3 步 · 完整性校验**（L1368-1369）

对拼好的 overlay_skill 重新 `facet_decompose`，校验拆出来的段集合 `== root_slots` 的段集合。这是防御 `facet_compose` 万一拼丢了一段（文本边界 bug）。丢段则整代 overlay 跳过，不评估。826 run 两代都过校验。

**第 4 步 · 评估与准入**（L1370-1381）

在 probe 集上评估 overlay_skill，得 pass 率 `op`、delta `od`、bootstrap CI 下界 `ol`。准入门——

```
admitted = (op >= base_pass - 0.06) and (ol > 0)
```

两个条件**必须同时满足**：① `op >= base_pass - 0.06`（LOST guard，pass 没有显著退步，容差 0.06，挡掉「叠加后整体反而变差」的候选）；② `ol > 0`（CI 下界为正，改进可信）。注意 overlay 的准入门槛**比单轴 best 门槛更松**——单轴 best 要求 `delta > best_val_delta`（要打败当前最优），overlay 只要 `admitted`（不显著退步 + CI>0）就能进 archive。这是因为 overlay 的价值在「多轴并存」本身，即便没破单轴 best 也值得留作 crossover 素材。

准入后才比 best：若 `od > best_val_delta and ol > 0` 则取代当前 best，置 `became_best=True`。

> 826 run 实测：iter0 overlay `delta=0.3268, CI=0.2535, admitted=True, became_best=False, n_axes=3`；iter1 overlay `delta=0.3239, admitted=True, became_best=False`。两代都被采纳进 archive，但都没破 best。

### 性质与诊断量：best_ratio=1.0 到底意味着什么

**对既有路径零侵入**：overlay 只组装叠加 skill 并参与 best 竞争，不改单轴变异逻辑、不改 `facet_edit_guard`、不动 leaves。`--no-overlay` 即退回纯单轴 GA，向后兼容。

**两个诊断量读什么**：

- `_facet_non_native_s0_ratio`（L1000-1025）：度量一个节点里「非本轴、非冻结、却仍是 S0 原文」的段占比。对**单轴最优 best**，除本轴外其余段全是 S0 → ratio ≈ 1.0（这正是「累积失效」的直接读数）。如果 overlay 真的把多轴改进拼进了 best，被替换段就 ≠ S0 → ratio 下降（理想 → 0）。一个精巧设计：overlay 命中 best 时节点 `facet_label="overlay"` 不在 branch_axes 里 → 没有本轴豁免 → 全部非冻结段计入分母 → ratio 能降到 0。这个量是「overlay 是否真把多轴改进固化进 best」的探针。

- `cumulative_diag.best_ratio`（L1472-1486）：**叠加 best 的 delta ÷ 单轴 best 的 delta**。`=1.0` 不是「overlay 没跑」，而是「overlay 跑了、admitted 了、但叠加后的 delta 没超过单轴最强轴的 delta」。

**为什么没超过（sub-additive）**：826 run 中 Option 单轴 best `delta=0.3394`，而 overlay 把 3 轴拼起来后 `delta=0.3268`——**拼了三个轴反而比单轴 Option 还低**。根因是失败模式高度集中于 Meta-options：Option 轴已饱和，Theorem/Hypotheses 轴的改进要么落在同一失败模式上（与 Option 重叠、信息冗余），要么本身弱。跨轴改进不可加（sub-additive），叠加不产生净增益，故 `became_best` 恒 false、best_ratio 恒 1.0、8238b5e8 最终仍是 4 段结构、未因叠加新增段。**这同时是 §二「算子触发但 sub-additive」的实测来源**：算子真的跑了（admitted=True, n_axes=3），只是没赢过单轴最优。

## 四、evolver 自身的优化内容（0.49 → 0.53 改了什么）
本节补齐这一空缺。结论先行：**三次提升全部来自同一算子 `facet_edit` 在 Option Comparison 单轴上的连续精炼，全部诊断驱动于同一类失败（Meta-options 元声明判定），内容从「启发式模式匹配」逐步改写为「可执行判定程序」**。

### 血统链（三个版本，三次同算子单轴编辑）

| 版本 | run | 生成操作 | Option Comparison 段新增内容 | test=106 |
|---|---|---|---|---|
| S0（`68571cb2`，1018字） | 起点 | — | 无 meta-claim 内容（仅2条通用 bullet） | 0.3011 |
| `abb71de55a`（1547字） | run_20260821 | `facet_edit` on S0·Option 轴 | **启发式触发识别**：「若题目问 strongest statement，立即检查是否存在声称 "a stronger result can be proven" 的选项，该选项在其余选项不可证或仅弱可证时多半正确」 | 0.4953 |
| `1dbbb821c3`（1703字） | run_20260824 iter2 | `facet_edit` on iter1·Option 叶 | **形式化定义**：把启发式改写为 meta-claim 的 iff 真值条件——「该选项正确 ⟺ 存在某个其余选项可证，且存在比它严格更强的陈述（更好常数/更宽定义域/更高正则性）也可证」 | 0.5220 |

> 826 run 的 `evolver_log.json` 确认 `init_skill_hash = 1dbbb821c3`，即 8238b5e8 是在 824 run 产物之上继续演化的，血统连续。Theorem-Level Precision / Hypotheses / Final Answer 三段在整个 826 run 中逐字未变，`cumulative_diag.best_ratio = 1.0`、`best_native = "Option Comparison"` 印证全部增益落在这一个轴。
>
> 口径注：0.3011（S0）与 0.5354（8238b5e8）为 test=106 同 seed 组、eval_k=3、4-seed 严格同口径；0.4953（abb71de55a）与 0.5220（1dbbb821）为 8-21/8-25 的 eval_k=3、4-seed 同口径但 seed 组不同。本节主张的是「内容操作化程度与 test 方向一致」的方向性结论，不依赖 S0 与 abb71de55a 的严格配对显著性。

### 算法上做了什么操作

三次编辑均为同一算子 `facet_edit`（`skill_evolver_math.py` L782-796 prompt / L1228 调用 / L863-890 guard），其机制为：

1. **诊断驱动（`make_diagnostics`，L352）**：把当前 skill 在 probe 集上答错的题逐题格式化——含定理文本、问题、选项、模型预测 vs 正确答案、模型推理摘录——拼成 `## DIAGNOSTIC FAILURES` 注入 prompt。LLM 看到的不是抽象目标，而是「这套题它现在具体错在哪」。
2. **单 slot 单 bullet 精炼**：`FACET_EDIT_PROMPT` 明令「只编辑 `{facet}` 段 / 其余逐字不变 / extend or replace at most one bullet」；`facet_edit_guard` 物理校验非目标 slot 的 md5 不变，否则拒候选。
3. **候选→评估→晋级**：候选过 guard 后在 probe 集评估（`eval_k=10`），经 LOST guard（不显著退步）与 `ci>0` 守门，取 `val_delta` 最优者晋级为该轴新叶，其余入 archive（keep-losers，供后续 crossover 备用）。

`branch_failure_types`（evolver 内置诊断探针）记录了驱动这些编辑的失败分布：826 run 的 iter1，Option Comparison 轴 **6/7 失败为 `Meta-options ('a stronger result can be proven') decision procedure`**，即模型反复在「存在更强可证结果」这类元声明题上判定错误。正是这一高度集中的失败模式，驱使 LLM 在三次编辑中逐步把该题型的处理从「看到就倾向选」改写为「按程序判定」。

### 内容演化的实质：从模式匹配到可执行程序

三次编辑在 Option 段累积的内容，恰好是同一个判定问题被逐步「操作化」的过程：

- `abb71de55a`：**触发识别**——告诉模型「这类选项多半正确」，是模式匹配式启发式，给判定结论但不给判定步骤。
- `1dbbb821c3`：**真值条件**——给出 meta-claim 成立的 iff 条件（存在可证且非最强），把「多半正确」形式化为可验证命题。
- `8238b5e8`：**判定程序**——给出三步操作（排序 → 识别最强可证 → 比较是否更强可证），把真值条件落成模型可逐步执行的 procedure。

test 随内容操作化程度单调上升（0.4953 → 0.5220 → 0.5354），且三次均为 4-seed 同口径、方向一致，说明**操作化（给可执行步骤而非给结论）是该题型上的有效优化方向**。这与 §二「算子能力边界」并不矛盾：facet_edit 能在单轴内把启发式精炼为程序（有效），但结构上无法新增 section / 领域特化（这是 skillopt 多出 6 段的所在，也是 gap 的来源）。evolver 的增益天花板因此被锁在「单轴内精炼」所能达到的上限。

## 五、8/28：算子G（展开型算子）— 实现 + API 验证

**设计决策**（采用「增加展开型算子以针对根因」的方案，不重跑判别实验——实验二已证明循环 parity 无效）：为 evolver 增设算子G（section-expansion），突破「单 slot 单 bullet」约束，使 LLM 由失败诊断驱动生成新决策程序 / 领域特化 section。`--expand` 默认关闭，向后兼容。

**实现**：新增 `EXPAND_SYSTEM`/`SECTION_EXPAND_PROMPT` 常量与 `section_expansion_guard`（构造性保证「只 add 不改」），接入主循环展开块、argparse 参数及 self-test（全部通过）。

**API 验证两轮**：
- **第一轮失败与根因确认**：2/2 expand 全部为 `llm-error`；隔离复现表明 `SECTION_EXPAND_PROMPT.format()` 必抛 `KeyError`（prompt 字面 `## {section_name}` 未转义，且 except 静默吞没异常造成误导）。已修复转义并暴露异常。
- **第二轮（重跑，约 8h40m）**：算子G **首次在运行中真正触发、被采纳（admitted）并一度成为最优 skill**（iter1 长出第 5 段「Distinguishing Strongest vs. Correct Statements」，Δ=+0.2155，became_best=Y）；iter2 出现首次被采纳的 crossover。

**但三项验收判据仅达成一项**：

| 验收判据 | 结果 |
|---|---|
| ① expand 触发 + 新 section admitted | ✅ 达成（算子机制可工作） |
| ② expand 长出第 5 段进最终 best | ❌ 未达成（overlay 叠 +0.231 更强） |
| ③ vs skillopt −0.0291 gap 收窄 | ❌ **未达成** — expand 版 test=106 4-seed=0.4654 **显著落后** 纯 overlay 基准 8238b5e8=0.5354，Δ=−0.0700，CI 上界<0 |

**根因（capability-ceiling，在验证集与测试集上均成立）**：失败模式高度单一（几乎全为 `Meta-options`，Option 轴已饱和）；overlay 已能叠加 +0.231；expand 长出的第 5 段与现有 Option/Theorem 段**内容重叠**（均讨论 strongest statement），增量信息有限 → 在验证集上不优于 overlay，在测试集上显著退步（亦为 val→test 脱节的又一实例）。

**纪律**：依据 CI 仅判定方向，**不强行启用 expand**。不为生成 section 而消耗 API 预算。

### 9/01 补：v2 修复（针对上述三根因协同修复，零 API 自测全绿）

用户要求「优化算法让其能够对不同轴之间进行交叉测试，或者允许它生成更多的 section」。代码级复核定位 v1 退步的**三处协同根因**，并各做一处修复（全在 `skill_evolver_math.py`）：

## 六、8/31：两项经验假设的实证检验

### 判决 1：emergence（§2.2b）是「结构性空结果」

设计的核心新颖性为「由失败模式聚类自动开启 facet 分支」（K=3 世代复现门控），但此前仅存在于设计文档、未实现（evolver 中硬编码 OFF）。以下用 test=106 真实失败数据检验 cluster key 的本体可行性：

- **Keyword 分类器**：约 87–93% 的失败归为 'meta-options' → 始终为单一类别，无新的失败簇可据以开启分支。
- **theorem_type**：**91% 题为多 type**（96/106）；12 hard-fail = **11 个不重复 type-combo**，唯一重复簇 n=2 < K=3；单 seed 亦呈散度（跨 4 seed 稳定，非伪影）；单 type coarsen 领先仅 n=3。
- → **在 K=3 门控下聚类永不触发，即结构性空结果**；这并非「尚未计算到」，而是**数据本体不产生重复簇**。决定 1（以 theorem_type 作为 cluster key）本体不可行。

**处置（经用户确认）**：写成**实证证伪证据**——作为论文中「设计→实现→实证证伪→根因」的诚实 novelty 主张，比「emergence 未实现」更具说服力。

### 判决 2：唯一正向信号「机制真实但正确层级不显著」

计划中唯一预先计算的正向信号 `routed=0.5487 / Δ+0.0134 / CI[+0.0008,+0.0283]` 原本**仅存在于会话转录中**（grep 检索无对应落盘记录）。用项目自有的 `_META_Q_SIG` 分类器（零 API）落盘重算：

- **数值逐位复现**（0.5487 / +0.0134 / CI=[+0.0008,+0.0283]，30 个 RNG seed 下 CI 下界恒 >0）→ 数值可信，此前仅未落盘。
- 增益机制：has_meta=89 / **not-meta=17**，全部 gain 来自 not-meta 子集，该子集 expand 跨 4 seed 稳定胜 base（+0.157/+0.098/+0.020/+0.059）。
- **但 per-seed 不显著**：per-seed paired t(3)=2.847，**p=0.0653**（未达显著）；per-qid bootstrap 的 CI>0 是 n=106 窄层级**伪精细显著性**。

**判决**：方向 B（双 skill test-time router）不作为提升 claim；**方向 A（将 fallback 逻辑内化为条件化单 skill）机制成立**——not-meta 是 expand 真正有所帮助的题型，值得以一次低代价 API 在 **per-seed 层级**验证。
