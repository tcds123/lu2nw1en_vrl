## 1. 落点: evolver 现在的信号在哪、为什么没用上

【事实】`skill_evolver_aime_v2.py` 与 `tf_global_v2_aime.py` 的现状:

| 信号 | 产生 | 消费 | 是否进入晋升? |
|---|---|---|---|
| `behavior_signature(text)` → `n_chars / n_steps / n_answer_tags / answer_pos / tail_loop / cycle_reps / cycle_block` | `skill_evolver_aime_v2.py:363` | `make_diagnostics` 里 `render_behavior` 渲染成一行英文诊断 (`:1454`, `:1547`) | **否** |
| `harness = {finish_reason, n_truncated, n_out_tokens, max_tokens_used, n_exceptions}` | `tf_global_v2_aime.py:191-219` (`run_one`) | `build_harness_summary` → `summarize_harness` (`:435`, `:455`) 渲染给 patcher | **否** |
| `pass_rate = n_pass / k` | `run_one:221` | `eval_on` → `per_item` → `lcb_score_from_deltas` (`:962`) → 门 `sd > best_val_delta - floor and sl > ci_gate` (`:3327`) | **是, 且是唯一晋升依据** |

即: **进化器"看得见"循环与截断, 但从不因之得分或失分**。LLM patcher 若自己没写「收尾纪律」段, 循环就不会被任何选择压力淘汰。
这也是我们此前"skill 主要机制是减少截断"两次归因被推翻 (issue #66/#67) 的结构性原因: 过程信号只被**描述**, 从未被**选择**。

另有两个口径缺陷 (直接威胁本计划的所有长度/截断统计, 属**阶段 0 必修**):

- **A1 截断未计错**【事实】`tf_global_v2_aime.py:212-215` 先 `evaluate_aime` 再 `if ev["em"]: n_pass += 1`, 不看 `finish_reason`; `paired_five_arm_v1.py:91-95` 同样。codex A1 在 7200 样本里查出 18 条。本地复算 5 臂 6000 样本: 宽松 vs 严格 pass@20 差 **0.05~0.6pp**。
  **但修正后仍不足以定性 (issue #71)**: 截断样本 pred==真值 24/557 集中在 |n|≤20 小整数 (截断 pred 小整数占 57~75%, 未截断几乎为 0), 同题对照下截断 pred 众数与未截断众数完全不同 → 这是 `extract_int_answer:108-111` **"全文最后一个整数"兜底**抽到残文, **不是答对**。
  → 阶段 0 除强制计错外, **必须加 `extract_strict()` (禁用兜底) 与截断样本三态审计** (A 有显式标记且已答对 / B 无标记 / C 无落地), 否则"截断是否必错"这件事本身未被测量过。工具: `for_review/code/tools/audit_truncation.py`。
- **A2 harness 空响应未拦截**【事实】`finish_reason=None` 但 `completion_tokens=0` 且正文 27k 字符的样本存在; `_to_int` 太松。→ 长度均值会被污染。
- **A3 k 票 = oracle pass@20**【事实】`sum(em)>0` 型 k-vote 实为 pass@20; `seed` 参数没有传给 API。→ 报告里不能把它叫 "k 次投票"。

### 2.3 读法 (三条, 直接决定计划走向)

1. 【事实】**现有 skill 是"更长的对"**: s0/d1/d2 严格 pass 增益 CI 显著, 同时干净答对长度 CI 显著**变长**。5 臂里唯一压长度的是 d3 (长度 −127~−264 tok), 但它的准确率增益 CI 含 0。→ 池子里**没有**一个"又准又短"的现成候选可抄, 反馈因子不是复述, 是必须新产出。
2. 【事实】**纯长度变化题占 17%~37%**, 且与成败无关 (FL 列 5~11 题)。→ 逐题「净答对长度」确实有可动的方差, 但**没有任何一臂稳定把 FL 题往下压** (d2_s2 的 11 题 FL 里有效赢 10, 是噪声而非机制)。
3. 【推断】**"纯截断变化但 pass 不变"的题 (TR_pass) 只有 0~2 题**: 与 issue #66/#67 一致 —— 在 30 题上"减少截断"几乎不可能被识别成机制。加反馈因子后指标必须换成**连续长度 + 题级分层**, 不能继续用"截断率"当主指标。

## 3. 设计: 反馈因子怎么做 (以及为什么不用 λ 加权或学分制)

### 3.1 被否掉的两条路 (有模拟证据)

【事实】模拟 (n=30, k=3, Jeffreys Beta-Binomial q=0.25, 镜像 `beta_binomial_lcb`):

- **λ 加权**: 需要一个自有量纲的 "长度分", 一旦为它设系数, 就等于允许"用长度换正确率"。而 30 题下正确率本身 sd=0.03~0.06, 换不起。
- **学分制 (给每条样本一个 [-1,1] 的 credit 再加总)**: 一个**不做任何实事**的固定 skill, 只要每题的 trace "早收尾"就能拿 d=+1 → 伪造 delta **+0.147**; 而真 optimum 的 delta 是 **+0.367**。学分把真信号的 40% 白送给了空转。→ **判否**。
- **逐题预算指示器** (正确→3 分, 干净错→1 分, 截断→0 分): 仍能选出真 optimum (+0.367, P>0=1.000), 且不可通过"假装早收尾"获益 (假早收尾只能拿到 1 分档)。

### 3.2 采用的方案: 三态预算指示器 + Pareto 晋升门

**逐样本三态** (只依赖已有的 `em` + `finish_reason`, 零新调用):

```
state(q,s) = PASS_CLEAN   若 em 且 finish_reason != 'length'
           = FAIL_CLEAN   若 非 em 且 finish_reason != 'length'
           = BUDGET       若 finish_reason == 'length'   (或 A2 类空响应)
```

**逐题预算指示器** (非仿射, 不可用线性权重等价表示):

```
B(q) = 1  若 ≥1 个 PASS_CLEAN
       0.5 若 无 PASS_CLEAN 但 ≥1 个 FAIL_CLEAN
       0  若 全部 BUDGET
```

**两道晋升门 (字典序, 不做加权和)**:

1. **正确率非劣门 (硬)**: 在**同一 k、同一 cap、同一 prompt** 下, 候选的严格 pass LCB 不低于 S₀ 的 LCB 减去预注册 δ_acc。δ_acc 取 **−1pp** (低于此即视为退步, 不看长度)。
2. **效率改进门 (硬, 独立成立)**: 在"两臂都 PASS_CLEAN 的题"上取配对净长度 `L_cand(q) − L_s0(q)` 的题级 bootstrap 95% CI 上界 < 0, 且点估计 ≤ **−15%**。只在共同可解子集上比, 避免"把难题做错来变短"。

两门同时成立才 ACCEPT; 只成立一门 → 进 **Pareto 池** (备选/多样性来源), 不晋升。

### 3.3 循环与重复: 复用已有检测器

【事实】`find_tail_loop` (尾窗 120 字符 × ≥5 重复) 与 `find_cycle` (块长 160 × ≥3 重复) 已实现并被 `behavior_signature` 调用, 但结果只喂 `render_behavior` 文案。
计划**不改检测器**, 只把两个布尔量 `tail_loop≥5 / cycle_reps≥5` 作为:

- **分诊器**: 命中循环的失败样本 → 强制贴 `Behavior-Loop` facet 标签 (已有 EFL 合并逻辑, `:1099`);
- **不准入判据**: 某候选若在**共同可解子集**上循环率上升, 即使长度下降也不进 ACCEPT (防"靠早放弃变短");
- **一致性自检**: 用 `completion_tokens` 与 `n_chars` 的比值变化判断"变短是真收尾还是被截断" (A1 修好后两者应当同向)。

### 3.4 记账口径 (必须与晋升口径分离)

- 对外报告 **6 个数, 绝不合成一个**: `strict_pass`, `trunc_rate`, `clean_pass_tokens_p50`, `clean_fail_tokens_p50`, `loop_rate`, `n_B_calls`。
- 「总 token」按 **每次 B 调用 × (输入 + 输出)** 记, 认领 skill 长度的成本 (codex E4: cap 只约束输出, 不等于总成本相等)。skill 每长 1k 字符 ≈ 250 输入 token × N 次调用。
- 至少留 **2 个 Pareto 点** (一个更准、一个更短) 进池, 这是"多目标多样性"的具体落法。

## 4. 为什么必须换数据集 (不是可选优化)

【事实】零效应模拟: n=30 题, k=3 → delta 的 sd = 0.027(p0=.10) / 0.039(p0=.20) / 0.052(p0=.33) / 0.061(p0=.50); P(delta ≥ +2pp | 无效) = 0.22~0.38; k 提到 5 只把 sd 从 0.0399 压到 0.0334。
【推断】"提长度但不能降准确率"要求同时判两个量, 30 题的联合检验功效更低; 而 §2 已显示 30 题的"纯长度题"只有 5~11 个。

数据集路线 (结合 codex §12 / `DATASET_SELECTION_REVIEW_20261114.md`):

| 优先级 | 数据集 | 规模 | 为什么适合长度优化 | 前置成本 |
|---|---|---|---|---|
| **P0** | **HumanEval+ / MBPP Pro** (已在 `data/CodeEval-Pro`) | HumanEval+ 164 / MBPP Pro 378 | 可执行判分 (无答案等价歧义); 长度方差极大 (短题 200 tok, 长题 8k+); 与 codex 的 APPS 线同族但更便宜 | 判分器已就绪, 零 |
| **P1** | **省力优先**: AIME24 + AIME25 合并 = **60 题** | 60 | 现有判分/协议/缓存全部复用, 只扩题量不换范式 | 0 新代码 |
| **P2** | LCB 未用窗口 200 题 | 200 | 规模化 + 可执行 | 需固定窗口与题源 commit (`36f292ea…`) |
| 备选 | HMMT / MATH-500 / OlympiadBench | — | codex §12 指出**必须新写判分器** (分数/根号/负数), 且 HMMT 单轮仅 30 题 | 新判分器 + 新模板, 不能只改 DATA 路径 |

**决策**: 阶段 1 用 **P1 (AIME24+25, 60 题) 做天花板检验**——若 60 题仍功效不足, 阶段 2 直接上 **P0 (MBPP Pro 378 子集 150 题)**, 不回头啃 AIME。
【假说】AIME 的地板 (12/30 全错) 是"题不可解"而非"太长被截断", 因此 AIME 的净长度方差有限; 代码题的长度方差更大, 更适合作为长度轴的主战场——需阶段 1 用实测长度分布验证。

## 5. 分阶段排期 (每阶段都有"停"的判据)

### 阶段 0 — 先把尺子修好 (0 API, 半天)

1. `tf_global_v2_aime.py:212-215` 与 `paired_five_arm_v1.py:90-95`: 改为 `if ev["em"] and finish_reason != "length"`; 保留 `em_loose` 字段以便与历史数字对照。**改动后所有历史结论需按严格口径重算** (§2 已给出)。
2. `run_one` 增记录 `n_chars / tail_loop / cycle_reps` 的**逐样本**值 (现在只有最后一次采样的 text), 供 §3.3 使用。
3. A2: `finish_reason=None` 且 `completion_tokens==0` 且有正文 → 记 `BUDGET`(不确定) 单列, 不进长度均值。
4. **截断审计 (issue #71)**: 加 `extract_strict()` 并跑 `for_review/code/tools/audit_truncation.py`; 阶段 1 的 pilot **必须落全文**, 以便对 A 类样本人工复核。
5. 零 API 回放: 对 5 臂 + cap 扫描已完成批次重算 §2 表, 落 `for_review/results/two_axis_baseline_20261116.json`。
**停**: 若严格口径下"CI 显著变长"的结论在 cap16384 与 cap8192 两个 cap 上都不成立 → §3.2 的效率门需重新校准 (但计划继续)。

### 阶段 1 — pilot: 60 题 (AIME24+25), 只测"是否存在可动空间" (~3600 调用)

- 题: 60 题全量 (AIME24 30 + AIME25 30); 每臂 k=5, seed=2; cap 固定 16384; **同一 prompt** (codex A4: 不要跨 cap 比)。
- 臂: `S₀` / `S₀ + 手写"停算纪律"段` (基线: 人类最短 prompt 能做到多少)。
- 产出: 每题 (严格 pass, 干净答对长度, BUDGET 率) 三元组 + 长度分布分位。
**停 (go/no-go)**: 「手写停算纪律」若在共同可解子集上长度下降 ≥15% 且 pass 非劣 → 说明**长度可动, 值得做进化**; 若完全不动 → 长度轴由"题本身难度"主导, 转到 P0 代码题再验。

### 阶段 2 — 反馈因子接入进化, 独立题确认 (~6000 调用)

- 在阶段 1 的题集上跑 2 轮进化 (每轮 3 候选 × 60 题 × k=5 ≈ 900 调用 ⇒ 2 轮 1800), 晋升用 §3.2 两道门。
- 冠军拿到**独立未参与进化的题 (AIME25 后半 + APPS/HumanEval 各 50)** 上确认: 预注册 δ = **acc ≥ −1pp 且 clean_pass_tokens ≤ −15%**, 题级 bootstrap CI 判定。
**停**: 冠军在独立题上 acc 跌破 −2pp → 记为"效率换准确率失败", 照实写负结果, 不调参挽救。

### 阶段 3 — 消融 (~16000 调用, 仅在阶段 2 出现正结果时启动)

4 臂: `L0`=现状 evolver / `L1`=+三态预算指示器 / `L2`=+Pareto 双门 / `L3`=+循环准入判据。
测: strict_pass, 净长度, BUDGET 率, 循环率, n_B_calls (成本)。主断言: `L2 > L0` 在净长度上显著, 且 `L2` 的 pass 不劣于 `L0`。

**总预算**: 0 + 3600 + 6000 + 16000 ≈ **25.6k B 调用**, 20 RPM 串行 ≈ **21.3 h** 墙钟 (不含 LLM patcher 调用)。若阶段 1 判否, 只花 3.6k (≈3 h)。

## 6. 淘汰规则 (预注册, 防又一次 winner's curse)

1. 任何候选的每题 B 调用数不得超过当时最优的 **2×**; 超了直接淘汰 (否则"多选题"必然赢)。
2. 每次 run 必须留下 **≥2 个 Pareto 点** (更准 / 更短各一), 只有 1 个点视为搜索失败。
3. 所有预注册轴 (pass/长度/BUDGET/循环/成本) 全量报告, **不许事后挑轴**。
