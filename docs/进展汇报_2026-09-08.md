## 概述

9 月以来的核心问题：在**真 S₀ 起点零 SkillOpt 嵌套**的公平条件下，evolver 能否 CI-gated 越过 SkillOpt 基线（test=106 4-seed 同窗口 paired CI95 下界 > 0）。3-break 框架（break-① 段级 donor 池 / break-② per-type expand / break-③ per-subset 准入）已使干净路径产出 `theo_iter6`（test=0.5542），但与 SkillOpt 同窗口均值（0.5605）的 paired CI95 = [−3.07, +4.32]pp 仍含 0——**方向一致但未越线**。诊断定位系统瓶颈为「val→test 不迁移」与「算子H（strengthen）结构性零触发」。

## 一、当前算法：facet-tree 算子进化（3-break 框架）

evolver 在 LiveMathematicaBench（177 题，1:3:6 拆为 train=18 / val=53 / test=106）上对 system prompt 做 facet-tree 遗传进化。每个 skill 是一个可分解为命名段（section）的 markdown，算子作用于段级。

**核心算子**：

| 算子 | 作用 | 关键约束 |
|---|---|---|
| `facet_edit`（单轴精炼） | 改一个命名段最多一个 bullet | `facet_edit_guard` 物理强制非目标段逐字不变 |
| `overlay`（跨轴叠加, E） | 每代末把各轴历史最优段拼进同一 skill | LOST guard + CI>0 准入；解决单轴改进不可累积 |
| `expand`（展开新段, G） | 失败驱动长新决策程序/领域特化 section | `find_uncovered_type_for_expand` 按段名签名挑**未覆盖的非-meta**类型；显式 skip meta |
| `crossover`（重组, X） | 2-parent 段嫁接 | guard + LLM coherence pass；本 run 开 pair_retries=2/cohere_retries=1/allow_merge |
| `strengthen`（加固, H） | 给现有段加一条 bullet | 两入口均结构性不可达（见 §三），9/8 方案1 修复 |

**3-break 改进**（针对诊断出的三处结构性失效）：

- **break-① 段级 donor 池**：`donor_topk=2`，crossover/overlay 可从跨历史 top-K 段取 donor，而非仅当前 best。
- **break-② per-type expand 覆盖选择**：`find_uncovered_type_for_expand` 按失败类型签名选未覆盖类型，保证 expand 攻的是「新洞」而非已饱和的 Meta-options。
- **break-③ per-subset 准入**：`subset_admit` 把整体 delta 被 meta 89 题淹没的 not-meta 增益救援出来（`classify_item_meta` 区分 meta/not-meta），避免正向 not-meta 信号被 meta 噪声埋没。

**CI-gated 纪律**：全程以 per-qid paired bootstrap CI95 判方向，test=106 4-seed eval_k=3 为定论指标，不看点估计。这避免了 eval 窗口方差造成的假信号。

## 二、已达成的实验结果

### 真公平起点血统链（零 SkillOpt 嵌套）

| 版本 | 来源 | test=106 4-seed | vs SkillOpt |
|---|---|---|---|
| S₀（`68571cb2`，1018字） | 真 initial.md 起点 | 0.2956 | −2.65pp |

- **泛化增益成立**：theo_iter6 vs S₀，Δ=+0.2586，CI 下界显著 >0——算法从 S₀ 学到真泛化。
- **与 SkillOpt 的差距**：theo_iter6 vs SkillOpt 同窗口 paired CI95 = [−3.07, +4.32]pp，**含 0 = 未越线**。差距由早期的 −8.4pp 收窄至 −0.63pp，但 CI-gated 北星（下界>0）尚未达成。

### 9/7 warm-start run（test 回归，但 strengthen 归因无效）

从 theo_iter6 续跑 4 iter。**test=106 4-seed 有效**：新产物 `57f757c6` 回归至 0.5417（−1.25pp vs theo_iter6），同窗口 vs skillopt CI95=[−6.05,+2.20]pp 含 0 但方向劣——**theo_iter6 仍是最强公平 artifact**，此结论可信。

⚠️ **纠正**：9/7 run 启动命令**漏 `--facet_tree`**（有 `--facet_axes`/`--freeze_facet` 但无 `--facet_tree` dispatch flag）→ 走 **flat path**（`generate_candidates`→cand0/1/2/3 round-robin focus），**不执行 `_run_facet_tree`**，即 expand/overlay/crossover/strengthen/per-type 全部不跑。故"9/7 坐实 strengthen 零 fire"**归因无效**——flat path 本就没有 strengthen 代码，零 fire 是必然的，非算子缺陷证据。9/7 的产物是 flat-path `generate_candidates` 产出的，其 Existence 轴来自 round-robin focus 而非 expand 算子。**test 数字可信，strengthen 归因作废。**

## 三、根因诊断：算子H（strengthen）结构性零触发

⚠️ **证据来源纠正**：仅 **9/4/9/5 run**（PID 44625，`strengthen_run_20260904_184549.log`，命令带 `--facet_tree`，日志有 `🌱 facet-tree init` + 8 个 `Facet-Tree Iter`，真 facet-tree 路径）坐实 strengthen **从未 fire**（8 iter 全程零触发）。9/7 run 漏 `--facet_tree` 走 flat path，**不能作为 strengthen 零 fire 证据**（已从证据链剔除，见 §二纠正）。代码级诊断定位两入口皆不可达（基于 9/4/9/5 真 facet-tree run + 源码级核实）：

1. **`target is None`（全覆盖）入口**（L2302）：要求所有非-meta 失败类型都有专属段。但 `find_uncovered_type_for_expand` 每 iter 都能找到新未覆盖类型（Implication→Existence→Quantifier→Regularity），4 iter 内类型空间远未穷尽，`target` 永远非 None。
2. **per-type 饱和入口**（L2367 `target in type_best_delta`）：`type_best_delta[target]` 只在 expand **采纳**时设置，而采纳即覆盖 → `find_uncovered_type` 跳过该类型 → 同类型永不再选 → 该分支为死代码。

**后果**：theo_iter6 停在「axis-bare 单轴」，双向测试启发式关键词全缺。strengthen 本应在既有段上长第 2 条双向决策 bullet 来关闭 ~0.5pp gap，但从未触发。

## 四、9/8 方案1：per-type strengthen 触发放宽（进行中）

### 改动（5 处，self-test 全绿，S₀ md5 字节复现未破坏）

`skill_evolver_math.py`：

1. 新函数 `find_covered_failing_type(counts, section_keys, exclude=None)`（L325）——镜像 `find_uncovered_type_for_expand`，找**已覆盖但仍在失败**的非-meta 类型。`exclude=target` 是 too-early-abandonment guard（给新段 1 iter 自然使用窗口）。
2. `--strengthen_per_type` flag（BooleanOptionalAction, 默认 off = 字节复现既有 run）。
3. 控制流（L2450-2463）：expand 候选循环后、`max-sections-reached` 前，追加 ADDITIVE 路径——若存在已覆盖+仍失败类型，fire strengthen 加固既有专段。**expand 永远优先（主探索不被 block）**。
4. self-test (q1)-(q6)：纯函数断言（covered-failing 返回最高频 / 无失败→None / skip-meta / exclude guard / 确定性 / 与 find_uncovered_type_for_expand 互补互斥）。

## 五、若方案1 不足的后续方向（已设计）

按用户方法论锚点「坚持探索不能半途而废，遇到问题不直接判算法证伪，而要研究为什么没接受、如何优化才能接受」：

- **方向 B（首要）：跨轴交叉变异遗传**。当前 crossover 2-parent 段嫁接 guard/cohere 频繁失败。做多 parent 段组装（3+ donor 同台）或基于失败分布定向选 donor。已设计 `recombine_facets_multi` + `select_donors_directed` + `--xo_multiparent`/`--xo_donor_directed`。
- **方向 C：树状回退 + 历史组合复现**。祖先链回溯，从被淘汰但含未被继承好段的失败节点取 donor。已设计 `select_donor_rescue`（uninherited 段 md5 比对）+ `trace_ancestors`（parent_idx 链）+ `--donor_rescue`/`--ancestor_replay`。
